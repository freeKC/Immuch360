# Immuch360

**당신의 미디어. 모든 화면. 모든 시점.**

기기, NAS, Immich 서버, 카메라, 드론에서 오는 평면, 360°, 3D 사진과 동영상. 계정이 필요 없습니다. Immuch360은 사진과 동영상이 있는 곳에서 바로 읽어 각 파일에 맞는 뷰어에서 재생하는 무료 오픈 소스 앱입니다: 평면으로, 둘러볼 수 있는 구체로, 3D로, 또는 헤드셋에서 사방을 둘러싸게. 휴대폰, 태블릿, TV, Meta Quest 헤드셋, 컴퓨터에서 실행됩니다.

**New: your flat photos, in 3D.** On a computer, "Make 3D (AI)" turns one photo into a 3D photo, a 3D scene or a 360° panorama; in a Meta Quest 3 or 3S, "AI relief" shows any flat photo in 3D. Experimental, and everything runs on your own machines: [see how](#turn-one-photo-into-3d-a-scene-a-panorama).

## 누구를 위한 앱인가요

- **360°나 3D로 촬영하고** 사진을 평면으로, 이중으로, 늘어진 채로 보는 대신 그 안을 둘러보고 싶다면: [360°, VR180, 3D](#explore-panoramas-360-vr180-and-3d).
- **사진과 영화가 NAS, 컴퓨터, Plex, Immich에 있고** 아무것도 복사하지 않고 TV에서 보고 싶다면: [TV에서](#watch-on-the-tv-with-the-remote), [NAS, 공유, Plex](#play-the-files-of-a-nas-a-computer-a-media-server-or-plex).
- **Meta Quest가 있고** 내 사진과 동영상 속에 들어가 보고 싶다면: [헤드셋에서](#step-inside-your-photos-and-videos-with-a-meta-quest).
- **사진이 평면이라** 3D 카메라 없이 3D로, 헤드셋에서 몸을 기울여 들여다보는 장면으로, 또는 360° 파노라마 안에서 보고 싶다면: [사진 한 장을 3D, 장면, 파노라마로 바꾸기](#turn-one-photo-into-3d-a-scene-a-panorama), 새 기능, 내 컴퓨터에서 AI가 만듭니다.
- **Immich를 운영하고 있고** 그 앱에 더해 몰입형 뷰어와, 휴대폰으로 로그인하는 큰 화면을 원한다면: [Immich 라이브러리](#keep-your-immich-library-with-more), [Immich와 비교](#compared-with-immich).
- **Tapo 카메라로 집을 지켜보고 있고** 사진 옆에서, TV에서도 카메라를 보고 싶다면(아직 실제 카메라로 확인하지 않음): [홈 카메라](#watch-your-home-cameras-on-the-big-screen).
- **DJI 드론을 날리고** DJI Fly 없이 휴대폰에서 실시간 화면을 보고, 함께 있는 사람들을 위해 Meta Quest나 Android TV에서도 보고 싶다면(실험적): [드론](#see-what-your-drone-sees-on-your-phone).

만들어야 할 Immuch360 계정은 없으며, 우리에게 오는 것도 없습니다: 앱은 사용자의 기기와 사용자가 고른 서버하고만 통신하며, AI 구성 요소는 사용자가 요청할 때만 다운로드합니다.

*Linux와 macOS: desktop build 11을 2026년 10월 26일 Ubuntu 24.04에서, 테스트용 Immich 서버와 테스트용 공유가 있는 컨테이너 안에서 시험했고, 작성자가 Mac에서도 시험했습니다. AI 행은 desktop build 13 코드의 테스트 build로 2026년 10월 27일부터 29일까지 확인했습니다: 3D 사진은 Linux PC의 컨테이너에서 Linux 앱으로, 장면은 RTX 4060 노트북의 Windows 앱과 같은 Linux PC의 엔진으로, 360° 파노라마는 그 노트북에서 만들었습니다. 아직 Mac에서는 시험하지 않았습니다.*

✅ 해당 플랫폼의 앱에서 지원 · ❌ 제공하지 않음 · 🔜 계획 중 · 🔧 CI 소스 코드에 있고 프로젝트 CI가 해당 시스템에서 빌드하고 실행했지만, 아직 그곳에서 실제 서버, 공유, 카메라로 확인하지 않음 · 평면만: 컴퓨터용 360° 동영상 렌더러가 Windows 전용이라 동영상이 안내 메시지와 함께 평면으로 재생됨; LG TV에서는 webOS가 동영상 프레임을 구체에 넘겨줄 수 있는지 아직 측정해야 하며, 테스터의 Samsung TV에서는 브라우저가 3D 화면에 검은 동영상 프레임을 넘겼습니다. "한쪽 눈"은 3D 파일이 평면 화면에서 왼쪽 눈만 보여준다는 뜻입니다. LG와 Samsung 열은 하나의 별도 TV 앱입니다: LG 버전 1.0.0은 공유와 Plex를 실제 서버로, 카메라를 프로젝트 빌드 호스트의 모의 카메라로 확인했지만 아직 TV에서는 확인하지 않았고, Samsung은 테스트 build 0.2.0입니다. 모든 ✅가 실제 기기에서 확인된 것은 아닙니다: 어디서 무엇을 확인했는지, 그리고 아직 확인해야 할 것은 [기능](../docs/immuch360/features.md), [플랫폼 지원](../docs/immuch360/platform-support.md), [호환성](../docs/immuch360/compatibility.md)에 있습니다.

AI 행에서 "읽음"은 기기가 컴퓨터가 만든 것을 열기만 하고 스스로 만들지는 않는다는 뜻입니다: 3D 사진은 두 눈 이미지를 나란히 보여 주고, 장면은 작은 3D 장면 표시가 붙은 사진으로 보이며, 파노라마는 360° 뷰어에서 열립니다. AI 표시란 "AI 360°" 배지, "사진 가장자리 너머는 AI가 생성함" 문장, 원본 사진의 윤곽을 말하며, iPhone, iPad, LG, Samsung 앱은 아직 이를 보여 주지 않습니다. 무언가를 만드는 것은 컴퓨터와 Quest뿐입니다. 이 행들에 대해 확인한 내용은 [사용 방법](#turn-one-photo-into-3d-a-scene-a-panorama)에 있으며, 기능 문서와 플랫폼 지원 문서에는 아직 없습니다.

- **Android 휴대폰과 태블릿**: 모든 기능을 갖춘 앱, 터치와 자이로스코프, 모든 소스 지원; build 32부터는 컴퓨터에서 만든 360° 파노라마를 AI 표시와 함께 엽니다.
- **iPhone과 iPad**: 모든 기능을 갖춘 앱이지만, 360° 동영상 플레이어는 재생과 일시정지만 지원하고, Tapo 실시간 화면과 휴대폰으로 로그인하기의 휴대폰 쪽 기능은 다음 iOS 릴리스에 포함되며, Apple이 멀티캐스트 권한을 허용하기 전까지 DLNA 검색은 유니캐스트 요청을 보냅니다.
- **Android TV와 Google TV**: 리모컨으로 조작하는 같은 APK이며 기본은 어두운 테마입니다. 뷰어 역할만 합니다: 백업, 업로드, 편집기는 숨겨져 있고 세부 정보는 읽기 전용이지만, 사진은 여전히 키 하나로 회전됩니다. 모든 검색 필터가 리모컨으로 동작합니다: 위치와 카메라는 선택지를 목록으로 열고, 날짜 필터는 모든 선택지를 보여주며, 태그, 위치, 날짜, 미디어 유형, 별점, 표시 옵션 시트는 지우기와 적용 버튼을 선택지 옆, 오른쪽으로 한 번 이동한 곳에 두고 화면 높이의 대부분을 사용합니다. 사진 그리드는 이미지 메모리를 덜 사용하며, 방향키를 누르고 있으면 최대 초당 약 10줄씩 이동합니다. build 28부터는 휴대폰에서 QR 코드나 짧은 코드로 로그인할 수 있습니다(두 에뮬레이터 사이에서 코드를 입력해 시험했으며, 카메라로는 아직 시험하지 않음). build 29부터는 동영상의 타임 바가 리모컨 포커스를 받고, 영화에는 오디오와 자막 메뉴가 생기며, 공유의 다음 파일이 자체 컨트롤과 함께 열립니다. Google TV 에뮬레이터에서 확인했으며, build 28은 10월 23일 실제 Android TV에서 실행했고, 그때 발견된 동영상 문제를 build 29에서 수정했습니다. 이 수정은 에뮬레이터에서 확인했지만 아직 그 TV에서는 확인하지 않았습니다. build 30부터는 Drone 카드가 휴대폰이 중계하는 DJI 드론의 실시간 영상을 드론의 수치, 장애물 링과 함께 보여줍니다(실험적): 페어링과 화면은 10월 25일 TCL Android TV에서 시험했으며, 이전 중계 방식에서는 끊김과 초록빛이 있었습니다. 10월 26일 build 30에서는 이를 해결하는 안정 스트림 덕분에 비행 중에도 그 TV에 화면이 계속 들어왔으며, 멈춤은 7번이었습니다.
- **webOS 5.0 이상의 LG TV**: 리모컨과 Magic Remote용 별도 앱으로, [immich-tv-webos](https://github.com/Seeky91/immich-tv-webos)를 기반으로 합니다: 360° 사진을 구체로 보여주는 Immich 뷰어, 키 하나로 사진 회전, 어두운 테마, 앱의 89개 언어(TV 앱 자체의 일부 문구는 아직 영어); TV에서 돌아가는 자체 서비스를 통한 네트워크 공유, Plex, Tapo 카메라의 실시간 화면(SMB는 webOS 22부터); 360° 동영상은 평면. 10월 24일 LG Content Store에 제출한 버전 1.0.0은 LG Cloud Test Lab에서 세 모델의 webOS 25 TV로 실행했습니다: 로그인, 휴대폰 로그인 페이지, 사진, 앨범, 동영상, 360° 화면, 슬라이드쇼, 검색, 모든 페이지에서의 뒤로가기. 버전 0.1.0은 테스터의 LG TV(webOS 22)에서 실행되었습니다. 공유와 Plex는 실제 서버로, 카메라는 프로젝트 빌드 호스트의 모의 카메라로 확인했으며, 아직 TV에서는 확인하지 않았습니다.
- **Tizen 5.5 이상의 Samsung TV**: Samsung TV용으로 패키징한 LG TV 앱으로, 테스트 build 0.2.0을 직접 서명해 설치해야 합니다: 리모컨용 Immich 뷰어, 직접 입력하는 로그인(서버 주소, 그다음 이메일과 비밀번호 또는 API 키), 슬라이드쇼, 구체 위의 360° 사진, 키 하나로 사진 회전, TV가 지원하는 기능을 알려주는 정보 페이지를 제공합니다. 휴대폰으로 로그인, 공유, Plex, 카메라는 아직 없고, 360° 동영상은 안내와 함께 평면으로 재생됩니다. 버전 0.1.0은 테스터의 Tizen 9 Samsung TV에서 실행되었습니다: 4K까지의 사진과 동영상은 재생되었고, 4K를 넘는 것은 디코딩되지 않았으며, TV의 브라우저는 3D 화면에 검은 동영상 프레임을 넘겼습니다. 버전 0.2.0에는 그때 나온 수정(TV 디코더를 넘는 동영상이나 멈추는 동영상에 대한 메시지, 안내와 함께 평면으로 재생되는 360° 동영상)이 들어 있으며, 아직 TV에서 실행하지 않았습니다.
- **Meta Quest 2, Pro, 3, 3S**: 창 형태의 앱과 몰입형 화면, 그리고 build 30부터 휴대폰이 중계하는 DJI 드론의 실시간 영상을 보여주는 Drone 카드(실험적)를 제공하며, 이 카드는 build 30에서 처음 테스트합니다. HEVC가 안전한 코덱이며, Quest 3에서는 H.264가 약 4096x2304에서 한계에 이릅니다. 테스트한 기기는 Quest 3뿐이며, Quest 2, Quest Pro, Quest 3S는 아직 테스트하지 못했습니다. build 32부터 Quest 3 또는 3S에서는 AI 입체감이 평면 사진을 헤드셋 안에서 계산해 3D로 보여 주고, 컴퓨터에서 만든 3D 사진, 장면, 파노라마도 3D로 열립니다(실험적).
- **Windows 10과 11**: 미리보기 단계이며, 갤러리 대신 폴더를 사용하고, 평면 및 360° 동영상을 위한 전용 플레이어(libmpv), 그래픽 칩에서 스티칭되는 원본 파일, 프로그램으로 열거나 창에 끌어다 놓은 파일과 폴더, APROGSYS가 서명한 설치 프로그램 또는 ZIP을 제공합니다. desktop build 13부터 "3D 만들기 (AI)"가 프로세서에서 사진을 3D 사진과 3D 장면으로, 8 GB 그래픽 카드에서 360° 파노라마로 바꿉니다.
- **Linux**: 프로젝트의 CI가 빌드한 .deb와 .rpm이며, Ubuntu 22.04와 24.04, Debian 12, Fedora 40과 44에 설치해 확인했습니다. 사진, 360° 사진, 그리고 시스템의 libmpv로 재생하는 평면 동영상을 지원하며(360°, 3D, 원본 동영상은 안내 메시지와 함께 평면으로 재생), desktop build 7부터는 X11 세션에서도 하드웨어 경로로 그립니다. SMB 공유는 Ubuntu 22.04와 Debian 12부터 지원합니다. 키링(GNOME Keyring 또는 KWallet)이 없어도 첫 실행 시 더 이상 25 s 동안 멈추지 않으며, 비밀번호를 세션 동안만 보관하고 설정에서 그 사실을 알려줍니다. desktop build 13부터 "3D 만들기 (AI)"가 프로세서에서 3D 사진과 장면을, 8 GB 그래픽 카드에서 360° 파노라마를 만듭니다(작은 크기로만, Intel 그래픽에서 시험함). 아직 실제 Linux PC에서는 실행하지 못했고, WSLg와 컨테이너에서만 실행했습니다.
- **macOS**: 프로젝트의 CI가 빌드한 DMG와 ZIP이며, 유니버설이고 서명되지 않았습니다(Gatekeeper가 한 번 묻습니다). 앱이 실행되고, Finder에서 넘긴 것을 포함해 전달받은 파일과 폴더를 열며, 비밀 정보를 로그인 키체인에 보관하고, 자체 libmpv로 평면 동영상을 재생합니다. 이는 먼저 프로젝트의 CI Mac에서 확인했고, 2026년 10월 26일 작성자가 Mac에서 desktop build 11을 시험해 보았으며 잘 동작했습니다. desktop build 13부터는 3D 사진과 장면도 프로세서에서 만듭니다(아직 Mac에서 시험하지 않음). Mac에서는 아직 360° 파노라마를 만들 수 없습니다.

<a id="install"></a>
<a id="get-it-on-your-device"></a>
## 기기에 설치하기

기기의 스토어에 게시된 곳에서 앱을 받거나, 그동안은 [Releases](https://github.com/freeKC/Immuch360/releases) 페이지에서 받으세요.

### Android 휴대폰과 태블릿

1. [Google Play](https://play.google.com/store/apps/details?id=com.aprogsys.immuch360), 또는 [Releases](https://github.com/freeKC/Immuch360/releases) 페이지의 APK: 휴대폰용 `Immuch360-v<version>-arm64-v8a-release.apk`, 어디서나 동작하는 범용 `Immuch360-v<version>-release.apk`도 있습니다.
2. 공식 Immich 앱과 함께 설치할 수 있습니다. GitHub의 APK는 자동으로 업데이트되지 않으므로 Releases 페이지를 계속 확인하세요. 스토어에서 앱을 한 번 설치하면 그 뒤로는 해당 스토어의 업데이트를 받으세요.

### iPhone과 iPad

1. App Store 버전은 Apple의 심사를 기다리고 있습니다. 게시되기 전까지는 Mac에서 Xcode로 앱을 직접 빌드하세요. [직접 빌드하기](../docs/immuch360/build.md)를 참고하세요.
2. "서버 없이 사용"을 탭하거나, 서버에 로그인하려면 "Immich 서버에 연결"을 탭합니다. build 24부터 둘 다 환영 페이지에 있습니다.

<a id="android-tv-and-google-tv"></a>
### Android TV와 Google TV

1. Google Play가 TV용 앱을 제공하기 전까지는 [Releases](https://github.com/freeKC/Immuch360/releases) 페이지의 범용 `Immuch360-v<version>-release.apk`를 사용하세요.
2. TV에서 개발자 옵션과 USB 디버깅을 켭니다(Google TV에서는: 설정, 시스템, 정보에서 "Android TV OS build"를 일곱 번 선택한 다음, 설정, 시스템, 개발자 옵션. 이름은 TV마다 다릅니다).
3. 같은 네트워크의 컴퓨터에서 adb(Android SDK Platform Tools)로: `adb connect <address of the TV>`, TV에 나오는 확인 창을 수락한 다음 `adb install -r Immuch360-v<version>-release.apk`.
4. 앱이 배너와 함께 TV의 앱 목록에 나타납니다. 다음 릴리스도 같은 방법으로 설치하세요: `-r`이 로그인과 설정을 유지합니다.

<a id="lg-tvs-webos"></a>
### LG TV(webOS)

1. 버전 1.0.0은 LG 심사 중입니다. LG Content Store에 올라오기 전까지는 Developer Mode로 설치합니다: webOS 5.0 이상의 LG TV, 같은 네트워크에 있는 컴퓨터, 무료 LG 개발자 계정이 필요합니다. TV에서 LG Content Store로 Developer Mode 앱을 설치하고 로그인한 뒤, Dev Mode Status를 켜고 TV가 다시 시작되도록 둡니다. TV의 IP 주소와 앱에 표시되는 passphrase를 적어 두세요.
2. 컴퓨터에 webOS CLI를 설치합니다(Node.js 18 이상): `npm install -g @webos-tools/cli`. 그런 다음 `ares-setup-device`로 TV를 등록하고(IP 주소, 포트 9922, 사용자 `prisoner`), passphrase를 묻는 `ares-novacom --device <name> --getkey`를 실행합니다.
3. [webOS 1.0.1 사전 릴리스](https://github.com/freeKC/Immuch360/releases/tag/webos-v1.0.1)에서 UHD TV라면 `Immuch360-webOS-1.0.1.ipk`를, LG가 1280x720 앱을 제공하는 Full HD TV라면 `Immuch360-webOS-1.0.1-1280x720.ipk`를 다운로드합니다. `SHA256SUMS.txt`로 확인한 다음 `ares-install --device <name> Immuch360-webOS-1.0.1.ipk`를 실행합니다. webosbrew의 [webOS Dev Manager](https://github.com/webosbrew/dev-manager-desktop)를 쓰면 명령줄 없이 같은 작업을 할 수 있습니다.
4. Developer Mode 세션은 1000시간 동안 유지되며 Developer Mode 앱의 EXTEND 버튼으로 연장할 수 있습니다. 세션이 만료되면 TV가 이렇게 설치한 앱을 삭제합니다. 자세한 내용은 [webos/README.md](../webos/README.md#install-on-a-tv-in-developer-mode)에 있습니다.
5. 앱이 LG Content Store에 올라오면 Developer Mode로 설치한 사본을 제거하고 스토어에서 설치하세요.

<a id="samsung-tvs-tizen"></a>
### Samsung TV(Tizen)

1. 테스트 build 0.2.0은 Samsung 스토어에 없으므로 직접 설치합니다. Tizen 5.5 이상의 Samsung TV(2020년 이후 모델), 같은 네트워크에 있는 컴퓨터, Samsung 계정이 필요합니다. TV에서 Apps, App Settings로 가서 12345를 입력하고, Developer mode를 켠 뒤 컴퓨터의 IP 주소를 입력하고 TV를 다시 시작합니다.
2. [Tizen 사전 릴리스](https://github.com/freeKC/Immuch360/releases/tag/tizen-v0.2.0)에서 `Immuch360-Tizen-0.2.0.wgt`를 다운로드하고 `SHA256SUMS.txt`로 확인합니다. Samsung TV는 해당 TV용으로 서명된 앱만 설치하므로, TV의 DUID가 등록된 Samsung 인증서로 패키지를 다시 서명해야 합니다: 커뮤니티 도구인 [Apps2Samsung](https://github.com/Apps2Samsung/Apps2Samsung)이 DUID를 읽고, Samsung 계정으로 패키지를 서명해 설치까지 해 주며, Samsung Certificate Extension이 있는 Tizen Studio로 같은 작업을 직접 할 수도 있습니다.
3. 앱을 열고 서버 주소를 입력한 다음 이메일과 비밀번호 또는 API 키를 입력해 로그인합니다. "이 TV 정보"에는 TV가 지원하는 기능이 텍스트와 QR 코드로 표시됩니다: 작동하지 않는 점과 함께 이 텍스트를 [Issues](https://github.com/freeKC/Immuch360/issues)나 [Discussions](https://github.com/freeKC/Immuch360/discussions)에 올려 주시면 가장 큰 도움이 됩니다.

<a id="meta-quest"></a>
### Meta Quest

1. [Horizon Store](https://www.meta.com/experiences/immuch360/1384208401440714/)에서: Meta가 각 제출물을 심사할 때마다 갱신되는 스토어 버전입니다.
2. 또는 [release](https://github.com/freeKC/Immuch360/releases)의 `-quest-release.apk` 파일을 개발자 모드에서 adb나 SideQuest로 사이드로드합니다: `adb install -r Immuch360-v<version>-quest-release.apk`, 그런 다음 헤드셋의 라이브러리에서 "Unknown sources"를 엽니다.
3. 스토어 버전과 GitHub APK는 서로 다른 키로 서명되어 있습니다: 하나에서 다른 것으로 바꾸려면 먼저 앱을 제거해야 하며, 그러면 로그인, 설정, 네트워크 공유 목록이 모두 사라집니다.

<a id="windows"></a>
### Windows

1. [desktop 사전 릴리스](https://github.com/freeKC/Immuch360/releases/tag/desktop-v3.3.0-rc.0-13)에서 `Immuch360-Desktop-3.3.0-rc.0-desktop.13-windows-x64-setup.exe`를 다운로드하고(`SHA256SUMS.txt`로 확인 가능) 실행합니다. 설치 프로그램과 ZIP은 서명되어 있으며, Windows는 게시자로 APROGSYS를 표시합니다. 이 게시자가 SmartScreen에 아직 낯선 동안에는 한 번 더 물어볼 수 있습니다: "추가 정보"를 선택한 다음 "그래도 실행"을 선택합니다.
2. "현재 사용자에게만 설치"(관리자 권한 불필요) 또는 "모든 사용자에게 설치"를 선택한 다음, 이미 Windows 언어로 선택되어 있는 설치 프로그램의 언어를 선택합니다.
3. 시작 메뉴에서 Immuch360 Desktop을 실행합니다. 사진과 동영상은 "연결 프로그램"에 나타나지만(파일을 마우스 오른쪽 버튼으로 클릭한 뒤 연결 프로그램), 기본 프로그램으로는 절대 지정되지 않습니다. 새 build를 처음 실행할 때는 Windows가 파일을 검사하는 동안 1분 정도 걸릴 수 있습니다.
4. Windows 10 또는 11, 64비트. 업데이트하려면 다음 build의 설치 프로그램을 실행하세요: 로그인, 폴더, 설정은 그대로 유지됩니다. 같은 릴리스의 ZIP은 폴더 형태의 같은 프로그램이므로, 원하는 곳에 압축을 풀고 그 안의 `immuch360.exe`를 실행하면 됩니다. desktop build 4부터 8까지가 시작 시 "duplicate column name: group_date"에서 멈췄던 컴퓨터에서도 build 9는 그 데이터베이스를 열고 데이터를 그대로 유지합니다.

### Linux

Ubuntu 22.04 이상과 Debian 12 이상에서는: `sudo apt install ./Immuch360-Desktop-3.3.0-rc.0-desktop.13-linux-amd64.deb`; Fedora 40 이상에서는: `sudo dnf install ./Immuch360-Desktop-3.3.0-rc.0-desktop.13-linux-x86_64.rpm`. 두 파일 모두 [desktop 사전 릴리스](https://github.com/freeKC/Immuch360/releases/tag/desktop-v3.3.0-rc.0-13)에 있습니다. 그런 다음 애플리케이션 목록에서 Immuch360 Desktop을 실행합니다. 미리보기 단계로, 컴퓨터의 폴더, 사진과 구체로 보는 360° 사진, 그리고 패키지가 설치하는 시스템의 libmpv로 재생하는 평면 동영상을 지원합니다(360°, 3D, 원본 동영상은 안내 메시지와 함께 평면으로 재생). SMB 공유는 Ubuntu 22.04와 Debian 12부터 동작합니다. Fedora에서는 카메라 동영상에 RPM Fusion의 FFmpeg가 필요합니다. GNOME Keyring이나 KWallet이 없으면 비밀번호는 세션 동안만 보관되며, 앱 설정에서 그 사실을 알려줍니다.

### macOS

`Immuch360-Desktop-3.3.0-rc.0-desktop.13-macos.dmg`를 [desktop 사전 릴리스](https://github.com/freeKC/Immuch360/releases/tag/desktop-v3.3.0-rc.0-13)에서 받아 열고 앱을 Applications로 드래그합니다(Apple 실리콘과 Intel, macOS 12 이상). 아직 서명도 공증도 되지 않았으므로, macOS 14 이하에서는 Control 키를 누른 채 클릭한 뒤 "열기"를 선택하고, macOS 15 이상에서는 "시스템 설정"의 "개인정보 보호 및 보안"에서 "무조건 열기"를 선택하세요. 작성자가 2026년 10월 26일 Mac에서 desktop build 11을 시험해 보았으며 잘 동작했습니다. 다른 Mac과 다른 macOS 버전은 시험하지 않았으니 제보를 환영합니다.

## 사용 방법

### 서버가 있든 없든 사진과 동영상 보기

Immuch360은 먼저 일반 사진과 동영상을 위한 갤러리이자 플레이어이며, 계정도 서버도 필요하지 않습니다. "서버 없이 사용"을 누르면 앱이 기기의 사진과 동영상으로 열리고, 모든 뷰어, 360° 목록, 네트워크 소스를 쓸 수 있으며, 아무것도 기기 밖으로 나가지 않습니다. Immich 서버가 있으면 타임라인, 앨범, 즐겨찾기, 추억, 검색이 서버에서 옵니다. 동영상은 소리, 탐색, 버퍼링 표시기, 오디오 트랙 선택이 있는 네이티브 플레이어에서 재생되며, 360°, Spatial, 컴퓨터 플레이어와, build 29부터는 자막도 표시하는 Android 앱의 평면 플레이어에서도 마찬가지입니다.

<img src="../.github/readme/b19-library-no-server.png" width="260" alt="서버 없이 본 라이브러리 탭: 맨 위에 360° 항목, 그 아래 360° 사진 두 장이 있는 이 장치에서, 그리고 NAS라는 공유가 있는 네트워크 공유">

1. 앱을 엽니다. 환영 페이지에 "당신의 미디어. 모든 화면. 모든 시점."과 세 가지 옵션이 나타나면, 첫 번째인 "서버 없이 사용"을 탭합니다. 서버는 나중에 설정이나 라이브러리 탭에서 연결할 수 있습니다.
2. 사진과 동영상에 대한 접근을 허용합니다. 거부하면 앱은 "접근 허용"과 "설정 열기" 버튼과 함께 "앱이 이 기기의 사진을 볼 수 없습니다"라고 표시합니다.
3. 사진 탭에는 기기의 타임라인이 나옵니다. 검색과 앨범은 서버에서 오는 기능이라 회색으로 표시됩니다. 라이브러리 탭에는 맨 위에 360°, 그 아래 이 장치에서(기기의 앨범)와 네트워크 공유가 있습니다. 오른쪽 위 메뉴에는 "이 기기만"이라고 표시됩니다: 아무것도 어디로도 전송되지 않습니다.
4. 사진이나 동영상을 탭하여 열고, 왼쪽이나 오른쪽으로 스와이프해 다음 파일로 이동하며, 꼬집거나 두 번 탭해 확대합니다. 동영상에서 위로 스와이프하면 세부 정보가 나옵니다: 코덱, 크기, 프레임 레이트, 비트레이트, 그리고 이 기기가 디코딩할 수 있는지 여부.
5. Android 휴대폰, 태블릿, TV에서는 build 29부터 여러 오디오 언어나 자막이 있는 영화의 컨트롤에 오디오 버튼과 자막 버튼이 생깁니다: 선택한 오디오 언어는 다음 영화에도 유지되며, 자막은 강제 자막을 제외하고 직접 선택할 때까지 꺼져 있습니다. Immich 앱의 Android 플레이어에는 둘 다 없습니다.

컴퓨터에서는 선택한 폴더가 갤러리 역할을 하며, 자체 사진이 없는 TV에서는 네트워크 소스가 그 역할을 합니다.

더 보기: [서버나 계정 없이](../docs/immuch360/user-guide.md#without-a-server-or-an-account), [뷰어와 동영상 플레이어](../docs/immuch360/user-guide.md#watch-your-photos-and-videos), [동영상 세부 정보와 디코더](../docs/immuch360/user-guide.md#video-details-decoders-and-why-a-video-stutters).

### 파노라마, 360°, VR180, 3D 탐색하기

Immuch360은 평면 사진과 동영상, 파노라마, 360° 사진과 동영상, VR180, 스테레오스코픽 3D, Apple 공간 사진, DJI 드론의 360° 구체 사진을 알아보고, 각각 맞는 뷰어에서 엽니다. 360° 사진은 손가락으로 돌리거나 휴대폰을 움직여 돌릴 수 있는 구체로 열리고, 360° 동영상은 소리가 있는 구체형 플레이어에서 재생됩니다. VR180 파일은 반구에 그려지며, 스테레오스코픽 3D 파일은 평면 화면에서는 한쪽 눈만, 헤드셋에서는 양쪽 눈을 모두 보여줍니다. 부분 파노라마는 원래의 크롭을 유지하고, 사진은 카메라가 촬영한 시점에서 시작합니다. 서버가 표시하지 않은 파일도 한 번의 탭으로 360°로 볼 수 있습니다.

<p align="center">

  <img src="../.github/readme/b19-video.png" width="420" alt="휴대폰을 가로로 들고 360° 플레이어에서 재생 중인 해안 도로 360° 동영상: 왼쪽 위에 닫기와 파일 이름, 오른쪽 위에 360°와 3D, 가운데에 이전, 뒤로 건너뛰기, 재생, 앞으로 건너뛰기, 다음, 아래쪽에 시간 막대">
</p>

1. 사진이나 동영상을 엽니다. 360° 파일은 썸네일에 360° 배지가 표시되며, 라이브러리 탭에는 기간, 소스, 종류, 카메라별로 필터링해 이를 모아 보는 360° 목록이 있습니다.
2. 상단 바에서 360°를 탭합니다. 드래그하면 둘러보고, 꼬집으면 확대하며, 자이로스코프 버튼을 탭하면 휴대폰을 움직여 둘러볼 수 있습니다.
3. 3D 버튼은 "모노 (3D 아님)", "3D, 위아래", "3D, 좌우" 순서로 전환되며, 360°/180° 버튼은 전체 구체와 VR180의 반구 사이를 전환합니다.
4. 360° 파일인데 평면으로 보일 때: 오른쪽 상단의 ⋮를 누른 뒤 "360°로 보기"를 선택합니다.

휴대폰과 태블릿에서는 스테레오스코픽 동영상이 평면 화면에서도 입체감을 가질 수 있습니다. Spatial 2.5D 플레이어는 전면 카메라로 머리 움직임을 따라가며 두 눈 사이의 시점을 보여줍니다(실험적 기능). iPhone으로 찍은 Apple 공간 사진은 자동으로 인식되어 Meta Quest에서 3D로 보여집니다.

### 사진 한 장을 3D, 장면, 파노라마로 바꾸기

사진은 대부분 평면이고, 다시 돌아가 3D로 찍을 수는 없습니다. Immuch360이 사진에 깊이를 줍니다. 컴퓨터에서 사진 한 장이 **3D 사진**, 헤드셋에서 몸을 기울여 들여다보는 **3D 장면**, 또는 주변 공간의 나머지를 상상해 채운 **360° 파노라마**가 됩니다. Quest 3 또는 3S는 어떤 평면 사진이든 입체감을 스스로 만듭니다. 모든 것이 내 컴퓨터와 헤드셋에서 실행됩니다: 클라우드도 계정도 없고, 원본은 절대 바뀌지 않습니다. build 32와 desktop build 13의 새 기능이며, 실험적이고 기본으로 켜져 있습니다. Immich 앱에는 이런 기능이 없습니다.

**컴퓨터에서**, Windows, Linux, macOS의 desktop build 13으로:

1. 라이브러리나 폴더에서 사진을 하나 이상 선택한 다음 "3D 만들기 (AI)".
2. 원하는 것을 고릅니다: "3D 사진", "3D 장면", "360° 파노라마", 또는 직접 찍은 360° 사진에는 "360° 사진의 3D 버전". 상자는 AI가 무엇을 추정하거나 지어낼지("이 파노라마의 약 96%를 AI가 새로 만들어 냅니다"), 이 컴퓨터에서 대략 얼마나 걸릴지, 파일이 어디에 저장될지 알려 줍니다: "원본 옆" 또는 "내가 선택한 폴더". 이 컴퓨터가 할 수 없는 유형은 회색으로 남고 이유가 함께 표시됩니다. 예: "Mac에서는 아직 지원되지 않음" 또는 "그래픽 카드 메모리: 6.0 GiB, 360° 파노라마에 필요한 메모리: 7.5 GiB".
3. 처음에는 상자가 그 유형의 구성 요소를 제안합니다: 다운로드, 한 번만. 구성 요소는 이 컴퓨터에서 실행되며 그 뒤로는 오프라인에서도 동작합니다.
4. 변환. 작업은 프로세서와 그래픽 카드라는 두 레인에 단계와 남은 시간과 함께 줄을 섭니다. 취소로 언제든 하나를 멈출 수 있고, 앱을 끝낼 때는 먼저 묻습니다.
5. Open the result. A 3D photo shows as "Left eye", "Side by side", "Wiggle" (the animation above) or "Red and cyan" for glasses; a scene has "Preview in 3D", turned with the mouse or the touchpad, and "Export for other 3D apps (.glb)"; a panorama opens in the 360° viewer.

새 파일은 모두 원본 옆에 저장되며 원본을 덮어쓰지 않습니다. 원본 폴더가 새 파일을 받지 않으면 직접 고른 폴더에 저장합니다. 네트워크 폴더에서는 그 폴더에 대해 허락한 뒤에만 저장합니다("Immuch360은 그곳에 새 파일만 쓰며 원본은 절대 건드리지 않습니다"). 라이브러리는 각 버전을 "AI 3D", "3D 장면", "AI 360°" 배지와 함께 원본에 연결해 "Immuch360 AI 버전" 앨범에 모으며, 이 앨범은 "AI 버전도 백업"을 켜지 않는 한 Immich 백업에서 빠집니다. 주의: 백업 앨범에서 "모두 선택"을 누르면 이 앨범도 선택되고 그 스위치가 켜집니다. Quest에서 파일을 보려면 NAS에 저장하거나, Immich 서버에 백업하거나, Windows에서 "이 컴퓨터를 네트워크에서 공유"를 켜세요.

**Meta Quest에서**, build 32로:

- **AI 입체감**: 라이브러리나 공유에서 아무 평면 사진이나 열고 위쪽 막대의 "AI 입체감"을 누르세요: 헤드셋이 입체감을 직접 추정해 사진을 3D로 보여 주며, "AI가 추정한 입체감"이라고 표시합니다. 99.5 MB 모델은 처음 누를 때 다운로드되고, 입체감은 캐시에 보관됩니다. 설정, 고급, "AI 및 3D"의 "AI 입체 사진을 2.5D로 열기 (실험적)"를 켜면 머리를 움직일 때 가까운 물체가 배경 앞에서 움직입니다. Quest 2나 Quest Pro에서는 같은 곳의 "Quest 2 및 Quest Pro에서 AI 입체감 사용 (테스트되지 않음)"을 켜기 전까지 버튼이 "이 헤드셋에서는 아직 테스트되지 않음"으로 회색 상태입니다.
- **3D photos and scenes from the computer**: "View in 3D" shows a 3D photo in true 3D. "View the 3D scene" on the original, or "Explore the 3D scene" on the scene, puts the scene in your room: lean in, or glide with the left thumbstick inside the rebuilt area ("Room to move: about 0.5 m each way" for the room shown above); the layers flatten and darken at its edge, a click on a thumbstick resets the view, and B or Y goes back.
- **파노라마**: 생성된 파노라마가 내 사진을 정면에 두고 주위 전체로 열리며, "사진 가장자리 너머는 AI가 생성함" 문구와 원본 사진의 가는 윤곽이 함께 나왔다가 몇 초 뒤에 사라집니다. 3D 버전은 진짜 3D입니다.

**휴대폰, 태블릿, TV에서는** 컴퓨터가 만든 파일을 그대로 열 뿐, 그곳에서 생성하는 것은 없습니다. Android 휴대폰, 태블릿, Android TV에서는 파노라마가 360° 뷰어에서 "AI 360°" 배지, 문장, 윤곽과 함께 열리고, iPhone, iPad, LG와 Samsung TV에서는 지금은 일반 360° 사진으로 열립니다. 장면은 모서리에 작은 3D 장면 표시가 붙은 사진으로 보이며, Android에서는 세부 정보에 "Meta Quest에서 열어 둘러보세요"가 추가됩니다. 3D 사진은 두 눈 이미지를 나란히 보여 줍니다.

**무엇이 진짜이고 무엇이 아닌지, 항상 밝힙니다.** 이것이 핵심이지 작은 글씨가 아닙니다. 3D 사진의 입체감은 사진 한 장에서 추정한 것이고, 사진에 가려진 부분은 채워 넣은 것으로 진짜가 아닙니다. 장면은 "사진 한 장에서 재구성됨, 그 한계 안에서 둘러보세요"입니다. 파노라마는 진짜 픽셀을 제자리에 두고 나머지를 지어내며, 보통 사진이라면 구의 약 90%이고, 상자가 시작 전에 그 비율을 알려 줍니다. 앱은 보는 자리에서 "AI가 추정한 입체감", "사진 가장자리 너머는 AI가 생성함"과 배지로 알리고, 파일도 알립니다: 우리 XMP에, 그리고 장면과 파노라마에는 AI로 만든 이미지의 IPTC 디지털 소스 유형으로 기록해, 다른 앱이 생성된 파노라마와 진짜 360° 사진을 구별할 수 있게 합니다. 원본은 절대 바뀌지 않으며, 컴퓨터나 헤드셋 밖으로 나가는 것은 없습니다. 상자의 말대로: "변환이 완료되었다고 해서 결과가 좋다는 보장은 없습니다."

**확인한 것**, 2026년 10월 29일까지 이 코드의 테스트 build로: 3D 사진은 Linux PC의 컨테이너에서 Linux 앱으로, 오프라인에서도; 장면은 RTX 4060 Laptop GPU 노트북의 Windows 앱(2 min 39 s에 열 개)과 Linux PC의 엔진으로; 그 노트북에서 파노라마 네 개를 각각 4 min 16 s에서 4 min 44 s에, 3D 버전은 약 30 s에 만들었고, 취소, 강제 종료된 앱, 그래픽 카드를 점유한 다른 프로그램을 시험했으며, 테스트 중 앱의 네트워크 연결은 전혀 없었습니다.

제한 사항: Mac에서는 아직 360° 파노라마가 없고("Mac에서는 아직 지원되지 않음"), 알맞은 그래픽 카드가 없을 때도 마찬가지이며, 상자가 이유를 알려 줍니다("Vulkan을 지원하는 그래픽 카드를 찾지 못했습니다", "내장 그래픽은 컴퓨터 메모리를 함께 사용합니다: 파노라마에는 너무 느립니다", 그래도 해 보려면 "내장 그래픽에서 시도 (테스트되지 않음)"). 파노라마 안에서 사진의 가장자리가 뚜렷한 색조 단차로 보일 수 있습니다. 대부분의 장면에 "화각을 추정함: 형태가 어긋날 수 있습니다"라고 표시됩니다. 장면에는 약 2 GB의 여유 메모리가 필요합니다(부족하면 "메모리 부족"). AI 버전을 백업하면 Immich의 중복 찾기가 사진과 그 장면을 짝지어 더 무거운 파일인 장면을 남기라고 자주 제안합니다: 원본을 남기세요. 휴대폰과 TV는 아무것도 만들지 않고, 헤드셋은 입체감만 만듭니다. 장면은 사진 한 장에서 만들며, 같은 장소의 여러 사진으로는 아직 만들지 않습니다.

**구성 요소**: 컴퓨터의 설정, "AI 및 3D"에는 기능별 구성 요소가 크기, 다운로드, 제거와 함께 나열되고, 이어서 "모든 AI 구성 요소 제거"와 다른 드라이브로 "AI 구성 요소 옮기기"가 있습니다. "AI 기능"을 끄면 AI 버튼이 모두 숨겨지고 아무것도 다운로드하지 않습니다. 각 파일은 SHA-256으로 확인합니다. Windows에서는 `%LOCALAPPDATA%\com.aprogsys\Immuch360 Desktop\ai-components`에 있으며 제거 프로그램이 이를 지웁니다(구성 요소를 옮긴 폴더는 지우지 않음). Linux에서는 대부분의 시스템에서 `~/.local/share/immuch360/ai-components`, Mac에서는 `~/Library/Application Support/com.aprogsys.immuch360.desktop/ai-components`에 있습니다. Quest에서는 "AI 및 3D"가 설정, 고급에 입체감 캐시와 함께 있습니다.

#### Android TV와 Google TV에서

같은 Android 앱이며, 처음 시작할 때부터 어두운 테마이고 리모컨이 유일한 입력 장치입니다. 뷰어에서 왼쪽과 오른쪽 방향키는 동영상이 재생 중일 때도 이전 또는 다음 사진이나 동영상으로 이동하며, 360° 사진이나 동영상에서는 방향키로 둘러봅니다.

<p align="center">
  <img src="../.github/readme/tv-b21-sphere.jpg" width="440" alt="Google TV의 구체 뷰어: 호숫가의 360° 파노라마, 왼쪽 상단에 닫기 버튼, 오른쪽 상단에 축소, 확대, 360°, 3D 버튼, 리모컨 방향키로 돌리는 모습">

1. adb로 APK를 설치합니다. [설치](#android-tv-and-google-tv)를 참고하세요. 환영 페이지에서 공유, Plex 서버, 카메라용으로 "네트워크 공유 또는 미디어 서버 추가"를, 또는 "서버 없이 사용", "Immich 서버에 연결"을 선택합니다. "Immich 서버에 연결" 페이지의 QR 코드를 휴대폰으로 스캔하면 TV가 로그인됩니다([휴대폰으로 로그인](#sign-in-a-tv-a-headset-or-a-computer-with-your-phone) 참고).
2. 뷰어에서는 리모컨의 재생/일시정지, 되감기, 빨리감기, 이전, 다음 버튼이 동작합니다. 동영상 재생 중 OK를 누르면 재생/일시정지가 선택된 컨트롤이 나타나고, OK를 한 번 더 누르면 일시정지됩니다. 그 뒤에 -10 s와 +10 s 버튼이, 영화에 있으면 오디오와 자막 버튼이 이어집니다. build 29부터는 재생 버튼에서 아래 방향키를 누르면 타임 바로 이동합니다: 왼쪽과 오른쪽 방향키는 한 번 누를 때마다 10 s씩 이동하고 누르고 있으면 더 빨리 이동하며, OK는 재생하거나 일시정지합니다. 컨트롤과 날짜는 마지막 키 입력 5 s 후에 사라지며, 그러면 왼쪽과 오른쪽 방향키로 이전 또는 다음 파일로 이동합니다. 공유에서는 그 파일이 자체 페이지에서, 그 파일을 조작하는 컨트롤과 함께 열립니다. 설정, 보기 옵션, 동영상, 반복을 켜지 않는 한 TV에서는 동영상이 더 이상 반복 재생되지 않습니다.
3. Menu 버튼, Info 버튼, 또는 OK를 길게 누르면 사진이나 동영상의 세부 정보가 읽기 전용으로 열립니다: 날짜, 장소, 카메라, 코덱, 크기, 비트레이트. TV가 디코딩할 수 없는 동영상은 끝없이 로딩하는 대신 코덱, 크기, TV 디코더의 한계와 함께 그 사실을 알려주며, 디코더의 한계를 넘는 360° 동영상은 360° 플레이어를 열기 전에 확인을 요청하고, 그 이유는 프로필 메뉴의 로그 페이지에 기록됩니다.

build 28은 10월 23일 실제 Android TV에서 실행했습니다. build 29의 동영상 수정은 그때 나온 것이며 Google TV 에뮬레이터에서 확인했지만, 아직 그 TV에서는 확인하지 않았습니다.

#### LG TV에서(webOS)

Immich의 공식 앱은 LG TV에 설치되지 않습니다. Immuch360에는 webOS 5.0 이상(2020년 TV부터)의 LG TV를 위한 자체 TV 앱이 있으며, 리모컨과 Magic Remote로 조작합니다: Immich 서버, 네트워크 공유, Plex 서버, Tapo 카메라를 보여주고, 360° 사진을 방향키로 돌리는 구체 위에 띄웁니다. 이 앱은 Seeky91의 [immich-tv-webos](https://github.com/Seeky91/immich-tv-webos)를 기반으로 하며, 타임라인, 앨범, 인물, 장소, 검색, 슬라이드쇼, 휴대폰으로 로그인하는 기능은 그 프로젝트에서 왔습니다. Seeky91에게 감사드립니다. 버전 1.0.0은 10월 24일 LG Content Store에 제출되었고 LG Cloud Test Lab의 webOS 25 TV에서 실행되었습니다. LG가 승인할 때까지는 Developer Mode로 설치하며, [Issues](https://github.com/freeKC/Immuch360/issues)에 올라오는 모든 제보가 도움이 됩니다.

1. Developer Mode의 TV에 설치합니다. [설치](#lg-tvs-webos)를 참고하세요. 자체 앱 ID를 사용하므로 Seeky91의 Immich TV와 함께 설치할 수 있습니다.
2. 휴대폰(QR 코드 스캔), 이메일과 비밀번호, 또는 API 키로 로그인합니다.
3. 방향키와 OK로 둘러봅니다. 뷰어에서는 동영상 재생 중에도 왼쪽과 오른쪽으로 이전 또는 다음 사진이나 동영상으로 이동합니다. 컨트롤은 마지막 키 입력 5 s 후에 사라지고, Info는 세부 정보를 열며, 채널 버튼으로 확대/축소하고, Magic Remote의 포인터와 휠도 동작합니다. GitHub에 있는 버전 1.0.1부터는 위쪽 키로 사진을 바로 확대하고, 이어서 방향키로 이동하며, 뒤로 키로 축소합니다. 사진이 아직 오는 중이면 로딩 표시가 나타납니다.
4. 360° 사진은 구체 위에 열립니다: 방향키를 한 번 누를 때마다 한 단계씩 돌고, 누르고 있으면 계속 돕니다. 서버가 360°로 표시하지 않은 2:1 사진에는 "360°로 보기"를 쓸 수 있습니다. VR180 사진은 반구 위에, 3D 사진은 한쪽 눈으로 표시됩니다. 노란색과 파란색 버튼은 평면 사진을 회전합니다.
5. 로그인한 뒤 앱 사이드바의 "네트워크 공유"에서 SMB, WebDAV, DLNA 공유, Plex 서버(plex.tv/link에서 코드로 로그인) 또는 Tapo 카메라를 추가합니다. 그 사진은 같은 뷰어에서 열리며, 360° 사진은 구체 위에 열립니다.

버전 1.0.0은 LG Content Store용으로 만들어졌습니다: 사진이나 환영 페이지에서 뒤로가기를 누르면 webOS 버전마다 기대하는 방식으로 앱을 나가고, 열린 팝업은 먼저 닫습니다. 15 s 안에 응답하지 않는 서버는 이유를 알려주는 메시지와 다시 시도 버튼으로 끝납니다. 개인정보 처리방침은 앱 안에서 열리며, [LG TV 섹션](../PRIVACY.md#lg-tvs-webos)을 휴대폰에서 읽을 수 있는 QR 코드가 함께 나옵니다. LG가 사진 앱에 요구하는 대로 TV는 Gallery 화질 모드를 사용하며, 두 번째 패키지는 LG가 1280x720 앱을 제공하는 Full HD TV에 맞춰져 있습니다.

제한 사항: SMB에는 webOS 22(2022년 TV) 이상이 필요합니다. 공유, Plex, 카메라는 TV에서 돌아가는 앱 자체 서비스를 통해 오며, 이 서비스가 앱 대신 읽어 옵니다. 프로젝트 빌드 호스트에서 실제 서버와 모의 카메라로 확인했지만, 아직 TV에서는 확인하지 않았습니다. 카메라의 실시간 화면은 영상만 나옵니다. 아직 지원하지 않는 것: 카메라의 녹화 영상(2026년 12월 이전에는 불가)과 소리, 구체 위의 360° 동영상(안내 메시지와 함께 평면으로 재생), 업로드. webOS 25 이전 버전에서는 Immich 앞단의 리버스 프록시가 CORS 헤더를 보내야 하며, 앱이 이 문제를 만나면 필요한 헤더를 설명해 줍니다. webOS 26은 아직 시험하지 않았습니다.

<a id="on-a-samsung-tv-tizen"></a>
#### Samsung TV에서(Tizen)

Tizen 5.5 이상의 Samsung TV(2020년 TV부터)는 같은 TV 앱을 테스트 build 0.2.0으로 받으며, 이 build는 Samsung 스토어에 없습니다: 직접 입력해 로그인, 타임라인, 앨범, 뷰어와 슬라이드쇼, 구체 위의 360° 사진, 키 하나로 사진 회전. 아직 없는 것: 휴대폰으로 로그인, 공유, Plex, 카메라. 이 기능들은 LG TV에서 백그라운드 서비스로 동작하는데, Samsung 버전에는 아직 그 서비스가 없습니다.

1. TV에 맞게 패키지를 서명하고 Developer mode에서 설치합니다. [설치](#samsung-tvs-tizen)를 참고하세요.
2. 서버 주소를 입력한 다음 이메일과 비밀번호 또는 API 키를 입력해 로그인합니다.
3. 방향키와 OK로 둘러봅니다. 360° 사진은 구체 위에 열립니다. 360° 동영상은 평면으로 재생되며 처음에 안내가 나옵니다. 테스터의 TV에서 TV의 브라우저가 3D 화면에 검은 동영상 프레임을 넘겼기 때문입니다.
4. TV 디코더가 받아들이는 범위를 넘는 동영상은 끝없이 로딩하는 대신 TV가 재생할 수 있는 크기와 파일의 크기를 알려줍니다. 멈추는 동영상은 비트레이트와 해결 방법을 담은 안내를 보여줍니다: 무거운 파일은 Immich가 트랜스코딩하게 하거나, 더 빠른 연결을 쓰세요. "이 TV 정보"는 TV의 동영상 한계를 알려줍니다.

버전 0.1.0은 테스터의 Tizen 9 Samsung TV에서 실행되었고, 0.2.0에는 그때 나온 수정이 들어 있습니다. 0.2.0은 아직 TV에서 실행하지 않았습니다. 실행해 본 뒤 정보 페이지의 텍스트를 [Discussions](https://github.com/freeKC/Immuch360/discussions)나 [Issues](https://github.com/freeKC/Immuch360/issues)에 올려 주시면 가장 큰 도움이 됩니다.

### 휴대폰으로 TV, 헤드셋, 컴퓨터에 로그인하기

**스캔. 로그인. 감상.** TV 리모컨이나 헤드셋으로 서버 주소, 이메일, 비밀번호를 입력하려면 몇 분이 걸립니다. Immich 서버에 로그인된 휴대폰의 Immuch360이 있으면 TV, Meta Quest, 컴퓨터가 몇 초 만에 로그인됩니다: 큰 화면에 QR 코드가 나타나고, 휴대폰으로 스캔하고, 확인하면, 화면에 라이브러리가 열립니다. 휴대폰 앱을 쓰면 비밀번호는 휴대폰에만 남습니다. Immich 앱에는 이런 기능이 없습니다.

<p align="center">
  <img src="../.github/readme/sign-in-with-your-phone.png" width="720" alt="실제 화면이 아닌 일러스트: 로그인 페이지에 QR 코드를 띄운 TV와, 그 앞에서 같은 코드를 스캔하는 휴대폰">
</p>

1. 큰 화면(Android TV와 Google TV, Meta Quest 창, Windows, Linux, macOS)에서 "Immich 서버에 연결"을 선택합니다: 로그인 페이지의 서버 입력란 옆에 "휴대폰으로 로그인", QR 코드, 10자리 코드가 표시됩니다.
2. 서버에 로그인된 휴대폰에서: 설정, "TV 또는 컴퓨터 연결", 그다음 "코드 스캔"을 선택합니다. 휴대폰으로 화면을 스캔할 수 없는 Meta Quest에서는 "대신 코드 입력"을 선택하고 헤드셋에 표시된 코드를 입력합니다.
3. 휴대폰이 "(화면)에 로그인할까요?"라고 묻고 6자리 숫자를 보여줍니다: 화면에도 같은 숫자가 표시되는지 확인한 다음 로그인을 탭합니다. 화면에 타임라인이 열립니다.

안전하게 유지되는 방법: 휴대폰과 화면은 같은 홈 네트워크에 있어야 하며, 코드는 최대 2분 동안 유효하고 한 번만 사용할 수 있습니다. 휴대폰은 서버에 그 화면을 위한 새 세션을 요청하고, 화면 이름을 붙여("거실 TV의 Immuch360") 암호화해서 화면으로 보내므로, 비밀번호는 휴대폰 밖으로 절대 나가지 않습니다. "TV 또는 컴퓨터 연결"에는 이 휴대폰으로 로그인한 화면이 각각 로그아웃 버튼과 함께 나열되며, Immich에서도 계정 설정, 승인된 기기에 나열되어 그곳에서 취소할 수도 있습니다. 휴대폰에서 로그아웃하면 그 화면들도 함께 로그아웃됩니다.

휴대폰 쪽 기능은 지금 Android에서 동작하며, iPhone과 iPad에서는 다음 iOS 릴리스부터 동작합니다. 휴대폰에 Immuch360이 없으면 휴대폰 카메라로 코드를 스캔하세요: 화면이 제공하는 페이지가 브라우저에서 열리며, 입력한 이메일과 비밀번호는 암호화되어 한 번만 사용됩니다. LG TV는 자체 QR 코드로 휴대폰 브라우저에서 로그인합니다. build 28부터는 휴대폰 앱의 스캐너가 이 코드를 인식해 그 페이지를 엽니다. Samsung TV는 지금은 직접 입력해 로그인합니다.

더 보기: [휴대폰으로 로그인](../docs/immuch360/user-guide.md#sign-in-a-tv-a-headset-or-a-computer-with-your-phone), [화면이 보내고 보관하는 것](../docs/immuch360/technical-details.md#sign-in-with-your-phone).

### NAS, 컴퓨터, 미디어 서버, Plex의 파일 재생하기

동영상이 NAS, 컴퓨터, 미디어 서버, Plex에 있나요? Immuch360은 네트워크의 서버를 직접 찾아내고, 둘러보고, 아무것도 복사하지 않은 채 앱의 모든 뷰어에서 사진과 동영상을 그 자리에서 재생합니다: SMB(Samba, Windows 공유), WebDAV(Nextcloud, Synology 등), DLNA 미디어 서버(Jellyfin, Emby, minidlna, NAS, TV 박스)까지 지원합니다. 휴대폰도 자신의 갤러리를 Wi-Fi로 헤드셋이나 모든 WebDAV 클라이언트에 공유할 수 있으며, Windows 컴퓨터도 마찬가지입니다.

<p align="center">
  <img src="../.github/readme/b19-add-share.png" width="260" alt="공유 추가 화면: 이름, 서버 이름 또는 주소, 포트 (선택 사항), 공유 이름, 공유 선택, 시작 폴더 (선택 사항), 계정명, 비밀번호, 연결 테스트, 그리고 결과 연결됨, 시작 폴더에 항목 2개">
  <img src="../.github/readme/b19-share-folder.jpg" width="260" alt="썸네일 격자로 보이는 네트워크 공유 폴더: 360° 배지가 붙은 360° 사진들과 재생 표시가 붙은 360° 동영상, 오른쪽 위에 선택 버튼">
</p>

1. 라이브러리 탭을 열고, 네트워크 공유, 그다음 +와 "네트워크 공유 (NAS, 컴퓨터, 미디어 서버)"를 선택합니다. build 24부터는 환영 페이지의 "네트워크 공유 또는 미디어 서버 추가"가 서버 없이 네트워크 공유를 바로 엽니다.
2. "네트워크에서 찾음" 아래에서 서버를 탭하거나, 양식을 직접 채웁니다: 종류, 서버 이름 또는 주소, 공유 또는 경로, 시작 폴더, 사용자 이름, 비밀번호.
3. "연결 테스트"를 탭한 뒤 저장합니다. 공유를 탭하면 둘러볼 수 있습니다: 먼저 폴더가, 그다음 360°로 인식된 파일에는 360° 배지가 붙은 사진과 동영상이 나타납니다.
4. Plex 서버라면: 네트워크 공유에서 +와 "Plex Media Server"를 선택한 다음 "네트워크에서 찾음" 아래의 서버를 탭하고, 토큰을 한 번 붙여넣은 뒤(페이지의 "받는 방법"이 찾는 곳을 알려줍니다) "연결 테스트"와 저장을 누릅니다.
5. Immich 서버가 연결된 상태에서 폴더의 파일을 선택하고 "Immich에 업로드"를 탭하면 서버로 전송됩니다.

플레이어는 앱 내부의 브리지를 통해 필요한 바이트만 바이트 범위로 읽어오므로, 탐색이 가능하고 기기에는 아무것도 저장되지 않습니다. SMB 동영상은 최대 6개의 연결을 병렬로 사용해 끊김 없이 재생됩니다. build 29부터는 M2TS로 녹화한 영화(Blu-ray, AVCHD 캠코더, TV 녹화기)가 Android 앱에서 SMB와 WebDAV 공유, 그리고 이를 transport stream으로 표시하는 DLNA 서버에서 재생되며, 크기를 0으로 표시하는 DLNA 서버에서도 더 이상 빈 동영상이 나오지 않습니다.

**plex.tv 없이 Plex Media Server**: 앱은 한 번만 붙여넣는 토큰으로 서버와 직접 페어링하여 라이브러리의 원본 파일을 실시간으로 읽어옵니다. 그래서 360°는 집에서든, 포트 포워딩을 통해 집 밖에서든 그대로 360°로 유지됩니다. LG TV에서는 plex.tv/link의 코드로 Plex에 로그인합니다.

<a id="keep-your-immich-library-with-more"></a>
### Immich 라이브러리를 그대로, 그리고 더 많이

[Immich](https://github.com/immich-app/immich) 서버를 사용하면 Immuch360은 웹 앱과 같은 서버와 계정을 쓰는 Immich 모바일 앱이 됩니다: 백업, 타임라인, 앨범, 검색, 인물, 추억, 공유, 파트너까지 모두 서버와 동기화됩니다. 공식 앱과 함께 설치할 수 있습니다. 그 위에 360° 배지와 목록, 모든 몰입형 뷰어, 각 동영상마다 원본 파일과 서버의 트랜스코딩된 스트림 중 선택, 동영상의 기술적 세부 정보, 그리고 공유나 기기에서 수동으로 서버에 보낸 파일까지 더해집니다.

1. 환영 페이지에서 "Immich 서버에 연결"을 탭한 뒤, Immich 앱에서처럼 서버 주소, 이메일, 비밀번호로 로그인합니다. 뒤로를 누르면 환영 페이지로 돌아갑니다. build 23까지는 로그인 페이지가 바로 열렸습니다. 라이브러리, 앨범, 백업 설정은 계정에 저장된 것을 그대로 사용합니다.
2. 설정의 Asset Viewer, Videos에서 "동영상 소스"는 이 기기가 디코딩할 수 있을 때는 원본을, 항상 원본을, 또는 항상 트랜스코딩된 스트림을 선택하도록 고를 수 있습니다.
3. 앱이 없는 사람에게 360° 사진을 보여주려면 Immich 공유 링크로 공유하세요: Immich 웹 앱이 그 사람의 브라우저에서 구체로 보여줍니다.

현재 build인 build 32는 build 28부터 31까지와 마찬가지로 2026년 10월 10일의 Immich `main`(버전 3.3.0-rc.0)을 기반으로 합니다. build 28은 같은 Immich `main`으로 빌드한 서버에서 테스트했으며, build 27은 Immich 3.2.4 서버에서도 테스트했습니다. 문제가 있으면 Immich 프로젝트가 아니라 [Issues](https://github.com/freeKC/Immuch360/issues)에 알려주세요.

무엇이 같고 Immuch360이 무엇을 더하는지는 [Immich와 비교](#compared-with-immich)에 있습니다.

TP-Link의 Tapo 카메라를 Tapo 앱 없이 사진 옆에서 봅니다. 앱은 카메라의 실시간 화면을 보여주고(Android 휴대폰과 태블릿, Android TV, Meta Quest, Windows, 그리고 영상만 LG TV; iPhone과 iPad는 다음 iOS 릴리스부터), 메모리 카드의 녹화 영상을 날짜별로 나열합니다(휴대폰, 태블릿, Android TV, Quest, 컴퓨터). 클립은 카메라에서 가져와 다른 동영상처럼 재생되며 Immich로 보낼 수 있습니다. 앱은 네트워크상의 카메라와만 통신하며, TP-Link의 서버와는 결코 통신하지 않고, 카메라의 어떤 설정도 바꾸지 않습니다.

**아직 실제 카메라로 확인하지 않았습니다.** 프로토콜은 펌웨어 1.3.4의 C510W 캡처를 바탕으로 작성했고, 앱은 모의 카메라로만 확인했습니다. "카메라 테스트"가 보여주는 모델과 펌웨어를 담은 보고가 큰 도움이 됩니다.

1. 먼저 Tapo 앱에서: 실시간 화면에 쓰이는 카메라 계정을 만들고(카메라 설정, Advanced Settings, Camera Account), Me, 그다음 Tapo Lab에서 Third-Party Compatibility를 켭니다.
2. Immuch360에서: 라이브러리, 네트워크 공유, +와 "Tapo 카메라". "네트워크에서 찾음" 아래의 카메라를 탭하거나 주소를 입력합니다.
3. 녹화 영상용으로 TP-Link 계정 비밀번호를, 실시간 화면용으로 카메라 계정을, 또는 둘 다 입력한 뒤 "카메라 테스트"와 저장을 누릅니다.
4. 카메라를 탭합니다: 페이지 맨 위에 소리, SD 또는 HD, 전체 화면이 있는 실시간 화면이 있고, 그 아래로 녹화 영상이 있는 날짜가 이어집니다. 클립을 탭하면 가져와 재생하며, ⋮ 메뉴에 "Immich에 업로드"가 있습니다.

### DJI 드론(실험적)

라이브러리의 Drone 카드는 실험적 기능이며 기본으로 켜져 있고, Immuch360이 DJI 드론으로 하는 일을 모아 둡니다: Android 휴대폰에서는 조종기를 통한 드론의 실시간 영상과, USB로 Immich에 가져오는 드론의 사진과 동영상; Meta Quest나 Android TV에서는 휴대폰이 중계하는 그 실시간 영상 시청. Immuch360은 DJI 제품이 아니며 DJI의 승인을 받지 않았고, DJI로는 아무것도 전송되지 않습니다.

<a id="your-dji-drones-live-video-on-your-phone-experimental"></a>
<a id="see-what-your-drone-sees-on-your-phone"></a>
#### 휴대폰에서 드론이 보는 화면 보기

<p align="center">
  <img src="../.github/readme/drone-live-phone.png" width="720" alt="실제 화면이 아닌 일러스트: 두 손이 위에 휴대폰을 끼운 드론 조종기를 들고 있고, 휴대폰 화면에는 해안의 실시간 항공 화면이 보이며, 해 질 녘 만 위로 작은 드론이 날고 있습니다">
</p>

DJI Fly 없이, 계정 없이 DJI 드론이 보는 화면을 Android 휴대폰에서 볼 수 있습니다: DJI RC-N3 조종기를 케이블로 휴대폰에 연결하면 Immuch360이 드론의 실시간 영상(1080p H.265)을 가로 방향 전체 화면으로, 케이블에서 읽은 비행 수치와 함께 보여줍니다. 드론 조종은 계속 조종기가 전적으로 맡습니다. RC-N3, DJI Neo 2, Samsung Galaxy S24+로 시험했습니다: build 29로 지상에서, 그리고 10월 24일과 25일에 build 30의 테스트 build로, 이어서 10월 26일에 build 30으로 비행 중에.

**어떤 조종기와 드론인가요**, 2026년 10월 26일 기준: 실시간 영상은 휴대폰을 거치하고 케이블로 연결하는 DJI 조종기를 통해 들어옵니다. 다른 조합을 시험해 보셨나요? 실시간 화면에서 "고급"을 열고 이어서 "진단"을 연 다음, 어떤 드론과 조종기를 썼는지, "진단"에 무엇이 나오는지 [Issues](https://github.com/freeKC/Immuch360/issues)에 알려주세요.

- **시험함**: 어떤 조종기로든 비행하려면 필요한 Digital Transceiver를 장착한 DJI Neo 2와 DJI RC-N3, 그리고 Samsung Galaxy S24+; 10월 23일 지상에서, 10월 24일부터 26일까지 실내 비행에서.
- **동작이 예상되나 시험하지 않음**: DJI가 RC-N3용으로 안내하는 다른 드론과 RC-N3의 조합(Neo, Flip, Mini 4 Pro, Mini 5 Pro, Air 3, Air 3S, Lito 1, Lito X1, 그리고 자체 안내서에 따른 Avata 360), 그리고 같은 케이블로 휴대폰을 거치하는 RC-N2와 같은 드론들 및 Neo 2의 조합. 앱은 H.265 영상만 보여주며, 비행 수치는 Neo 2에서만 검증되었습니다: 다른 드론에서는 화면이나 수치가 나오지 않을 수 있습니다.
- **지원하지 않음**: 자체 화면이 있는 조종기(DJI RC, RC 2, RC Pro 2), 따라서 DJI가 그중 하나와 함께 판매하는 Mavic 4 Pro; DJI 고글; RC-N1, RC-N1C 및 더 오래된 조종기; 조종기 없이 휴대폰에서 Wi-Fi로 조종하는 드론.

듣기만 합니다. 조종기나 드론에 명령을 보내는 일은 결코 없습니다: 조종기가 열리고 20초 후부터 페이지가 매초 쓰는 1바이트는 조종기가 데이터를 받는지만 알려줄 뿐, 어떤 명령도 담고 있지 않습니다.

실시간 화면에는 드론의 배터리와 모터 작동 시간, 그리고 비행 중에는 이륙 지점 기준 높이, 수직 속도, 속도, 드론 아래까지의 거리가 표시됩니다. 수치는 우리가 직접 캡처한 비행 데이터로 증명된 뒤에만 그곳에 표시됩니다: 높이, 속도, 아래까지의 거리는 10월 25일 실내 비행 두 번의 캡처로 최대 1.8 m 높이와 1.5 m/s까지 증명했으며, 그 이상은 아직입니다. 이 수치를 그곳에 표시하는 것은 build 30의 새 기능이며 build 30에서 처음 테스트합니다. 높이는 이륙 후 약 1.5 s, 드론이 땅이나 손을 떠난 뒤 표시되며, 어떤 항공기도 할 수 없는 방식으로 튀면 모터가 멈출 때까지 숨겨집니다. Advanced에는 배터리의 전압과 온도, 방위(0이 북쪽과 맞는지는 확인하지 않음), 모터가 추가되고, Diagnostics에는 링크가 주는 모든 수치가 배터리 전류까지 나옵니다. 위성, 위치, 홈까지의 거리는 표시되지 않습니다. 수치는 아직 DJI Fly와 비교하지 않았으니, 이 수치를 믿고 비행하지 마세요.

**장애물 링**, 기본으로 켜짐: 드론의 센서가 가까운 무언가를 감지하면 화면 중앙 둘레에 반투명한 원이 나타나고 장애물 쪽으로 호가 그려집니다. 호는 가까워질수록 호박색에서 빨간색으로 바뀌고, 옆에 거리가 표시되며, 점점 빨라지는 짧은 틱이 함께 나옵니다. 가까운 것이 없으면 아무것도 표시되지 않습니다. 원과 호의 방향은 10월 25일 실내 비행에서, 방향이 옵션이던 테스트 build로 확인했습니다. 기본으로 표시되는 것은 build 30에서 처음 테스트합니다. Advanced에서 거리("Glow from", 3.0 m, "Strong glow from", 1.0 m)를 정하거나, 원 대신 화면 가장자리의 테두리를 고르거나, 링, 소리, 진동을 끌 수 있습니다. 링은 드론의 센서가 알려주는 것만 보여줍니다: Sport 모드나 장애물 회피가 꺼져 있으면 아무것도 나오지 않으며, 빛이 없다고 길이 비어 있다는 뜻은 아닙니다. 정보용일 뿐입니다: Immuch360은 드론을 조종하거나 멈추지 않습니다.

1. Drone 카드는 라이브러리에 있고, 그 페이지에 "DJI live video"가 있습니다: 설정, 고급의 "DJI live video (experimental)"는 기본으로 켜져 있습니다.
2. 드론과 조종기를 켜고 DJI Fly를 닫은 다음, "DJI live video"를 열고 안전 안내를 읽습니다.
3. 조종기를 케이블로 휴대폰에 연결합니다. Android가 어떤 앱으로 열지 물으면 "항상"을 고르지 말고 Immuch360을 선택하세요. "항상"을 고르면 조종기를 DJI Fly에서 빼앗게 됩니다. USB 모드를 물으면 충전만을 선택하세요. 그 뒤로는 조종기를 연결하면 이 화면이 저절로 열립니다(Advanced의 "Open this screen when the remote is plugged in", 기본으로 켜짐).
4. Remote, Drone, Picture가 차례로 켜지고, 몇 초 안에 화면이 전체 화면으로 나옵니다. 세 버튼(나가기, "Send to a headset or a TV", Advanced)과 수치는 화면 옆 검은 띠에 있습니다. "Live" 같은 알림은 약 5초 뒤 사라지고 아무 곳이나 탭하면 다시 나타나며, 화면 위의 어떤 것도 드론에 작용하지 않습니다. 조치를 요구하는 오류는 계속 남아 있습니다.
5. Advanced에는 링크의 캡처를 `Download/Immuch360/dji-link`에 저장하는 "Save a capture for a bug report", 조종기 없이 다시 재생하는 "Play a saved capture", 그리고 링크가 주는 모든 수치를 보여주는 Diagnostics가 있습니다.

조종기는 드론의 저장소를 열지 않으므로 조종기를 통해서는 드론의 사진과 동영상에 접근할 수 없습니다: [아래](#bring-a-drones-or-a-camera-cards-photos-and-videos-to-immich)처럼 드론 자체에서 USB로, 또는 카드에서 복사하세요. 페이지에 안내된 대로 저장한 캡처는 공개하지 마세요: 드론의 영상과 조종기 및 기체의 일련번호가 들어 있고, 위치가 들어 있을 수도 있습니다. Diagnostics가 보여주는 내용을 담은 [Issues](https://github.com/freeKC/Immuch360/issues) 보고가 도움이 되며, 특히 다른 DJI 조종기에 대한 보고라면 더욱 좋습니다.

<a id="watch-it-in-a-meta-quest-or-on-an-android-tv"></a>
#### Meta Quest나 Android TV에서 보기

조종기에 연결된 휴대폰은 드론의 화면과 수치를 같은 로컬 네트워크에 있는 Meta Quest나 Android TV 또는 Google TV의 Immuch360으로 보내, 함께 있는 사람들이 볼 수 있게 합니다. 헤드셋은 창으로, 또는 더 크게 눈앞의 비행 화면으로 보여주고, TV는 전체 화면으로 보여주며, 휴대폰과 같은 수치와 장애물 링이 나옵니다. 이들은 보기만 합니다: 헤드셋이나 TV에서 하는 어떤 동작도 조종기나 드론에 닿지 않습니다. "보기 전용" 같은 알림은 몇 초 뒤 사라지고 키, 탭, 버튼으로 다시 나타납니다. 드론의 화면은 10월 24일 가정용 Wi-Fi로 Quest 3에 한 번 도달했습니다. 수치와 장애물 링이 있는 헤드셋 창과 비행 화면은 build 30에서 처음 테스트하며, Quest 2, Pro, 3S는 시험하지 않았습니다. 헤드셋에서 원이 화면 중앙을 가린다면 메뉴의 "가장자리 테두리"로 중앙을 비워 둘 수 있습니다. TCL Android TV에서는 10월 25일 페어링과 화면을 시험했으며, 이전 중계 방식에서는 끊김과 초록빛이 있었습니다. 10월 26일 build 30에서는 안정 스트림으로 전환한 뒤, 드론이 18 Mbit/s를 보낸 비행 내내 TV가 화면을 계속 보여주었으며, 멈춤은 7번, 가장 긴 것은 1.7 s였습니다. 화면이 어떻게 보였는지는 기록하지 않았습니다. build 31부터는 TV의 안전 안내가 리모컨 포커스를 유지합니다(위젯 테스트로 확인했으며, 그 TV에서는 아직 확인하지 않음). build 30에서는 그 아래의 화면이 포커스를 가져갈 수 있어서 안내를 읽을 수도 수락할 수도 없었고, 빠져나가는 유일한 방법은 페이지를 떠나는 뒤로 버튼뿐이었습니다. 헤드셋이나 TV를 보면서 비행하려면 드론을 계속 눈으로 지켜보는 관찰자가 옆에 있어야 합니다(EU 오픈 카테고리). 관찰자가 없다면 드론을 직접 보세요.

1. 휴대폰의 실시간 화면에서 "Send to a headset or a TV"를 탭하고 켭니다.
2. **Meta Quest**: Immuch360을 열고 라이브러리, Drone으로 가서 휴대폰을 고릅니다. 휴대폰에 표시된 코드를 입력합니다(그 휴대폰에 대해 한 번만). 화면이 창에서 열리고, "Open the flight view"를 누르면 더 커지며, B나 Y를 누르면 창으로 돌아옵니다.
3. **Android TV와 Google TV**: Immuch360을 열고 라이브러리, Drone으로 갑니다. "Let this TV watch" 아래에 TV가 코드와 그 QR 코드를 보여줍니다: 휴대폰의 같은 패널에서 "Add a TV"를 탭하고 스캔하거나 입력합니다. 그런 다음 TV에서 휴대폰을 선택하고 OK를 누르면 화면이 전체 화면으로 나옵니다. OK는 수치를 보이거나 숨기고, Menu는 옵션을 엽니다.
4. 휴대폰과 화면은 같은 로컬 네트워크에 있어야 합니다. 집 밖에서는 휴대폰의 핫스팟을 켜고(지원하면 5 GHz 대역으로) 헤드셋이나 TV에서 그 핫스팟에 연결하세요.
5. 버그 보고용으로 헤드셋의 메뉴와 TV의 Options에는 Diagnostics와 "Save a reception record"가 있으며, 이것은 그 화면이 받은 것을 보관합니다.

**전송 품질**은 build 30의 새 기능으로 휴대폰의 "고급"에 있습니다: 비행 중 드론은 약 18 Mbit/s를 보내는데, 10월 25일 휴대폰에서 공유기를 거쳐 TV로 가는 가정용 Wi-Fi 경로는 비행 시간의 3분의 1 동안만 이 전체 스트림을 전달했습니다. 나머지 시간에는 TV 화면이 끊기고, 깨지고, 초록빛을 띠었습니다. 기본값인 "자동"에서는 Wi-Fi가 따라가지 못하는 화면이, 휴대폰이 그 화면을 위해 다시 인코딩한 안정된 화면을 받습니다: 최대 1080p, 초당 30장, 그 Wi-Fi가 전달할 수 있는 속도로, 깨지는 대신 디테일을 줄여 깨끗하게 유지되도록 만들어졌습니다. 그 Wi-Fi가 안정된 화면을 30 s 동안 끊김 없이 전달하고 나면, 다음 착륙이나 이륙 때 드론 자체의 화면으로 돌아갑니다. 10월 26일 그 TV의 Wi-Fi는 한 번도 그러지 못했고, TV는 안정된 화면에 머물렀으며, 59초 중 44초 동안 초당 15장이었습니다. "전체 스트림"은 항상 드론의 화면을 그대로 보내고, "안정 스트림"은 항상 휴대폰의 화면을 보냅니다. 안정된 화면은 10월 26일 build 30으로 처음 휴대폰에서 실행되었습니다: Galaxy S24+가 하드웨어 HEVC, 고정 비트레이트로 인코딩했습니다. 이더넷 케이블로 연결한 TV나 휴대폰 자체 핫스팟에 연결한 화면은 Wi-Fi 구간이 두 개가 아니라 하나만 남습니다.

이 build에 없는 것: iPhone과 iPad의 드론 기능(시작하지 않음), LG와 Samsung TV로의 중계, 1.8 m와 1.5 m/s를 넘는 수치의 증명, 그다음 위성과 홈까지의 거리. 이것들은 야외 비행을 기다리고 있습니다.

<a id="bring-a-drones-or-a-camera-cards-photos-and-videos-to-immich"></a>
#### 드론이나 카메라 카드의 사진과 동영상을 Immich로 가져오기

DJI 드론의 사진과 동영상을 USB로 Immich 서버에 바로 가져옵니다: 드론 또는 카드 리더를 Android 휴대폰에 연결하고 새 파일을 골라 보내면, 동영상은 드론의 비행 데이터로 지도에 표시되고 드론의 360° 구체 사진은 360°로 표시됩니다. Immich 앱은 이미 휴대폰 갤러리에 있는 것만 백업하며, Immich 서버는 아직 DJI Neo 2 동영상의 위치를 읽지 못합니다. 이 페이지는 실험적 기능으로 Android 휴대폰과 태블릿에서만 사용할 수 있으며, 아직 실제 드론으로 시험하지 않았습니다.

<p align="center">
  <img src="../.github/readme/dji-drone-import.png" width="720" alt="실제 화면이 아닌 일러스트: 테라스 테이블 위의 드론이 케이블로 휴대폰에 연결되어 있고, 사진과 동영상이 드론에서 휴대폰 갤러리로 호를 그리며 넘어갑니다">
</p>

1. 라이브러리에서 Drone 카드를 연 다음 "Photos and videos from the drone"을 엽니다. 이 페이지의 설정인 설정, 고급의 "DJI drones (experimental)"은 기본으로 켜져 있습니다. 페이지를 숨기려면 그곳에서 끄세요.
2. 드론(Neo 2는 꺼진 상태여도 됩니다) 또는 카드 리더를 USB-C 데이터 케이블로 휴대폰에 연결합니다. 화면이 없는 DJI 조종기(RC-N1, RC-N2, RC-N3)에는 사진이 저장되지 않습니다. DJI 드론 페이지에서 "드론 또는 카드 선택"을 탭하고, 선택 화면의 사이드 메뉴에서 그것을 고른 뒤, DCIM 폴더를 열거나 드라이브 전체를 그대로 두고, "이 폴더 사용"과 허용을 차례로 누릅니다.
3. 페이지에는 사진과 동영상이 날짜별로 나열되며, .LRF, .SRT, .THM, .m4a 부속 파일은 제외됩니다. "새 항목 모두 선택"을 탭한 다음 "Immich에 업로드"를 탭합니다. 이전에 보낸 파일에는 구름 표시가 붙고 건너뜁니다. "기기에 보관"을 누르면 대신 파일을 휴대폰 갤러리의 "Immuch360 import" 앨범으로 복사합니다.
4. 동영상을 지도에 표시하려면 비행 전에 DJI Fly에서 Video Subtitles를 켜세요(동영상 모드, Settings, Camera). 그러면 드론이 각 동영상 옆에 .SRT 파일을 기록하고, 앱이 그 파일에서 위치를 읽어 업로드 후 Immich가 위치를 찾지 못한 경우 서버에 설정합니다.

DJI 드론(Mini, Air, Mavic 등, 카메라로 인식)의 360° 구체 사진은 360° 태그가 없어도 Immuch360에서 360°로 표시됩니다. Immich에는 이 태그가 필요합니다: 기본적으로 꺼져 있는 업로드 옵션 "Immich용으로 드론 구체 사진에 360° 태그 달기"는 사진을 변경하지 않고 옆에 작은 .xmp 파일을 함께 보내, Immich에서도 구체로 표시되게 합니다. Neo 2에는 구체나 파노라마 모드가 없어 사진과 동영상이 평면입니다. Neo 2 클립의 소리를 휴대폰이 녹음한 경우 그 소리는 별도의 .m4a 파일에 있습니다: 페이지가 해당 클립을 표시하며, Immich는 소리 없이 받습니다(소리를 유지하려면 DJI Fly로 다운로드하세요). DCIM 폴더가 있는 카메라 카드라면 카드 리더에서 같은 방식으로 동작합니다. DJI로는 아무것도 전송되지 않습니다.

더 보기: [USB로 DJI 드론](../docs/immuch360/user-guide.md#dji-drones-photos-and-videos-over-usb-experimental), [DJI 링크 진단](../docs/immuch360/user-guide.md#dji-link-diagnostics-experimental).

<a id="open-the-raw-files-of-360-cameras"></a>
### 360° 카메라의 원본 파일 열기

Insta360 카메라의 원본 .insp 사진과 .insv 동영상(렌즈 한 개 또는 두 개, 트랙 한 개, 트랙 두 개 또는 파일 두 개), GoPro MAX의 .360 파일과 DJI Osmo 360의 .osv 파일은 재생되는 동안 앱이 파일에 기록된 캘리브레이션으로 스티칭하며, 어디에도 아무것도 설치할 필요가 없습니다.

1. 앱이 읽을 수 있는 곳에 원본 파일을 두세요: SMB나 WebDAV 공유, Immich 서버(.insp와 .insv만 받음), 또는 컴퓨터의 폴더. Android 휴대폰의 갤러리는 원본 파일을 목록에 표시하지 않으므로, 휴대폰에 복사한 원본 파일은 갤러리에도 앱에도 나타나지 않습니다.
2. 파일 두 개로 이루어진 녹화는 두 파일을 함께 두세요: 앱은 첫 번째 파일 옆에서 다른 하나를 찾습니다.
3. 파일을 열고 360°를 탭합니다. 사진에는 캘리브레이션 출처와 함께 "RAW 360° 파일, 앱에서 스티칭됨"이 표시되고, 동영상은 재생되는 동안 스티칭됩니다.

Linux와 macOS는 원본 동영상을 평면으로 재생하며, 듀얼 피시아이 .dng 파일은 지금은 평면으로 표시됩니다.

더 보기: [360° 카메라 원본 파일](../docs/immuch360/user-guide.md#raw-360-camera-files-without-the-cameras-app).

<a id="turn-a-photo-with-one-key"></a>
### 키 하나로 사진 회전하기

편집기를 열지 않고 한 번 눌러 사진을 90° 회전합니다: 모든 플랫폼에서 버튼, 키보드 키, 또는 TV 리모컨의 컬러 버튼으로 회전할 수 있습니다. Immich 앱은 편집기 안에서 사진을 회전하지만, Immuch360은 키 하나로 회전하며, Immich 2.6 이상 서버에 있는 내 사진은 같은 서버 편집기를 거치므로 웹 앱과 다른 기기에서도 회전된 상태로 보입니다. 그 밖의 사진은 이 기기에서만 회전됩니다. 360°, 180°, 3D 사진은 회전되지 않으므로 몰입형 화면은 수평을 유지합니다.

<p align="center">
  <img src="../.github/readme/rotate-one-key.png" width="720" alt="실제 화면이 아닌 일러스트: 휴대폰 화면의 사진이 시계 방향으로 4분의 1 회전하고, 그 아래 둥근 버튼 줄에서 회전 버튼에 불이 들어와 있습니다">
</p>

1. **휴대폰, 태블릿, Meta Quest 창**: 사진을 열고 아래쪽 줄에서 편집 앞에 있는 Rotate를 탭하면 시계 방향으로 회전합니다. 길게 누르면 반대 방향으로 회전합니다. 키보드에서는 R과 Shift+R.
2. **Android TV와 Google TV**: 뷰어에서 포커스가 어디에 있든 리모컨의 노란색 버튼은 사진을 시계 방향으로, 파란색 버튼은 반시계 방향으로 회전합니다. 컬러 버튼이 없는 리모컨에서는 아래 방향키를 누르세요: 사진 아래에 Rotate가 선택된 바가 나타나며(사진에 텍스트 버튼이 있으면 오른쪽으로 한 번 더 이동), OK를 누를 때마다 사진이 회전합니다.
3. **LG TV(webOS)**: Android TV와 같은 노란색과 파란색 버튼, 키보드의 R과 Shift+R, 또는 사진 컨트롤의 회전 버튼. Samsung TV도 키 하나로 사진을 회전합니다.
4. **Windows, Linux, macOS**: R은 시계 방향, Shift+R은 반시계 방향으로 회전하며, 상단 바에서 전체 화면 앞에 있는 회전 버튼도 사용할 수 있습니다.
5. **네트워크 공유, Plex, 카메라의 사진**: 상단 바 맨 앞의 회전 버튼, R과 Shift+R, 또는 노란색과 파란색 버튼.

회전이 저장되는 곳: Immich 2.6 이상에서 내 계정의 사진은 서버의 사진 편집기로 회전되며, 원본 파일은 그대로 두고 회전된 이미지를 만듭니다(작업 중에는 얇은 바가 표시되고, 네 번 회전하거나 반대로 한 번 회전하면 원본으로 돌아갑니다). 기기의 사진, 공유의 사진, 파트너나 공유 앨범의 사진, 그리고 이전 버전 서버의 모든 사진은 이 기기에서만 해당 사진에 대해 회전되며 파일은 절대 변경되지 않습니다. Immich 사진인 경우 앱이 이를 한 번 알려줍니다. Android, iOS, 컴퓨터 앱에서 기기에 보관된 회전은 뷰어에는 표시되지만 썸네일, 슬라이드쇼, 추억에는 아직 표시되지 않습니다. 동영상, 잠긴 폴더, 그리고 모든 360°, 180°, 3D 사진에는 Rotate가 없습니다.

<a id="use-your-computer-as-the-media-player"></a>
### 컴퓨터를 미디어 플레이어로 쓰기

Windows 컴퓨터에서 Immuch360 Desktop은 서버 없이 사용자가 고른 폴더를 읽고, 평면 및 360° 동영상을 자체 플레이어로 재생하며, 같은 공유와 서버를 둘러보고, 집에서 컴퓨터를 헤드셋과 공유할 수 있습니다. Linux와 macOS에서는 미리보기로 제공되며, 360° 동영상은 평면으로 재생됩니다.

<p align="center">

</p>

## Immich와 비교

Immuch360은 Immich 모바일 앱 전체를 유지하면서 그 주변에 기능을 더합니다. 요약하면:

| | Immich 앱과 비교한 Immuch360 |
|---|---|
| **같은 점** | Immich 서버와 계정: 백업, 타임라인, 앨범, 검색, 인물, 추억, 공유와 파트너, 모두 서버와 동기화됩니다. 공식 앱 옆에 나란히 설치됩니다. |
| **서버 불필요** | 서버나 계정 없이도 기기의 사진과 동영상, 컴퓨터의 폴더, 네트워크 공유로 동작합니다. Plex와 카메라는 각자의 로그인을 쓰며, Immuch360 계정은 결코 쓰지 않습니다. |
| **360°와 몰입형** | 구체로 보는 360° 사진과 동영상, 파노라마, VR180과 3D, Meta Quest의 몰입형 화면, 360° 배지와 360° 목록. Immich 모바일 앱의 360° 보기는 2024년 1월부터 요청되어 왔지만 아직 없습니다. |
| **사진으로 만드는 3D** | 컴퓨터에서 사진 한 장이 3D 사진, 3D 장면, 360° 파노라마가 되고, Meta Quest 3 또는 3S에서는 어떤 평면 사진도 입체감을 얻습니다: 내 컴퓨터와 헤드셋에서 AI가 만들고, 앱과 파일에 그렇게 표시하며, 원본은 절대 바뀌지 않습니다. Immich 앱은 3D로 아무것도 만들지 않습니다. |
| **TV에서** | Android TV와 Google TV에서 같은 앱, 그리고 LG TV용 TV 앱이 있으며 이 앱은 Samsung TV용 테스트 build로도 패키징됩니다. Immich의 공식 앱은 LG TV에 설치되지 않습니다. |
| **휴대폰으로 로그인** | 휴대폰이 TV, 헤드셋, 컴퓨터의 QR 코드를 스캔하면 로그인되며, 비밀번호는 휴대폰에만 남습니다. Immich 앱에는 이런 기능이 없습니다. |
| **공유와 Plex** | SMB, WebDAV, DLNA 공유와 Plex 서버를 그 자리에서 재생하고, 그 파일을 직접 골라 서버로 보냅니다. |
| **Tapo 카메라** | 실시간 화면과 메모리 카드의 녹화 영상을 사진 옆에서; 아직 실제 카메라로 확인하지 않음. |
| **키 하나로 회전** | Immich 앱은 편집기에서 사진을 회전합니다. Immuch360은 키 하나로 회전하며, Immich 2.6 이상에 있는 내 사진은 같은 서버 편집기를 거치므로 웹 앱과 다른 기기에서도 회전된 상태로 보입니다. |
| **동영상** | Android 플레이어의 오디오와 자막 메뉴(Immich 앱의 Android 플레이어에는 없음); 동영상마다 고르는 원본 파일 또는 트랜스코딩된 스트림; 동영상의 기술 세부 정보. |
| **드론** | DJI 드론의 사진과 동영상을 USB로 보내며, 동영상은 비행 데이터로 지도에 표시됩니다(Immich 앱은 이미 휴대폰 갤러리에 있는 것만 백업합니다). 그리고 RC-N3 조종기를 통한 드론의 실시간 영상을 비행 수치, 장애물 링과 함께 휴대폰에서 보고 Meta Quest나 Android TV로 중계합니다. 둘 다 실험적입니다. |
| **보고할 곳** | Immich 프로젝트가 아니라 [Immuch360 Issues](https://github.com/freeKC/Immuch360/issues). |

기능별 상세 비교는 [Immich 앱과 비교](../docs/immuch360/compatibility.md#compared-with-the-immich-app)에 있습니다.

## 개인정보

개발자에게는 아무것도 전송되지 않습니다: 계정도, 분석도, 충돌 보고 서비스도, 광고도 없습니다. 앱은 사용자가 직접 선택한 서버(Immich 서버, 공유, Plex 서버, 카메라)와만 통신하며, 서버가 없을 때는 아무와도 통신하지 않습니다. 비밀번호와 토큰은 기기의 보안 저장소에 남아 있습니다. LG와 Samsung TV에는 앱용 보안 저장소가 없으므로, 그곳에서는 앱 자체 저장소에 암호화되지 않은 상태로 저장됩니다. 카메라는 Spatial 2.5D 플레이어와, 로그인할 화면의 코드를 스캔할 때만 기기에서 사용되며, 그 이미지는 저장되거나 어디로도 전송되지 않습니다. 휴대폰으로 로그인한 화면은 비밀번호가 아니라 자체 세션을 받으며, 이 세션은 홈 네트워크에서 암호화되어 전송됩니다. LG TV는 휴대폰 브라우저의 페이지로 로그인하며, 이 페이지는 이메일과 비밀번호를 홈 네트워크에서 암호화하지 않은 채 TV로 보내고, TV는 세션만 보관합니다. 드론 페이지의 캡처와 수신 기록은 공유하지 않는 한 기기에 남습니다: 드론의 영상이 들어 있고 위치가 들어 있을 수 있으며, 캡처에는 조종기와 기체의 일련번호도 들어 있습니다. 드론의 화면과 수치는 휴대폰에서 페어링한 헤드셋과 TV로만, 로컬 네트워크에서 암호화되지 않은 채 전송되며, Wi-Fi에 공유한 휴대폰과 같은 방식입니다. DJI에도 TP-Link에도 아무것도 전송되지 않습니다. 전체 정책은 [PRIVACY.md](../PRIVACY.md)에 있으며, 소스별 세부 사항은 [사용자 가이드](../docs/immuch360/user-guide.md#privacy)에 있습니다.

**AI 기능**은 내 기기에서만 동작합니다. 사진, 그 입체감, 장면, 파노라마는 컴퓨터나 헤드셋에서 계산되며 어디로도 보내지 않습니다. 앱은 요청한 구성 요소를 다운로드할 때만 연결합니다. GitHub의 이 프로젝트 릴리스에서, 안 되면 모델의 공식 페이지가 있을 때 그곳에서 받고, 각 파일을 SHA-256으로 확인한 뒤 오프라인으로 동작합니다. 컴퓨터에서 모델을 실행하는 ONNX Runtime은 공식 빌드에서 Microsoft로 원격 측정 데이터를 보내지만, Immuch360은 이를 끕니다. 새 파일은 원본 옆에 저장되며 원본을 덮어쓰지 않고, "AI 버전도 백업"을 켤 때만 Immich 서버로 갑니다(백업 앨범의 "모두 선택"도 이 설정을 켭니다).

360° 사진 뷰어는 dmitry-brazhenko가 작성한 업스트림 pull request [immich-app/immich#31169](https://github.com/immich-app/immich/pull/31169)를 기반으로 하며, 이는 bencefr의 프로토타입인 [#30192](https://github.com/immich-app/immich/pull/30192)를 바탕으로 만들어졌습니다. 두 분 모두에게 감사드립니다. TV에서 검색 필터의 리모컨 조작 수정과 앨범 정렬은 mlc70의 [mlc70/Immuch-Android-TV#1](https://github.com/mlc70/Immuch-Android-TV/pull/1) 작업에서 시작되었고, 액션 레일과 화면 높이의 80퍼센트를 차지하는 필터 시트는 mlc70의 [mlc70/Immuch-Android-TV#3](https://github.com/mlc70/Immuch-Android-TV/pull/3)에서 왔으며 작성자 정보도 그대로 유지했습니다. mlc70에게 감사드립니다. Samsung TV용으로도 패키징되는 LG webOS 앱은 Seeky91의 [immich-tv-webos](https://github.com/Seeky91/immich-tv-webos)를 기반으로 하며, MIT 라이선스로 자체 폴더에 보관되어 있습니다. Seeky91에게 감사드립니다. Tapo 카메라 기능은 [pytapo](https://github.com/JurajNyiri/pytapo), [Home Assistant Tapo Control](https://github.com/JurajNyiri/HomeAssistant-Tapo-Control), [python-kasa](https://github.com/python-kasa/python-kasa)가 문서화한 내용을 바탕으로 작성되었습니다. Meta Quest 화면은 오픈소스가 아닌 Meta Spatial SDK를 사용하므로 이 포크에만 남아 있습니다. SMB 공유는 LGPL 2.1 이상 라이선스의 libsmb2를 사용합니다: build 27과 desktop build 7부터 모든 build에 그 고지, 라이선스 전문, 소스 압축 파일 `Immuch360-libsmb2-sources.tar.gz`가 포함되며, 이 파일은 각 릴리스에도 첨부됩니다. Windows와 macOS build에는 프로젝트가 LGPL 라이선스로 빌드한 libmpv([mpv](https://mpv.io) 라이브러리, [FFmpeg](https://ffmpeg.org) 포함)와 그 라이선스 및 소스가 함께 들어 있으며, 앱의 라이선스 페이지(프로필 메뉴 맨 아래의 라이선스)에 나열되어 있습니다. 이 페이지에 언급된 플랫폼들의 세부 정보와 상표에 대한 내용은 [라이선스와 상표](../docs/immuch360/platform-support.md#license-and-trademarks)에 있습니다.

AI 기능은 다른 사람들이 만든 모델과 엔진을 실행하며, 이들은 요청할 때만 이 저장소의 사전 릴리스 [ai-components-1](https://github.com/freeKC/Immuch360/releases/tag/ai-components-1), [ai-components-2](https://github.com/freeKC/Immuch360/releases/tag/ai-components-2), [ai-components-3](https://github.com/freeKC/Immuch360/releases/tag/ai-components-3)에서 다운로드됩니다. 각 파일과 그 출처, 라이선스, SHA-256은 [MODEL-LICENSES.md](https://github.com/freeKC/Immuch360/blob/immuch360/licenses/ai-components/MODEL-LICENSES.md)에 있습니다. 만든 분들께 감사드립니다:

- **3D 사진**: Depth Anything V2 Small(Apache 2.0), 컴퓨터에서는 ONNX Runtime(MIT)이, 헤드셋에서는 Quest APK에 포함된 LiteRT 2.3.0(Apache 2.0)이 실행합니다.
- **3D 장면**: MoGe-2 ViT-S(MIT), 프로젝트가 MIT 가중치에서 ONNX로 내보냄, 그리고 LaMa(Apache 2.0).
- **360° 파노라마**: VAE를 포함한 FLUX.2 klein base 4B(Apache 2.0), Qwen3 4B(Apache 2.0), nomadoor의 360° LoRA(Apache 2.0), MI-GAN(MIT), Real-ESRGAN x4plus(BSD 3 Clause), 이를 stable-diffusion.cpp와 ggml(MIT)이 실행하며, 프로젝트의 CI가 빌드하고 Windows에서 서명했습니다.

nomadoor의 360° LoRA는 모델 카드상 Apache 2.0이며 CC0와 퍼블릭 도메인 이미지로 학습했고, 일부는 CC BY입니다: 그 부분의 저작자 표시는 MODEL-LICENSES.md의 다음 버전에 들어갑니다. 여기에는 비상업용 라이선스가 하나도 없고, CUDA가 필요한 것도 없습니다. ONNX Runtime과 LiteRT에는 다른 라이브러리가 들어 있으며 각 고지문에 나열되어 있고, 그중에는 약한 카피레프트 라이선스인 MPL 2.0의 Eigen이 있습니다.

이 페이지의 캡처는 앱의 실제 화면입니다: 휴대폰 화면은 에뮬레이터의 Android build에서, Android TV 화면은 Google TV 에뮬레이터에서, LG와 Samsung 화면은 TV를 대신하는 브라우저에서, Windows 화면은 Windows 11 PC에서, Meta Quest 창은 Quest 3에서 찍었으며, 모두 [Poly Haven](https://polyhaven.com)의 CC0 파노라마를 썼습니다. 헤드셋의 몰입형 화면은 작성자 자신의 미디어로 Quest 3에서, iPad 화면은 iPad 시뮬레이터에서 CC0 Poly Haven 파노라마로 찍었습니다. AI 생성 기능의 그림은 Poly Haven의 CC0 사진으로 만든 앱의 실제 결과물이며, Windows 앱의 실제 캡처 두 장이 함께 있습니다. 첫 이미지와 TV, 로그인, 회전, 카메라, 드론 그림은 프로젝트를 위해 만든 일러스트입니다: 앱의 화면도, 다른 회사의 로고도, 얼굴도 담고 있지 않습니다. 각 이미지는 출처, 날짜, 라이선스와 함께 [CAPTURES.md](../.github/readme/CAPTURES.md)에 정리되어 있습니다.

## 로드맵

아직 하지 않은 일을 가능성이 높은 순서로 적었습니다. 여기 있는 것은 약속이 아니며, [이슈 트래커](https://github.com/freeKC/Immuch360/issues)에 의견을 주시면 무엇을 먼저 할지 정하는 데 도움이 됩니다.

### 고급 기능

전체 범위를 알고 싶은 독자를 위해, 앱이 읽고 재생할 수 있는 것을 정리했습니다. 각 항목은 [사용자 가이드](../docs/immuch360/user-guide.md)와 [호환성 페이지](../docs/immuch360/compatibility.md)에서 자세히 설명합니다.

<details>
<summary><b>형식, 소스, 재생, 하드웨어 자세히</b></summary>

- **형식**: 평면 사진과 동영상(기기가 디코딩할 수 있는 것: MP4, MOV, MKV 등); 이퀴렉탱귤러 360° 사진과 동영상; 부분 파노라마(GPano 크롭); VR180; 파일에서 읽거나(st3d 박스) 프레임에서 추정한 상하 또는 좌우 스테레오스코픽 3D; Apple 공간 사진(HEIC 스테레오 쌍)과 공간 동영상(MV-HEVC, 한쪽 눈); 원본 Insta360 .insp와 .insv, GoPro .360, DJI .osv; 구체에 톤 매핑된 10비트 HLG와 PQ 소스.
- **투영과 메타데이터**: 서버나 공유에 범위 요청을 보내 파일에서 읽어오는 GPano와 구형 메타데이터; 카메라의 초기 시점; 카메라로 인식되는 DJI 드론의 구체 사진과, Immich에서도 인식되도록 하는 선택적 .xmp 사이드카; 기기에 기억되는 "360°로 보기"; 파일이나 파일명에서 인식되는 VR180; .SRT 비행 로그에서 읽는 드론 동영상의 위치; 변환된 복사본이 아니라 원본 파일을 재생하기 때문에 그대로 보존되는 메타데이터; Immich 편집기로 저장하거나 기기에 보관하는 90° 회전(몰입형 파일에는 적용하지 않음).
- **네이티브 재생**: Android와 TV에서는 Media3, iOS에서는 SceneKit과 AVFoundation, 헤드셋에서는 Meta Spatial SDK, Windows에서는 libmpv; 기기가 디코딩할 수 있는 것에 따라 원본 또는 트랜스코딩된 스트림을 선택; 설정의 고급 항목에 있는 기기의 동영상 디코더 목록; 오디오 트랙 선택, Android 플레이어의 자막, 버퍼링 표시기.
- **기기에서 스티칭되는 원본 파일**: 사진을 위한 Flutter 프래그먼트 셰이더; 단일 트랙 동영상을 위한 플레이어 내 GPU 효과; 트랙 또는 파일마다 렌즈가 하나씩 있는 동영상을 위한 동시 하드웨어 디코더 두 개와 GPU 컴포지터(Android와 Quest에서는 OpenGL ES 3, iOS에서는 Metal, Windows에서는 데스크톱 빌드 5부터 앱이 그래픽 칩에서 프레임을 짝 맞추는 libmpv 플레이어 두 개); 카메라 자체의 캘리브레이션(Mei, V6, 등거리 모델)과 가속도계 기록; 기기가 디코더 두 개를 동시에 실행할 수 없을 때는 렌즈 한 개, 트랜스코딩된 스트림, 카메라의 LRV 복사본, 또는 스티칭되지 않은 동영상으로 폴백합니다.
- **소스**: 기기의 갤러리; 컴퓨터의 폴더; 시스템 폴더 선택기를 통해 USB로 연결한 드론 또는 카메라 카드(Android, 실험적); 드론의 실시간 영상을 위해 케이블로 연결한 DJI RC-N3 조종기(Android, 실험적), 로컬 네트워크로 Meta Quest나 Android TV에 중계; Immich 서버; SMB 2와 3, WebDAV, DLNA/UPnP; 서버 고유의 인증서로 검증하는 HTTPS 기반 Plex; 로컬 네트워크(HTTPS와 RTSP)를 통한 Tapo 카메라; Wi-Fi에서 WebDAV 서버로 공유되는 휴대폰이나 컴퓨터; Bonjour/mDNS, 로컬 네트워크 스캔, SSDP, GDM, TP-Link 탐색으로 찾아내고 주소가 바뀌어도 계속 추적되는 서버.
- **필요할 때 읽기**: 바이트 범위와 세션별 토큰으로 플레이어에 데이터를 제공하는 로컬 브리지; 큰 블록, 미리 읽기, 최대 6개의 SMB 연결 병렬 처리; 각 동영상의 한 프레임으로 만드는 썸네일; 기기에 아무것도 복사하지 않음.
- **하드웨어**: 존재하는 모든 곳에서 측정된 한계(Quest 3의 H.264 상한, 소프트웨어 디코더에서 최대 2048x2048 렌즈 두 개)와 함께 사용되는 하드웨어 디코더; Windows에서는 디코딩된 각 프레임으로부터 그래픽 칩이 360° 화면을 그리며, 각 컴퓨터에서 프레임 크기를 측정하고 내장 또는 전용 그래픽 칩을 감지합니다.
- **플랫폼별 세부 사항**: 휴대폰의 자이로스코프와 Spatial 2.5D 플레이어; Quest의 몰입형 화면, 컨트롤러, 손 인식; Android TV의 리모컨 배치, 키보드 대화상자, TV 배너; 컴퓨터에서는 마우스와 키보드, 전체 화면, 단일 창, 프로그램으로 열거나 그 창에 끌어다 놓은 파일과 폴더, Windows에 디코더가 있을 때 폴더의 파일처럼 읽히는 HEIC, AVIF, TIFF와 카메라 원본 사진, 그리고 비밀번호와 토큰을 위한 Windows의 데이터 보호 기능.
- **AI 생성 기능**: 3D 사진은 왼쪽 눈이 먼저인 전체 폭 나란히 JPEG이며, 입체감은 프로세서에서 ONNX Runtime 1.31.0(Intel Mac에서는 1.23.2)으로 실행한 Depth Anything V2 Small에서 얻음; 장면은 깊이가 끊기는 곳에서 잘린 레이어 glTF 장면을 담은 JPEG이며, MoGe-2 ViT-S와 LaMa로 만들고 .glb 내보내기 지원; 6144 x 3072의 360° 파노라마는 Vulkan 위의 stable-diffusion.cpp로 FLUX.2 klein base 4B와 360° LoRA가 생성하고, 이음매는 MI-GAN이 잇고, 디테일은 Real-ESRGAN이 높이며, 진짜 픽셀을 되돌려 놓음; 360° 사진의 위아래 3D 버전; 모든 파일에 우리 XMP(종류, 출처, 원본의 SHA-1, 품질 플래그), 장면과 파노라마에는 IPTC 디지털 소스 유형; Quest의 입체감은 LiteRT가 그래픽 칩이나 프로세서에서 계산해 캐시에 보관; 컴퓨터에서는 두 레인의 대기열과, Vulkan으로 그래픽 카드를 읽고 다른 프로그램이 메모리를 점유하는 동안 기다리는 게이트; 각 구성 요소는 SHA-256으로 확인하고, Windows 생성기는 서명됨.
- **설계부터 지켜지는 개인정보 보호**: 계정 없음, 클라우드 없음, 분석 없음; 기기의 보안 저장소에 있는 비밀번호와 토큰(앱용 보안 저장소가 없는 LG와 Samsung TV에서는 앱 자체 저장소에 암호화되지 않은 상태로 저장); 휴대폰으로 로그인한 화면은 비밀번호가 아니라 자체 세션을 받으며, 이 세션은 홈 네트워크에서 암호화되어 전송됨(LG TV는 휴대폰 브라우저의 페이지에서 홈 네트워크를 통해 암호화되지 않은 비밀번호를 받고, 세션만 보관함); 기기에서만 사용되는 Spatial 플레이어와 코드 스캐너의 카메라; 오직 사용자의 네트워크에서만 접근하는 공유, Plex, 카메라; 기기에서 계산하는 AI, 요청할 때만 다운로드하고 SHA-256으로 확인하는 구성 요소, 꺼 둔 ONNX Runtime 원격 측정.
