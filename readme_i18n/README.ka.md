# Immuch360

Immuch360 არის Immich-ის მობილური აპი 360° ფოტოებითა და ვიდეოებით, რომლებშიც შეგიძლიათ ირგვლივ მიმოიხედოთ, და ასევე უფასო პლეერი ბრტყელი, 360°, 3D და VR180 ფოტოებისა და ვიდეოებისთვის Android ტელეფონებსა და პლანშეტებზე, iPhone-სა და iPad-ზე, Meta Quest ჩაფხუტებზე (Quest 3 და 3S, ხოლო ბილდ 21-დან Quest 2 და Quest Pro, გამოუცდელი), ხოლო ბილდ 20-დან Android TV-სა და Google TV-ზეც. Immuch360 Desktop, იგივე აპი Windows კომპიუტერზე, გამოვიდა წინასწარი ვერსიის სახით, იხილეთ [Windows კომპიუტერზე](#on-a-windows-computer-immuch360-desktop-preview).

ის განკუთვნილია მათთვის, ვინც იღებს 360° კამერით (Insta360, GoPro MAX, DJI Osmo 360, Ricoh Theta, Samsung Gear 360) ან ტელეფონის სფერული ფოტოს რეჟიმით, ან აქვს ჩაფხუტი, და სურს საკუთარი კადრების ნახვა Immich სერვერიდან, თავად ტელეფონიდან, NAS-იდან, მედია სერვერიდან ან Plex სერვერიდან: იგივე სერვერი, იგივე ანგარიში, სერვერის დანამატის გარეშე, ან საერთოდ სერვერის გარეშე. ბილდ 20-დან ის Tapo კამერებსაც აჩვენებს, პირდაპირ და მათი მეხსიერების ბარათის ჩანაწერებით.

## 360° ფოტოები და ვიდეოები სფეროს სახით

თქვენ ფოტოების მარქაფს ინახავთ [Immich](https://github.com/immich-app/immich) სერვერზე და ზოგიერთი მათგანი 360° კამერით ან ტელეფონის სფერული ფოტოს რეჟიმით არის გადაღებული. ოფიციალურ მობილურ აპში ეს სურათები ბრტყელ, გაწელილ ზოლად ჩანს და 360° ვიდეოებიც ბრტყლად იკვრება. Immich-ის ვებ აპს შეუძლია 360° ფოტოს სფეროს სახით ჩვენება, მობილურ აპს კი არა: ამას 2024 წლის იანვრიდან ითხოვენ [დისკუსიაში #6572](https://github.com/immich-app/immich/discussions/6572).

Immuch360 მათ სფეროს სახით ხსნის, რომელშიც ირგვლივ მიმოიხედავთ, Android და iOS ტელეფონებსა და პლანშეტებზე.

ფოტო ბრუნავს, როცა მას გადაათრევთ, დიდდება თითებით ან ორმაგი შეხებით, სწრაფი გადათრევის შემდეგ კიდევ ცოტას ბრუნავს, იხსნება კამერის მიერ ჩაწერილ საწყის ხედზე (GPano მეტამონაცემები) და გადიდებისას უფრო მკაფიო ტექსტურას იღებს; ნაწილობრივი პანორამებიც მუშავდება (GPano ჩამოჭრა). ვიდეო იკვრება ჩაშენებულ სფერულ პლეერში ხმით, გადათრევით და გიროსკოპით.

უკვე შეკერილი 360° ფაილები ყველგან მუშაობს: ექსპორტები Insta360 აპიდან ან Studio-დან, GoPro Player-იდან, Ricoh Theta-დან და ტელეფონის სფერული ფოტოები. პირდაპირ კამერიდან აღებულ დაუმუშავებელ ფაილებს აპი კერავს, იხილეთ [კამერების დაუმუშავებელი 360° ფაილები](#raw-360-camera-files-without-the-cameras-app).

- **360° ფოტო სფეროს სახით**: დახურვა ზედა მარცხენა კუთხეში; ზედა მარჯვენა კუთხეში 360°/180° ღილაკი, 3D განლაგების ღილაკი და გიროსკოპი.
- **360° ვიდეო 360° პლეერში**: მართვის ღილაკებისთვის შეეხეთ სურათს; 360° და 3D ზედა მარჯვენა კუთხეში.

### 360° ფოტოს გახსნა სფეროს სახით

1. გახსენით ფოტო ქრონოლოგიიდან, ალბომიდან, [360° სიიდან](#find-your-360-shots-the-360-list) ან გაზიარების საქაღალდიდან. 360° ფოტოების მინიატურებს 360° ნიშანი აქვს.
2. შეეხეთ 360°-ს მნახველის ზედა ზოლში. იხსნება სფერული მნახველი ჩატვირთვის მაჩვენებლით, სანამ სრული სურათი იტვირთება; ბრტყელ ხედში არსებული გადიდება ნარჩუნდება.
3. ირგვლივ მიმოსახედად გადაათრიეთ, გასადიდებლად თითებით გაშალეთ, მისაახლოებლად ორჯერ შეეხეთ. სწრაფი გადათრევის შემდეგ ხედი კიდევ ცოტას ბრუნავს და ნელდება.
4. ტელეფონის მობრუნებით მიმოსახედად შეეხეთ გიროსკოპის ღილაკს ზედა მარჯვენა კუთხეში (ნაგულისხმევად გამორთულია).
5. ზედა მარჯვენა კუთხის დანარჩენი ორი ღილაკია 360°/180° (სრული სფერო ან VR180 ნახევარსფერო, ნაწილობრივ პანორამებზე არ ჩანს) და 3D (სტერეოსკოპიული ფოტოს განლაგება), იხილეთ [3D და VR180](#3d-and-vr180-photos-and-videos). დაუმუშავებელ Insta360 ფოტოს მხოლოდ გიროსკოპი აქვს.
6. დახურეთ ზედა მარცხენა კუთხის ჯვრით.

### 360° ვიდეოს დაკვრა

1. გახსენით ვიდეო და შეეხეთ 360°-ს ზედა ზოლში. 360° ვიდეოზე 360° ღილაკი პირველია; ტელეფონებსა და პლანშეტებზე მას Spatial ღილაკი მოსდევს, სანამ ეს პარამეტრი ჩართულია (იხილეთ [Spatial 2.5D](#depth-on-a-flat-screen-spatial-25d-experimental)).
2. ჩაშენებული 360° პლეერი სრულ ეკრანზე იხსნება და ხმით უკრავს: Android-ზე Media3, iOS-ზე SceneKit.
3. ირგვლივ მიმოსახედად გადაათრიეთ ან ამოძრავეთ ტელეფონი. Android-ის პლეერი ყოველთვის მიჰყვება ტელეფონს; iOS-ის პლეერს აქვს გიროსკოპის გადამრთველი, ნაგულისხმევად ჩართული.
4. მართვის ღილაკებისთვის შეეხეთ სურათს: ზემოთ დახურვა, 360°/180° და 3D, შემდეგ დაკვრა, გადახვევის ღილაკები და Android-ზე დროის ზოლი. iOS-ის პლეერს ჯერჯერობით მხოლოდ დაკვრა და პაუზა აქვს.
5. როცა ვიდეოს ორი ან მეტი აუდიო ტრეკი აქვს (ენები, კომენტარი), „აუდიო ტრეკი“ ღილაკით შეგიძლიათ ერთ-ერთის არჩევა. სანამ ვიდეო იტვირთება ან ჩერდება, პლეერი აჩვენებს „იტვირთება“ წარწერას თავისი დაკვრის ბუფერის შევსებით.

პლეერი უკრავს ტელეფონზე შენახულ ფაილს ან ქსელური გაზიარების ფაილს, თუ ასეთი არსებობს. წინააღმდეგ შემთხვევაში ნაკადს თქვენი სერვერიდან იღებს: ნაგულისხმევად ტრანსკოდირებულ ნაკადს, ან ორიგინალს, თუ ამას მოითხოვთ მორგება, Asset Viewer (აქტივების მნახველი), „ვიდეოს წყარო“ განყოფილებაში (ბილდ 15-დან; მანამდე „Force original video“ (ორიგინალი ვიდეოს იძულებით დაკვრა) გადამრთველი), იხილეთ [ვიდეოს დეტალები და დეკოდერები](#video-details-decoders-and-why-a-video-stutters).

### 360° ფაილი, რომელიც ბრტყლად ჩანს: ნახვა 360°-ად

ზოგიერთ 360° ფაილს პროექციის ტეგი არ აქვს, ამიტომ სერვერი მათ 360°-ად არ მონიშნავს და ისინი ბრტყლად ჩანს.

1. გახსენით ფოტო ან ვიდეო და შეეხეთ ⋮-ს ზედა მარჯვენა კუთხეში.
2. შეეხეთ „ნახვა 360°-ად“ პუნქტს, რომელიც სლაიდშოუსა და გადმოწერას შორისაა. 360° ღილაკი ზედა ზოლში ჩნდება.
3. გასაუქმებლად იგივე პუნქტი ახლა ამბობს „აღარ ჩაითვალოს 360°-ად“.

არჩევანი ტელეფონზე ინახება და სერვერზე არაფერს ცვლის. ქსელური გაზიარების ფაილზე ის მხოლოდ მიმდინარე ნახვისთვის მოქმედებს.

### შეზღუდვები

- **iOS-ის 360° ვიდეო პლეერი**: დაკვრა და პაუზა, დროის ზოლი ჯერ არ არის.
- **წინა და შემდეგი**: ტელეფონების 360° პლეერები ჯერ არ გადადიან წინა ან შემდეგ მედიაზე; Quest-ის იმერსიული ხედი გადადის.
- **ძალიან დიდი პანორამები**: ფოტო მაქსიმუმ 8192x4096 ზომით ნაჩვენებია, რაც ტელეფონების GPU-ების უმეტესობის მიერ მიღებული უდიდესი ტექსტურაა, ამიტომ უფრო დიდი პანორამა ამ ზომამდე მცირდება.
- **ორმაგი თევზის თვალის .dng**: კვლავ ბრტყლად ჩანს.

### გაზიარების დამატება

1. გახსენით ბიბლიოთეკის ჩანართი, შემდეგ ქსელური გაზიარებები. პირველად გვერდზე წერია „გაზიარებები ჯერ არ არის“ და არის „გაზიარების დამატება“ ღილაკი; ზედა მარჯვენა კუთხის + იგივეს აკეთებს ნებისმიერ დროს. ბილდ 20-დან ორივე გეკითხებათ, რისი დამატება გსურთ: „ქსელური გაზიარება (NAS, კომპიუტერი, მედია სერვერი)“, „Plex Media Server“ თუ „Tapo კამერა“. აირჩიეთ პირველი.
2. „გაზიარების დამატება“ გვერდი ჯერ თქვენი ქსელის სერვერებს ეძებს და მათ „ნაპოვნია ქსელში“ ქვეშ ჩამოთვლის, მათი ტიპით (SMB, WebDAV, DLNA, ტელეფონი, ხოლო ბილდ 20-დან Plex და Tapo). ძიებას დაახლოებით ექვს წამამდე სჭირდება; „ხელახლა სკანირება“ მას თავიდან იწყებს. ის იყენებს Bonjour/mDNS-ს და ლოკალური ქსელის სკანირებას, რომელიც ნამდვილი SMB ან WebDAV გაცვლით დასტურდება, ბილდ 19-დან SSDP ძიებას DLNA მედია სერვერებისთვის, ხოლო ბილდ 20-დან GDM-ს, Plex-ის აღმოჩენის პროტოკოლს, და TP-Link-ის აღმოჩენის პროტოკოლს Tapo კამერებისთვის.
3. შეეხეთ სერვერს: ტიპი, სერვერი, პორტი და გზა ივსება. Plex სერვერი ან Tapo კამერა ამის ნაცვლად თავის საკუთარ, უკვე შევსებულ გვერდს ხსნის.
4. სიაში არ არის? შეავსეთ ფორმა ხელით. ტიპი: „SMB (Samba, Windows-ის გაზიარება)“, „WebDAV (Nextcloud, Synology და სხვა)“, „DLNA მედია სერვერი (Jellyfin, NAS, TV ბოქსი)“ ან, ბილდ 20-დან, „Plex Media Server“, რომელიც [Plex Media Server, plex.tv-ის გარეშე](#plex-media-server-without-plextv) გვერდს ხსნის. შემდეგ სახელი, „სერვერის სახელი ან მისამართი“ (სახელი ან მისამართი; სრული მისამართი, როგორიცაა `smb://nas/photos`, `\\nas\photos` ან `https://nas:5006/photos`, დანარჩენ ველებს ავსებს), „პორტი (არასავალდებულო)“, როცა ის ჩვეულებრივი არ არის, „გაზიარება“ SMB-სთვის ან „WebDAV მისამართის გზა“ WebDAV-ისთვის, „საწყისი საქაღალდე (არასავალდებულო)“, „მომხმარებლის სახელი“ და „პაროლი“, და „დაცული კავშირი (HTTPS)“ WebDAV-ისთვის.
5. SMB: სერვერისა და მომხმარებლის სახელის აკრეფის შემდეგ „აირჩიეთ გაზიარება“ სერვერის გაზიარებებს ჩამოთვლის.
6. DLNA: მედია სერვერს არც მომხმარებლის სახელი აქვს და არც პაროლი. მიუთითეთ სერვერი, პორტი და მისი მოწყობილობის აღწერის „აღწერის გზა“ (minidlna-სთვის `/rootDesc.xml`), ან სერვერის ველში ჩასვით სრული მისამართი, მაგალითად `http://192.168.1.10:8200/rootDesc.xml`.
7. შეეხეთ „კავშირის შემოწმება“-ს. პასუხია „დაკავშირებულია, საწყის საქაღალდეში N ელემენტია“, ან ახსნა, თუ რატომ ვერ მოხერხდა. შემდეგ შეეხეთ შენახვას ფორმის ბოლოში.

ცარიელი პაროლით მომხმარებლის სახელი ისე იგზავნება, როგორც არის: Freebox Server-ს თავისი დისკებისთვის `freebox` და პაროლის გარეშე სჭირდება. გაზიარების მოგვიანებით შესაცვლელად ან წასაშლელად გამოიყენეთ ფანქარი მის გვერდით ქსელური გაზიარებების გვერდზე.

### დათვალიერება და დაკვრა

1. შეეხეთ გაზიარებას. ჯერ საქაღალდეებია, შემდეგ ფოტოები და ვიდეოები მინიატურების ბადეში (ასევე თითოეული ვიდეოს ერთი კადრი, მოწყობილობის ქეშში შენახული). 360°-ად ამოცნობილებს 360° ნიშანი აქვთ, ხოლო ბილდ 19-დან Apple-ის სივრცით ფოტოებსა და ვიდეოებს 3D ნიშანი. განსაახლებლად ქვემოთ ჩამოწიეთ.
2. შეეხეთ ფოტოს: ის სრულ ეკრანზე იხსნება (თითებით გადიდება, ორმაგი შეხება), და მისი 360° ღილაკი სფერულ მნახველს ხსნის.
3. შეეხეთ ვიდეოს: ის ჩაშენებულ პლეერში იკვრება (დაკვრა, პაუზა, გადახვევა), 360° ღილაკით, რომელიც 360° პლეერს ხსნის მისი 3D და 360°/180° ღილაკებით, ხოლო ტელეფონზე სტერეოსკოპიული ფაილებისთვის Spatial ღილაკით.
4. Quest-ზე 360° ღილაკი იმერსიულ ხედს ხსნის, ხოლო ბილდ 19-დან „ნახვა 3D-ში“ Apple-ის სივრცით ფოტოს 3D-ში ხსნის.
5. ⋮ მენიუში არის „ნახვა 360°-ად“ 360° ტეგის არმქონე ფაილებისთვის, ხოლო ტელეფონზე „Spatial 2.5D“ არასტერეოსკოპიული ვიდეოებისთვის.

360°, 3D და VR180 ამოიცნობა ფაილის GPano ან სფერული მეტამონაცემებიდან, რომლებიც დიაპაზონის მოთხოვნებით (range requests) იკითხება, ხოლო VR180 ასევე ფაილის სახელიდან. ბილდ 16-დან ამოიცნობა დაუმუშავებელი Insta360 ფაილებიც (.insp ფოტო სახელით ან კამერის კალიბრაციის ბლოკით, .insv ვიდეო სახელითა და კადრით) და იკერება.

### გაზიარების ფაილების გაგზავნა Immich-ში

ბილდ 15-დან, როცა სერვერთან ხართ დაკავშირებული:

1. გაზიარების საქაღალდეში ხანგრძლივად დააჭირეთ ფოტოს ან ვიდეოს, ან შეეხეთ არჩევას ზედა მარჯვენა კუთხეში.
2. მონიშნეთ, რაც გსურთ, ან გამოიყენეთ „ამ საქაღალდის ყველა ფოტოსა და ვიდეოს არჩევა“.
3. შეეხეთ „Immich-ზე ატვირთვა“-ს. ფაილები გაზიარებიდან თქვენს სერვერზე სათითაოდ გადაიცემა, თითოეულ ფილაზე პროგრესით, ხოლო ქვედა ზოლში წერია „იგზავნება 3 / 12“ გაუქმების ღილაკით. გაგზავნისას აპი ღია დატოვეთ.
4. ბოლოს აპი გეუბნებათ, რამდენი გაიგზავნა და რამდენი იყო უკვე სერვერზე: სერვერი საკუთარ ასლს ინახავს და უკვე არსებული ფაილების დუბლიკატებს შლის. ადრე გაგზავნილ ფაილებს ნიშანი აქვთ („ადრე გაიგზავნა Immich-ზე“) და შემდეგ ჯერზე გამოიტოვება.

გაზიარებიდან გახსნილ ფოტოს ან ვიდეოს მის მენიუში იგივე პუნქტი აქვს. სერვერის გარეშე გვერდზე წერია „ასატვირთად დაუკავშირდით Immich სერვერს“. მოწყობილობის ფოტოები და ვიდეოები იგივე გზით იგზავნება ბიბლიოთეკის ჩანართიდან: On this device, ალბომი, არჩევა, „Immich-ზე ატვირთვა“, მათ შორის იმ ალბომებიდან, რომლებიც მარქაფის არჩევანში არ შედის; გაგზავნის შემდეგ ისინი დამარქაფებულად ითვლება.

### როგორ იკვრება ჩამოტვირთვის გარეშე

პლეერები საჭირო ბაიტებს აპის შიგნით არსებული ხიდის მეშვეობით კითხულობენ (მხოლოდ loopback მისამართი, შემთხვევითი ტოკენი თითოეული სესიისთვის, ბაიტების დიაპაზონები), ამიტომ ვიდეოში გადახვევა მუშაობს და მოწყობილობაზე არაფერი კოპირდება. პლეერები და ჩაფხუტის მნახველი გაზიარების მისამართს არასოდეს იღებენ, მხოლოდ ხიდის 127.0.0.1-ს; სერვერთან მოთხოვნებს თავად აპი აგზავნის.

გლუვი დაკვრისთვის გაზიარება დიდი ბლოკებით იკითხება, ფაილი წაკითხვებს შორის ღია რჩება, პლეერზე წინ 16 მბ-მდე იკითხება და დაკვრადი ვიდეო ექვსამდე პარალელური SMB კავშირით იკითხება, ცალკე იმ კავშირისგან, რომელიც მინიატურებსა და სიებს ემსახურება. Freebox Server თითოეულ წაკითხვაზე ნელა პასუხობს: ერთი კავშირი 4,5 მბ/წმ-ს იძლევა, ექვსი 19 მბ/წმ-ს, რაც საკმარისია 132 მბიტ/წმ-იანი 5.7K ექსპორტისთვის.

სანამ პლეერი მონაცემებს ელოდება, 360° და Spatial პლეერები აჩვენებენ „იტვირთება“ წარწერას თავიანთი დაკვრის ბუფერის შევსებით; ბრტყელი პლეერი „იტვირთება“ წარწერას პროცენტის გარეშე აჩვენებს, სანამ ვიდეო იტვირთება ან ჩერდება.

### DLNA მედია სერვერები

ბილდ 19-დან აპი მედია სერვერების SSDP ძიებას ქსელის multicast ჯგუფს უგზავნის და იგივე მოთხოვნას ლოკალური /24 ქსელის ყველა მისამართის 1900 პორტზე, შემდეგ კითხულობს ყოველი მოპასუხე სერვერის მოწყობილობის აღწერას და ინარჩუნებს მათ, რომლებიც თავიანთ კონტენტს აქვეყნებენ (ContentDirectory).

საქაღალდეები და ფაილები სერვერის Browse მოქმედებით ჩამოითვლება, გვერდ-გვერდ, და მათი სათაურებით სახელდება: ფაილი თავისი ტიპის გაფართოებას იღებს, როცა სათაურს არ აქვს, და საქაღალდეში იგივე სათაურის მეორე ფაილი `name (2)` ხდება. აუდიო გამოირიცხება. მინიატურები ალბომის ყდებია ან სერვერის მიერ შექმნილი პატარა სურათები, რომლებსაც თავად აპი ტვირთავს, ხოლო როცა სერვერს ისინი არ აქვს, აპის საკუთარი მინიატურა გამოიყენება. ფაილი იკვრება სერვერის მიერ შეთავაზებული ორიგინალიდან, და არა გარდაქმნილი ასლიდან, როცა სერვერი ორივეს სთავაზობს, დიაპაზონის მოთხოვნებით იკითხება, ამიტომ გადახვევა მუშაობს.

შემოწმებულია minidlna-სა და Gerbera-ზე; აღმოჩენა ნამდვილ ქსელში, Plex, Jellyfin, NAS, Freebox Server, iPhone და Quest ბილდ 19-ის მოწყობილობაზე ტესტირებაა.

### გადაადგილებული გაზიარება

ბილდ 19-დან DLNA გაზიარება და ტელეფონის გაზიარება (იხილეთ [ამ ტელეფონის გაზიარება ქსელში](#share-this-phone-on-the-network)) ინარჩუნებენ იმ იდენტიფიკატორს, რომელსაც მათი სერვერი აცხადებს. როცა ერთ-ერთი მათგანი თავის მისამართზე აღარ პასუხობს (როუტერმა ახალი მისამართი მისცა, სერვერი სხვა პორტზე გადაიტვირთა), მისი საქაღალდის გვერდი აჩვენებს „(სახელი)-ის ძიება ქსელში“ და გაზიარებას იქ გადაიტანს, სადაც ის ახლა პასუხობს: DLNA სერვერის შემთხვევაში დაუყოვნებლივ, რადგან მას პაროლი არ აქვს, ხოლო მომხმარებლის სახელითა და პაროლით დაცული გაზიარების შემთხვევაში დადასტურების შემდეგ („გამოვიყენოთ ახალი მისამართი?“), რომელიც ორივე მისამართს აჩვენებს, რადგან ისინი ახალ მისამართზე გაიგზავნებოდა.

ბილდ 20-დან ქსელის სხვა მისამართზე ხელახლა ნაპოვნი Plex სერვერიც დაუყოვნებლივ გადაიტანება: მისი სერტიფიკატი ამტკიცებს, რომ ეს იგივე სერვერია, სანამ ტოკენი გაიგზავნება. Tapo კამერას მისივე გვერდიდან მისი MAC მისამართით ეძებს, იხილეთ [Tapo კამერები](#tapo-cameras-live-view-and-the-recordings-of-the-memory-card).

- **DLNA**: სერვერი, რომელიც ფაილის მხოლოდ გარდაქმნილ ასლს სთავაზობს, სწორედ ამ ასლს იძლევა; საქაღალდე მაქსიმუმ 20 000 ელემენტს ჩამოთვლის.
- **მინიატურები**: ფოტოების მინიატურები მთელ ფაილს დეკოდირებენ და 30 მბ-ზე დიდი ფოტოები მინიატურას არ იღებენ.
- **პლეერები**: აუდიო ტრეკის არჩევა ბრტყელ პლეერში ჯერ არ არის. ტელეფონზე საქაღალდის ერთი ფაილიდან შემდეგზე გადასრიალება ჯერ შეუძლებელია (Quest-ის იმერსიულ ხედს საქაღალდის 360° ფაილებისთვის წინა და შემდეგი აქვს). ქსელურ ფაილზე გაკეთებული 3D ან 180° არჩევანი არ ინახება.
- **ატვირთვები**: ისინი მხოლოდ მაშინ მუშაობენ, როცა აპი ღიაა, და ფაილი, რომელიც სერვერს უკვე აქვს, სრულად იგზავნება, სანამ სერვერი მას დუბლიკატად მონიშნავს.

## Plex Media Server, plex.tv-ის გარეშე

თქვენი ვიდეოები Plex-შია, და Plex თქვენს 360° ფოტოებსა და ვიდეოებს ბრტყლად აჩვენებს, როგორც ამას მის ფორუმზე არსებული მოთხოვნები აღწერს (ერთი მათგანი 2017 წლიდან ღიაა). თქვენ ასევე გსურთ ეს ბიბლიოთეკა ჩაფხუტში, ტელევიზორზე და სახლის გარეთ. Immich აპი მხოლოდ თქვენს Immich სერვერს კითხულობს, ხოლო ბილდ 19-ის DLNA ტიპი Plex-ის DLNA მხარეს მხოლოდ სახლში აღწევს.

ბილდ 20-დან Immuch360 პირდაპირ უკავშირდება თქვენს Plex Media Server-ს, plex.tv-ის გარეშე: ის სერვერს ქსელში პოულობს, თქვენ ერთხელ ჩასვამთ ტოკენს, და აპი თქვენი ბიბლიოთეკების ორიგინალ ფაილებს პირდაპირ კითხულობს, აპის ყველა მნახველში (360°, 3D, VR180, Spatial 2.5D, Quest-ის იმერსიული ხედი, ტელევიზორის პულტი), სახლში და, თქვენი პორტის გადამისამართების მეშვეობით, სახლის გარეთ. არაფერი კოპირდება, ხოლო თქვენ მიერ არჩეული ფაილები შეიძლება Immich-ში გაიგზავნოს.

### Plex სერვერის დამატება

1. გახსენით ბიბლიოთეკის ჩანართი, შემდეგ ქსელური გაზიარებები, შემდეგ + და „Plex Media Server“. გაზიარების ფორმის „Plex Media Server“ ტიპი და Plex ჭდით მონიშნული სერვერი „ნაპოვნია ქსელში“ ქვეშ იმავე გვერდს ხსნის.
2. „Plex სერვერის დამატება“ გვერდი თქვენი ქსელის Plex სერვერებს ეძებს („მიმდინარეობს Plex სერვერების ძიება თქვენს ქსელში“) და მათ „ნაპოვნია ქსელში“ ქვეშ ჩამოთვლის. შეეხეთ თქვენსას: ბარათი აჩვენებს მის სახელს, მის Plex ვერსიას და მოკლე იდენტიფიკატორს.
3. სიაში არ არის? აკრიფეთ მისი „სერვერის მისამართი“, მაგალითად `192.168.1.20`, `192.168.1.20:32400` ან `https://...plex.direct:32400`, შემდეგ შეეხეთ „მოძებნა“-ს. აპი სერვერის სერტიფიკატს კითხულობს და სხვას არაფერს აგზავნის.
4. მიიღეთ ტოკენი კომპიუტერზე: გახსენით Plex ვებ-ბრაუზერში და შედით, გახსენით თქვენი ბიბლიოთეკის ნებისმიერი ფოტო ან ვიდეო, შემდეგ „...“, „Get Info“, „View XML“. ახალი ჩანართი იხსნება მისამართზე, რომელიც `X-Plex-Token=...`-ით მთავრდება. დააკოპირეთ ეს მთელი მისამართი.
5. ჩასვით ის „წვდომის ტოკენი“ ველში, ან გაგზავნეთ ტელეფონზე და შეეხეთ „ჩასმა ბუფერიდან“-ს: აპი მისგან სერვერსა და ტოკენს იღებს. მხოლოდ `X-Plex-Token=`-ის შემდეგი ტექსტიც მუშაობს. გვერდზე „როგორ მივიღოთ“ იგივეს ამბობს; სერვერის ადმინისტრატორებს ასევე შეუძლიათ გამოიყენონ სერვერის `Preferences.xml` ფაილის `PlexOnlineToken` მნიშვნელობა, რომელსაც ვადა არ გასდის. ტელევიზორზე OK კლავიატურის დიალოგს ხსნის: აკრიფეთ ტოკენი იქ (ის ჩვეულებრივ 20 სიმბოლოა).
6. შეეხეთ „კავშირის შემოწმება“-ს. პასუხია „დაკავშირებულია: N ბიბლიოთეკა“, ან ის ამბობს, რა არის არასწორად, მაგალითად „Plex სერვერმა ეს ტოკენი უარყო.“
7. შემდეგ „წვდომა სახლის გარედან“ აჩვენებს, რას ამბობს სერვერი: „სერვერი ამბობს, რომ ხელმისაწვდომია მისამართზე (მისამართი):(პორტი).“ ან „სერვერმა არ თქვა თავისი სახლის გარეთა მისამართი.“ სერვერის სახლის გარეთ გამოსაყენებლად აკრიფეთ თქვენი საჯარო მისამართი ან DynDNS სახელი „სახლის გარეთა მისამართი (IP ან სახელი)“ ველში, ხოლო Plex-ში (პარამეტრები, დისტანციური წვდომა) გადამისამართებული პორტი „სახლის გარეთა პორტი“ ველში. ის, რასაც თქვენ აკრეფთ, ყოველთვის უპირატესია იმაზე, რასაც სერვერი ამბობს.
8. „სახელი“ სერვერის სახელია, თუ მას არ შეცვლით, ხოლო „საწყისი საქაღალდე (არასავალდებულო)“ ერთ ბიბლიოთეკას პირდაპირ გახსნის. შეეხეთ შენახვას. სერვერი გაზიარებებთან ერთად ჩამოითვლება, როგორც `plex://` და მისი მისამართი.

### თქვენი Plex ბიბლიოთეკების დათვალიერება

1. შეეხეთ სერვერს ქსელურ გაზიარებებში. პირველი დონე ჩამოთვლის ბიბლიოთეკებს, რომლებსაც აპი აჩვენებს: ფოტოები, ფილმები და სხვა ვიდეოები, სერიალები. მუსიკა არ ჩანს.
2. ბიბლიოთეკის ქვეშ მისი საქაღალდეებია ისე, როგორც სერვერის დისკზეა (Plex-ის „საქაღალდეების მიხედვით“ ხედი), შემდეგ ფოტოები და ვიდეოები მათი ფაილის სახელებით, Plex-ის მიერ შექმნილი მინიატურებით. ფოტო ბიბლიოთეკა, რომლის საქაღალდეების ხედი არ პასუხობს, ამის ნაცვლად თავის ალბომებს აჩვენებს.
3. 360° და 3D თავად ფაილების წაკითხვით ამოიცნობა, როგორც ნებისმიერ გაზიარებაზე: 360° ფოტოები 360° ნიშანს იღებს, Apple-ის სივრცითი ფოტოები კი 3D ნიშანს.
4. გახსენით ფოტო ან ვიდეო, როგორც ნებისმიერ გაზიარებაზე: 360°, 3D, 360°/180°, Spatial 2.5D ტელეფონზე, იმერსიული ხედი Quest-ში, პულტი ტელევიზორზე. ვიდეო ორიგინალი ფაილის სახით იკითხება, ბაიტების დიაპაზონებით აპის ლოკალური ხიდის გავლით, ამიტომ გადახვევა მუშაობს და მისი 360° და 3D მეტამონაცემები პლეერებამდე უცვლელად აღწევს.
5. მონიშნეთ ფაილები და შეეხეთ „Immich-ზე ატვირთვა“-ს, რომ ისინი თქვენს სერვერზე გაგზავნოთ, როგორც ნებისმიერი გაზიარებიდან (იხილეთ [გაზიარების ფაილების გაგზავნა Immich-ში](#send-files-of-a-share-to-immich)).

### სახლის გარეთ

ყოველ ჯერზე, როცა სერვერს ხსნის, აპი ჯერ სახლის მისამართს ცდის, ხოლო 400 ms-ის შემდეგ სახლის გარეთა მისამართს. გამოიყენება პირველი, რომელიც თქვენი სერვერით უპასუხებს; როცა ეს სახლის გარეთა მისამართია, საქაღალდის გვერდი აჩვენებს გლობუსის ხატულას წარწერით „დაკავშირებულია სახლის გარეთა მისამართით“.

ამისთვის საჭიროა Plex-ში ჩართული დისტანციური წვდომა (პარამეტრები, დისტანციური წვდომა) თქვენი როუტერის მიერ გადამისამართებული პორტით: plex.tv-ის გარეშე აპს Plex-ის რელეს გამოყენება არ შეუძლია, ამიტომ პორტის გადამისამართების გარეშე სერვერი მხოლოდ სახლში იხსნება, ხოლო სახლის გარეთ გვერდი ამბობს: „თქვენი Plex სერვერი სახლის ქსელის გარედან მიუწვდომელია. Plex-ში ჩართეთ დისტანციური წვდომა პორტის გადამისამართებით (პარამეტრები, დისტანციური წვდომა) ან შეიყვანეთ მისი საჯარო მისამართი.“

სერვერის მიერ მოწოდებული მისამართი ყოველი სახლიდან დაკავშირებისას ხელახლა ისწავლება. როცა ის გარედან არ პასუხობს (როუტერი, რომელიც მისამართს იცვლის, ორი როუტერი ზედიზედ), აკრიფეთ თქვენი მისამართი სერვერის გვერდზე. როცა ტოკენი მუშაობას წყვეტს (მაგალითად, გამოხვედით ბრაუზერის სესიიდან, საიდანაც ის დააკოპირეთ), საქაღალდის გვერდი ამას ამბობს და გთავაზობთ „ახალი ტოკენის ჩასმა“-ს, რომელიც სერვერის გვერდს ტოკენის ველზე ხსნის.

## ამ ტელეფონის გაზიარება ქსელში

თქვენი ფოტოები და ვიდეოები ტელეფონზეა და გსურთ მათი ნახვა ჩაფხუტში, კომპიუტერის, NAS-ის ან Immich სერვერის გარეშე. ბილდ 19-დან ტელეფონი, Android ან iPhone, Wi-Fi-ით საკუთარ ფოტოებსა და ვიდეოებს ემსახურება, ხოლო Meta Quest მათ უკრავს. Immich აპს მსგავსი არაფერი აქვს.

### ჩართვა ტელეფონზე

1. გახსენით ბიბლიოთეკის ჩანართი, შემდეგ ქსელური გაზიარებები. პირველი ფილაა „ამ ტელეფონის გაზიარება ქსელში“ (წერია „გამორთულია“, ან „ჩართულია“ მისამართით).
2. შეეხეთ მას, შემდეგ ჩართეთ „ფოტოებისა და ვიდეოების გაზიარება Wi-Fi-ით“. აპი ითხოვს ფოტოებისა და ვიდეოების ნებართვას, თუ ის აკლია, ხოლო Android 13-დან ასევე შეტყობინებების ნებართვას.
3. გვერდი აჩვენებს მისამართს (მაგალითად `http://192.168.1.20:8360`: პორტი 8360, ან სხვა თავისუფალი, თუ ის დაკავებულია), სახელს, რომლითაც ტელეფონი ცხადდება („Immuch360 on“ და ტელეფონის სახელი), მომხმარებლის სახელს (`phone` და ოთხი ციფრი) და პაროლს (რვა სიმბოლო), თითოეულს კოპირების ღილაკით, შემდეგ „N მოწყობილობა დაკავშირებულია“ (მოწყობილობები, რომლებმაც ის ბოლო წუთში გამოიყენეს) ბოლოს მიწოდებული ფაილით.

მომხმარებლის სახელი და პაროლი ერთხელ იქმნება და ინახება, ამიტომ ჩაფხუტი თავის შენახულ გაზიარებას ინარჩუნებს; „ახალი პაროლი“ პაროლს ცვლის. ეს ფილა ჩაფხუტზე არ ჩანს.

### გახსნა ჩაფხუტში

1. ჩაფხუტში გახსენით ბიბლიოთეკა, ქსელური გაზიარებები, შემდეგ +.
2. „ნაპოვნია ქსელში“ ქვეშ შეეხეთ ტელეფონს: მომხმარებლის სახელი ივსება.
3. ერთხელ აკრიფეთ პაროლი (ჰარები და მთავრული ასოები მნიშვნელობა არ აქვს), შემდეგ შენახვა.

ამის შემდეგ ეს ჩვეულებრივი WebDAV გაზიარებაა: 360° ამოცნობა, დაუმუშავებელი ფაილები, იმერსიული ხედი, ვიდეოებში გადახვევა. ქსელის ნებისმიერ WebDAV კლიენტსაც შეუძლია მისი წაკითხვა. როცა ტელეფონი სხვა მისამართს იღებს, ჩაფხუტი მას ეძებს და ახალი მისამართის გამოყენებამდე გეკითხებათ (იხილეთ [გადაადგილებული გაზიარება](#a-share-that-moved)).

### რას ემსახურება და რამდენ ხანს

- **საქაღალდეები**, მხოლოდ წასაკითხად: `Albums` (ტელეფონის თითოეული ალბომი), `By month` (ყოველი ფოტო და ვიდეო თვეების მიხედვით, უახლესი პირველი) და `360` (360° ფოტოები და ვიდეოები, რომლებიც აპმა ტელეფონზე იპოვა, დაუმუშავებელი ფაილებისა და იმათ ჩათვლით, რომლებსაც 360°-ად ნახულობთ). ფაილები საკუთარ სახელებს ინარჩუნებენ. iPhone-ზე ცოცხალი ფოტო (Live Photo) თავის სტატიკურ სურათს იძლევა, რედაქტირებული ფოტო ან ვიდეო თავის რედაქტირებულ ვერსიას, ხოლო მხოლოდ iCloud-ში შენახული გამოირიცხება.
- **Android**: გაზიარება წინა პლანის სერვისში მუშაობს შეტყობინებით (მისამართი და მომხმარებლის სახელი) და შეჩერების ღილაკით, და Wi-Fi-სა და პროცესორს ფხიზლად ინარჩუნებს, ამიტომ ის გამორთული ეკრანითაც გრძელდება. აპის გადასრიალებით დახურვა მას აჩერებს.
- **iPhone და iPad**: iOS სერვერს ფონურ დროს არ აძლევს, ამიტომ გაზიარება მხოლოდ მაშინ მუშაობს, როცა აპი წინა პლანზეა, და ამ დროს ეკრანი ჩართული რჩება. ის პაუზდება, როცა აპი ფონზე გადადის, და იგივე მისამართითა და პაროლით გრძელდება, როცა დაბრუნდებით.
- **როდის ჩერდება**: გადამრთველით, შეჩერების ღილაკით, 60 წუთის განმავლობაში ყოველგვარი მოთხოვნის გარეშე, და აპის დახურვისას. ის არასოდეს იწყება თავისით: აპის ყოველი გაშვებისას გამორთულია.
- **უსაფრთხოება**: მხოლოდ ლოკალური ქსელი. გაზიარება მხოლოდ ტელეფონის Wi-Fi, Ethernet და ჰოტსპოტის მისამართებზე უსმენს, არასოდეს მობილური ინტერნეტის ან VPN მისამართზე, და მხოლოდ ლოკალური მისამართის მქონე მოწყობილობებს პასუხობს. ყოველ მოთხოვნას მომხმარებლის სახელი და პაროლი სჭირდება (HTTP Basic); ერთი მოწყობილობიდან ერთ წუთში ათი არასწორი პაროლი მას ერთი წუთით ბლოკავს. პაროლი Wi-Fi-ით დაუშიფრავად გადაიცემა (უბრალო HTTP): გამოიყენეთ გაზიარება იმ ქსელში, რომელსაც ენდობით, და გამორთეთ, როცა დაასრულებთ.
- **ტელეფონის საკუთარი ჰოტსპოტი**: ჩაფხუტს შეუძლია მას დაუკავშირდეს; თუ იქ ტელეფონს ვერ პოულობს, აკრიფეთ გვერდზე ნაჩვენები მისამართი.
- **ჯერ არ არის შემოწმებული მოწყობილობაზე**: სერვერი შემოწმდა ერთეულოვანი ტესტებით და ბოლოდან ბოლომდე ტესტებით ჩაფხუტის საკუთარი WebDAV კლიენტითა და მედია ხიდით, კომპიუტერზე. ტელეფონი, რომელიც Quest 3-ს ემსახურება (აღმოჩენა, 4 გბ ვიდეო დაკრული და გადახვეული, 30 წუთი გამორთული ეკრანით, ჰოტსპოტი, შეჩერება შეტყობინებიდან), და iPhone-ის მხარე, რომელიც ჯერ iPhone-ზე არ გაშვებულა, ბილდ 19-ის მოწყობილობაზე ტესტირებაა.

## Tapo კამერები: პირდაპირი ხედი და მეხსიერების ბარათის ჩანაწერები

სახლში Tapo კამერები გაქვთ, და გსურთ ბაღის კამერისა და წუხანდელი კლიპების ნახვა თქვენი ფოტოების გვერდით Tapo აპის გახსნის გარეშე, და კლიპის შენახვა Immich-ში. Immich აპს კამერებისთვის არაფერი აქვს, ხოლო Tapo აპი ცალკე აპია, თქვენს TP-Link ანგარიშში შესული, სადაც კლიპები თქვენი ფოტოებისგან განცალკევებულია.

ბილდ 20-დან Immuch360 Tapo კამერას ქსელური გაზიარებების გვერდით ამატებს. ის კამერას პირდაპირ აჩვენებს Android ტელეფონებსა და პლანშეტებზე, Android TV-სა და Meta Quest-ზე, ხოლო ყველა პლატფორმაზე მისი მეხსიერების ბარათის ჩანაწერებს, დღეების მიხედვით: კლიპი კამერიდან მიიღება, შემდეგ ნებისმიერი ვიდეოს მსგავსად იკვრება და შეიძლება Immich-ში გაიგზავნოს. აპი კამერას მხოლოდ თქვენს ქსელში ესაუბრება, არასოდეს TP-Link-ის სერვერებს, და კამერაზე არასოდეს არაფერს ცვლის.

### კამერის დამატება

1. ჯერ Tapo აპში: შექმენით კამერის ანგარიში კამერის პარამეტრებში, გაფართოებული პარამეტრები, კამერის ანგარიში (მომხმარებლის სახელი და პაროლი ამ კამერისთვის, პირდაპირი ხედისთვის), და ჩართეთ მესამე მხარის თავსებადობა, მე, შემდეგ Tapo Lab.
2. Immuch360-ში გახსენით ბიბლიოთეკის ჩანართი, შემდეგ ქსელური გაზიარებები, შემდეგ + და „Tapo კამერა“.
3. „კამერის დამატება“ გვერდი კამერებს ეძებს („მიმდინარეობს Tapo კამერების ძიება თქვენს ქსელში“) და მათ „ნაპოვნია ქსელში“ ქვეშ Tapo ჭდით ჩამოთვლის. შეეხეთ თქვენსას „კამერის მისამართი“-ს შესავსებად, ან აკრიფეთ მისი მისამართი. გაზიარების ფორმაში Tapo ჭდით მონიშნული კამერა იმავე გვერდს ხსნის.
4. „სახელი“: როგორ ჩამოითვლება კამერა.
5. „ჩანაწერები მეხსიერების ბარათზე“ ქვეშ, „TP-Link ანგარიშის პაროლი“: იმ ანგარიშის პაროლი, რომელსაც Tapo აპში იყენებთ. ის ჩანაწერებს ხსნის; თქვენი ელფოსტის მისამართი საჭირო არ არის.
6. „პირდაპირ“ ქვეშ, „კამერის ანგარიშის მომხმარებლის სახელი“ და „კამერის ანგარიშის პაროლი“: პირველი ნაბიჯის კამერის ანგარიში.
7. ორიდან ერთიც საკმარისია („შეიყვანეთ TP-Link ანგარიშის პაროლი, კამერის ანგარიში ან ორივე.“): მხოლოდ TP-Link-ის პაროლი ჩანაწერებს იძლევა, მხოლოდ კამერის ანგარიში კი პირდაპირ ხედს.
8. შეეხეთ „კამერის შემოწმება“-ს. ის აჩვენებს „ჩანაწერები: (მოდელი), მიკროპროგრამა (ვერსია)“ მეხსიერების ბარათის მდგომარეობით, და „პირდაპირი ხედი: (ვიდეო), ხმა (აუდიო)“, ან რა ვერ მოხერხდა თითოეულისთვის.
9. შეეხეთ შენახვას. კამერა „კამერები“ ქვეშ ჩამოითვლება, გაზიარებების შემდეგ, თავისი მოდელით, როგორც კი ის ცნობილი გახდება, და `tapo://` თავისი მისამართით.

### პირდაპირ ყურება

1. შეეხეთ კამერას. მისი პირდაპირი ხედი მისი გვერდის ზედა ნაწილშია: „კამერასთან დაკავშირება“, შემდეგ სურათი „პირდაპირ“ ნიშნით.
2. სურათზე არსებული ღილაკები: ხმა, თავიდან გამორთული („ხმის ჩართვა“; „ამ მოწყობილობაზე ხმა არ არის“, როცა მოწყობილობას მისი დაკვრა არ შეუძლია), SD ან HD, და „სრული ეკრანი“.

4. ფოტო სფერულ მნახველში იხსნება ქვემოთ წარწერით: „დაუმუშავებელი 360° ფაილი, აპის მიერ შეკერილი“, და კალიბრაციის წყარო: „ფაილიდან წაკითხული ობიექტივების კალიბრაცია“, „იმავე კამერის ობიექტივების კალიბრაცია“ (შენახული იმავე კამერის სხვა ფაილიდან, სერიული ნომრით, ან მოდელით იმ ფაილისთვის, რომელიც მხოლოდ თავის მოდელს ასახელებს), ან „ობიექტივების ნომინალური მნიშვნელობები, შესაძლოა ნაკერები ჩანდეს“ (X3-ის მნიშვნელობები, როცა უკეთესი არაფერია).
5. ვიდეო ჩაშენებულ 360° პლეერში იხსნება და დაკვრისას იკერება. მისი 3D და 360°/180° ღილაკები დამალულია, რადგან დაუმუშავებელი ვიდეო ერთი სრული სფეროა. ვიდეო პლეერები და ჩაფხუტი წარწერას არ აჩვენებენ.
6. ჩაფხუტში იმერსიული ხედი ფოტოსთვის შეკერილ დროებით სურათს იღებს, ხოლო ვიდეოსთვის იგივე GPU ეფექტს, რაც ტელეფონზე. დაუმუშავებელი ფოტოს მომზადებისას პროგრესის მაჩვენებელი ჯერ არ არის.
7. თუ სურათი უცნაური მიმართულებით იხსნება (მაგალითად, ფოტო, რომელიც ბრტყლად დადებული კამერით არის გადაღებული), ტელეფონზე გადაათრიეთ, ხოლო ჩაფხუტში მოაბრუნეთ მარჯვენა ჯოისტიკით ან შემობრუნების ღილაკით.

### როცა მოწყობილობას ორივე ობიექტივის დაკვრა არ შეუძლია

ორობიექტივიანი ვიდეოს დაკვრამდე აპი მოწყობილობას ეკითხება, შეუძლია თუ არა ამ ზომისა და სიხშირის ორი დეკოდერის გაშვება, და როცა პასუხი უარყოფითია, ტელეფონი გაფრთხილებს: „ამ დაუმუშავებელ ვიდეოს ერთდროულად ორი (ზომა) ვიდეოდეკოდერი სჭირდება: ამ მოწყობილობაზე შეიძლება შეუფერხებლად არ დაიკრას“. როცა დეკოდერებს მუშაობა არ შეუძლიათ (მაგალითად, ორი 2880x2880 H.264 ობიექტივი Quest 3-ზე), აპი ერთ ობიექტივს უკრავს და ამას გეუბნებათ, სფეროს ნახევარი შავი რჩება, შემდეგ კი სერვერის ტრანსკოდირებულ ნაკადს, თუ ის არსებობს. თუ GPU ეფექტს მოწყობილობაზე მუშაობა არ შეუძლია, ვიდეო შეკერვის გარეშე იკვრება, ორი წრე სფეროზე, შეტყობინებით „360°-ის შეკერვა ამ მოწყობილობაზე ვერ მოხერხდა“.

## 3D და VR180 ფოტოები და ვიდეოები

Immich აპში სტერეოსკოპიული 360° ფოტო ან ვიდეო ორივე თვალს ერთდროულად აჩვენებს, ორმაგ სურათს, ხოლო VR180 ფაილი, რომელიც მხოლოდ წინა ნახევარს ფარავს, მთელ სფეროზეა გაწელილი.

Immuch360 3D განლაგებებს, ზემოთ და ქვემოთ ან გვერდიგვერდ, ფაილიდან ამოიცნობს (ვიდეოს st3d ყუთიდან), ან კადრის ფორმიდან ვარაუდობს, და ყველა მნახველს აქვს 3D ღილაკი მათ შესაცვლელად. ტელეფონი მარცხენა თვალს აჩვენებს; Meta Quest თითოეულ თვალს თავის ნახევარს აჩვენებს, ნამდვილ 3D-ში. VR180 ფაილები ნახევარსფეროზე იხატება, უკანა მხარე შავია გაწელილი სურათის ნაცვლად. ისინი ფაილიდან ამოიცნობა (სფერული საზღვრები ან ბადე, GPano ჩამოჭრა) ან სახელში „vr180“-ის ან „180“-ის მიხედვით, და ყველა მნახველს აქვს 360°/180° ღილაკი.

### განლაგების ან დაფარვის შეცვლა

1. გახსენით ფოტო ან ვიდეო სფეროს სახით (360° ღილაკი).
2. 3D ღილაკი რიგრიგობით ცვლის „მონო (არა 3D)“, „3D, ზემოთ და ქვემოთ“ და „3D, გვერდიგვერდ“ ვარიანტებს; მისი მინიშნება მიმდინარე განლაგებას ასახელებს.
3. 360°/180° ღილაკი „360°, სრული სფერო“-სა და „180°, ნახევარსფერო (VR180)“-ს შორის გადართავს. ნაწილობრივ პანორამებზე არ ჩანს.
4. ჩაფხუტში იგივე ორი ღილაკი იმერსიული ხედის საინფორმაციო პანელზეა.

360°/180° არჩევანი მოწყობილობაზე ბიბლიოთეკის მედიისთვის ინახება, ქსელური გაზიარების ფაილისთვის კი ჯერ არა. 3D არჩევანი მნახველის დახურვისას არ ინახება: შემდეგ ჯერზე ისევ ფაილის მიერ გამოცხადებული ან ნავარაუდევი განლაგება გამოიყენება (ქვემოთ აღწერილი Spatial 2.5D პლეერი საკუთარს ინახავს).

შემოწმებულია Galaxy S24+-სა და Quest 3-ზე ნამდვილი 3D 360° სანიმუშო ვიდეოებით (VRTogether, Vuze, Kandao) და 3D ფოტოთი; VR180 Android ემულატორსა და Galaxy S24+-ზე სინთეტიკური მედიით. სხვა კამერებიდან ანგარიშები მისასალმებელია.

## სიღრმე ბრტყელ ეკრანზე: Spatial 2.5D (ექსპერიმენტული)

სტერეოსკოპიულ ვიდეოს ბრტყელ ეკრანზეც შეუძლია სიღრმის შეძენა. ვიდეოს ორი თვალი სიღრმეს იძლევა, წინა კამერა თქვენს თავს მიჰყვება, ხოლო აპი მათ შორის ხედს სინთეზირებს, ამიტომ ეკრანი სცენისკენ გახსნილი ფანჯარასავით იქცევა: თავი გაამოძრავეთ და ახლომდებარე საგნები ფონის მიმართ გადაინაცვლებს. მხოლოდ ტელეფონები და პლანშეტები.

### გამოყენება

1. შეამოწმეთ, რომ ჩართულია: მორგება, Asset Viewer, ვიდეოები, „Spatial 2.5D (ექსპერიმენტული)“. ნაგულისხმევად ჩართულია; მისი გამორთვა Spatial ღილაკს ყველგან აქრობს.
2. გახსენით ვიდეო. სანამ პარამეტრი ჩართულია, ზედა ზოლი ყველა ვიდეოზე Spatial ღილაკს აჩვენებს (მბრუნავი 3D ხატულა); ქსელური გაზიარების საქაღალდეში მას მხოლოდ სტერეოსკოპიული ფაილები იღებენ, დანარჩენებს კი Spatial 2.5D ⋮ მენიუში აქვთ.
3. შეეხეთ მას. წინა კამერის ნებართვა პირველად მოითხოვება; კამერა მხოლოდ ღილაკზე დაჭერის შემდეგ გამოიყენება.
4. ზედა მარჯვენა კუთხეში: აუდიო ტრეკი, როცა ვიდეოს ორი ან მეტი აქვს, მიმდინარე განლაგება (შეეხეთ სიისთვის: ავტომატური, არ არის სტერეოსკოპიული, გვერდიგვერდ, ზემოთ და ქვემოთ, ბოლო ორი ასევე გაცვლილი თვალებით), 360°/180° 360° ვიდეოზე, და ხელახლა ცენტრირება, რომელიც თქვენი თავის მიმდინარე პოზიციას ცენტრად იღებს.
5. ქვემოთ: დაკვრა, დროის ხაზი, შემდეგ თავის მოძრაობის მგრძნობელობა, სანამ თქვენი თავი თვალყურის დევნების ქვეშაა, და ხედვის წერტილის სლაიდერი L-დან R-მდე, რომელიც ხედვის წერტილს ხელით ამოძრავებს; ის ჩნდება, როცა თავის თვალყურის დევნება გამორთულია ან თქვენი სახე დაკარგა.
6. დახურეთ ჯვრით ან სისტემის „უკან“ ღილაკით.

როცა მორგება, დამატებით, პრობლემების გადაწყვეტა ჩართულია, პლეერი ზედა მარცხენა კუთხეში ფენას ამატებს (რენდერისა და დისპარიტეტის სიხშირეები, ხარისხის დონე, ხედვის წერტილი, თვალყურის დევნების მდგომარეობა), ხედვის წერტილის სლაიდერს ყოველთვის აჩვენებს და ამატებს „Disparity map“ (დისპარიტეტის რუკა) მოსანიშნ ველს, რომელიც სურათის ნაცვლად შეფასებულ სიღრმეს აჩვენებს.

### ფორმატები, კონფიდენციალურობა და შეზღუდვები

- **ფორმატები**: გვერდიგვერდ და ზემოთ და ქვემოთ, ასევე გაცვლილი თვალებით, სრული ან ნახევარი სიგანით, ბრტყელი, 360° და VR180. განლაგება ფაილიდან იკითხება, სხვა შემთხვევაში კადრის ფორმიდან ან ფაილის სახელიდან ივარაუდება (sbs, ou, tb და მსგავსი; ნახევარი სიგანის ფაილი მხოლოდ სახელით ამოიცნობა), და შეიძლება ხელით აირჩიოთ პლეერში. არჩევანი ბიბლიოთეკის ვიდეოსთვის ინახება, ქსელური გაზიარების ფაილისთვის კი არა.
- **კამერა**: სურათები მხოლოდ მოწყობილობაზე მუშავდება, არასოდეს ინახება და არასოდეს იგზავნება არსად. Quest-ის ბილდს საერთოდ არ აქვს კამერის ნებართვა (ჩაფხუტს არ აქვს კამერა, რომელიც აპს შეუძლია გამოიყენოს), და Spatial პლეერი იქ არ არის შეთავაზებული: მისი ღილაკი და პარამეტრი ჩაფხუტზე დამალულია.
- **შეზღუდვები**: ექსპერიმენტული, მხოლოდ ტელეფონები და პლანშეტები (არა Meta Quest-ზე), საჭიროებს OpenGL ES 3.0-ს ან Metal-ს. სიღრმე შეფასებაა. საუკეთესოდ მუშაობს ჰორიზონტალურ რეჟიმში კარგად განათებული სახით. შემოწმებულია Galaxy S24+-ზე; iPhone-ის გამოხმაურება მისასალმებელია.
- **სარეზერვო ვარიანტი**: თუ რამე არასწორად წავა (კამერა არ არის, მოწყობილობა არ არის მხარდაჭერილი, განლაგება ვერ იკითხება), ჩვეულებრივ პლეერს დაუბრუნდებით.

## Apple-ის სივრცითი ფოტოები და ვიდეოები

iPhone იღებს სივრცით ფოტოებსა და ვიდეოებს, და Immich სერვერი მათ შესახებ არაფერს ამბობს: Immich აპში ისინი ბრტყელი ფოტო ან ვიდეოა. ბილდ 19-დან Immuch360 მათ ფაილების წაკითხვით ამოიცნობს და Meta Quest ჩაფხუტში სივრცით ფოტოს 3D-ში აჩვენებს. ეს არ არის ზემოთ აღწერილი Spatial 2.5D პლეერი, რომელიც გვერდიგვერდ და ზემოთ და ქვემოთ ვიდეოებისთვისაა.

- **სივრცითი ფოტოები** HEIC ფაილებია (`.heic`, `.heif`, `.hif`), რომლებიც ორ სურათს შეიცავენ, თითო თვალზე, სტერეო წყვილად დაჯგუფებულს. აპი ფაილის თავს კითხულობს (მოწყობილობაზე, სერვერის ორიგინალს დიაპაზონის მოთხოვნით, ან ქსელური გაზიარების ფაილს) და პასუხს ტელეფონზე ინახავს, ამიტომ ფოტო მხოლოდ ერთხელ იკითხება.
- **სივრცითი ვიდეოები** (MV-HEVC) ვიდეო ტრეკიდან ამოიცნობა: მეორე ფენა და ორივე თვალი გამოცხადებული.

### სივრცითი ფოტოს ნახვა 3D-ში ჩაფხუტში

1. ჩაფხუტში გახსენით სივრცითი ფოტო მნახველში, ან ქსელური გაზიარების საქაღალდეში, სადაც სივრცით ფოტოებსა და ვიდეოებს 3D ნიშანი აქვთ.
2. შეეხეთ „ნახვა 3D-ში“-ს ზედა ზოლში (გაზიარების ფოტოს გვერდსაც აქვს).
3. იმერსიული ხედი იხსნება ფოტოთი ბრტყელ ჩარჩოზე თქვენგან 2 მ წინ, თითოეული თვალი საკუთარ სურათს იღებს, სიგანით, რომელიც კამერის ხედვის ველიდან არის აღებული, როცა ფაილი მას იძლევა (სხვა შემთხვევაში 48°). ფაილში ჩაწერილი დისპარიტეტის კორექცია გამოიყენება.
4. ჯოისტიკი ზემოთ ან ქვემოთ მას ადიდებს ან ამცირებს (6°-იანი ნაბიჯებით, 30°-დან 90°-მდე); მარჯვენა ჯოისტიკი მარცხნივ ან მარჯვნივ მას თქვენს წინ აბრუნებს.
5. საინფორმაციო პანელის 3D ღილაკი 3D-სა და „2D (მარცხენა თვალი)“-ს შორის გადართავს. შემობრუნებისა და 360°/180° ღილაკები დამალულია.
6. დასაბრუნებლად დააჭირეთ B ან Y.

სივრცითი ფოტოდან წინა და შემდეგი ჯერ ხელმისაწვდომი არ არის („წინა და შემდეგი სივრცითი ფოტოებისთვის ჯერ ხელმისაწვდომი არ არის“). თუ ჩაფხუტს მეორე თვალის დეკოდირება არ შეუძლია, ფოტო 2D-ში ჩანს შეტყობინებით „მეორე თვალის დეკოდირება ვერ მოხერხდა: ნაჩვენებია 2D-ში“. 3D ხედი ორიგინალ ფაილს აჩვენებს, Immich-ში გაკეთებული რედაქტირების გარეშე.

### ყველა სხვა ადგილას

- **ფოტოები**: ტელეფონები, პლანშეტები და ჩაფხუტის ფანჯარა მარცხენა თვალს აჩვენებენ, როგორც ადრე, ხოლო ტექნიკური დეტალები ახალ სტრიქონს იღებს, მაგალითად „Apple-ის სივრცითი ფოტო, ორი ხედი 3072 x 3072“, ხედვის ველით, როცა ფაილი მას იძლევა. სერვერის ფოტოებს ქრონოლოგიაში ნიშანი არ აქვთ: აპი ამას იგებს, როცა ფოტო იხსნება.
- **ვიდეოები**: ისინი თავიანთ საბაზო ფენას, ერთ თვალს, აპის ყველა პლეერში უკრავენ. Android-ს მეორე ხედის დეკოდირების საჯარო გზა არ აქვს; MV-HEVC-ის საკუთარი დეკოდერის მქონე მოწყობილობას (ზოგიერთ Qualcomm ჩიპზე) ნაცვლად ვიდეო გადაეცემოდა, რაც ჯერ არ არის შემოწმებული. სესიაში ასეთი ვიდეოს პირველი დაკვრა ამბობს „სივრცითი ვიდეო: ეს მოწყობილობა ერთ თვალს უკრავს“ (ქსელური გაზიარების ვიდეოს ნაცვლად 3D ნიშანი აქვს), ხოლო მის ტექნიკურ დეტალებში წერია „Apple-ის სივრცითი ვიდეო (MV-HEVC), ნაჩვენებია 2D-ში“, ფაილში ჩაწერილი თვალით, ბაზისური მანძილით (baseline) და ხედვის ველით.
- **დეკოდერები**: მორგება, დამატებით, „ამ მოწყობილობის ვიდეო დეკოდერები“ შეიცავს MV-HEVC პუნქტს, რომელიც მოწყობილობის შესაბამის დეკოდერს ჩამოთვლის ან ამბობს, რომ ის არ არის.

### ჯერ არ არის შემოწმებული მოწყობილობაზე

ამოცნობა შემოწმდა Apple-ის საკუთარი გამოსახულებების ბიბლიოთეკის მიერ ჩაწერილ სანიმუშო სივრცით ფოტოზე და სინთეტიკურ ფაილებზე, ხოლო 3D კომპოზიცია ერთეულოვანი ტესტებით. ჩაფხუტში ხედი (ორივე თვალი დეკოდირებული, ფოტო სწორად მდგარი და არა სარკისებური, სიღრმე სწორი მიმართულებით, კომფორტი 2 მ-ზე) და ნამდვილი iPhone-ის ფოტოები და ვიდეოები ბილდ 19-ის მოწყობილობაზე ტესტირებაა. ანგარიშები მისასალმებელია, [ჟურნალი](#logs) განყოფილების სტრიქონებით.

## Meta Quest 3 ჩაფხუტში

ადამიანები Quest 3-ს საკუთარი 360° ფოტოებისა და ვიდეოების სანახავად ყიდულობენ, შემდეგ კი კითხულობენ, სად განათავსონ ფაილები, როგორ გადაიტანონ ისინი ჩაფხუტზე კაბელის გარეშე და რომელი პლეერი გამოიყენონ: მაღაზიის 360° და 3D ვიდეო პლეერები ფასიანია.

იგივე Android აპი Quest 3-სა და 3S-ზე, ხოლო ბილდ 21-დან Quest 2-სა და Quest Pro-ზე (გამოუცდელი), ფანჯრის სახით მუშაობს, თქვენი მთელი ბიბლიოთეკით. მისი 360° ღილაკი ხსნის იმერსიულ ხედს, სადაც ფოტო ან ვიდეო ყველა მხრიდან გარს გაკრავთ და ირგვლივ თავის მობრუნებით იყურებით, სტერეოსკოპიული ფაილებისთვის ნამდვილ 3D-ში (Meta Spatial SDK).

მედია მოდის თქვენი Immich სერვერიდან, თავად ჩაფხუტიდან, NAS-იდან, მედია სერვერიდან, ტელეფონიდან ან Plex სერვერიდან და ადგილზე იკვრება (მედია სერვერი და ტელეფონი ბილდ 19-დან, Plex სერვერი ბილდ 20-დან, ჯერ ჩაფხუტზე შეუმოწმებელი), ხოლო ბილდ 20-დან ფანჯარა Tapo კამერებსაც აჩვენებს. ის უფასო და ღია კოდისაა. შემოწმებულია Quest 3-ზე და ერთი მომხმარებლის მიერ Insta360 X4 8K HEVC ვიდეოებით.

### იმერსიული ხედის გახსნა

1. დააყენეთ აპი ჩაფხუტზე: სანამ Horizon Store-ის განცხადება დამტკიცდება, APK ხელით დააყენეთ (sideload), იხილეთ [დაყენება](#install).
2. შედით თქვენი Immich სერვერით, ან შეეხეთ „სერვერის გარეშე გამოყენება“-ს ჩაფხუტის საკუთარი ფოტოებისა და ვიდეოებისთვის.
3. გახსენით 360° ფოტო ან ვიდეო მნახველში, ქრონოლოგიიდან, 360° სიიდან, ალბომიდან ან გაზიარების საქაღალდიდან.
4. დააჭირეთ 360° ღილაკს, ან „ნახვა 360°-ად“ ⋮ მენიუში. ჩაფხუტზე ისინი პირდაპირ იმერსიულ ხედს ხსნიან, ტელეფონების სფერული მნახველის ნაცვლად.
5. ირგვლივ მიმოიხედეთ თავის მობრუნებით.
6. ფანჯარაში დასაბრუნებლად დააჭირეთ B ან Y, ან საინფორმაციო პანელის „უკან“ ღილაკს.

- **ხედის შემობრუნება**: რომ უკან თავის მობრუნების გარეშე გაიხედოთ. მარჯვენა ჯოისტიკი დაჭერისას ბრუნვას აგრძელებს, და ერთხაზიანი ფენა კუთხეს აჩვენებს.
- **ერთხაზიანი ფენა**: ბილდ 16-დან ჯოისტიკით გადახვევა, ფოტოს შემობრუნება, ან წინა და შემდეგი აჩვენებს ერთხაზიან ფენას (დროს, კუთხეს ან მედიის სახელს) და საინფორმაციო პანელი დამალული რჩება. ბილდ 17-მდე ნებისმიერი ჯოისტიკი წინა ან შემდეგ მედიაზე გადადიოდა.

### საინფორმაციო პანელი, წინა და შემდეგი

ვიდეოს საინფორმაციო პანელს აქვს დროის ზოლი (პოზიცია, ხანგრძლივობა, რამდენია ბუფერში) ორ 10-წამიან გადახვევის ღილაკს შორის; მის ქვემოთ არის „წინა“, „დაკვრა“ ან „პაუზა“ და „შემდეგი“, შემდეგ „შემობრუნება“, 3D, 360°/180° და „უკან“. ფოტოს იგივე რიგები აქვს დროის ზოლისა და „დაკვრის“ გარეშე. 3D განლაგება და 360°/180° არჩევანი მხოლოდ პანელის ღილაკებზეა.

წინა და შემდეგი გადადის იმ ადგილის 360° მედიაზე, საიდანაც მოხვედით, იმერსიული ხედის დატოვების გარეშე: ქრონოლოგია, 360° სია (გაფილტრული), ალბომი, ქსელური გაზიარების საქაღალდე, ან ჩაფხუტის საკუთარი მედია (On this device). ბრტყელი ფოტოები და ვიდეოები გამოიტოვება. როცა აპში ქრონოლოგიიდან, ალბომიდან ან 360° სიიდან ბრუნდებით, ის იმ მედიაზე ჩერდება, რომელსაც უყურებდით (გაზიარების საქაღალდის გვერდი თქვენ მიერ გახსნილ ფაილზე რჩება), ხოლო ვიდეო, რომელზეც იმერსიული ხედი გახსენით, იქიდან გრძელდება, სადაც შეაჩერეთ.

ბილდ 17-დან მარჯვენა ჯოისტიკი ხედს აბრუნებს, როგორც ჩაფხუტის აპების უმეტესობაში: ერთი ბიძგი 30°-ით აბრუნებს, დაჭერა ბრუნვას აგრძელებს, ამიტომ ის, რაც თქვენს უკანაა, წინ გამოდის თავის ან სკამის მობრუნების გარეშე; წინა და შემდეგი მარცხენა ჯოისტიკზეა.

ბილდ 16-დან, ჩაფხუტში მომხმარებლის გამოხმაურების შემდეგ, ჯოისტიკით გადახვევა, შემობრუნება ან წინა/შემდეგი აჩვენებს ერთხაზიან ფენას (დრო, კუთხე ან მედიის სათაური), რომელიც 1,5 წამის შემდეგ ქრება, საინფორმაციო პანელის გამოჩენის ნაცვლად; პანელი კვლავ ჩნდება A-თი, X-ით, სახელურით ან მენიუს ღილაკით. იგივე ბილდი უზრუნველყოფს, რომ პანელის გადართვამ იმუშაოს, როცა კონტროლერები იძინებენ, იღვიძებენ ან ხელების თვალყურის დევნებას უთმობენ ადგილს, და ამ გადასვლებს ჟურნალში იწერს, იხილეთ [ჟურნალი](#logs).

„ნახვა 3D-ში“-თი გახსნილი Apple-ის სივრცითი ფოტო სფეროზე არ თავსდება: ის თქვენს წინ ცურავს, იხილეთ [Apple-ის სივრცითი ფოტოები და ვიდეოები](#apple-spatial-photos-and-videos).

### რას აჩვენებს ჩაფხუტი

ფოტოები ჯერ წინასწარ ხედს აჩვენებენ, შემდეგ ორიგინალს, რომელიც მაქსიმუმ 8192x4096-მდე მცირდება (აპის ზღვარი). ვიდეოები უკრავენ ჩაფხუტზე შენახულ ფაილს, თუ ასეთი არსებობს, ხოლო ქსელური გაზიარების ფაილს აპის ლოკალური ხიდის მეშვეობით; სხვა შემთხვევაში ნაკადს თქვენი სერვერიდან იღებენ ვიდეოს წყაროს პარამეტრის მიხედვით (ბილდ 15-დან; ნაგულისხმევად ორიგინალი, და სერვერის ტრანსკოდირებული ვერსია, როცა ორიგინალის ნაკადად გადაცემა შეუძლებელია ან ის ჩაფხუტის დეკოდერებს აღემატება, იხილეთ [ვიდეოს დეტალები და დეკოდერები](#video-details-decoders-and-why-a-video-stutters)). ბილდ 16-დან აქ კამერების დაუმუშავებელი ფაილებიც იხსნება, აპის მიერ შეკერილი; დაუმუშავებელი ვიდეოსთვის 3D და 360°/180° ღილაკები დამალულია, რადგან ის ერთი სრული სფეროა.

3D განლაგებები, ზემოთ და ქვემოთ და გვერდიგვერდ, 360° და VR180, 3D-ში ნაჩვენებია, თითოეული თვალი კადრის თავის ნახევარს იღებს. განლაგება ფაილიდან მოდის, როცა ფაილი მას აცხადებს (ვიდეოები), სხვა შემთხვევაში ფორმიდან ივარაუდება (კვადრატი: ზემოთ და ქვემოთ, 4:1: გვერდიგვერდ); როცა ის არასწორია, გამოიყენეთ საინფორმაციო პანელის 3D ღილაკი.

- **3D 360° ვიდეო ჩაფხუტში**: ზემოთ და ქვემოთ სტერეოსკოპიული ვიდეო, თითოეული თვალი თავისას იღებს (Kandao Obsidian-ის ნიმუში).

ეს სურათები გადაღებულია აპით ფრანგულ ენაზე, ბილდ 14-მდე. პანელს ახლა ასევე აქვს დროის ზოლი ორ 10-წამიან გადახვევის ღილაკს შორის, „წინა“ და „შემდეგი“, და „შემობრუნება“.

### თუ სურათი თქვენკენ არ არის მიმართული

მოაბრუნეთ ის მარჯვენა ჯოისტიკით (ან საინფორმაციო პანელის „შემობრუნება“ ღილაკით), სანამ მისი ცენტრი თქვენს წინ არ აღმოჩნდება. კუთხე ნაჩვენებია როგორც „სურათი შემობრუნებულია N გრადუსზე“, პანელზე ან ერთხაზიან ფენაზე, როცა პანელი დამალულია: გამოაქვეყნეთ ეს რიცხვი [issue-ში](https://github.com/freeKC/Immuch360/issues) თქვენი კამერის მოდელთან ერთად, რომ ის ნაგულისხმევ მნიშვნელობად იქცეს. საწყისი ორიენტაცია ჯერ ყველა კამერისთვის არ არის დადასტურებული.

### იმერსიული ხედის შეზღუდვები

- **წინა და შემდეგი**: ისინი წინ ეძებენ მაქსიმუმ 400 მედიას ქრონოლოგიაში და 50 ფაილს გაზიარების საქაღალდეში, მაქსიმუმ 12 წამის განმავლობაში; ამის შემდეგ პანელი ამბობს, რომ წინა ან შემდეგი 360° მედია არ არის. გაზიარების საქაღალდე ფაილ-ფაილ მოწმდება, ამიტომ ბევრი ბრტყელი ფაილის შემდეგ პირველი 360° ფაილის პოვნას შეიძლება რამდენიმე წამი დასჭირდეს. სივრცითი ფოტოდან ისინი ჯერ ხელმისაწვდომი არ არის.
- **3D არჩევანი**: 3D ღილაკით არჩეული განლაგება მნახველის დახურვისას არ ინახება; 360°/180° არჩევანი ინახება ბიბლიოთეკის მედიისთვის.
- **გადახვევა**: ვიდეო, რომლის წყაროც ბაიტების დიაპაზონის მოთხოვნებს არ პასუხობს, ვერ გადაიხვევა; პანელი ამას ამბობს.
- **ბრტყელი ვიდეოები**: ბრტყელი (არა 360°) სტერეოსკოპიული ვიდეო ფანჯარაში იკვრება ორივე თვალის ხილვადობით; იმერსიული 3D ხედი 360° და VR180 მედიისთვისაა.
- **სხვა**: კოდეკები, რომლებსაც ჩაფხუტი დეკოდირებს, მაღაზია, ნებართვები და APK-ის ზომა აღწერილია [Meta Quest 3](#meta-quest-3) განყოფილებაში.

## ყურება ტელევიზორზე (Android TV და Google TV)

გსურთ 360° ფოტოები და ვიდეოები, თქვენი ალბომები და თქვენი NAS-ის ან Plex სერვერის ვიდეოები დიდ ეკრანზე, დივანზე მსხდომი ოჯახისთვის, ტელევიზორის პულტით. Immich-ის მობილური აპი სატელევიზიო აპი არ არის: მომხმარებელმა, რომელმაც ის ტელევიზორზე დააყენა, აღმოაჩინა, რომ ის მაუსით მუშაობს და არა პულტით ([განხილვა #1614](https://github.com/immich-app/immich/discussions/1614)), ხოლო Immich-ის გუნდი ოფიციალურ სატელევიზიო აპს არ გეგმავს ([განხილვა #13748](https://github.com/immich-app/immich/discussions/13748)).

ბილდ 20-დან იგივე Android აპი Android TV-სა და Google TV-ზე მუშაობს, პულტით, როგორც ერთადერთი შეყვანით: ერთი APK ტელეფონებისა და ტელევიზორებისთვის, ისრებით მოსაბრუნებელი 360° და 3D მნახველები, და ქსელური გაზიარებები, Plex და Tapo კამერები ტელევიზორზე, Immich სერვერით ან მის გარეშე.

<a id="install-it-on-the-tv"></a>
### დაყენება ტელევიზორზე

1. სანამ Google Play აპს ტელევიზორებისთვის შესთავაზებს, რაც სატელევიზიო რელიზის Google-ის განხილვას ელოდება, აიღეთ უნივერსალური `Immuch360-v<version>-release.apk` [Releases](https://github.com/freeKC/Immuch360/releases) გვერდიდან.
2. ტელევიზორზე ჩართეთ დეველოპერის პარამეტრები და USB გამართვა (Google TV-ზე: პარამეტრები, სისტემა, შესახებ, შვიდჯერ აირჩიეთ „Android TV OS build“, შემდეგ პარამეტრები, სისტემა, დეველოპერის პარამეტრები; სახელები ტელევიზორების მიხედვით განსხვავდება).
3. იმავე ქსელში მყოფი კომპიუტერიდან, adb-ით (Android SDK Platform Tools): `adb connect <address of the TV>`, დაეთანხმეთ მოთხოვნას ტელევიზორზე, შემდეგ `adb install -r Immuch360-v<version>-release.apk`.
4. აპი ტელევიზორის აპებს შორის ჩნდება, თავისი ბანერით. შემდეგი რელიზი იმავე გზით დააყენეთ: `-r` შესვლასა და პარამეტრებს ინარჩუნებს.

### პირველი გაშვება

1. შედით ისე, როგორც ტელეფონზე: ისრები ჩარჩოს ველიდან ველზე გადააადგილებს, ხოლო OK ველზე („აკრეფისთვის დააჭირეთ OK-ს“) ტელევიზორის კლავიატურას დიალოგში ხსნის, სერვერის მისამართის, ელფოსტისა და პაროლისთვის.
2. ან აირჩიეთ „სერვერის გარეშე გამოყენება“. ტელევიზორს საკუთარი ფოტოები არ აქვს, ამიტომ ფოტოების ჩანართი ამბობს „ამ ტელევიზორს საკუთარი ფოტოები ან ვიდეოები არ აქვს: გახსენით ქსელური გაზიარება ბიბლიოთეკიდან.“ ქსელური გაზიარებების ღილაკით. დაამატეთ იქ გაზიარება, Plex სერვერი ან კამერა, როგორც ტელეფონზე (იხილეთ [ქსელური გაზიარებები](#network-shares-a-nas-a-computer-or-a-media-server)).

### გადაადგილება პულტით

- ისრები ჩარჩოს გადააადგილებს, OK ხსნის იმას, რაზეც ის დგას, უკან ღილაკი უკან ბრუნდება. ჩანართიდან უკან ღილაკი გვერდით მენიუში გადადის, შემდეგ ფოტოებზე, შემდეგ აპიდან გამოდის.
- არხის ზემოთ და ქვემოთ ღილაკები ერთ ჯერზე ერთ გვერდს გადაახვევს.
- მნახველებში მუშაობს პულტის დაკვრისა და პაუზის, წინ გადახვევის, უკან გადახვევის, შემდეგისა და წინას ღილაკები, ხოლო ინფორმაციის ღილაკი ფოტოს ან ვიდეოს დეტალებს აჩვენებს.

### ფოტოები და ვიდეოები პულტით

1. **ფოტო**: მარცხნივ და მარჯვნივ წინაზე ან შემდეგზე გადადის, OK მართვის ელემენტებს აჩვენებს ან მალავს, ზემოთ ზედა ზოლზე გადადის (სადაც 360° ღილაკია), ხოლო ქვემოთ ქვედა ზოლზე.
2. **ვიდეო**: OK აპაუზებს, მართვის ელემენტების ჩვენებით, ან უკრავს. დაკვრისას მარცხნივ და მარჯვნივ 10 წამით უკან ან წინ ხტება; პაუზისას ისინი წინა ან შემდეგ ელემენტზე გადადის, როგორც მინიშნება ამბობს: „დაპაუზებულია: ისრები წინა ან შემდეგ ელემენტზე გადადის“.
3. **360° ფოტო**, 360° ღილაკიდან: ისრებით ირგვლივ იყურებით, დაჭერისას უფრო სწრაფად, და ხედი თანდათან ჩერდება. OK ზედა ზოლის ღილაკებზე გადადის, „გადიდება“-ზე, „დაპატარავება“-ს, ხედვის არისა და 3D-ის გვერდით; არხის ზემოთ და ქვემოთ ღილაკებიც ადიდებს და აპატარავებს. უკან ღილაკი ღილაკებიდან სურათზე ბრუნდება, შემდეგ ხურავს. მინიშნება ამბობს „ისრები ირგვლივ დასათვალიერებლად, OK მართვისთვის, უკან დასახურად“.
4. **360° ვიდეო**, 360° ღილაკიდან: ისრებით ირგვლივ იყურებით, სანამ მართვის ელემენტები დამალულია, OK აპაუზებს და მათ აჩვენებს, უკან ღილაკი მათ მალავს, შემდეგ ხურავს. მინიშნება ამბობს „ისრები ირგვლივ დასათვალიერებლად, OK დასაპაუზებლად და მართვის საჩვენებლად, უკან დასახურად“.
5. **მოგონებები**: მარცხნივ და მარჯვნივ ფოტოებს გადაუყვება და შემდეგ მოგონებაზე გადადის, ზემოთ დახურვის ღილაკზე გადადის, ხოლო ქვემოთ „View in timeline (ქრონოლოგიაში ნახვა)“-ზე.
6. **გაზიარებები და Plex**: იგივე ღილაკები გაზიარების ფოტოებისა და ვიდეოების გვერდებზე, სადაც მარცხნივ და მარჯვნივ საქაღალდის წინა ან შემდეგ ფაილს ხსნის.

### პულტის განლაგების პარამეტრი

მორგება, მორგება (Preferences), „პულტის განლაგება“: „დიდი ფოკუსის ჩარჩოები და პულტის ღილაკები, სენსორული ეკრანის საჭიროების მქონე მართვის ელემენტების გარეშე. ავტომატური მას Android TV-სა და Google TV-ზე რთავს.“ ავტომატური ნაგულისხმევია; ჩართული შეეფერება პლანშეტს, რომელსაც კლავიატურით ან სათამაშო კონტროლერით მართავენ; გამორთული მას ტელევიზორზე გამორთავს. ეს პარამეტრი მხოლოდ Android-ზე არსებობს. ისრები და OK მნახველებში კლავიატურით ან სათამაშო კონტროლერით მუშაობს, პარამეტრის მიუხედავად.

## ვიდეოს დეტალები, დეკოდერები და რატომ ჭედავს ვიდეო

ადამიანები კითხულობენ, რომელ კოდეკს, ზომასა და ბიტრეიტს უკრავს Quest 3, და რატომ ჭედავს 5.7K ექსპორტი ჩაფხუტში, როცა ტელეფონზე უპრობლემოდ იკვრება. პასუხი აპარატული დეკოდერია: Quest 3-ის (XR2 Gen 2) H.264 დეკოდერის ზღვარი დაახლოებით 4096x2304-ია, ამიტომ 5760x2880 H.264 ვიდეო (დონე 6.0, დაახლოებით 200 მბიტ/წმ, Insta360-ის ჩვეულებრივი ექსპორტი) ჩაფხუტზე დაახლოებით 17 fps-ით დეკოდირდება, ბლოკური დამახინჯებებით, მაშინ როცა იგივე ფაილი ტელეფონზე კარგად იკვრება.

იგივე ვიდეო HEVC-ში (H.265) ჩაფხუტზე კარგად იკვრება: Insta360 X4 8K HEVC ვიდეო (7680x3840, 29,97 fps, 210 მბიტ/წმ, Main პროფილი, დონე 6.1, 8 ბიტი) იმერსიულ ხედში შეუფერხებლად იკვრება, თავისი საწყისი გარჩევადობით და ტრანსკოდირების გარეშე (Quest 3-ის ერთი მომხმარებლის ცნობით).

Immich აპს აქვს ერთი „Force original video“ გადამრთველი და მხოლოდ კოდეკს აჩვენებს. Immuch360 აჩვენებს, რა არის ვიდეო და რას დეკოდირებს მოწყობილობა, და ირჩევს ფაილს, რომელიც დაიკვრება.

### ვიდეოს დეტალების წაკითხვა

1. გახსენით ვიდეო და გადაასრიალეთ ზემოთ: დეტალები სურათის ქვემოთ ჩნდება.
2. კოდეკი: კოდეკი თავისი პროფილითა და კოდეკების სტრიქონით, კადრის ზომა და კადრების სიხშირე, მაგალითად „H.264 High (avc1.640033) • 3840 x 1920 • 30 fps“, როგორც ზემოთ მოცემულ სურათზე.
3. ბიტრეიტი (ბილდ 18-დან): ვიდეო ტრეკის ბიტრეიტი, ან ის, რასაც ფაილი აცხადებს; სხვა შემთხვევაში მონიშნულია „მთელი ფაილი, ხმის ჩათვლით“ ან „შეფასებულია ფაილის ზომით“.
4. გამოსახულება (ბილდ 18-დან): ბიტის სიღრმე, SDR ან HDR გადაცემის ფუნქცია (HLG, PQ, Dolby Vision) და ფერთა სივრცე.
5. დეკოდირდება ამ მოწყობილობაზე: დიახ ან არა, აპარატული ან პროგრამული, დეკოდერის მიერ მიღებული უდიდესი ზომა, და „(პროფილი)-სთვის დეკოდერი არ არის“, როცა მოწყობილობას კოდეკი აქვს, მაგრამ ეს პროფილი არა.

სტრიქონი მხოლოდ ფაილის წაკითხვის შემდეგ ჩნდება და მხოლოდ იმაზე, რასაც ფაილი ამბობს. Apple-ის სივრცითი ფოტო ან ვიდეო საკუთარ სტრიქონს იღებს, იხილეთ [Apple-ის სივრცითი ფოტოები და ვიდეოები](#apple-spatial-photos-and-videos).

### რას დეკოდირებს მოწყობილობა

მორგება, დამატებით, „ამ მოწყობილობის ვიდეო დეკოდერები“ (ბილდ 15-დან) ჩამოთვლის, რას დეკოდირებს ტელეფონი ან ჩაფხუტი: კოდეკი, აპარატული ან პროგრამული, უდიდესი ზომა, კადრების სიხშირე, ხოლო ბილდ 18-დან პროფილები (Main, Main 10, HDR10). ბილდ 19-დან მას აქვს MV-HEVC პუნქტი, Apple-ის სივრცითი ვიდეოების კოდეკი. კოპირების ღილაკი სიას ბუფერში ათავსებს შეცდომის ანგარიშისთვის.

### ორიგინალის ან ტრანსკოდირებული ნაკადის არჩევა

1. გახსენით მორგება, Asset Viewer, შემდეგ ვიდეოები.
2. „ვიდეოს წყარო“-ში („რომელი ფაილი ითამაშება, როცა სერვერს აქვს ტრანსკოდირებული ასლი“) აირჩიეთ „ორიგინალი, როცა ეს მოწყობილობა მას დეკოდირებს“, „ყოველთვის ორიგინალი“ ან „ყოველთვის ტრანსკოდირებული ნაკადი“.

ბილდ 15-დან არჩევანი სერვერის ყველა ვიდეოზე ვრცელდება: ბრტყელ პლეერზე, 360° და Spatial პლეერებზე და Quest-ის იმერსიულ ხედზე. სანამ არ აირჩევთ, ტელეფონი ინარჩუნებს იმას, რასაც ძველი „Force original video“ გადამრთველი ამბობდა (ნაგულისხმევად გამორთული: ტრანსკოდირებული ნაკადი, რომელიც თავად ორიგინალია, როცა სერვერს ის არ ტრანსკოდირებია), ხოლო Quest ორიგინალს უკრავს, როცა ჩაფხუტს მისი დეკოდირება შეუძლია.

შემოწმება ფაილიდან კოდეკს, ზომასა და კადრების სიხშირეს კითხულობს და აპარატულ დეკოდერებს ადარებს (Quest 3-ზე H.264 გაზომილი 4096x2304-ით არის შეზღუდული). პლეერი, რომელსაც ორიგინალის დეკოდირება არ შეუძლია, ტრანსკოდირებულ ნაკადზე გადადის შეტყობინებით: „ითამაშება ტრანსკოდირებული ნაკადი: ორიგინალი (კოდეკი და ზომა) აღემატება ამ მოწყობილობის დეკოდირების შესაძლებლობებს“.

ჩაფხუტში იმერსიული ხედი ორიგინალს იწყებს და, პირველ კადრებზე, სერვერის ტრანსკოდირებულ ნაკადზე გადადის, როცა ორიგინალი დეკოდერებს აღემატება, და ამას საინფორმაციო პანელზე ამბობს; როცა ტრანსკოდირებული ნაკადი არ არის, როცა ის მაინც ძალიან დიდია, ან როცა ფაილი ჩაფხუტიდან ან ქსელური გაზიარებიდან მოდის, საინფორმაციო პანელი ამას 10 წამის განმავლობაში ამბობს, იმის მითითებით, თუ რა უნდა შეიცვალოს. ბილდ 14, რომელიც Horizon Store-ს წარედგინა, მხოლოდ 4096x2304-ზე დიდ H.264-ს ამოწმებს და შემდეგ იმავე გზით სერვერის დაკვრის ნაკადს ცდის.

დაუმუშავებელი ორობიექტივიანი ვიდეოებისთვის შემოწმება ერთდროულად ორ დეკოდერს ითხოვს, ხოლო ბილდ 19-დან პროგრამულ დეკოდერს არ აძლევს ორ ნაკადს, რომელთაგან თითოეული 2048x2048-ზე დიდია, იხილეთ [კამერების დაუმუშავებელი 360° ფაილები](#raw-360-camera-files-without-the-cameras-app).

### მიეცით ჩაფხუტს ვიდეო, რომლის დეკოდირებაც შეუძლია

Immich-ში გადადით ადმინისტრაცია, მორგება, Video Transcoding Settings (ვიდეოს ტრანსკოდირების პარამეტრები) და აირჩიეთ ერთ-ერთი:

- **ყველა H.264 ვიდეო ხელახლა კოდირებული HEVC-ში**: დააყენეთ Video codec (ვიდეო კოდეკი) HEVC-ზე და Target resolution (სამიზნე გარჩევადობა) Original-ზე (ნაგულისხმევი 720p 360° ვიდეოს 1440x720-მდე შეამცირებდა), ხოლო Accepted video codecs-ში (მისაღები ვიდეო კოდეკები) მხოლოდ HEVC დატოვეთ. ბიბლიოთეკის ყველა H.264 ვიდეო ტრანსკოდირდება, არა მხოლოდ 360° ვიდეოები, და ჩაფხუტი სრული გარჩევადობის HEVC-ს იღებს.
- **მხოლოდ ის, რაც 1440p-ზე დიდია**: Accepted video codecs-ში H.264 დატოვეთ, Transcode policy (ტრანსკოდირების პოლიტიკა) დააყენეთ „Videos higher than target resolution or not in an accepted format“-ზე (სამიზნეზე მაღალი გარჩევადობის ან არამისაღები ფორმატის ვიდეოები) და Target resolution 1440p-ზე, სასურველია Video codec HEVC-ზე დაყენებით. ყველაფერი უფრო დიდი ტრანსკოდირდება და ჩაფხუტი 2880x1440-ს იღებს. ჩვეულებრივი 4K ვიდეოებიც 1440p-მდე ტრანსკოდირდება.

ეს პარამეტრები მთელ სერვერზე, ყველა მომხმარებელსა და ყველა აპზე ვრცელდება, ხოლო დიდი ბიბლიოთეკის ხელახალ კოდირებას საათობით CPU დრო და დამატებითი დისკის ადგილი სჭირდება; ორიგინალები არ იცვლება. HEVC-ის მხარდაჭერის არმქონე ბრაუზერები (Firefox სისტემების უმეტესობაზე, Chrome აპარატული HEVC-ის გარეშე) Immich-ის ვებ აპში HEVC ტრანსკოდირებას ვერ დაუკრავენ. ახალი ვიდეოებისთვის ყველაზე მარტივი გამოსავალია H.265-ში ექსპორტი Insta360 აპიდან ან Studio-დან. ამ პარამეტრების შეცვლის შემდეგ არსებული ვიდეოები ხელახლა უნდა ტრანსკოდირდეს: ადმინისტრაცია, Job Queues (დავალებების რიგები) (Immich-ის ძველ ვერსიებში დავალებები), Transcode videos (ვიდეოების ტრანსკოდირება), ყველა.

ალტერნატივა, და ერთადერთი ქსელური გაზიარების ან ჩაფხუტის ფაილებისთვის (მათ ტრანსკოდირებული ნაკადი არ აქვთ), არის ექსპორტის HEVC-ში ხელახლა კოდირება მის ატვირთვამდე ან გაზიარებაზე კოპირებამდე:

```bash
ffmpeg -i VID_360.mp4 -c:v libx265 -crf 20 -preset medium -tag:v hvc1 -c:a copy -movflags +faststart VID_360_hevc.mp4
exiftool -overwrite_original -tagsFromFile VID_360.mp4 -XMP-GSpherical:all VID_360_hevc.mp4
exiftool -ProjectionType VID_360_hevc.mp4        # must print: equirectangular
```

`-tag:v hvc1` HEVC ტრეკს ისე მონიშნავს, როგორც Apple-ის მოწყობილობები და ბრაუზერები ელიან, `-c:a copy` ხმას ისე ინარჩუნებს, როგორც არის. ffmpeg ექსპორტის 360° ტეგს კარგავს, exiftool-ის სტრიქონი მას უკან აკოპირებს; მის გარეშე Immich ვიდეოს ბრტყელ ვიდეოდ აჩვენებს.

### ორიგინალები, რომელთა ნაკადად გადაცემა შეუძლებელია

როცა სერვერი ორიგინალზე HTTP Range მოთხოვნებს უგულებელყოფს და MP4 ინდექსი (moov) ფაილის ბოლოშია, პირველ კადრამდე მთელი ფაილის ჩამოტვირთვა იქნებოდა საჭირო, ამიტომ აპი სერვერის დაკვრის ნაკადზე გადადის. ## დანარჩენი ყველაფერი Immich-ია

ყველაფერი, რასაც ოფიციალური Immich მობილური აპი აკეთებს, აქაც არის: მარქაფი, ქრონოლოგია, ალბომები, ძებნა, გაზიარება, პარტნიორები, ყველაფერი თქვენს სერვერთან სინქრონიზებული, იგივე სერვერითა და იგივე ანგარიშით, რაც ვებ აპში. Immuch360 ოფიციალური აპის გვერდით დგება (პაკეტი `com.aprogsys.immuch360`). ორი განსხვავებაა, ბილდ 15-დან: „Force original video“ გადამრთველი ზემოთ აღწერილ ვიდეოს წყაროს არჩევანად იქცა, ხოლო მოწყობილობის ალბომიდან ხელით ატვირთული ფოტოები და ვიდეოები დამარქაფებულად ითვლება. ტელევიზორზე, ბილდ 20-დან, აპი მნახველია, იხილეთ [ყურება ტელევიზორზე](#watch-on-your-tv-android-tv-and-google-tv).

მიმდინარე ბილდი, ბილდი 21 (ვერსია 3.3.0-rc.0, ბილდის ნომერი 3030019), დაფუძნებულია Immich 3.3.0-rc.0-ზე (Immich-ის `main`, ჯერ არა სტაბილური რელიზი). ბილდი 19 გამოიცადა Immich 3.2 სერვერით, ხოლო ბილდები 20 და 21 არაფერს ცვლის იმაში, რასაც აპი სერვერს სთხოვს. პრობლემები შეატყობინეთ [Issues](https://github.com/freeKC/Immuch360/issues)-ში და არა Immich პროექტს. თავად Immich-ის სრული დოკუმენტაციისთვის იხილეთ [immich.app](https://immich.app).

## Meta Quest 3

Immuch360 ასევე მუშაობს Meta Quest ჩაფხუტებზე Horizon OS v69-ით ან უფრო ახლით. ბილდ 21-დან Horizon Store-ის ბილდი მითითებულია Quest 2-ის, Quest Pro-ს, Quest 3-ისა და 3S-ისთვის, იმ ოთხისთვის, რომლებსაც უნივერსალური `-release.apk` უკვე ასახელებს; პირველი Quest არა, მაღაზია მას აღარ იღებს.

Quest 3 და 3S გამოცდილია. Quest 2 და Quest Pro ჯერ გამოუცდელია: მათი ვიდეო დეკოდერები უფრო ნელია, ხოლო ზღვრები, რომლებსაც აპი ამოწმებს, Quest 3-ზე გაიზომა, ამიტომ დიდი H.264 ვიდეო შეიძლება შეტყობინებით უარყოფილ იქნას ან მათზე შეფერხებით დაიკრას. ამ ორი ჩაფხუტიდან ანგარიშები მისასალმებელია [Issues](https://github.com/freeKC/Immuch360/issues)-ში.

მისი გამოყენება აღწერილია [Meta Quest 3 ჩაფხუტში](#in-the-meta-quest-3-headset) განყოფილებაში; ეს განყოფილება ეხება დაყენებას და იმას, რაც ჩაფხუტზე განსხვავდება.

ჩაფხუტის ბილდი სერვერებთან მხოლოდ HTTPS-ით ურთიერთობს, ან უბრალო HTTP-ით სახლის ქსელის სახელებთან (`.local`, `.lan`, `.home`, `.internal`, `.home.arpa`) და თავად ჩაფხუტთან, როგორც ამას Horizon Store მოითხოვს. სერვერი, რომელიც IP-ით უბრალო HTTP მისამართად არის აკრეფილი, მაგალითად `http://192.168.1.10:2283`, ამ ბილდის მიერ უარყოფილია: გამოიყენეთ HTTPS, სახლის ქსელის სახელი (`nas.local`), ან უნივერსალური `-release.apk`, რომელიც ტელეფონების ღია პოლიტიკას ინარჩუნებს.

ლოკალური ქსელის უბრალო HTTP მისამართზე არსებულ WebDAV, DLNA და ტელეფონის გაზიარებებს ეს არ ეხება: აპი მათ თავად კითხულობს და თავის პლეერებს მხოლოდ თავისი ლოკალური ხიდის მისამართს აძლევს (DLNA-სა და ტელეფონის გაზიარებისთვის, რომლებიც ბილდ 19-ში ახალია, ეს ჩაფხუტზე ჯერ დასადასტურებელია). ბილდ 20-დან Plex სერვერს HTTPS-ით უკავშირდება, ხოლო Tapo კამერას თავად აპი, მის პირდაპირ ხედს RTSP-ით, რომელიც HTTP არ არის: არცერთს ეს არ უნდა ეხებოდეს (ჩაფხუტზე დასადასტურებელია).

### დაყენება

Meta-მ Horizon Store-ის განცხადება 2026 წლის 7 ოქტომბერს ბილდ 14-ით დაამტკიცა, ხოლო ბილდი 21 წარდგენილია მის პირველ განახლებად. სანამ მაღაზიის გვერდი საჯარო გახდება, ან თუ ბილდის მიღება მაღაზიაზე ადრე გსურთ, ხელით დააყენეთ რელიზის `-quest-release.apk` ფაილი (აგებულია ჩაფხუტისთვის: 64 ბიტი, სამიზნე SDK 34, მხოლოდ ის ნებართვები, რომლებსაც ჩაფხუტი იყენებს), ან უნივერსალური `-release.apk`:

1. ერთხელ ჩართეთ დეველოპერის რეჟიმი. Meta Horizon-ის ტელეფონის აპში გახსენით Devices (მოწყობილობები), აირჩიეთ ჩაფხუტი, შემდეგ Headset settings (ჩაფხუტის პარამეტრები), შემდეგ Developer mode (დეველოპერის რეჟიმი). ამისთვის საჭიროა დეველოპერის ანგარიში, რომელიც უფასოა developers.meta.com-ზე. კომპიუტერზე ასევე გჭირდებათ adb (Android SDK Platform Tools) ან SideQuest.
2. დაუკავშირეთ ჩაფხუტი კომპიუტერს USB-C კაბელით. ჩაფხუტში მიიღეთ „Allow USB debugging“ (USB-ით გამართვის დაშვება).
3. დააყენეთ APK:

   ```bash
   adb devices                      # the headset must be listed as "device"
   adb install -r Immuch360-v<version>-quest-release.apk   # for example Immuch360-v3.3.0-rc.0-21-quest-release.apk
   ```

- **დაუხვეწავი ადგილები**: 663 დესკტოპ ტესტიდან 656 გადის Windows-ზე (7 განზრახ გამოტოვებულია), ერთმანეთის მიყოლებით გახსნილი 200 პლეერი გაჟონვას არ ტოვებს, და Windows 11 კომპიუტერზე აპი ეშვება, ხსნის შენახულ სესიას Immich სერვერზე, სინქრონიზდება, უკრავს ვიდეოს და სუფთად იხურება. თითოეული ფუნქციის ხელით ტესტირება ნამდვილ კომპიუტერზე ჯერ კიდევ მიმდინარეობს.

<a id="build-it-yourself-on-windows"></a>
### ააწყვეთ თავად Windows-ზე

დაგჭირდებათ Windows 10 ან 11 x64-ზე, Flutter 3.47.2 Windows-ისთვის, Visual Studio 2022 ან მისი Build Tools „Desktop development with C++“ სამუშაო დატვირთვით, Windows-ის პარამეტრებში ჩართული Developer Mode (Flutter-ს ის მოდულებისთვის სჭირდება), და Python 3 შეფუთვის სკრიპტისთვის.

1. მიიღეთ წყაროები და გაუშვით კოდის გენერაცია. მთავარი შტო, `immuch360`, კომპიუტერის ვერსიასაც აწყობს: გადასართავი შტო არ არის. კოდის გენერაცია Java-სა და Node-ს იყენებს, ამიტომ გაუშვით Linux-ზე, macOS-ზე ან WSL-ში; WSL-ის შემთხვევაში კლონი შეინახეთ Windows დისკზე, რომელსაც WSL `/mnt/c` ან `/mnt/d`-ის ქვეშ ხედავს:

   ```bash
   git clone https://github.com/freeKC/Immuch360.git
   cd Immuch360/mobile
   mise install
   mise run install
   mise run codegen
   ```

2. Windows-ზე, იმავე `mobile` საქაღალდეში, ააწყვეთ აპი. პირველი აწყობა GitHub-იდან ჩამოტვირთავს ვიდეო პლეერის ბიბლიოთეკებს (libmpv და ANGLE) და თითოეულ არქივს მისი SHA-256-ით ამოწმებს:

   ```bat
   flutter pub get
   REM try it, with hot reload: a debug build, with a profile of its own (Immuch360 Desktop Debug), so it runs next to the app
   flutter run -d windows -t lib/main_desktop.dart
   REM the app, in build\windows\x64\runner\Release\immuch360.exe
   flutter build windows --release -t lib/main_desktop.dart
   ```

3. `Release` საქაღალდე იმ კომპიუტერზე მუშაობს, რომელმაც ის ააწყო. სხვა კომპიუტერისთვის შეინახეთ მთელი საქაღალდე და დაამატეთ Visual C++ runtime `immuch360.exe`-ის გვერდით. კლონის ძირიდან შეფუთვის სკრიპტი მას აკოპირებს, გამოტოვებს იმას, რაც მხოლოდ Android-ს ემსახურება, ამატებს ვიდეო პლეერის ლიცენზიებს, ამოწმებს, რომ აპის მიერ ჩატვირთული ყველა DLL საქაღალდეშია ან თავად Windows-ში, და ქმნის ZIP-ს:

   ```bat
   python .github\desktop\windows_bundle.py --release mobile\build\windows\x64\runner\Release --out <folder> --zip <file.zip>
   ```

Immuch360 Desktop-ის CI (`.github/workflows/immuch360-desktop.yml`) მუშაობს `desktop` შტოზე, რომელიც `immuch360`-ს მიჰყვება: Linux-ზე ტელეფონის შემოწმებები (ტელეფონის ბილდებში არაფერი იცვლება) და მთელი ტესტების ნაკრები, Windows-ზე დესკტოპ ტესტები, და იგივე ZIP; მისი Linux და macOS დავალებები (`flutter build linux` და `flutter build macos`, იმავე `-t lib/main_desktop.dart`-ით) ამ სისტემებზე ჯერ არ გაშვებულა.

<a id="build-it-yourself"></a>
## ააგეთ თავად

აგების ჯაჭვი იგივეა, რაც Immich mobile-ის (Flutter 3.47, მართული [mise](https://mise.jdx.dev)-ით):

```bash
git clone https://github.com/freeKC/Immuch360.git
cd Immuch360/mobile
mise install
mise run install
mise run codegen
flutter build apk --release --flavor phone                                   # phones: the universal APK of the GitHub releases (add --split-per-abi for the per ABI files)
flutter build appbundle --release --flavor phone                             # the App Bundle sent to Google Play (also mise run build:android)
flutter build apk --release --flavor quest --target-platform android-arm64 --android-project-arg arm64only=true   # Meta Quest 2, Pro, 3 and 3S: the -quest-release.apk of the releases (also mise run build:quest)
flutter build ios --release                                                  # iPhone and iPad, on a Mac with Xcode and your own signing team
```

მაღაზიების ეკრანის სურათები გადაიღება სიმულატორის debug ბილდებზე, რომლებიც აგებულია `--dart-define=IMMUCH_SCREENSHOTS=true`-ით, რაც მხოლოდ debug ბანერს მალავს.

Android-ის ორი ვარიანტი (flavor) ერთი და იგივე აპია. ბილდ 20-დან `phone` თავს სატელევიზიო აპადაც აცხადებს (ტელევიზორის გამშვების ჩანაწერი და ბანერი, სენსორული ეკრანი საჭირო არ არის), რასაც `quest` გამოტოვებს.

`quest` SDK 34-ს უმიზნებს და მხოლოდ იმ ნებართვებს ინარჩუნებს, რომლებსაც ჩაფხუტი იყენებს (ფოტოები, ვიდეოები, შეტყობინებები): მედიის მართვა, ფონური მდებარეობა, ძველი მეხსიერება, აუდიო, მედიის მდებარეობა, მოწყობილობის მდებარეობა და კამერა წაშლილია `android/app/src/quest/AndroidManifest.xml`-ში, რადგან Meta Horizon Store პირველ ორს უარყოფს და ყველა სხვა მგრძნობიარე ნებართვისთვის დასაბუთებას ითხოვს; იგივე ფაილი მხარდაჭერილ მოწყობილობებად Quest 2-ს, Quest Pro-ს, Quest 3-სა და 3S-ს ასახელებს და უბრალო HTTP-ს თავად ჩაფხუტითა და სახლის ქსელის სახელებით ზღუდავს. APK მხოლოდ 64-ბიტიანია მისი ბრძანების ხაზის ორი დამატებითი არგუმენტის გამო (`--target-platform android-arm64 --android-project-arg arm64only=true`). `phone` არის ის, რასაც Google Play მოითხოვს.

საკუთარ Mac-ზე iOS-ისთვის ასაგებად გამოიყენეთ Xcode და თქვენი საკუთარი ხელმოწერის გუნდი; Xcode 26-ით ჯერ ერთხელ გაუშვით `xcodebuild -downloadComponent MetalToolchain`, რადგან Spatial shader-ებს ის სჭირდება. Mac-ის გარეშე iOS ბილდები Codemagic-ზე (ჰოსტინგის Mac) ეშვება ამ საცავის `codemagic.yaml` ფაილიდან. Android-ის რელიზის ბილდები GitHub Actions-ზე ეშვება (`.github/workflows/immuch360-release.yml`).

## ჟურნალი

Android-სა და Quest-ზე `adb logcat` აჩვენებს ჩაფხუტის იმერსიულ ხედს `Immuch360` ტეგით (ბილდ 19-დან ასევე Apple-ის სივრცითი ფოტოს ორ თვალს: როგორ დეკოდირდა მეორე თვალი, ჩამოჭრა, სად განთავსდა ფოტო), დეკოდერების შემოწმებებს `VideoDecoders`-ით, გვერდიგვერდ დაუმუშავებელი ვიდეოს შეკერვას `DualFisheyeEffect`-ით, და ბილდ 18-ის ორობიექტივიან დაკვრას `TwoLensPlayer`, `TwoLensCompositor` და `LensVideoRenderer` ტეგებით:

```bash
adb logcat -c
# reproduce the problem, then
adb logcat -d -v time -s Immuch360 VideoDecoders DualFisheyeEffect TwoLensPlayer TwoLensCompositor LensVideoRenderer
adb logcat -d -v time > quest-full.log      # everything, including crashes and decoder errors (it can contain your server address, check before sharing)
adb logcat -d -v time -s PhoneShareService PhoneShareApi   # on the phone that shares itself (from build 19)
```

ბილდ 19-დან DLNA კლიენტი, ტელეფონის გაზიარება და Apple-ის სივრცითი მედიის ამოცნობა ასევე წერენ აპის საკუთარ ჟურნალში (ჟურნალი, ზედა მარჯვენა კუთხეში პროფილის სურათის მენიუში), `Ssdp`, `DlnaFileSystem`, `NetworkBrowserPage`, `PhoneShare`, `PhoneShareServer`, `AppleSpatialService`, `HeicStereoProbe` და `NetworkMediaService` სახელებით. ბილდ 20-დან ტელევიზორის რეჟიმი იქ წერს `TvMode` და `TvTextEntry` სახელებით, Plex სერვერები `Gdm`, `UdpTransport`, `PlexClient`, `PlexFileSystem` და `PlexServerEditPage` სახელებით, ხოლო Tapo კამერები `TapoDiscovery`, `TapoHttps`, `TapoLogin`, `TapoControl`, `TapoMedia`, `TapoFileSystem`, `TapoTest`, `TapoCamera`, `CameraPage`, `CameraEditPage` და `CameraLiveView` სახელებით; Plex-ის სტრიქონები არასოდეს შეიცავს ტოკენს, მისამართს ან სათაურს, ხოლო კამერის სტრიქონებში პაროლები არ შედის. ჟურნალის სტრიქონები მოწყობილობაზე რჩება, თუ თავად არ დააკოპირებთ.

კომპიუტერზე (Immuch360 Desktop) ჟურნალის გვერდს ასევე აქვს „ჟურნალის ფაილში შენახვა“: ჟურნალი, ან ჟურნალისა და ბოლო ავარიების ანგარიშების ZIP, როცა ასეთები არსებობს (მაშინ შემოთავაზებული სახელი „with-crash-reports“-ით მთავრდება). ავარიის ანგარიში პატარა minidump-ია: ნაკადები, სად გაჩერდნენ ისინი და მხოლოდ ის, რაც მათი გამოძახებების მისადევნებლად არის საჭირო, პროგრამის ფაილების სახელებით, მაგრამ მათი საქაღალდეების გარეშე; არა აპის მეხსიერება.

desktop build 2-დან კომპიუტერის ვიდეო პლეერი იქ წერს `DesktopVideo`, `DesktopPlayer`, `DesktopVideoController`, `PlayerPool` და `VideoThumbnailGrabber` ტეგებით, mpv-ის საკუთარი გაფრთხილებების ჩათვლით, ტოკენებისა და პაროლების ამოღებით. გაზიარებამდე შეამოწმეთ ჟურნალი: ის შეიძლება თქვენი სერვერის მისამართს შეიცავდეს.
