# Immuch360

Immuch360 は、見回せる 360° の写真と動画に対応した Immich モバイルアプリで、平面、360°、3D、VR180 の写真と動画を再生できる無料のプレーヤーでもあります。Android のスマートフォンとタブレット、iPhone と iPad、Meta Quest ヘッドセット（Quest 3 と 3S、ビルド 21 からは Quest 2 と Quest Pro も、未テスト）、そしてビルド 20 からは Android TV と Google TV で動作します。 Windows パソコンで動く同じアプリ、Immuch360 Desktop をプレビュー版として公開しました。[Windows パソコンで](#on-a-windows-computer-immuch360-desktop-preview) を参照してください。

360° カメラ（Insta360、GoPro MAX、DJI Osmo 360、Ricoh Theta、Samsung Gear 360）やスマートフォンのフォトスフィアモードで撮影する人、またはヘッドセットを持っていて、自分の撮影データを Immich サーバー、スマートフォン本体、NAS、メディアサーバー、Plex サーバーから見たい人のためのアプリです。同じサーバー、同じアカウントのまま使え、サーバー用のプラグインは不要で、サーバーなしでも使えます。ビルド 20 からは Tapo カメラも、ライブ映像とメモリーカードの録画を表示できます。

## 360° の写真と動画を球体で

写真を [Immich](https://github.com/immich-app/immich) サーバーにバックアップしていて、その一部は 360° カメラやスマートフォンのフォトスフィアモードで撮ったものだとします。公式モバイルアプリでは、それらの写真は平らに引き伸ばされた帯として表示され、360° 動画も平面で再生されます。Immich のウェブアプリは 360° 写真を球体で表示できますが、モバイルアプリではできません。これは 2024 年 1 月から [ディスカッション #6572](https://github.com/immich-app/immich/discussions/6572) で要望されています。

Immuch360 は、Android と iOS のスマートフォンとタブレットで、これらを見回せる球体として開きます。

写真はドラッグで回転し、ピンチやダブルタップでズームし、素早くドラッグした後も少し回り続け、カメラが記録した初期視点（GPano メタデータ）から始まり、ズームインするとより鮮明なテクスチャに切り替わります。部分的なパノラマにも対応しています（GPano の切り抜き）。動画は、音声、ドラッグ、ジャイロスコープに対応したネイティブの球体プレーヤーで再生されます。

スティッチ済みの 360° ファイルはどこでも動作します：Insta360 アプリや Studio、GoPro Player、Ricoh Theta からの書き出し、スマートフォンのフォトスフィアなどです。カメラから直接取り出した RAW ファイルはアプリがスティッチします。[カメラの RAW 360° ファイル](#raw-360-camera-files-without-the-cameras-app) を参照してください。

- **球体で表示した 360° 写真**：左上に閉じるボタン、右上に 360°/180° ボタン、3D レイアウトボタン、ジャイロスコープ。
- **360° プレーヤーで再生中の 360° 動画**：画像をタップすると操作ボタンが表示されます。右上に 360° と 3D。

### 360° 写真を球体で開く

1. タイムライン、アルバム、[360° リスト](#find-your-360-shots-the-360-list)、または共有フォルダーから写真を開きます。360° 写真のサムネイルには 360° バッジが付いています。
2. ビューアー上部のバーで 360° をタップします。球体ビューアーが開き、フル画像の読み込み中は読み込みインジケーターが表示されます。平面表示でのズームはそのまま引き継がれます。
3. ドラッグで見回し、ピンチでズーム、ダブルタップで拡大します。素早くドラッグすると、視点が少し回り続けてから減速します。
4. スマートフォンを動かして見回すには、右上のジャイロスコープボタンをタップします（初期設定ではオフ）。
5. 右上の残り 2 つのボタンは 360°/180°（全天球または VR180 の半天球、部分的なパノラマでは非表示）と 3D（ステレオ写真のレイアウト）です。[3D と VR180](#3d-and-vr180-photos-and-videos) を参照してください。Insta360 の RAW 写真にはジャイロスコープのボタンだけがあります。
6. 左上の × で閉じます。

### 360° 動画を再生する

1. 動画を開き、上部のバーで 360° をタップします。360° 動画では 360° ボタンが最初に並び、スマートフォンとタブレットでは、その設定がオンの間は続けて Spatial ボタンが表示されます（[Spatial 2.5D](#depth-on-a-flat-screen-spatial-25d-experimental) を参照）。
2. ネイティブの 360° プレーヤーが全画面で開き、音声付きで再生します：Android では Media3、iOS では SceneKit です。
3. ドラッグするか、スマートフォンを動かして見回します。Android のプレーヤーは常にスマートフォンの動きに追従し、iOS のプレーヤーにはジャイロスコープの切り替えがあります（初期設定ではオン）。
4. 画像をタップすると操作ボタンが表示されます：上部に閉じる、360°/180°、3D、その下に再生、スキップボタン、そして Android ではタイムバー。iOS のプレーヤーには今のところ再生と一時停止しかありません。
5. 動画に音声トラックが 2 つ以上ある場合（言語、解説など）、「音声トラック」ボタンで選べます。動画の読み込み中や途切れたときは、プレーヤーに「読み込み中」と再生バッファーの充填率が表示されます。

プレーヤーは、スマートフォンに保存されたファイル、またはネットワーク共有のファイルがあればそれを再生します。なければサーバーからストリーミングします：初期設定では変換済みストリーム、設定、アセットビューアー、「動画のソース」で指定すればオリジナルです（ビルド 15 から。それ以前は「常にオリジナル画質の動画を再生する」スイッチ）。[動画の詳細とデコーダー](#video-details-decoders-and-why-a-video-stutters) を参照してください。

### 平面で表示される 360° ファイル：360°で表示

一部の 360° ファイルには投影方式のタグがないため、サーバーが 360° と判定せず、平面で表示されます。

1. 写真または動画を開き、右上の ⋮ をタップします。
2. スライドショーとダウンロードの間にある「360°で表示」をタップします。上部のバーに 360° ボタンが表示されます。
3. 元に戻すには、同じ項目が「360°として扱わない」に変わっているので、それをタップします。

この選択はスマートフォンに記憶され、サーバー上は何も変わりません。ネットワーク共有のファイルでは、その表示のときだけ有効です。

### 制限

- **iOS の 360° 動画プレーヤー**：再生と一時停止のみで、タイムバーはまだありません。
- **前へと次へ**：スマートフォンの 360° プレーヤーでは、前後のメディアへの移動はまだできません。Quest のイマーシブビューではできます。
- **非常に大きなパノラマ**：写真は最大 8192x4096 で表示されます。これは多くのスマートフォンの GPU が扱える最大のテクスチャサイズで、それより大きなパノラマはこのサイズに縮小されます。
- **デュアル魚眼の .dng**：まだ平面で表示されます。

<a id="without-a-server-or-an-account"></a>
## サーバーもアカウントもなしで

Immich サーバーがない、またはアカウントを作りたくない。ただスマートフォンの 360° 写真を、ジャイロスコープで回せる球体として開きたい。Immich アプリは、まずログインを求めます。

ログイン画面の「サーバーなしで使用」を選ぶと、Immuch360 はデバイス本体の写真と動画で開き、360°、3D、VR180、Spatial の各ビューアー、360° リスト、ネットワーク共有（ビルド 20 からは Plex サーバーと Tapo カメラも）を使えます。Immich のアカウントは不要です。サーバーの機能は、サーバーに接続するまで非表示またはグレー表示になり、データがデバイスの外に出ることはありません。Meta Quest では、ヘッドセット本体の写真と動画で開きます。自身の写真や動画を持たないテレビでは、ネットワーク共有へ案内します（[テレビで見る](#watch-on-your-tv-android-tv-and-google-tv) を参照）。

### サーバーなしで始める

1. アプリを開きます。ログイン画面で、サーバーアドレスと設定の下にある「サーバーなしで使用」をタップします。
2. 写真と動画へのアクセスを許可します。拒否すると、アプリに「アプリはこのデバイスの写真にアクセスできません」と表示され、「アクセスを許可」と「設定を開く」が示されます。
3. 写真タブにはデバイスのタイムラインが表示されます。検索とアルバムはサーバーの機能なのでグレー表示のままです。ライブラリタブの上部に 360°、続いてデバイス上の項目（デバイスのアルバム）とネットワーク共有があります。
4. 右上のメニューには「このデバイスのみ」と表示されます：アプリはこのデバイスの写真と動画を表示し、どこにも何も送信しません。

### 後からサーバーに接続する

1. 設定を開きます（右上のメニューから設定）。最初の項目が「サーバーに接続」、「Immichサーバーと同期して、バックアップ、検索、共有を行います」です。右上のメニューにも同じ項目があります。
2. いつも通りログインします。タイムライン、アルバム、バックアップなど、サーバーの機能が表示されます。

### 制限

- **デバイス本体のギャラリー**：アプリはデバイスのギャラリーにある写真と動画を表示します。iPhone では、iCloud にだけ保存されているファイルは、デバイスにダウンロードされるまで 360° ファイルのスキャン対象になりません。
- **サーバーなし**の場合、360° リストにはデバイスのスキャンで見つかったものと、360° として表示することを選んだファイルが入ります。[360° リスト](#find-your-360-shots-the-360-list) を参照してください。

<a id="network-shares-a-nas-a-computer-or-a-media-server"></a>
## ネットワーク共有：NAS、パソコン、メディアサーバー

360° 動画が NAS やパソコンにあり、先にコピーせずにスマートフォンやヘッドセットで見たい。ヘッドセットでは結局ファイルを 1 つずつケーブルでコピーすることになり、Plex や Jellyfin などのメディアサーバーは、各フォーラムの要望にあるように 360° 動画を平面で再生します。Immich アプリが読めるのは自分の Immich サーバーだけです。

Immuch360 は、SMB（Samba、Windows）、WebDAV、そしてビルド 19 からは DLNA/UPnP（メディアサーバー：Jellyfin、minidlna、Gerbera、Emby、NAS、TV ボックス）に対応したあらゆるサーバーの写真と動画を、共有から直接参照して再生します。ビルド 20 からは Plex Media Server に専用の種類があります。[Plex Media Server、plex.tv なしで](#plex-media-server-without-plextv) を参照してください。

ネットワーク上のサーバーを自動で見つけ、アプリの他の部分と同じビューアー（360°、3D、VR180、Spatial 2.5D、Quest のイマーシブビュー）でファイルをそのまま再生します。Immich サーバーの有無にかかわらず、スマートフォンでも Meta Quest 3 でも使えます。何もダウンロードしません。サーバーに接続している場合は、選んだファイルを Immich アカウントに送信できます（ビルド 15 から）。

### 共有を追加する

1. ライブラリタブを開き、ネットワーク共有を開きます。最初は「共有はまだありません」と表示され、「共有を追加」ボタンがあります。右上の + でもいつでも同じことができます。ビルド 20 からは、どちらも何を追加するかを尋ねます：「ネットワーク共有 (NAS、コンピューター、メディアサーバー)」、「Plex Media Server」、「Tapo カメラ」。最初のものを選びます。
2. 「共有を追加」画面は、まずネットワーク上のサーバーを探し、「ネットワーク上で見つかったサーバー」の下に種類（SMB、WebDAV、DLNA、電話、ビルド 20 からは Plex と Tapo）と一緒に一覧表示します。検索には最大で約 6 秒かかります。「再スキャン」でやり直せます。Bonjour/mDNS と、実際の SMB または WebDAV のやり取りで確認するローカルネットワークのスキャンを使い、ビルド 19 からは DLNA メディアサーバーの SSDP 検索、ビルド 20 からは Plex の検出方式である GDM と、Tapo カメラ用の TP-Link の検出プロトコルも使います。
3. サーバーをタップすると、種類、サーバー、ポート、パスが入力されます。Plex サーバーや Tapo カメラの場合は、入力済みの専用の画面が開きます。
4. 一覧にない場合は、フォームに手動で入力します。種類：「SMB（Samba、Windows 共有）」、「WebDAV（Nextcloud、Synology など）」、「DLNA メディアサーバー (Jellyfin、NAS、TV ボックス)」、またはビルド 20 からの「Plex Media Server」のいずれか。「Plex Media Server」は [Plex Media Server、plex.tv なしで](#plex-media-server-without-plextv) の画面を開きます。続いて名前、「サーバー名またはアドレス」（名前またはアドレス。`smb://nas/photos`、`\\nas\photos`、`https://nas:5006/photos` のような完全なアドレスを入れると他の欄も埋まります）、通常と異なる場合は「ポート（任意）」、SMB なら「共有名」、WebDAV なら「WebDAV アドレスのパス」、「開始フォルダー（任意）」、「ユーザー名」と「パスワード」、WebDAV では「安全な接続（HTTPS）」を入力します。
5. SMB：サーバーとユーザー名を入力すると、「共有を選択」でサーバーの共有が一覧表示されます。
6. DLNA：メディアサーバーにはユーザー名もパスワードもありません。サーバー、ポート、デバイス記述の「説明のパス」（minidlna なら `/rootDesc.xml`）を指定するか、`http://192.168.1.10:8200/rootDesc.xml` のような完全なアドレスをサーバーの欄に貼り付けます。
7. 「接続をテスト」をタップします。「接続しました。開始フォルダーに N 件の項目があります」と表示されるか、失敗した理由が示されます。その後、フォームの下部にある保存をタップします。

パスワードが空のユーザー名は、そのまま送信されます：Freebox Server のディスクには `freebox` というユーザー名とパスワードなしが必要です。後で共有を変更または削除するには、ネットワーク共有の画面で共有の横にある鉛筆アイコンを使います。

### 参照して再生する

1. 共有をタップします。最初にフォルダー、次に写真と動画がサムネイル付きのグリッドで表示されます（各動画の 1 フレームもデバイスにキャッシュされます）。360° と認識されたものには 360° バッジが付き、ビルド 19 からは Apple の空間写真と空間ビデオに 3D バッジが付きます。下に引っ張ると更新します。
2. 写真をタップすると全画面で開き（ピンチ、ダブルタップ）、その 360° ボタンで球体ビューアーが開きます。
3. 動画をタップすると、ネイティブプレーヤーで再生されます（再生、一時停止、シーク）。360° ボタンで 360° プレーヤーと、その 3D と 360°/180° のボタンが使え、スマートフォンではステレオのファイルに Spatial ボタンがあります。
4. Quest では、360° ボタンでイマーシブビューが開き、ビルド 19 からは「3D で表示」で Apple の空間写真を 3D で開けます。
5. ⋮ メニューには、360° タグのないファイル用に「360°で表示」があり、スマートフォンではステレオでない動画用に「Spatial 2.5D」があります。

360°、3D、VR180 は、範囲リクエストで読み込んだファイルの GPano または球面メタデータから認識され、VR180 はファイル名からも認識されます。ビルド 16 からは Insta360 の RAW ファイルも認識され（.insp 写真は名前またはカメラのキャリブレーションブロックから、.insv 動画は名前とフレームから）、スティッチされます。

<a id="send-files-of-a-share-to-immich"></a>
### 共有のファイルを Immich に送信する

ビルド 15 から、サーバーに接続しているとき：

1. 共有フォルダーで写真または動画を長押しするか、右上の選択をタップします。
2. 送信したいものにチェックを付けるか、「このフォルダーのすべての写真と動画を選択」を使います。
3. 「Immichにアップロード」をタップします。ファイルは共有からサーバーへ 1 つずつストリーミングされ、各タイルに進行状況が、下部のバーに「12件中3件を送信中」とキャンセルボタンが表示されます。送信中はアプリを開いたままにしてください。
4. 最後に、送信した数とすでにサーバーにあった数が表示されます：サーバーは自分のコピーを保持し、すでにあるファイルの重複を除きます。以前に送信したファイルには印（「以前Immichに送信済み」）が付き、次回はスキップされます。

共有から開いた写真や動画のメニューにも同じ項目があります。サーバーがない場合は「アップロードするにはImmichサーバーに接続してください」と表示されます。デバイスの写真と動画も、ライブラリタブから同じ方法で送信できます：デバイス上の項目、アルバム、選択、「Immichにアップロード」。バックアップ対象に選んでいないアルバムのものも送信でき、送信後はバックアップ済みとして数えられます。

### ダウンロードせずに再生する仕組み

プレーヤーは、アプリ内部のブリッジ（ループバックアドレスのみ、セッションごとのランダムなトークン、バイト範囲指定）を通して必要なバイトだけを読み込むため、動画のシークが使え、デバイスには何もコピーされません。プレーヤーとヘッドセットのビューアーが共有のアドレスを受け取ることはなく、ブリッジの 127.0.0.1 だけを受け取ります。サーバーへのリクエストはアプリ自身が行います。

滑らかに再生するため、共有は大きなブロック単位で読み込まれ、ファイルは読み込みの合間も開いたままになり、プレーヤーの先を最大 16 MB 先読みし、再生中の動画は、サムネイルや一覧に使う接続とは別に、最大 6 本の SMB 接続で並行して読み込まれます。Freebox Server は読み込みごとの応答が遅く、1 本の接続では 4.5 MB/s ですが、6 本なら 19 MB/s となり、132 Mbit/s の 5.7K 書き出しに十分です。

データを待っている間、360° プレーヤーと Spatial プレーヤーには「読み込み中」と再生バッファーの充填率が表示され、平面のプレーヤーでは動画の読み込み中や途切れたときに、割合なしで「読み込み中」と表示されます。

### DLNA メディアサーバー

ビルド 19 から、アプリはメディアサーバーの SSDP 検索をネットワークのマルチキャストグループに送り、同じリクエストをローカルの /24 ネットワークのすべてのアドレスのポート 1900 に送ります。その後、応答した各サーバーのデバイス記述を読み、コンテンツを公開しているもの（ContentDirectory）を残します。

フォルダーとファイルはサーバーの Browse アクションでページごとに一覧表示され、タイトルで名前が付けられます：タイトルに拡張子がないファイルにはその種類の拡張子が付き、同じフォルダーに同じタイトルのファイルが 2 つあれば 2 つ目は `name (2)` になります。音声ファイルは除外されます。サムネイルはアルバムアートまたはサーバーが作る小さな画像で、アプリ自身が読み込みます。サーバーにない場合はアプリ独自のサムネイルを使います。ファイルは、サーバーがオリジナルと変換済みコピーの両方を提供している場合はオリジナルから、範囲リクエストで読み込んで再生するので、シークが使えます。

minidlna と Gerbera で確認済みです。実際のネットワークでの検出、Plex、Jellyfin、NAS、Freebox Server、iPhone、Quest は、ビルド 19 の実機テストの対象です。

<a id="a-share-that-moved"></a>
### 移動した共有

ビルド 19 から、DLNA の共有と電話の共有（[この電話をネットワークで共有](#share-this-phone-on-the-network) を参照）は、サーバーが通知する ID を保持します。共有がそのアドレスで応答しなくなった場合（ルーターが新しいアドレスを割り当てた、サーバーが別のポートで再起動したなど）、フォルダーの画面に「ネットワーク上で (名前) を探しています」と表示され、現在応答している場所へ共有を移します。パスワードのない DLNA サーバーではすぐに移し、ユーザー名とパスワードのある共有では、それらが新しいアドレスに送られるため、両方のアドレスを示した確認「新しいアドレスを使用しますか？」の後に移します。

ビルド 20 からは、ネットワーク上の別のアドレスで再び見つかった Plex サーバーもすぐに移します：トークンを送る前に、証明書によって同じサーバーであることを確認します。Tapo カメラは、カメラの画面から MAC アドレスで探します。[Tapo カメラ](#tapo-cameras-live-view-and-the-recordings-of-the-memory-card) を参照してください。

### 制限

- **SMB**：SMB 2 と 3 のみで、SMB 1 には対応していません。
- **WebDAV**：Basic 認証のみ（Digest にはまだ対応していません）。自己署名の HTTPS 証明書はデバイスにインストールする必要があります。
- **サーバーの検出**：ネットワークのスキャンと DLNA、Plex、Tapo の検索はローカルの /24 ネットワークのみを対象とし、iOS ではローカルネットワークの許可が必要です。iPhone と iPad では、Apple がアプリにマルチキャストのエンタイトルメントを付与するまで、DLNA 検索はユニキャストのリクエストのみを送り、それに応答しないサーバーもあります（Linux 上の minidlna）。その場合は説明のアドレスで追加してください。
- **DLNA**：変換済みコピーしか提供しないサーバーからは、そのコピーが届きます。1 つのフォルダーに一覧表示されるのは最大 20,000 項目です。
- **サムネイル**：写真のサムネイルはファイル全体をデコードするため、30 MB を超える写真にはサムネイルが付きません。
- **プレーヤー**：平面のプレーヤーではまだ音声トラックを選べません。スマートフォンでは、フォルダー内のファイルから次のファイルへのスワイプはまだできません（Quest のイマーシブビューでは、フォルダー内の 360° ファイルの前へと次へが使えます）。ネットワーク上のファイルで選んだ 3D や 180° の設定は記憶されません。
- **アップロード**：アプリを開いている間だけ行われます。サーバーにすでにあるファイルも、サーバーが重複と報告するまでは全体が送信されます。

<a id="plex-media-server-without-plextv"></a>
## Plex Media Server、plex.tv なしで

動画は Plex にあり、Plex のフォーラムの要望（2017 年から未対応のものもあります）にあるように、Plex では 360° の写真と動画が平面で表示されます。そのライブラリをヘッドセットでも、テレビでも、外出先でも見たいはずです。Immich アプリが読むのは Immich サーバーだけで、ビルド 19 の DLNA の種類で届くのは自宅にいるときの Plex の DLNA 側だけです。

ビルド 20 から、Immuch360 は plex.tv を使わずに Plex Media Server と直接ペアリングします：ネットワーク上でサーバーを見つけ、トークンを一度貼り付けるだけで、アプリはライブラリの元のファイルをそのまま読み込み、アプリのすべてのビューアー（360°、3D、VR180、Spatial 2.5D、Quest のイマーシブビュー、テレビのリモコン操作）で再生します。自宅でも、ポート転送を通して外出先でも使えます。何もコピーせず、選んだファイルは Immich に送信できます。

### Plex サーバーを追加する

1. ライブラリタブを開き、ネットワーク共有、+、「Plex Media Server」の順に選びます。共有のフォームの種類「Plex Media Server」や、「ネットワーク上で見つかったサーバー」にある Plex タグ付きのサーバーからも、同じ画面が開きます。
2. 「Plex サーバーを追加」画面はネットワーク上の Plex サーバーを探し（「ネットワーク上の Plex サーバーを探しています」）、「ネットワーク上で見つかったサーバー」の下に一覧表示します。自分のサーバーをタップすると、名前、Plex のバージョン、短い ID がカードに表示されます。
3. 一覧にない場合は、「サーバーのアドレス」に `192.168.1.20`、`192.168.1.20:32400`、`https://...plex.direct:32400` のように入力し、「検索」をタップします。アプリはサーバーの証明書を読み取るだけで、他には何も送りません。
4. コンピューターでトークンを入手します：ウェブブラウザーで Plex を開いてサインインし、ライブラリの任意の写真か動画を開いて、「...」、「Get Info」、「View XML」の順に選びます。`X-Plex-Token=...` で終わるアドレスで新しいタブが開きます。そのアドレス全体をコピーします。
5. それを「アクセストークン」に貼り付けるか、スマートフォンに送って「クリップボードから貼り付け」をタップします：アプリはそこからサーバーとトークンを取り出します。`X-Plex-Token=` の後の文字列だけでも使えます。画面の「入手方法」にも同じ説明があります。サーバーの管理者は、サーバーの `Preferences.xml` ファイルにある `PlexOnlineToken` の値も使えます。こちらは期限切れになりません。テレビでは OK でキーボードのダイアログが開くので、そこにトークンを入力します（通常 20 文字です）。
6. 「接続をテスト」をタップします。「接続済み: N 個のライブラリ」と表示されるか、「Plex サーバーがこのトークンを拒否しました。」のように問題点が示されます。
7. 続いて「自宅外からのアクセス」に、サーバーが伝える内容が表示されます：「サーバーは (アドレス):(ポート) で接続できると伝えています。」または「サーバーは自宅外のアドレスを伝えませんでした。」外出先からサーバーを使うには、公開アドレスか DynDNS の名前を「自宅外のアドレス (IP または名前)」に、Plex（設定、リモートアクセス）で転送したポートを「自宅外のポート」に入力します。入力した値は、サーバーが伝える内容より常に優先されます。
8. 「名前」は変更しない限りサーバーの名前になり、「開始フォルダー（任意）」で 1 つのライブラリを直接開くこともできます。保存をタップします。サーバーは共有と一緒に、`plex://` とアドレスで一覧に表示されます。

### Plex のライブラリを参照する

1. ネットワーク共有でサーバーをタップします。最初の階層には、アプリが表示するライブラリ（写真、映画とその他の動画、テレビ番組）が並びます。音楽は表示しません。
2. ライブラリの下には、サーバーのディスク上と同じフォルダー（Plex の「フォルダー別」表示）が並び、その後に写真と動画がファイル名で、Plex が作成したサムネイル付きで並びます。フォルダー表示が応答しない写真ライブラリでは、代わりにアルバムを表示します。
3. 360° と 3D は、どの共有とも同じくファイル自体を読んで判別します：360° の写真には 360° のバッジ、Apple の空間写真には 3D のバッジが付きます。
4. 写真や動画は、どの共有とも同じように開けます：360°、3D、360°/180°、スマートフォンでの Spatial 2.5D、Quest のイマーシブビュー、テレビのリモコン操作。動画は元のファイルとして、アプリのローカルブリッジを通したバイト範囲指定で読み込むため、シークが使え、360° と 3D のメタデータがそのままプレーヤーに届きます。
5. ファイルを選んで「Immichにアップロード」をタップすると、どの共有からとも同じようにサーバーに送信できます（[共有のファイルを Immich に送信する](#send-files-of-a-share-to-immich) を参照）。

### 外出先から

サーバーを開くたびに、アプリはまず自宅のアドレスを試し、400 ms 後に自宅外のアドレスを試します。最初にあなたのサーバーとして応答したものを使います。それが自宅外のアドレスの場合、フォルダーの画面に「自宅外のアドレスで接続中」というラベルの地球のアイコンが表示されます。

これには、Plex でリモートアクセス（設定、リモートアクセス）をオンにし、ルーターでポートを転送しておく必要があります：plex.tv を使わないため、アプリは Plex のリレーを使えません。ポート転送のないサーバーは自宅でしか開けず、外出先では画面に「Plex サーバーには自宅のネットワーク外から接続できません。Plex でポート転送を使ったリモートアクセスをオンにするか (設定、リモートアクセス)、公開アドレスを入力してください。」と表示されます。

サーバーが伝えるアドレスは、自宅で接続するたびに改めて取得します。それが外から応答しない場合（アドレスが変わるルーター、ルーターの二重構成など）は、サーバーの画面で自分のアドレスを入力してください。トークンが使えなくなった場合（たとえば、コピー元のブラウザーセッションからサインアウトした場合）は、フォルダーの画面にその旨が表示され、「新しいトークンを貼り付け」が提示されます。これを選ぶと、サーバーの画面がトークンの欄で開きます。

### Plex や DLNA の種類との比較

- **元のファイル**：アプリが読むのはファイルそのもので、Plex が変換したコピーではありません。そのため 360°、3D、VR180 のメタデータがそのまま残り、アプリのビューアーがそれを使います。Plex のアプリでは、これらのファイルは平面で表示されます。
- **plex.tv なし**：アプリが通信するのはあなたのサーバーだけで、常に HTTPS を使います。トークンを送る前に、サーバーの ID に結び付いたサーバー自身の plex.direct 証明書でサーバーを確認します。トークンはデバイスの安全なストレージに保存され、リクエストヘッダーであなたのサーバーにだけ送られます。
- **同じサーバーを DLNA として追加する場合との比較**：ディスク上と同じフォルダー、Plex のサムネイル、自宅外からのアクセス、安全な接続。

### 制限

- **登録済みのサーバーのみ**：サーバーは Plex で登録（一度 Plex アカウントにサインイン）されている必要があり、それによって plex.direct 証明書が発行されます。登録されていない場合、画面に「このアドレスは Plex の証明書なしで応答しています。Plex でサーバーを登録するか、SMB、WebDAV、DLNA の共有として追加してください。」と表示されます。
- **IPv4 のみ**：「IPv6 アドレスにはまだ対応していません。サーバーの IPv4 アドレスを入力してください。」
- **トークン**は Plex サーバーへの完全なアクセス権を与えます。アプリでサーバーを削除すると、デバイス上のトークンは消えますが、無効化はされません：「トークンは、コピー元のブラウザーセッションからサインアウトするまでサーバー上で有効なままです。」有効期限のあるトークンではその日付が表示され、アプリはトークンを更新できません。
- **外出先から**：ポート転送経由のみで、リレーはありません。
- **ライブラリ**：音楽は表示されず、1 つのフォルダーに表示されるのは最大 20,000 項目で、制限付きのユーザーには「このトークンではサーバーのライブラリを読み取れません。」と表示されることがあります。
- **カメラの RAW 360° ファイル**（.insv、.insp、.360、.osv）は Plex が一覧に含める場合にのみ表示されます。含まれない場合は、同じ NAS のフォルダーを SMB または WebDAV の共有として追加してください。[カメラの RAW 360° ファイル](#raw-360-camera-files-without-the-cameras-app) を参照してください。
- **サーバーの検出**：「Enable local network discovery (GDM)」の設定がオフのサーバーは見つからないため、アドレスを入力してください。iPhone と iPad では、検索はユニキャストのリクエストのみを送ります。同じサーバーの DLNA 側も DLNA タグ付きで一覧に表示されることがあります：Plex タグの付いた行を選んでください。
- **デバイスではまだ確認していません**：ペアリング、フォルダー、動画のバイト範囲指定、サムネイル、誤ったトークン、自宅外のアドレスは、コンピューターから実際の Plex Media Server 1.42.1 を相手に確認し、写真とテレビ番組のライブラリはシミュレーションしたサーバーでのみ確認しました。スマートフォン、Quest、iPhone、テレビでの再生と、自宅外のアドレスへの切り替えは、ビルド 20 のデバイステストです。
- Immuch360 は Plex とは提携していません。

<a id="share-this-phone-on-the-network"></a>
## この電話をネットワークで共有

写真と動画はスマートフォンにあり、パソコンも NAS も Immich サーバーも使わずにヘッドセットで見たい。ビルド 19 から、Android または iPhone のスマートフォンが自分の写真と動画を Wi-Fi で配信し、Meta Quest がそれを再生します。Immich アプリにはこのような機能はありません。

### スマートフォンでオンにする

1. ライブラリタブを開き、ネットワーク共有を開きます。最初のタイルが「この電話をネットワークで共有」です（「オフ」、またはアドレス付きの「オン」と表示されます）。
2. それをタップし、「Wi-Fi で写真とビデオを共有」をオンにします。写真と動画の許可がない場合はアプリが求め、Android 13 以降では通知の許可も求めます。
3. 画面には、アドレス（`http://192.168.1.20:8360` など：ポート 8360、使用中の場合は別の空きポート）、スマートフォンが通知される名前（「Immuch360 on」の後にスマートフォンの名前）、ユーザー名（`phone` と 4 桁の数字）、パスワード（8 文字）がそれぞれコピーボタン付きで表示され、続いて「N 台のデバイスが接続中」（直近 1 分間に使ったデバイス）と最後に配信したファイルが表示されます。

ユーザー名とパスワードは一度作られると保持されるので、ヘッドセットは保存した共有をそのまま使えます。「新しいパスワード」でパスワードを置き換えます。このタイルはヘッドセットには表示されません。

### ヘッドセットで開く

1. ヘッドセットで、ライブラリ、ネットワーク共有、+ の順に開きます。
2. 「ネットワーク上で見つかったサーバー」の下のスマートフォンをタップすると、ユーザー名が入力されます。
3. パスワードを一度入力し（スペースや大文字小文字は区別されません）、保存します。

あとは他の WebDAV 共有と同じです：360° の検出、RAW ファイル、イマーシブビュー、動画のシーク。ネットワーク上のどの WebDAV クライアントからも読めます。スマートフォンのアドレスが変わると、ヘッドセットはそれを探し、新しいアドレスを使う前に確認します（[移動した共有](#a-share-that-moved) を参照）。

### 配信する内容と期間

- **フォルダー**（読み取り専用）：`Albums`（スマートフォンの各アルバム）、`By month`（すべての写真と動画を月別に、新しい順）、`360`（アプリがスマートフォンで見つけた 360° の写真と動画。RAW ファイルや 360° として表示しているものも含む）。ファイルは元の名前のままです。iPhone では、Live Photos は静止画、編集した写真や動画は編集後のバージョンになり、iCloud にだけ保存されているものは除外されます。
- **Android**：共有は通知（アドレスとユーザー名）と停止ボタン付きのフォアグラウンドサービスで動作し、Wi-Fi とプロセッサーを起動したままにするので、画面がオフでも続きます。アプリをスワイプして閉じると停止します。
- **iPhone と iPad**：iOS はサーバーにバックグラウンドの実行時間を与えないため、共有はアプリが前面にある間だけ動作し、その間は画面がオンのままになります。アプリがバックグラウンドに移ると一時停止し、戻ると同じアドレスとパスワードで再開します。
- **停止するとき**：スイッチを切ったとき、停止を押したとき、リクエストが 60 分間ないとき、アプリを閉じたときです。自動で始まることはなく、アプリを起動するたびにオフになっています。
- **セキュリティ**：ローカルネットワークのみです。共有はスマートフォンの Wi-Fi、イーサネット、テザリングのアドレスでのみ待ち受け、モバイルデータや VPN のアドレスでは待ち受けず、ローカルアドレスのデバイスにだけ応答します。すべてのリクエストにユーザー名とパスワードが必要です（HTTP Basic）。1 台のデバイスから 1 分以内に 10 回パスワードを間違えると、そのデバイスは 1 分間ブロックされます。パスワードは Wi-Fi 上を暗号化されずに流れます（平文の HTTP）。信頼できるネットワークで使い、終わったらオフにしてください。
- **スマートフォン自身のテザリング**：ヘッドセットも接続できます。そこでスマートフォンが見つからない場合は、画面に表示されたアドレスを入力してください。
- **まだ実機で確認していません**：サーバーは、ユニットテストと、ヘッドセット自身の WebDAV クライアントとメディアブリッジを使ったエンドツーエンドテストで、パソコン上で確認しました。Quest 3 に配信するスマートフォン（検出、4 GB の動画の再生とシーク、画面オフで 30 分、テザリング、通知からの停止）と、まだ iPhone で動かしていない iPhone 側は、ビルド 19 の実機テストの対象です。

<a id="tapo-cameras-live-view-and-the-recordings-of-the-memory-card"></a>
## Tapo カメラ：ライブ映像とメモリーカードの録画

自宅に Tapo カメラがあり、Tapo アプリを開かずに庭のカメラや昨夜のクリップを写真と並べて見て、クリップを Immich に残したい。Immich アプリにはカメラ向けの機能がなく、Tapo アプリは TP-Link アカウントにサインインする別のアプリで、クリップは写真とは別の場所にあります。

ビルド 20 から、Immuch360 はネットワーク共有と並べて Tapo カメラを追加できます。Android のスマートフォンとタブレット、Android TV、Meta Quest ではカメラのライブ映像を表示し、すべてのプラットフォームでメモリーカードの録画を日ごとに表示します：クリップはカメラから取得され、他の動画と同じように再生でき、Immich に送信できます。アプリはあなたのネットワーク内でだけカメラと通信し、TP-Link のサーバーとは通信せず、カメラの設定を変えることもありません。

### カメラを追加する

1. まず Tapo アプリで：カメラの設定の「高度な設定」、「カメラアカウント」でカメラアカウント（このカメラ用のユーザー名とパスワードで、ライブ映像に使います）を作成し、「自分」、「Tapo Lab」でサードパーティ互換をオンにします。
2. Immuch360 でライブラリタブを開き、ネットワーク共有、+、「Tapo カメラ」の順に選びます。
3. 「カメラを追加」画面はカメラを探し（「ネットワーク上の Tapo カメラを探しています」）、「ネットワーク上で見つかったサーバー」の下に Tapo タグ付きで一覧表示します。自分のカメラをタップして「カメラのアドレス」を入力するか、アドレスを手で入力します。共有のフォームで Tapo タグ付きのカメラを選んでも、同じ画面が開きます。
4. 「名前」：一覧に表示されるカメラの名前です。
5. 「メモリーカード上の録画」の下の「TP-Link アカウントのパスワード」：Tapo アプリで使っているアカウントのパスワードです。これで録画を開けます。メールアドレスは不要です。
6. 「ライブ」の下の「カメラアカウントのユーザー名」と「カメラアカウントのパスワード」：手順 1 のカメラアカウントです。
7. どちらか一方だけでもかまいません（「TP-Link アカウントのパスワード、カメラアカウント、またはその両方を入力してください。」）：TP-Link のパスワードだけなら録画、カメラアカウントだけならライブ映像が使えます。
8. 「カメラをテスト」をタップします。メモリーカードの状態とともに「録画: (モデル)、ファームウェア (バージョン)」と「ライブ映像: (映像)、音声 (音声)」が表示されるか、それぞれで失敗した内容が表示されます。
9. 保存をタップします。カメラは共有の後の「カメラ」の下に、判明したモデルと、`tapo://` とアドレスで表示されます。

### ライブで見る

1. カメラをタップします。ライブ映像は画面の上部にあります：「カメラに接続中」の後、ライブのバッジ付きで映像が表示されます。
2. 映像上のボタン：音声（最初はオフ。「音声をオン」、デバイスで再生できない場合は「このデバイスでは音声がありません」）、SD または HD、「全画面表示」。
3. スマートフォンでは画面内で SD、全画面で HD を表示し、Quest では HD を表示します。戻るを押すと、まず全画面表示を終了します。
4. 映像の下には、モデルとファームウェア、そして「メモリーカード: (合計) 中 (使用量) 使用」や「メモリーカードなし」のようなメモリーカードの情報が表示されます。

iPhone と iPad では、ライブ映像の場所に「ライブ映像は今後のバージョンで iPhone と iPad に対応します。録画はすでにここで再生できます。」と表示されます。カメラアカウントがない場合、画面に「ライブ映像を見るにはカメラアカウントを追加してください。」と表示されます。

### 録画を再生して残す

1. カメラの画面の「メモリーカード上の録画」の下に、録画のある日が新しい順に月ごとに並びます。TP-Link アカウントのパスワードがない場合は「録画を見るには TP-Link アカウントのパスワードを追加してください。」と表示されます。
2. 日付をタップします。その日のクリップがカメラ自身の時刻で時間ごとに並び、それぞれに開始時刻、長さ、イベントの場合はカメラのサムネイル、種類（動き、人物、ペット、車両、赤ちゃんの泣き声、動物、常時録画、イベント）が表示されます。
3. クリップをタップします。アプリはカメラからクリップを取得し（「カメラから動画を取得中: N%」、キャンセル可能）、音声とシーク付きで動画プレーヤーで再生します。取得済みのクリップには「このデバイス上」と表示され、次回からはすぐに開きます。
4. クリップを Immich に残すには、サーバーに接続した状態で、動画の ⋮ メニューから「Immichにアップロード」を選びます。
5. 空き容量を増やすには：取得済みのクリップを長押しすると「このデバイス上のコピーを削除」が表示され（スマートフォン）、カメラの画面には容量とともに「このカメラから取得した動画を削除」があります。
6. 右上の更新ボタンを押すか、画面を下に引くと、カメラに再度問い合わせます。

カメラがそのアドレスで応答しなくなった場合、カメラの画面はネットワーク上で MAC アドレスによってカメラを探し、同じ証明書を示した時点で、現在応答している場所へ移します。アプリが最初に見た証明書と異なる証明書を示すカメラについては、代わりに確認が表示されます：「(アドレス) のカメラが以前と異なる証明書を示しています。リセットまたは交換した場合のみ続行してください。」

### Tapo アプリとの比較

- **自宅のネットワーク内だけ**：アプリはローカルネットワーク上でカメラ自体と通信し、TP-Link のサーバーとは一切通信しません。TP-Link アカウントにサインインしないため、メールアドレスは不要です。
- **録画が通常の動画になる**：取得したクリップは音声付きの H.264 動画で、Immich に送信でき、メモリーカードが上書きした後も Immich に残ります。
- **他のものと並べて**：Immich サーバーの有無にかかわらず、スマートフォン、テレビ、Quest（ウィンドウ内）で使え、共有と同じようにネットワーク上で見つかります。
- **読み取り専用**：アプリがカメラに求めるのは表示する内容だけです。設定を変えることも、カメラ上のものを削除することもありません。

### 制限

- **デバイスではまだ確認していません**：ビルド 20 はまだ実際のカメラで動かしていません。プロトコルはファームウェア 1.3.4 の C510W をキャプチャした内容（2026 年半ばの V4 ログイン）を基に作成し、アプリはテストの中でシミュレーションしたカメラを相手に確認しました。「カメラをテスト」が示すモデルとファームウェア、そして [ログ](#logs) の行を添えたご報告を歓迎します。
- **ライブ映像**：Android のスマートフォンとタブレット、Android TV、Quest のみで、iPhone と iPad にはまだ対応していません。TP-Link の制限が適用されます：Tapo アプリを含め、1 台のカメラにつき同時に最大で HD 2 本と SD 2 本のストリームまでで、Tapo Care、メモリーカード、RTSP または ONVIF を使う録画機器をすべて同時に動かすことはできません。
- **カメラ**：バッテリー式のカメラと Tapo ハブ経由のカメラには対応していません。
- **録画**：ダウンロードは 1 台のカメラにつき一度に 1 つです。Tapo アプリがメモリーカードを参照している間は、アプリは 4 秒、8 秒、12 秒後に再試行し、その後「カメラは Tapo アプリなど別の視聴者が使用中です。1 分後にもう一度お試しください。」と表示します。H.265 の録画はまだ変換できず（「この録画は H.265 で、このバージョンではまだ変換できません。」）、常時録画にはサムネイルがなく、クリップは完全に取得してから再生されます。
- **パスワード**：誤ったパスワードは毎回数えられ、何度か続くとカメラはしばらくロックされます（「誤ったパスワードが多すぎたため、カメラがロックされています。N 分後にもう一度お試しください。」）。アプリが拒否されたパスワードを自動で再試行することはありません：カメラに再度問い合わせるのは「カメラをテスト」か再試行だけです。カメラが設定用のパスワードは受け付けるのに動画用には受け付けない場合は、Tapo アプリでサードパーティ互換をオフにしてから再度オンにし、カメラを再起動してください。
- **容量**：取得したクリップはアプリのキャッシュに残り、すべてのカメラを合わせて最大 1 GB です（最後に再生したのが最も古いものから削除されます）。システムがそのキャッシュを消去することがあり、カメラを削除するとそのクリップも削除されます。
- **外出先から**：アプリはあなたのネットワーク上のアドレスでカメラに接続するため、ネットワークの外からは使えません。
- Immuch360 は TP-Link とは提携していません。

<a id="raw-360-camera-files-without-the-cameras-app"></a>
## カメラの RAW 360° ファイルを、カメラのアプリなしで

Insta360 のカメラは、レンズの 2 つの魚眼の円を、1 枚の画像に左右に並べて、または 2 つのトラックや 2 つのファイルに記録します（.insp は JPEG、.insv は MP4）。そこから 360° 画像を得る公式の方法は、Insta360 アプリまたは Studio です。X4、X5、X6、GoPro MAX、DJI Osmo 360 を持っている人は、カードに入った RAW ファイルをどうすればよいか尋ねています。Immich のウェブアプリは、どの .insp も正距円筒図法の画像として扱い、2 つの円を球体に巻き付けてしまいます。モバイルアプリでは平面で表示されます。

ビルド 16 から、Immuch360 はこれらのファイルを、スマートフォン、タブレット、ヘッドセット上で自らスティッチします。サーバーに何かをインストールする必要はありません：

- **Insta360 の .insp 写真**（ビルド 16）：球体ビューアーの前に GPU でスティッチ、最大 8192x4096、より小さいサイズでの CPU フォールバックあり。
- **両方のレンズを 1 つのトラックに収めた Insta360 の .insv 動画**（ビルド 16）：プレーヤー内の GPU エフェクトでスティッチ。
- **Insta360 X4、X4 Air、X5、X6 の .insv 動画、レンズごとに正方形のトラック 1 つ**（ビルド 18）：レンズごとに 1 つ、2 つのデコーダーを同時に使い、GPU コンポジターで球体にスティッチ。
- **5.7K 以上の Insta360 X3 以前の機種：`_00_` と `_10_` の 2 つのファイル**（ビルド 18）：同上、もう一方のファイルは最初のファイルの隣から探す。
- **GoPro MAX と MAX 2 の .360：それぞれキューブの 3 面を持つ 2 つのトラック**（ビルド 18）：同上、重なる列をブレンド。
- **DJI Osmo 360 の .osv：正方形の 10 ビットのトラック 2 つ**（ビルド 18）：同上、ファイルの Kannala-Brandt キャリブレーションを使用。
- **デュアル魚眼の .dng**（未対応）：平面で表示。

### RAW ファイルを見る

1. RAW ファイルをアプリが読める場所に置きます：デバイス本体のギャラリー（カメラのカードからコピー）、Immich サーバー（.insp と .insv は受け付け、.360 と .osv は拒否）、SMB または WebDAV の共有、そしてビルド 19 からは電話の共有と、これらのファイルを一覧表示する DLNA サーバー（まだ確認していません）。
2. X3 のペアの 2 つのファイルは一緒に置いておきます：アプリは、デバイス、サーバー、共有フォルダーのいずれでも、最初のファイルの隣でもう一方のファイルを探します。もう一方がない場合、アプリは「この記録はレンズごとに1つずつ、2つのファイルに分かれていますが、隣に(名前)が見つかりませんでした」と表示し、2 つのファイルを一緒に置くか、カメラのアプリから動画を書き出すよう案内します。
3. ファイルを開き、360° をタップします。RAW ファイルには 360° ボタンが、RAW 写真には 360° バッジが付きます。ビルド 18 からは、サーバー上の Insta360 の RAW ファイルも名前で見つけられ、360° リストに入ります。
4. 写真は球体ビューアーで開き、下部にラベルが表示されます：「RAW 360°ファイル、アプリでスティッチ」と、キャリブレーションの出どころ：「ファイルから読み込んだレンズキャリブレーション」、「同じカメラのレンズキャリブレーション」（同じカメラの別のファイルから、シリアル番号で、またはモデル名しか記録されていないファイルではモデルで保持したもの）、または「公称レンズ値、継ぎ目が見える場合あり」（より良い値がないときの X3 の値）です。
5. 動画はネイティブの 360° プレーヤーで開き、再生しながらスティッチされます。RAW 動画は 1 つの全天球なので、3D と 360°/180° のボタンは非表示です。動画プレーヤーとヘッドセットにはラベルは表示されません。
6. ヘッドセットでは、イマーシブビューは写真にはスティッチ済みの一時画像を、動画にはスマートフォンと同じ GPU エフェクトを使います。RAW 写真の準備中の進行状況インジケーターはまだありません。
7. 画像が変な方向を向いて開いた場合（たとえばカメラを平らに置いて撮った写真）、スマートフォンではドラッグし、ヘッドセットでは右スティックまたは回転ボタンで回してください。

### デバイスが両方のレンズを再生できない場合

2 つのレンズの動画を再生する前に、アプリはそのサイズとフレームレートのデコーダーを 2 つ動かせるかをデバイスに問い合わせます。できない場合、スマートフォンでは「このRAW動画には(サイズ)のビデオデコーダーが同時に2つ必要です。このデバイスではスムーズに再生されない可能性があります。」と警告が出ます。デコーダーが動かせない場合（たとえば Quest 3 での 2880x2880 の H.264 レンズ 2 つ）、アプリは片方のレンズだけを再生してその旨を表示し、球体の半分は黒いままになります。その後、変換済みストリームがあればサーバーのそれを使います。デバイスで GPU エフェクトが動かない場合、動画はスティッチされずに、2 つの円が球体に載った状態で再生され、「このデバイスでは360°のスティッチに失敗しました」と表示されます。

ビルド 19 から、Android と Quest では：

- **コーデックのハードウェアデコーダーがない**場合（エミュレーター、TV ボックス）：ソフトウェアデコーダーを使い、2 つ同時に動かすときはチェックによりレンズごとに 2048x2048 までに制限されます。
- **デバイスがまったくデコードできないレンズ**（そのコーデックのデコーダーがない、またはそのプロファイルを持つデコーダーがない）は、片方のレンズの段階を飛ばし、サーバーの変換済みストリーム、なければスティッチしていないオリジナルを通常のプレーヤーで、そのプレーヤー自身のメッセージとともに再生します。
- **サイズやフレームレートが拒否されたのに試したレンズ**は、最初のフレームが描画されてから片方のレンズのメッセージを表示します。
- **片方のレンズのデコーダーが失敗し**、変換済みストリームがない場合、動画はエラーで止まらずにスティッチなしで再生されます。
- **Android エミュレーター**で、反対側のレンズのフレームが一瞬映り込むことはなくなりました（各レンズのテクスチャを毎フレーム外部テクスチャのターゲットにバインドするようになりました）。

### スティッチの仕組み

- **アプリが読むもの**：カメラが各ファイルの末尾に付けるキャリブレーションブロック（レンズモデル、中心、各レンズの向き、キャリブレーションのキャンバスサイズ）と、地平線を水平にするための加速度センサーの記録です。キャリブレーション文字列 V3 の Mei（統一カメラ）モデルを最初に使い、次に V6（X6 と以降のファームウェア）をその最初の項とともに使い、最後に古い等距離射影の文字列 V1 を使います。ファイルにキャリブレーションがある場合、カメラのモデルから推測することはありません。Insta360 X5 と X6 のキャリブレーション（V6、インデックス付きトレーラー）と X4 の動画ウィンドウはファイルから読み込みます。
- **読み込む場所**：サーバー（オリジナルファイルの末尾のバイトを範囲リクエストで読み込み）、デバイス本体のギャラリー、そして共有です。
- **写真と動画**：写真は球体ビューアーの前に Flutter のフラグメントシェーダーでスティッチされます。動画はキャリブレーションとともにネイティブプレーヤーに渡され、Android と Quest では Media3 の GL エフェクト、iOS では SceneKit のシェーダーで処理されます。
- **2 つのトラックまたは 2 つのファイルに分かれた 2 つのレンズ**：プレーヤーは両方を同時にデコードし（レンズごとにハードウェアデコーダー 1 つ、タイムスタンプで対応付け）、GPU コンポジターで球体にスティッチします：Android と Quest では ExoPlayer と OpenGL ES 3、iOS では Metal による AVFoundation コンポジターです。10 ビットの HLG と PQ のソースは、8 ビットの球体用にトーンマッピングされます。

### 制限

- **継ぎ目**：スティッチはカメラのキャリブレーションだけを使い、継ぎ目の最適化は行わないため、カメラに近い物体には、カメラ自身のプレビューと同じように継ぎ目が見えることがあります。
- **地平線**：水平補正には、カメラがファイルに記録した加速度センサーの値の平均を使います。動画は録画の開始時点から一度だけ水平補正され、手ぶれ補正はされないので、手持ちの動画は揺れが残り、地平線が少し傾くことがあります。GoPro と DJI のファイルは水平補正されません（カメラの地平線のままです）。
- **キャリブレーションのないファイル**：キャリブレーションブロックのないファイル（X3 の HDR グループのメンバー `_008` と `_009`）は、同じカメラまたは同じモデルの別のファイルからアプリが保持したキャリブレーションを使い、何も見たことがなければ X3 の公称値を使います。
- **確認済みの内容**：写真は X3 のファイルを Insta360 Studio で書き出したものと比較しました（同じ構図、水平な地平線、ヨーのずれは 1 度未満）。シングルトラックの動画は、低解像度の X3 ファイルを使って Android エミュレーターで確認しました。2 トラックと 2 ファイルの処理は、実際の X4、X3 ペア、GoPro MAX、Osmo 360 のファイルで、アプリの CPU による参照スティッチャー（水平、連続した継ぎ目）と Android のユニットテストで確認しました。スマートフォン、Quest、iPhone での再生はまだビルド 18 と 19 の実機テストの対象で、RAW ファイルはまだ iPhone で動かしていません。フィードバックをお待ちしています。
- **サーバー上**：Immich サーバーは .360 と .osv のアップロードを拒否するため、この 2 つの形式はデバイスと共有にしか存在しません。

<a id="3d-and-vr180-photos-and-videos"></a>
## 3D と VR180 の写真と動画

Immich アプリでは、ステレオの 360° 写真や動画は両目の画像が同時に表示されて二重に見え、前方の半分しかカバーしない VR180 のファイルは球体の全周に引き伸ばされます。

Immuch360 は、上下または左右の 3D レイアウトをファイル（動画の st3d ボックス）から認識するか、フレームの形から推測します。どのビューアーにも、それを変更する 3D ボタンがあります。スマートフォンは左目を表示し、Meta Quest はそれぞれの目にそれぞれの半分を表示して本物の 3D になります。VR180 のファイルは半球に描画され、背面は引き伸ばされた画像ではなく黒になります。VR180 はファイル（球面の範囲やメッシュ、GPano の切り抜き）から、または名前に含まれる「vr180」や「180」から認識され、どのビューアーにも 360°/180° ボタンがあります。

### レイアウトや範囲を変更する

1. 写真または動画を球体で開きます（360° ボタン）。
2. 3D ボタンは「モノ (3D ではない)」、「3D、上下」、「3D、左右」を順に切り替えます。ツールチップには現在のレイアウトが表示されます。
3. 360°/180° ボタンは「360°、全天球」と「180°、半天球 (VR180)」を切り替えます。部分的なパノラマでは表示されません。
4. ヘッドセットでは、同じ 2 つのボタンがイマーシブビューの情報パネルにあります。

360°/180° の選択は、ライブラリのメディアについてはデバイスに記憶されますが、ネットワーク共有のファイルについてはまだ記憶されません。3D の選択はビューアーを閉じると記憶されず、次回はファイルが宣言しているレイアウト、または推測したレイアウトが再び適用されます（下の Spatial 2.5D プレーヤーは独自に記憶します）。

Galaxy S24+ と Quest 3 で、実際の 3D 360° のサンプル動画（VRTogether、Vuze、Kandao）と 3D 写真を使って確認しました。VR180 は Android エミュレーターと Galaxy S24+ で、合成したメディアを使って確認しました。他のカメラでの報告をお待ちしています。

<a id="depth-on-a-flat-screen-spatial-25d-experimental"></a>
## 平面の画面に奥行きを：Spatial 2.5D（試験運用）

ステレオ動画は、平面の画面でも奥行きを持たせることができます。動画の両目の画像から奥行きを求め、前面カメラが頭の動きを追い、アプリがその間の視点を合成するので、画面が景色をのぞく窓のように振る舞います：頭を動かすと、近くの物体が背景に対してずれて見えます。スマートフォンとタブレットのみです。

### 使い方

1. オンになっているか確認します：設定、アセットビューアー、動画、「Spatial 2.5D (試験運用)」。初期設定ではオンで、オフにするとすべての場所から Spatial ボタンが消えます。
2. 動画を開きます。設定がオンの間は、上部のバーのすべての動画に Spatial ボタン（回転する 3D アイコン）が表示されます。ネットワーク共有のフォルダーではステレオのファイルにだけ表示され、それ以外のファイルでは ⋮ メニューに Spatial 2.5D があります。
3. タップします。初回は前面カメラの許可が求められます。カメラはボタンを押した後にだけ使われます。
4. 右上：動画に 2 つ以上ある場合は音声トラック、現在のレイアウト（タップすると一覧：自動、ステレオではない、左右、上下、後の 2 つはそれぞれ左右の目を入れ替えたものも）、360° 動画では 360°/180°、そして現在の頭の位置を中心にする中央に戻す。
5. 下部：再生、タイムライン、頭を追跡している間は頭の動きの感度、そして視点を手動で動かす L から R までの視点スライダー。スライダーは頭の追跡がオフのとき、または顔を見失ったときに表示されます。
6. × またはシステムの戻るで閉じます。

設定、詳細設定、トラブルシューティングがオンの場合、プレーヤーは左上にオーバーレイ（描画と視差の更新レート、品質段階、視点、追跡の状態）を追加し、視点スライダーを常に表示し、画像の代わりに推定した奥行きを表示する「Disparity map」（視差マップ）チェックボックスを追加します。

### 形式、プライバシー、制限

- **形式**：左右と上下、左右の目を入れ替えたもの、フル幅とハーフ幅、平面、360°、VR180 に対応します。レイアウトはファイルから読み込み、なければフレームの形やファイル名（sbs、ou、tb など。ハーフ幅のファイルは名前でしか認識されません）から推測し、プレーヤーで手動で選ぶこともできます。この選択はライブラリの動画については記憶されますが、ネットワーク共有のファイルについては記憶されません。
- **カメラ**：画像はデバイス上でのみ処理され、保存されることも、どこかに送信されることもありません。Quest 用のビルドにはカメラの許可がまったくなく（ヘッドセットにはアプリが使えるカメラがありません）、Spatial プレーヤーも提供されません：そのボタンと設定はヘッドセットでは非表示です。
- **制限**：試験運用で、スマートフォンとタブレットのみ（Meta Quest では使えません）、OpenGL ES 3.0 または Metal が必要です。奥行きは推定値です。横向きで、顔が明るく照らされているときに最もよく動作します。Galaxy S24+ で確認しました。iPhone でのフィードバックをお待ちしています。
- **フォールバック**：何か問題が起きた場合（カメラがない、対応していないデバイス、読み取れないレイアウト）、通常のプレーヤーに戻ります。

<a id="apple-spatial-photos-and-videos"></a>
## Apple の空間写真と空間ビデオ

iPhone は空間写真と空間ビデオを撮影できますが、Immich サーバーはそれについて何も伝えないため、Immich アプリでは平面の写真や動画になります。ビルド 19 から、Immuch360 はファイルを読んでそれらを認識し、Meta Quest ヘッドセットで空間写真を 3D で表示します。これは、左右や上下の動画向けである上の Spatial 2.5D プレーヤーとは別のものです。

- **空間写真**は HEIC ファイル（`.heic`、`.heif`、`.hif`）で、片目ずつ 2 枚の画像をステレオペアとしてまとめて持っています。アプリはファイルの先頭部分を読み（デバイス上、範囲リクエストによるサーバーのオリジナル、またはネットワーク共有のファイル）、結果をスマートフォンに記憶するので、写真を読むのは 1 回だけです。
- **空間ビデオ**（MV-HEVC）は動画トラックから認識されます：2 つ目のレイヤーがあり、両目が宣言されていることです。

### ヘッドセットで空間写真を 3D で見る

1. ヘッドセットで、ビューアーで空間写真を開くか、ネットワーク共有のフォルダーで開きます。フォルダーでは空間写真と空間ビデオに 3D バッジが付いています。
2. 上部のバーで「3D で表示」をタップします（共有の写真画面にもあります）。
3. イマーシブビューが開き、写真は 2 m 前方の平面のフレームに表示され、それぞれの目に専用の画像が届きます。幅は、ファイルにカメラの視野角があればそれから決まります（なければ 48°）。ファイルに書かれた視差の調整が適用されます。
4. スティックを上下に倒すと大きくまたは小さくなります（6° 刻み、30° から 90° まで）。右スティックを左右に倒すと、写真が目の前に戻ります。
5. 情報パネルの 3D ボタンで 3D と「2D (左目)」を切り替えます。回転ボタンと 360°/180° ボタンは非表示です。
6. B または Y を押して戻ります。

空間写真からの前へと次へはまだ使えません（「空間写真では前へ・次へはまだ使用できません」）。ヘッドセットが 2 つ目の目をデコードできない場合、写真は「2 つ目の目をデコードできませんでした: 2D で表示」とともに 2D で表示されます。3D 表示ではオリジナルのファイルを表示し、Immich で行った編集は反映されません。

### その他の場所では

- **写真**：スマートフォン、タブレット、ヘッドセットのウィンドウでは、これまで通り左目を表示し、技術的な詳細に 1 行が加わります。たとえば「Apple 空間写真、3072 x 3072 の 2 つのビュー」で、ファイルに視野角があればそれも表示します。サーバーの写真にはタイムラインでバッジが付きません：開いたときにアプリが判定します。
- **動画**：アプリのどのプレーヤーでも、ベースレイヤー、つまり片目を再生します。Android には 2 つ目のビューをデコードする公開された方法がありません。MV-HEVC 専用のデコーダーを持つデバイス（一部の Qualcomm チップ）には代わりに動画をそのまま渡しますが、これはまだ確認していません。セッション内でこのような動画を初めて再生すると「空間ビデオ: このデバイスでは片目のみ再生します」と表示され（ネットワーク共有の動画には代わりに 3D バッジが付きます）、技術的な詳細には「Apple 空間ビデオ (MV-HEVC)、2D で表示」と、ファイルに記録された目、基線長、視野角が表示されます。
- **デコーダー**：設定、詳細設定、「このデバイスの動画デコーダー」に MV-HEVC の項目があり、デバイスにその形式のデコーダーがあれば一覧表示し、なければないと表示します。

### まだ実機で確認していません

検出は、Apple 自身の画像ライブラリで書き出したサンプルの空間写真と合成ファイルで確認し、3D の合成はユニットテストで確認しました。ヘッドセットでの表示（両目のデコード、写真が正立して鏡像になっていないこと、奥行きの向きが正しいこと、2 m での見やすさ）と、実際の iPhone の写真と動画は、ビルド 19 の実機テストの対象です。[ログ](#logs) の行を添えて報告していただけると助かります。

<a id="in-the-meta-quest-3-headset"></a>
## Meta Quest 3 ヘッドセットで

Quest 3 を買うのは自分の 360° 写真や動画を見るためなのに、ファイルをどこに置くか、ケーブルなしでヘッドセットにどう入れるか、どのプレーヤーを使うかで迷う人がいます。ストアの 360° や 3D 動画のプレーヤーは有料です。

同じ Android アプリが、Quest 3 と 3S、ビルド 21 からは Quest 2 と Quest Pro（未テスト）でも、ライブラリ全体を持ったウィンドウとして動作します。360° ボタンでイマーシブビューが開き、写真や動画に囲まれて、頭を動かして見回せます。ステレオのファイルは本物の 3D になります（Meta Spatial SDK）。

メディアは Immich サーバー、ヘッドセット本体、NAS、メディアサーバー、スマートフォン、Plex サーバーから、その場で再生されます（メディアサーバーとスマートフォンはビルド 19 から、Plex サーバーはビルド 20 から、まだヘッドセットでは確認していません）。ビルド 20 からは、ウィンドウに Tapo カメラも表示されます。無料のオープンソースです。Quest 3 で確認済みで、Insta360 X4 の 8K HEVC 動画を使うユーザーにも確認していただきました。

### イマーシブビューを開く

1. アプリをヘッドセットにインストールします：Horizon Store の掲載が承認されるまでは、APK をサイドロードします。[インストール](#install) を参照してください。
2. Immich サーバーでログインするか、ヘッドセット本体の写真と動画を使うなら「サーバーなしで使用」をタップします。
3. タイムライン、360° リスト、アルバム、共有フォルダーから、360° の写真または動画をビューアーで開きます。
4. 360° ボタン、または ⋮ メニューの「360°で表示」を押します。ヘッドセットでは、スマートフォンの球体ビューアーではなく、直接イマーシブビューが開きます。
5. 頭を動かして見回します。
6. ウィンドウに戻るには、B または Y、または情報パネルの戻るボタンを押します。

| 操作 | コントローラー | ハンドトラッキング |
|---|---|---|
| アプリに戻る | B または Y | 戻るボタン |
| 動画の再生または一時停止 | 情報パネルが非表示のときにトリガー | 再生または一時停止ボタン |
| 情報パネルの表示・非表示 | A、X、グリップ、またはメニュー | メニューのジェスチャー、またはパネルが非表示のときにピンチ |
| 視点の回転（ビルド 17 から） | 右スティックを左右に、1 回倒すごとに 30° | 回転ボタン（90°） |
| 前または次のメディア | 左スティックを左右に | 前へと次へのボタン |
| 動画で 10 秒戻るまたは進む | スティックを下または上に | 2 つのスキップボタン、またはタイムバーをドラッグ |
| 画像を 90° 回転 | 写真ではスティックを下または上に、動画では回転ボタン | 回転ボタン |
| 3D レイアウトの変更（モノ、上下、左右） | 3D ボタン | 3D ボタン |
| 全天球または半天球（VR180） | 360°/180° ボタン | 360°/180° ボタン |

この表のボタンとタイムバーは、情報パネルのものです。コントローラーでも使えます：レイで指してトリガーを押します。

- **視点の回転**：頭を回さずに後ろを見るためのものです。右スティックは倒し続けると回り続け、1 行のオーバーレイに角度を表示します。
- **1 行のオーバーレイ**：ビルド 16 から、スティックでのシーク、写真の回転、前へと次へでは 1 行のオーバーレイ（時間、角度、またはメディア名）を表示し、情報パネルは非表示のままです。ビルド 17 より前は、どちらのスティックでも前または次のメディアに移動しました。

### 情報パネル、前へと次へ

動画の情報パネルには、10 秒スキップの 2 つのボタンの間にタイムバー（位置、長さ、バッファー済みの量）があり、その下に前へ、再生または一時停止、次へ、さらに回転、3D、360°/180°、戻るが並びます。写真のパネルも同じ並びで、タイムバーと再生がありません。3D レイアウトと 360°/180° の選択は、パネルのボタンでのみ行えます。

前へと次へは、イマーシブビューを離れずに、開いた元の場所にある 360° メディアを順に移動します：タイムライン、360° リスト（絞り込んだ状態のまま）、アルバム、ネットワーク共有のフォルダー、ヘッドセット本体のメディア（デバイス上の項目）です。平面の写真と動画はスキップされます。タイムライン、アルバム、360° リストからアプリに戻ると、見ていたメディアの位置に戻り（共有フォルダーの画面は開いたファイルのまま）、イマーシブビューを開いたときの動画は中断した位置から再開します。

ビルド 17 から、多くのヘッドセットアプリと同じように右スティックで視点を回転します：1 回倒すと 30° 回り、倒し続けると回り続けるので、頭や椅子を回さなくても後ろにあるものが前に来ます。前へと次へは左スティックです。

ビルド 16 からは、ヘッドセットでのユーザーのフィードバックを受けて、スティックでのシーク、回転、前へ・次へでは、情報パネルを出す代わりに 1 行のオーバーレイ（時間、角度、メディアのタイトル）を表示し、1.5 秒後に消えるようにしました。パネルは A、X、グリップ、メニューボタンで表示されます。同じビルドで、コントローラーがスリープしたり、復帰したり、ハンドトラッキングに切り替わったりしてもパネルの切り替えが動作し続けるようにし、その切り替わりをログに記録しています。[ログ](#logs) を参照してください。

「3D で表示」で開いた Apple の空間写真は球体には貼られず、目の前に浮かんで表示されます。[Apple の空間写真と空間ビデオ](#apple-spatial-photos-and-videos) を参照してください。

### ヘッドセットに表示されるもの

写真はまずプレビューを表示し、その後オリジナルを最大 8192x4096（アプリの上限）に縮小して表示します。動画は、ヘッドセットに保存されたファイルがあればそれを再生し、ネットワーク共有のファイルはアプリのローカルブリッジを通して再生します。それ以外は「動画のソース」の設定に従ってサーバーからストリーミングします（ビルド 15 から。初期設定ではオリジナルで、オリジナルがストリーミングできない場合やヘッドセットのデコーダーの能力を超える場合はサーバーの変換済みバージョン。[動画の詳細とデコーダー](#video-details-decoders-and-why-a-video-stutters) を参照）。ビルド 16 からはカメラの RAW ファイルもここで開け、アプリがスティッチします。RAW 動画は 1 つの全天球なので、3D と 360°/180° のボタンは非表示です。

上下と左右の 3D レイアウト、360° と VR180 は、それぞれの目にフレームの半分ずつを届けて 3D で表示します。レイアウトは、ファイルが宣言していればそれを使い（動画）、なければ形から推測します（正方形なら上下、4:1 なら左右）。間違っている場合は、情報パネルの 3D ボタンを使ってください。

### 画像が正面を向いていない場合

右スティック（または情報パネルの回転ボタン）で、画像の中心が正面に来るまで回します。角度はパネル、またはパネルが非表示のときは 1 行のオーバーレイに「画像を N 度に回転しました」と表示されます：その数値をカメラの機種名とともに [Issue](https://github.com/freeKC/Immuch360/issues) に投稿していただければ、初期値にできます。開始時の向きは、まだすべてのカメラで確認できていません。

### イマーシブビューの制限

- **前へと次へ**：タイムラインでは最大 400 件先まで、共有フォルダーでは 50 ファイルまでを、最大 12 秒かけて探します。それを超えると、前または次の 360° メディアがないとパネルに表示されます。共有フォルダーはファイルを 1 つずつ確認するため、平面のファイルが多く続いた後の最初の 360° ファイルを見つけるには数秒かかることがあります。空間写真からはまだ使えません。
- **3D の選択**：3D ボタンで選んだレイアウトはビューアーを閉じると記憶されません。360°/180° の選択は、ライブラリのメディアについては記憶されます。
- **シーク**：ソースがバイト範囲リクエストに応答しない動画はシークできません。その旨がパネルに表示されます。
- **平面の動画**：平面（360° ではない）のステレオ動画は、両目の画像が見える状態でウィンドウ内で再生されます。イマーシブな 3D 表示は 360° と VR180 のメディア用です。
- **その他**：ヘッドセットがデコードできるコーデック、ストア、許可、APK のサイズについては [Meta Quest 3](#meta-quest-3) を参照してください。

<a id="watch-on-your-tv-android-tv-and-google-tv"></a>
## テレビで見る（Android TV と Google TV）

360° の写真と動画、アルバム、そして NAS や Plex サーバーの動画を、ソファにいる家族と一緒に大きな画面で、テレビのリモコンを使って見たい。Immich モバイルアプリはテレビ用のアプリではありません：テレビにインストールしたユーザーは、マウスでは動くもののリモコンでは操作できないことに気付き（[ディスカッション #1614](https://github.com/immich-app/immich/discussions/1614)）、Immich チームには公式のテレビアプリを作る予定はありません（[ディスカッション #13748](https://github.com/immich-app/immich/discussions/13748)）。

ビルド 20 から、同じ Android アプリが Android TV と Google TV で、リモコンだけを入力として動作します：スマートフォンとテレビで共通の 1 つの APK、矢印キーで向きを変える 360° と 3D のビューアー、そしてネットワーク共有、Plex、Tapo カメラをテレビで、Immich サーバーの有無にかかわらず使えます。

<a id="install-it-on-the-tv"></a>
### テレビにインストールする

1. Google Play がテレビ向けにアプリを提供するまで（テレビ向けリリースの Google の審査待ちです）、[Releases](https://github.com/freeKC/Immuch360/releases) ページからユニバーサル版の `Immuch360-v<version>-release.apk` を入手してください。
2. テレビで開発者向けオプションと USB デバッグをオンにします（Google TV の場合：設定、システム、デバイス情報で「Android TV OS ビルド」を 7 回選択し、その後 設定、システム、開発者向けオプション。名前はテレビによって異なります）。
3. 同じネットワーク上のコンピューターから、adb（Android SDK Platform Tools）で `adb connect <address of the TV>` を実行し、テレビに表示される確認を承認してから、`adb install -r Immuch360-v<version>-release.apk` を実行します。
4. アプリはバナー付きでテレビのアプリ一覧に表示されます。次のリリースも同じ方法でインストールします：`-r` によってログインと設定が保持されます。

### 初回起動

1. スマートフォンと同じようにログインします：矢印キーで枠を項目から項目へ動かし、項目の上で OK を押す（「OK を押して入力」）と、サーバーのアドレス、メールアドレス、パスワード用のテレビのキーボードがダイアログで開きます。
2. または「サーバーなしで使用」を選びます。テレビには自身の写真がないため、写真タブには「このテレビには自身の写真や動画がありません: ライブラリからネットワーク共有を開いてください。」とネットワーク共有のボタンが表示されます。そこからスマートフォンと同じように、共有、Plex サーバー、カメラを追加します（[ネットワーク共有](#network-shares-a-nas-a-computer-or-a-media-server) を参照）。

### リモコンでの移動

- 矢印キーで枠を動かし、OK で枠のある項目を開き、戻るで前に戻ります。タブからは、戻るでサイドメニュー、次に写真、次にアプリの終了へと進みます。
- チャンネルの上下キーで 1 ページずつスクロールします。
- ビューアーでは、リモコンの再生と一時停止、早送り、巻き戻し、次、前のキーが使え、情報キーで写真や動画の詳細を表示します。

### リモコンで写真と動画を見る

1. **写真**：左右で前後の写真に移り、OK でコントロールの表示と非表示を切り替え、上で上部のバー（360° ボタンがある場所）、下で下部のバーに移ります。
2. **動画**：OK で一時停止してコントロールを表示するか、再生します。再生中は左右で 10 秒戻るか進み、一時停止中は前後の項目に移ります。ヒントには「一時停止中: 矢印で前後の項目に移動します」と表示されます。
3. **360° 写真**、360° ボタンから：矢印キーで見回し、押し続けると速くなり、離すと視点がゆっくり止まります。OK で上部のバーのボタンに移り、「拡大」が選ばれます。その隣に「縮小」、視野、3D があります。チャンネルの上下キーでも拡大と縮小ができます。戻るでボタンから画像に戻り、もう一度押すと閉じます。ヒントには「矢印で見回す、OK でコントロール、戻るで閉じる」と表示されます。
4. **360° 動画**、360° ボタンから：コントロールが非表示の間は矢印キーで見回し、OK で一時停止してコントロールを表示し、戻るでコントロールを隠し、もう一度押すと閉じます。ヒントには「矢印で見回す、OK で一時停止してコントロールを表示、戻るで閉じる」と表示されます。
5. **思い出**：左右で写真を順に移動して次の思い出に進み、上で閉じるボタン、下で「タイムラインで見る」に移ります。
6. **共有と Plex**：共有の写真と動画の画面でも同じキーが使え、左右でフォルダーの前後のファイルを開きます。

### リモコン用レイアウトの設定

設定、設定（Preferences）、「リモコン用レイアウト」：「大きなフォーカス枠とリモコンのキーで操作し、タッチスクリーンが必要なコントロールは表示しません。自動では Android TV と Google TV でオンになります。」既定値は自動です。オンはキーボードやゲームパッドで操作するタブレットに向いており、オフにするとテレビでもオフになります。この設定は Android にのみあります。ビューアーでの矢印キーと OK は、設定にかかわらずキーボードやゲームパッドで使えます。

### 制限

- **ビューアーとして**：テレビではアプリは表示と再生を行います。バックアップ、アップロード、編集、削除、共有、複数項目の選択、キャスト、Spatial 2.5D、ジャイロスコープ、地図と撮影場所、「この電話をネットワークで共有」は表示されません。
- **サインイン**：OAuth はウェブページを開きますが、テレビではそれができません：「(プロバイダー) でのサインインはウェブページを開きますが、このテレビではできません。代わりにメールアドレスとパスワードでサインインしてください。」
- **リンク**はブラウザーを開く代わりに「別のデバイスで開く」の下にアドレスを表示し、文字はシステムのキーボードのダイアログで入力します。
- **メモリ**：メモリの少ないテレビでは、360° 写真の表示は最大 4096x2048 で、拡大時の高精細な画像はありません。
- **動画**：何を再生できるかはテレビのデコーダー次第で、スマートフォンと同じ「動画のソース」の設定とデコーダーの確認が使えます（[動画の詳細とデコーダー](#video-details-decoders-and-why-a-video-stutters) を参照）。テレビではまだ計測していません。
- **デバイスではまだ確認していません**：テレビ対応は自動テストでのみ確認しており、テレビでもテレビのエミュレーターでもまだ動かしていません。確認が必要な点：矢印キーで 360° 動画が回る向き、テキストダイアログでのテレビのキーボード（Gboard）、赤外線リモコンの OK キー、余白、テレビのホーム画面のバナー。ご報告を歓迎します。
- **テレビ向けの Google Play** は、テレビ向けリリースの Google の審査待ちです。それまでは APK を使ってください。
- **その他のテレビ**：Fire TV はテストしておらず、Apple TV 版はありません。

## 360° の撮影データを見つける：360° リスト

360° の撮影データは他の写真に混ざっていて、球体やパノラマを絞り込む方法が Immich に要望されています（[ディスカッション #12824](https://github.com/immich-app/immich/discussions/12824)）。Immich アプリにはそのようなリストはありません。

Immuch360 は、360° 写真のサムネイルに 360° バッジを付け（ネットワーク共有のフォルダーでは 360° 動画にも）、ライブラリタブの上部に 360° の項目を置きます。ビルド 18 から、このリストには、サーバーがある場合は、サーバーが 360° と判定した写真と動画、名前で見つけた Insta360 の RAW ファイル、360° カメラ自身がスティッチした写真、360° として表示することを選んだもの、さらにデバイスのスキャンで見つかったものが入ります。サーバーがない場合は、デバイスのスキャンで見つかったものと、360° として表示することを選んだものが入ります。コピーがどこにあっても 1 回だけ、新しい順に表示されます。

<img src="../.github/readme/b19-360-list.png" width="260" alt="4 件の 360° リスト、撮影日のシートを開いた状態：すべて、件数付きの 2026 年、年全体、件数付きの 2026 年 8 月と 2026 年 4 月、2025 年、カスタム">

### リストを絞り込む

1. ライブラリタブを開き、360° をタップします（サーバーがある場合はお気に入りの隣、ない場合は単独で表示）。
2. 期間を指定するには撮影日をタップします：すべて、年（開くと「年全体」と各月が件数付きで表示されます）、または日付の範囲を指定するカスタムです。
3. サーバーがある場合は、メディアの場所を選びます：「サーバー上」、「デバイス上の項目」、そして該当するものがあれば「自分と共有中」です。
4. 種類を選びます：写真、動画、3D、VR180。
5. リストに 2 台以上のカメラが含まれる場合、2 行目に EXIF のメーカーと機種名から件数付きで一覧表示されます。それらの情報がない RAW ファイルは拡張子のブランド名（Insta360、GoPro、DJI）で、それ以外は「不明なカメラ」と表示されます。
6. 同じグループ内（場所、写真と動画、3D と VR180、カメラ）のチップは足し合わされ、グループ間ではリストを絞り込みます。クリアですべてリセットされます。「これらのフィルターに一致する360°の写真や動画はありません」は、フィルターで何も残らないことを意味します。
7. 写真または動画を開きます。Quest のイマーシブビューでは、前へと次へは絞り込んだリストに従います。

<a id="video-details-decoders-and-why-a-video-stutters"></a>
## 動画の詳細、デコーダー、動画がカクつく理由

Quest 3 が再生できるコーデック、サイズ、ビットレートは何か、5.7K の書き出しがスマートフォンでは再生できるのにヘッドセットではカクつくのはなぜか、という質問があります。答えはハードウェアデコーダーです：Quest 3（XR2 Gen 2）の H.264 デコーダーの上限は約 4096x2304 のため、5760x2880 の H.264 動画（レベル 6.0、約 200 Mbit/s、Insta360 の一般的な書き出し）はヘッドセットでは約 17 fps でしかデコードできず、ブロックノイズが出ます。同じファイルでもスマートフォンでは問題なく再生できます。

同じ動画を HEVC（H.265）にするとヘッドセットでもよく再生できます：Insta360 X4 の 8K HEVC 動画（7680x3840、29.97 fps、210 Mbit/s、Main プロファイル、レベル 6.1、8 ビット）は、ネイティブ解像度のまま変換なしでイマーシブビューで滑らかに再生されます（Quest 3 のユーザーからの報告）。

Immich アプリには「常にオリジナル画質の動画を再生する」スイッチが 1 つあるだけで、コーデックしか表示しません。Immuch360 は、動画が何であり、デバイスが何をデコードできるかを表示し、再生できるファイルを選びます。

<img src="../.github/readme/b19-video-details.png" width="260" alt="360° 動画の詳細：コーデック H.264 High (avc1.640033)、3840 x 1920、30 fps。ビットレート 16 Mbit/s。映像 8 ビット、SDR、BT.709。このデバイスでデコード可能：はい、ハードウェア、最大 4096 x 2304">

### 動画の詳細を読む

1. 動画を開き、上にスワイプします：画像の下に詳細が表示されます。
2. コーデック：プロファイルとコーデック文字列付きのコーデック、フレームサイズ、フレームレートです。たとえば上の画像のように「H.264 High (avc1.640033) • 3840 x 1920 • 30 fps」となります。
3. ビットレート（ビルド 18 から）：動画トラックのビットレート、またはファイルが宣言しているビットレートです。それ以外の場合は「ファイル全体、音声を含む」または「ファイルサイズからの推定」と記されます。
4. 映像（ビルド 18 から）：ビット深度、SDR または HDR の伝達特性（HLG、PQ、Dolby Vision）、色空間です。
5. このデバイスでデコード可能：可否、ハードウェアかソフトウェアか、デコーダーが扱える最大サイズ、そしてデバイスにコーデックはあってもそのプロファイルがない場合は「(プロファイル)のデコーダーがありません」です。

各行はファイルを読み込んだ後にだけ、ファイルが示す情報についてだけ表示されます。Apple の空間写真や空間ビデオには専用の行が加わります。[Apple の空間写真と空間ビデオ](#apple-spatial-photos-and-videos) を参照してください。

### デバイスがデコードできるものを見る

設定、詳細設定、「このデバイスの動画デコーダー」（ビルド 15 から）に、スマートフォンやヘッドセットがデコードできるものが一覧表示されます：コーデック、ハードウェアかソフトウェアか、最大サイズ、フレームレート、そしてビルド 18 からはプロファイル（Main、Main 10、HDR10）です。ビルド 19 からは、Apple の空間ビデオのコーデックである MV-HEVC の項目もあります。コピーボタンで一覧をクリップボードにコピーし、不具合報告に使えます。

### オリジナルか変換済みストリームかを選ぶ

1. 設定、アセットビューアー、動画の順に開きます。
2. 「動画のソース」（「サーバーに変換済みのコピーがある場合に再生するファイル」）の下で、「このデバイスでデコードできる場合はオリジナル」、「常にオリジナル」、「常に変換済みストリーム」のいずれかを選びます。

ビルド 15 から、この選択はサーバーのすべての動画に適用されます：平面のプレーヤー、360° と Spatial のプレーヤー、Quest のイマーシブビューです。選ぶまでは、スマートフォンでは以前の「常にオリジナル画質の動画を再生する」スイッチの設定が引き継がれ（初期設定はオフ：変換済みストリーム。サーバーが変換していない場合はオリジナルそのもの）、Quest ではヘッドセットがデコードできる場合はオリジナルを再生します。

チェックでは、ファイルからコーデック、サイズ、フレームレートを読み取り、ハードウェアデコーダーと比較します（Quest 3 の H.264 は実測値の 4096x2304 に制限）。オリジナルをデコードできないプレーヤーは、変換済みストリームに切り替えて「変換済みストリームを再生しています: オリジナル (コーデックとサイズ) はこのデバイスのデコード能力を超えています」と表示します。

ヘッドセットでは、イマーシブビューはオリジナルで再生を始め、最初のフレームの時点でオリジナルがデコーダーの能力を超えている場合は、サーバーの変換済みストリームに切り替えて、その旨を情報パネルに表示します。変換済みストリームがない場合、それでも大きすぎる場合、ファイルがヘッドセット本体やネットワーク共有のものである場合は、情報パネルにその旨と変更すべき点を 10 秒間表示します。Horizon Store に提出したビルド 14 は、4096x2304 を超える H.264 だけを確認し、その場合は同じようにサーバーの再生用ストリームを試します。

2 つのレンズの RAW 動画では、チェックでデコーダーを同時に 2 つ求め、ビルド 19 からは、それぞれ 2048x2048 を超える 2 つのストリームをソフトウェアデコーダーには割り当てません。[カメラの RAW 360° ファイル](#raw-360-camera-files-without-the-cameras-app) を参照してください。

### ヘッドセットがデコードできる動画を用意する

Immich で、管理、設定、動画の変換設定に進み、次のいずれかを選びます：

- **すべての H.264 動画を HEVC で再エンコード**：動画コーデックを HEVC に、解像度をオリジナルに設定し（初期値の 720p では 360° 動画が 1440x720 に縮小されます）、容認する動画コーデックには HEVC だけを残します。360° 動画だけでなく、ライブラリのすべての H.264 動画が変換され、ヘッドセットにはフル解像度の HEVC が届きます。
- **1440p を超えるものだけ**：容認する動画コーデックに H.264 を残し、変換ポリシーを「設定解像度を超える動画、または容認されていない形式の動画」に、解像度を 1440p に設定します。できれば動画コーデックも HEVC にします。それより大きいものはすべて変換され、ヘッドセットには 2880x1440 が届きます。通常の 4K 動画も 1440p に変換されます。

これらの設定はサーバー全体、すべてのユーザーとすべてのアプリに適用され、大きなライブラリの再エンコードには何時間もの CPU 時間と追加のディスク容量が必要です。オリジナルは変更されません。HEVC に対応していないブラウザー（多くのシステムの Firefox、ハードウェア HEVC のない Chrome）では、Immich のウェブアプリで HEVC に変換した動画を再生できません。新しい動画については、Insta360 アプリや Studio から H.265 で書き出すのが最も簡単です。これらの設定を変更した後は、既存の動画をもう一度変換する必要があります：管理、待機中のジョブ（古い Immich ではジョブ）、動画を変換、すべて。

もう 1 つの方法で、ネットワーク共有やヘッドセット本体のファイル（変換済みストリームがありません）にとっては唯一の方法が、アップロードや共有へのコピーの前に、書き出したファイルを HEVC で再エンコードすることです：

```bash
ffmpeg -i VID_360.mp4 -c:v libx265 -crf 20 -preset medium -tag:v hvc1 -c:a copy -movflags +faststart VID_360_hevc.mp4
exiftool -overwrite_original -tagsFromFile VID_360.mp4 -XMP-GSpherical:all VID_360_hevc.mp4
exiftool -ProjectionType VID_360_hevc.mp4        # must print: equirectangular
```

`-tag:v hvc1` は HEVC トラックに Apple のデバイスやブラウザーが期待するラベルを付け、`-c:a copy` は音声をそのまま残します。ffmpeg は書き出したファイルの 360° タグを落としてしまうので、exiftool の行でそれを書き戻します。これがないと、Immich は動画を平面の動画として表示します。

### ストリーミングできないオリジナル

サーバーがオリジナルへの HTTP Range リクエストを無視し、MP4 のインデックス（moov）がファイルの末尾にある場合、最初のフレームまでにファイル全体をダウンロードする必要があるため、アプリはサーバーの再生用ストリームに切り替えます。Immich の前段にあるリバースプロキシーが応答をバッファリングしたり、Range ヘッダーを取り除いたりすると、この問題が起こることがあります。

<a id="everything-else-is-immich"></a>
## それ以外はすべて Immich

公式の Immich モバイルアプリでできることは、すべてここでもできます：バックアップ、タイムライン、アルバム、検索、共有、パートナー。すべてサーバーと同期され、ウェブアプリと同じサーバー、同じアカウントを使います。Immuch360 は公式アプリと並べてインストールできます（パッケージ `com.aprogsys.immuch360`）。違いは 2 つあり、どちらもビルド 15 からです：「常にオリジナル画質の動画を再生する」スイッチが上で説明した「動画のソース」の選択に変わったこと、そしてデバイスのアルバムから手動でアップロードした写真と動画がバックアップ済みとして数えられることです。テレビでは、ビルド 20 からアプリはビューアーになります。[テレビで見る](#watch-on-your-tv-android-tv-and-google-tv) を参照してください。

アプリを持っていない人に 360° 写真を見せるには、Immich の共有リンクで共有してください：Immich のウェブアプリは、その人のブラウザーで 360° 写真を球体として表示します。

現在のビルド、ビルド 21（バージョン 3.3.0-rc.0、ビルド番号 3030019）は Immich 3.3.0-rc.0（Immich の `main`、まだ安定版ではありません）をベースにしています。ビルド 19 は Immich 3.2 サーバーでテストしており、ビルド 20 と 21 ではアプリがサーバーに求める内容は何も変わっていません。問題は Immich プロジェクトではなく、[Issues](https://github.com/freeKC/Immuch360/issues) に報告してください。Immich 自体の詳しいドキュメントは [immich.app](https://immich.app) を参照してください。

- **この電話をネットワークで共有**：ユニットテストと、ヘッドセットの WebDAV クライアントを使ったエンドツーエンドテストをパソコン上で実施。Quest に配信するスマートフォンと iPhone 側はビルド 19 の実機テストの対象。
- **Plex Media Server**：コンピューターから実際の Plex Media Server 1.42.1 を相手に確認（ペアリング、フォルダー、バイト範囲指定、サムネイル、自宅外のアドレス）。デバイスではまだ確認していません。
- **Tapo カメラ**：シミュレーションしたカメラで確認。実際のカメラではまだ確認していません。
- **Android TV と Google TV**：自動テストで確認。テレビではまだ確認していません。
- **Windows パソコンで動く同じアプリ**：Windows 上で 475 件のデスクトップ自動テスト。Windows 11 のパソコンでは、アプリが起動し、Immich サーバーの保存済みセッションを開き、同期し、正常に終了します。各機能の手動テストは進行中です。
- **Insta360 の RAW の .insp 写真とシングルトラックの .insv 動画**：写真は X3 のファイルを Insta360 Studio で書き出したものと比較、動画は低解像度の X3 ファイルを使い Android エミュレーターで確認。まだ iPhone では動かしていません。
- **トラックごとまたはファイルごとにレンズが 1 つの RAW 動画**：実際の X4、X3 ペア、GoPro MAX、Osmo 360 のファイルで解析とスティッチを確認。再生はビルド 18 と 19 の実機テストの対象。
- **デュアル魚眼の .dng**：予定。
- **サーバーの動画と動画デコーダー**：Android エミュレーターでテスト済み。Quest 3 の H.264 の上限はヘッドセットで実測。
- **動画の技術的な詳細**：完了。

### 同じ目的で使われている他のアプリ

- **Immich のウェブアプリ**
  - 困ること：360° 写真を球体で表示しますが、RAW の .insp を完成したパノラマとして扱い、2 つの円を球体に巻き付けます。VR 表示はまだ要望の段階です（[ディスカッション #14768](https://github.com/immich-app/immich/discussions/14768)）。
  - Immuch360 の対応：RAW ファイルをデバイス上でスティッチし、Quest ではイマーシブビューを開きます。
- **Insta360 アプリまたは Studio**
  - 困ること：見る前に、カードの RAW ファイルを 360° 画像に変換する必要があります。
  - Immuch360 の対応：RAW の .insp と .insv ファイル、GoPro の .360 と DJI の .osv ファイルを直接開きます。
- **Plex、Jellyfin、Synology Photos**
  - 困ること：各フォーラムのスレッドにあるように、360° の写真と動画が平面で表示されるか、認識されません（Plex への要望は 2017 年から未対応）。
  - Immuch360 の対応：ビルド 20 からは Plex のライブラリそのものを、または同じフォルダーを SMB、WebDAV、DLNA で読み込み、サーバー側を何も変えずに球体で再生します。
- **Tapo アプリ**
  - 困ること：TP-Link アカウントにサインインする別のアプリで、クリップは写真とは別の場所にある。
  - Immuch360 の対応：カメラを写真と並べて表示し、あなたのネットワーク内だけで通信し、クリップを Immich に送れる動画として残します（ビルド 20 から）。
- **テレビ上の Immich モバイルアプリ**
  - 困ること：テレビ用アプリではない：マウスでは動くがリモコンでは操作できないとユーザーが報告。
  - Immuch360 の対応：同じアプリを、リモコン向けに（ビルド 20 から）。
- **ヘッドセットへのファイルのコピー**
  - 困ること：見る前に、ファイルを 1 つずつケーブルでコピーする必要があります。
  - Immuch360 の対応：Immich、NAS、メディアサーバー、スマートフォンから、その場で再生します。
- **Quest ストアの 360° と 3D のプレーヤー**
  - 困ること：有料。
  - Immuch360 の対応：無料のオープンソース（AGPL）。

<a id="formats-and-sources-by-platform"></a>
## プラットフォーム別の形式とソース

Immuch360 はギャラリーであり、無料のメディアプレーヤーでもあります：公式アプリでは再生できないものを、2 つ目のリストのソースから、ファイルに合ったプレーヤーで再生します。

- **平面の動画（MP4、MOV、MKV など、デバイスがデコードできるもの）**
  - Android スマートフォン：Immich のプレーヤー、ネットワーク共有にはネイティブプレーヤー。
  - iPhone、iPad：同じ。ただし共有の MKV と AVI ファイルは iOS では開けません（サーバー上のものは変換して再生）。
  - Meta Quest：ウィンドウ内。
  - Android TV、Google TV：スマートフォンと同じ。OK で一時停止、左右で 10 秒移動。
- **360° 写真**
  - Android スマートフォン：球体ビューアー、ジャイロスコープ。
  - iPhone、iPad：同じ。
  - Meta Quest：イマーシブ、周囲全体。
  - Android TV、Google TV：矢印キーで向きを変える球体ビューアー、チャンネルキーで拡大縮小。
- **360° 動画**
  - Android スマートフォン：球体上のネイティブ Media3 プレーヤー、ジャイロスコープ、シーク、音声トラックの選択、バッファリング表示。
  - iPhone、iPad：球体上のネイティブ SceneKit プレーヤー、ジャイロスコープ、音声トラックの選択、バッファリング表示。再生と一時停止のみで、タイムバーはまだなし。
  - Meta Quest：イマーシブ、ステレオのファイルは本物の 3D、10 秒スキップ付きのタイムバー、前と次のメディア。
  - Android TV、Google TV：スマートフォンと同じ Media3 プレーヤー、矢印キーで向きを変更。
- **3D 360°（上下、左右）**
  - Android スマートフォン：左目、レイアウトボタン。
  - iPhone、iPad：同じ。
  - Meta Quest：それぞれの目にフレームの半分ずつ。
  - Android TV、Google TV：左目、レイアウトボタン。
- **VR180（半天球）の写真と動画**
  - Android スマートフォン：半天球、360°/180° ボタン。
  - iPhone、iPad：同じ。
  - Meta Quest：イマーシブな半天球。
  - Android TV、Google TV：半天球、360°/180° ボタン。
- **Spatial 2.5D（ステレオ動画から平面の画面に奥行き）**
  - Android スマートフォン：ネイティブプレーヤー、前面カメラによる頭の追跡。
  - iPhone、iPad：同じ。
  - Meta Quest：提供なし。
  - Android TV、Google TV：提供なし。
- **Apple の空間写真（HEIC のステレオペア、ビルド 19 から）**
  - Android スマートフォン：左目、詳細の 1 行で空間写真であることを表示。
  - iPhone、iPad：同じ。
  - Meta Quest：3D で表示：イマーシブビューに浮かぶ写真で両目、3D または 2D、サイズ変更可能。
  - Android TV、Google TV：左目、詳細の 1 行。
- **Apple の空間ビデオ（MV-HEVC、ビルド 19 から）**
  - Android スマートフォン：片目（ベースレイヤー）、通知付き。
  - iPhone、iPad：同じ。
  - Meta Quest：ウィンドウ内で片目、通知付き。
  - Android TV、Google TV：片目、通知付き。
- **Insta360 の RAW の .insp 写真（ビルド 16 から）**
  - Android スマートフォン：球体ビューアーの前に GPU でスティッチ、最大 8192x4096。
  - iPhone、iPad：同じ。
  - Meta Quest：イマーシブ、ヘッドセット用に準備したスティッチ済み画像から。
  - Android TV、Google TV：スマートフォンと同じ。
- **両方のレンズを 1 つのトラックに収めた Insta360 の RAW の .insv（ビルド 16 から）**
  - Android スマートフォン：Media3 プレーヤー内の GPU エフェクトでスティッチ。
  - iPhone、iPad：SceneKit のシェーダーでスティッチ。
  - Meta Quest：イマーシブ、同じ GPU エフェクトでスティッチ。
  - Android TV、Google TV：スマートフォンと同じ。
- **トラックごとまたはファイルごとにレンズが 1 つの RAW 動画（ビルド 18 から）：Insta360 X4、X4 Air、X5、X6 の .insv、X3 ペア、GoPro .360、DJI .osv**
  - Android スマートフォン：レンズごとに 1 つ、2 つのハードウェアデコーダーを同時に使い（ビルド 19 からは、ハードウェアデコーダーのないデバイスではソフトウェアデコーダー、レンズごとに最大 2048x2048）、GL コンポジターで球体にスティッチ。デバイスが 2 つを動かせない場合は、片方のレンズ、次に変換済みストリーム、次にスティッチなしの動画。
  - iPhone、iPad：Metal を使った独自の AVFoundation コンポジター。
  - Meta Quest：イマーシブ、同じ 2 つのデコーダーとコンポジター（3840x1920 のパネル）。
  - Android TV、Google TV：テレビが 2 つのデコーダーを同時に動かせる場合、スマートフォンと同じ。
- **Tapo カメラのライブ映像（ビルド 20 から）**
  - Android スマートフォン：Media3 の RTSP プレーヤー：画面内で SD、全画面で HD、音声ボタン。
  - iPhone、iPad：まだなし：今後対応する旨のカードを表示。
  - Meta Quest：ウィンドウ内で HD。
  - Android TV、Google TV：スマートフォンと同じ。
- **Tapo カメラの録画（ビルド 20 から）**
  - Android スマートフォン：メモリーカードから音声付きの H.264 動画として取得し、シーク付きで再生。
  - iPhone、iPad：同じ。
  - Meta Quest：同じ、ウィンドウ内。
  - Android TV、Google TV：同じ。

ビルド 20 からの Android TV と Google TV の項目はまだテレビで確認していません（[テレビで見る](#watch-on-your-tv-android-tv-and-google-tv) を参照）。カメラの項目はまだ実際のカメラで確認していません。

Windows では、Immuch360 Desktop のプレビュー版が、平面と 360° の写真（Insta360 の未加工 .insp 写真を含む）を、マウスとキーボードで、サーバー、パソコンのフォルダー、共有、Plex から表示します。動画はまだ再生できず、プレースホルダーが表示されます（[まだできないこと](#not-there-yet) を参照）。

- **自分の Immich サーバー**：設定、アセットビューアー、「動画のソース」の指定に従い、オリジナルまたはサーバーの変換済みストリーム（[動画の詳細とデコーダー](#video-details-decoders-and-why-a-video-stutters) を参照）。ウェブアプリと同じアカウント。
- **スマートフォンやヘッドセット本体**：ログイン画面の「サーバーなしで使用」、またはライブラリタブのデバイス上の項目。
- **NAS またはパソコン**：SMB と WebDAV の共有、ビルド 19 からは DLNA メディアサーバーも。ネットワーク上で見つけてそのまま読み込み（SMB の動画は最大 6 本の接続で）、何もコピーしません。ビルド 15 からは、選んだファイルを Immich アカウントに送信できます。
- **別のスマートフォン（ビルド 19 から）**：そのスマートフォンで「この電話をネットワークで共有」：ヘッドセット、またはネットワーク上のどの WebDAV クライアントからも、そのアルバム、月別のフォルダー、360° メディアを読めます。
- **Plex Media Server（ビルド 20 から）**：写真、映画、テレビ番組のライブラリをフォルダー別に表示し、元のファイルをサーバー自身の証明書で確認した HTTPS でそのまま読み込みます。自宅でも自宅外のアドレス経由でも、すべてのプラットフォームで使えます。[Plex Media Server、plex.tv なしで](#plex-media-server-without-plextv) を参照。
- **Tapo カメラ（ビルド 20 から）**：カメラアカウントでライブ映像（Android、Android TV、Quest）、TP-Link アカウントのパスワードでメモリーカードの録画（すべてのプラットフォーム）、ローカルネットワーク内のみ。[Tapo カメラ](#tapo-cameras-live-view-and-the-recordings-of-the-memory-card) を参照。
- **Windows パソコンのフォルダー（デスクトップ プレビュー版）**：Immuch360 Desktop で選んだフォルダーを、スマートフォンのギャラリーの代わりに読み込みます。パソコンはそれらをヘッドセットと共有することもできます。[Windows パソコンで](#on-a-windows-computer-immuch360-desktop-preview) を参照してください。

<a id="meta-quest-3"></a>
## Meta Quest 3

Immuch360 は Horizon OS v69 以降の Meta Quest ヘッドセットでも動作します。ビルド 21 から、Horizon Store のビルドは Quest 2、Quest Pro、Quest 3、3S を対象としています。これはユニバーサル版の `-release.apk` がすでに挙げている 4 機種です。初代 Quest は対象外で、ストアはもう受け付けていません。

Quest 3 と 3S はテスト済みです。Quest 2 と Quest Pro はまだテストしていません：これらは動画デコーダーが遅く、アプリが確認する上限は Quest 3 で測定したものなので、大きな H.264 動画はメッセージを出して拒否されたり、カクついたりすることがあります。この 2 機種での報告は [Issues](https://github.com/freeKC/Immuch360/issues) で歓迎します。

使い方は [Meta Quest 3 ヘッドセットで](#in-the-meta-quest-3-headset) にあります。このセクションでは、インストール方法とヘッドセットで異なる点を説明します。

ヘッドセット用のビルドは、Horizon Store の要件に従い、HTTPS か、ホームネットワークの名前（`.local`、`.lan`、`.home`、`.internal`、`.home.arpa`）とヘッドセット自身に対する平文の HTTP でのみサーバーと通信します。`http://192.168.1.10:2283` のように IP を使った平文の HTTP アドレスで入力したサーバーは、このビルドでは拒否されます：HTTPS、ホームネットワークの名前（`nas.local`）、またはスマートフォンと同じ制限のないポリシーを持つユニバーサル版の `-release.apk` を使ってください。

ローカルネットワークの平文の HTTP アドレスにある WebDAV、DLNA、電話の共有は対象外です：アプリが自分で読み込み、プレーヤーにはローカルブリッジのアドレスだけを渡します（DLNA と電話の共有はビルド 19 の新機能で、ヘッドセットではまだ確認が必要です）。ビルド 20 からは、Plex サーバーには HTTPS で接続し、Tapo カメラにはアプリ自身が接続して、ライブ映像は HTTP ではない RTSP を使います：どちらも対象にはならないはずです（ヘッドセットで確認が必要です）。

<a id="install"></a>
### インストール

Meta は 2026 年 10 月 7 日にビルド 14 で Horizon Store の掲載を承認し、ビルド 21 を最初のアップデートとして提出しています。ストアのページが公開されるまで、またはストアより先にビルドを入手したい場合は、リリースの `-quest-release.apk` ファイル（ヘッドセット向けのビルド：64 ビット、ターゲット SDK 34、ヘッドセットが使う許可のみ）、またはユニバーサル版の `-release.apk` をサイドロードしてください：

1. 開発者モードを一度だけ有効にします。Meta Horizon のスマートフォンアプリで、Devices（デバイス）を開き、ヘッドセットを選んで、Headset settings（ヘッドセットの設定）、Developer mode（開発者モード）の順に進みます。これには developers.meta.com で無料で作れる開発者アカウントが必要です。パソコンには adb（Android SDK Platform Tools）または SideQuest も必要です。
2. USB-C ケーブルでヘッドセットをパソコンに接続します。ヘッドセットで「Allow USB debugging」（USB デバッグを許可）を承認します。
3. APK をインストールします：

   ```bash
   adb devices                      # the headset must be listed as "device"
   adb install -r Immuch360-v<version>-quest-release.apk   # for example Immuch360-v3.3.0-rc.0-21-quest-release.apk
   ```

4. ヘッドセットでライブラリを開き、「Unknown sources」（提供元不明）のフィルターを選んで、Immuch360 を起動します。
5. サイドロードした APK は自動では更新されません：次のリリースも同じ方法でインストールしてください（`adb install -r` ではログインと設定が保持されます）。Horizon Store 版と GitHub の APK は異なる鍵で署名されているため、ヘッドセットは一方の上にもう一方をインストールできません：切り替えるには先にアプリをアンインストールする必要があり、ログイン、設定、ネットワーク共有の一覧は失われます。

### ウィンドウ内

アプリ全体が、サイズを変更できる 2D ウィンドウで動作します：ログイン、タイムライン、アルバム、検索、ライブラリタブ（360° リスト、デバイス上の項目、ネットワーク共有）、設定、そして平面の写真や動画を再生する写真と動画のビューアーです。

ヘッドセットでは、360° ボタンと ⋮ メニューの 360°で表示は、スマートフォンの球体ビューアーではなく、直接イマーシブビューを開きます。Spatial 2.5D ボタンとその設定は表示されません。

ビルド 19 からは、Apple の空間写真に 3D で表示ボタンがあり、この電話をネットワークで共有のタイルは表示されません：スマートフォンの共有を読む側がヘッドセットだからです。ビルド 20 からは、Plex サーバーと Tapo カメラもウィンドウで開き、カメラのライブ映像は HD です。「リモコン用レイアウト」の設定は自動のままで、ヘッドセットではオフになります。

### ヘッドセットでの制限

- **動画コーデック**：HEVC（H.265）が確実な選択です。H.264 は約 4096x2304 が上限です。アプリが何を確認するか、ヘッドセットがデコードできる動画をどう用意するかは、[動画の詳細とデコーダー](#video-details-decoders-and-why-a-video-stutters) を参照してください。
- **ストア**：ストア版はビルド 14 から始まります。「ビルド 15 から」以降と記した機能は、最初のアップデートであるビルド 21 で、Meta の審査が終わりしだい届きます（テスター向けのストアのアルファテストチャンネルには、新しいビルドが毎回届きます）。GitHub の APK にはすでにすべて含まれています。
- **許可**：ヘッドセット用のビルドが求めるのは、写真と動画（サーバーなしのモード）と通知（バックアップの進行状況）の許可だけです。スマートフォン用のビルドと異なり、ストレージ、音声、位置情報、カメラの許可はありません。そのため、Wi-Fi の名前に応じたサーバーの切り替えはヘッドセットでは使えません。
- **APK のサイズ**：Spatial SDK により、約 56 MB の 64 ビット ARM ネイティブコードが加わります。これはスマートフォンでも同じで、スマートフォンでは読み込まれることはありません。
- **ライセンス**：イマーシブビューは Meta Spatial SDK を使用しており、Meta Platform Technologies SDK License Agreement のもとで配布されています。

<a id="on-a-windows-computer-immuch360-desktop-preview"></a>
## Windows パソコンで：Immuch360 Desktop（プレビュー版）

Immich ライブラリはサーバーにあり、ほかの写真はパソコンのフォルダーに、動画は NAS や Plex サーバーにある。そして 360° 写真を大きな画面で見回したい、あるいはパソコンの写真をヘッドセットで見せたい。Immuch360 Desktop は Windows パソコンで動く同じアプリで、スマートフォンアプリと同じソースからビルドしています。

パソコンでは、Immich はブラウザで使うウェブアプリを提供しています。**Immuch360 Desktop が加えるもの**：サーバーもアカウントも不要なパソコンのフォルダー、アプリから閲覧できる SMB、WebDAV、DLNA、Plex の共有、球体として開く Insta360 の未加工 .insp 写真、そして自宅の Meta Quest とのパソコンの共有です。

この最初のビルドはプレビュー版です：写真は動作し、動画は次のデスクトップ ビルドで対応します。スマートフォン、タブレット、Quest、テレビのアプリはこれによって変わらず、Immuch360 という名前のままです。

<a id="download-and-install-on-windows"></a>
### Windows でのダウンロードとインストール

最初のビルドは GitHub のプレリリース [Immuch360 Desktop 3.3.0-rc.0, desktop build 1 (Windows preview)](https://github.com/freeKC/Immuch360/releases/tag/desktop-v3.3.0-rc.0-1) です。ファイルは `Immuch360-Desktop-3.3.0-rc.0-desktop.1-windows-x64.zip`（33.5 MB、展開すると 65 ファイル）で、確認用の `SHA256SUMS.txt` が付いています。`desktop` ブランチのコミット 21f285c34 からビルドしました：スマートフォンのビルド 20 にパソコン版を加えたものです。Windows 10 または 11（64 ビット）が必要です。

1. ZIP をダウンロードし、どこにでも展開します（例えばドキュメント）。
2. 展開したフォルダーから `immuch360.exe` を起動します。フォルダーはそのまま残してください：プログラムは隣にあるファイルを必要とします。
3. ファイルはまだ署名されていないため、Windows SmartScreen が「Windows によって PC が保護されました」と表示することがあります：「詳細情報」を選び、次に「実行」を選びます。スマート アプリ コントロールがオンの環境では、署名されていないプログラムはブロックされます。
4. ウィンドウが開くのを待ちます。新しいビルドの最初の起動には 10 秒から 1 分ほどかかります。おそらく Microsoft Defender が新しいファイルをスキャンしているためです：その間にアプリをもう一度起動しないでください。2 回目以降の起動は 1、2 秒です。
5. ログイン画面で、アドレス、メールアドレス、パスワードを使って Immich サーバーにサインインするか、「サーバーなしで使用」をクリックします。

ZIP を確認するには、ダウンロードしたフォルダーでコマンドプロンプトを開き、`certutil -hashfile Immuch360-Desktop-3.3.0-rc.0-desktop.1-windows-x64.zip SHA256` を実行します：結果は `SHA256SUMS.txt` に書かれているものと同じです。インストーラーと自動更新はまだありません：[Releases](https://github.com/freeKC/Immuch360/releases) ページを確認し、次のビルドも同じ方法で展開してください。

### プレビュー版でできること

- **Immich サーバー**：タイムライン、アルバム、人物、思い出、検索、そしてサーバーの写真のフルサイズ表示。スマートフォンと同じです。
- **サーバーなし**：写真と動画のフォルダー（ピクチャとビデオが候補に出ます）が、スマートフォンのギャラリーの代わりになります。選んだフォルダーの外は何も読み込まず、サーバーなしでは何もパソコンの外に出ません。
- **アップロードとバックアップ**：アプリが開いている間、それらのフォルダーから Immich サーバーへ。
- **360° 写真を球体で表示**、マウスとキーボードで。Insta360 カメラの未加工 .insp 写真もスマートフォンと同じように開きます。
- **ネットワーク共有**：Samba (SMB)、WebDAV、DLNA メディアサーバー、そして plex.tv を使わない Plex サーバーを、スマートフォンと同じように閲覧できます：写真は開き、動画は動画プレーヤーを待っています（[まだできないこと](#not-there-yet) を参照）。Tapo カメラについては、メモリーカードの録画：一覧と、クリップの取得。
- **このパソコンをネットワークで共有**：フォルダーのアルバム、月、360° メディアを読み取り専用で、自宅の Meta Quest やほかのデバイスに。スマートフォンが自分を共有するのと同じです。
- **ファイル**：サーバーからのダウンロードは選んだフォルダーに保存され、「フォルダーに保存」は選んだ写真と動画のコピーを残し、ログページには「ログをファイルに保存」があります。

### パソコンで使う

1. **フォルダーを選びます。** サーバーなしでは、タイムラインの最初に「写真と動画のフォルダーを選択」が表示されます：「フォルダーを追加」をクリックします。サーバーありでは、フォルダーが選ばれるまで、同じカードがライブラリの「このパソコン上」の下と、バックアップするアルバムに表示されます。その後は「このパソコン上のフォルダー」の行が表示され、設定の「このパソコン」にも同じ行があります。
2. **クラウド、USB、ネットワークのフォルダー。** OneDrive（またはほかのクラウドドライブ）がオンラインのみに置いているファイルは、数えますが読み込みません。そのため、フォルダーを追加してもクラウド全体はダウンロードされません：「ダウンロードして含める」で、必要なときに取得します。別のドライブ文字で戻ってきた USB ドライブも写真を保ちます。ネットワークフォルダー、メモリーカードや USB ドライブ上のフォルダー（Windows が取り出せるように）は変更を監視しません：そこにファイルを追加したら「更新」を使ってください。
3. **360° 写真を見回す**：マウスでドラッグ、ホイール、ダブルクリック、または + と -（AZERTY を含むどのキー配列でも）でズーム、矢印キーで移動します。F または F11 で全画面に切り替え、Escape で戻ります。Home と End で最初と最後の写真へ、I で詳細を表示します。
4. **写真から写真へ移動**：平面の写真では、左右の矢印キー、またはマウスを動かすと端に出る山形の矢印で、前と次の写真に移動します。説明欄に入力した文字はテキストに残ります。
5. **パソコンをヘッドセットと共有**：ライブラリを開き、次にネットワーク共有を開きます。最初のタイルが「このパソコンをネットワークで共有」で、[この電話をネットワークで共有](#share-this-phone-on-the-network) のパソコン版です。「ネットワークで写真とビデオを共有」をオンにし、そのセクションの説明どおりにヘッドセットでパソコンを追加します。共有はアプリを閉じたとき、または 1 時間使われなかったときに停止します。
6. **ネットワークを許可**：Windows が、Immuch360 Desktop にネットワークの使用を許可するか尋ねることがあります。プライベートネットワークで許可してください。許可しないとヘッドセットがパソコンを見つけられません。Windows がパブリックとするネットワーク（カフェ、ホテル）や種類を判別できないネットワークでは、「このセッションだけ共有」を選ばない限り共有は始まらず、パソコンは共有しているネットワークでのみ自分を知らせます。
7. **設定、「このパソコン」**：フォルダー、ダウンロードフォルダー、共有を探したりパソコンを共有したりするのに使うネットワークアダプター（Wi-Fi と Ethernet など、複数ある場合）、そして信頼する証明書：Windows が単独では信頼しない HTTPS アドレスのための、自分のサーバーの認証局の PEM ファイルです。クライアント証明書は、スマートフォンと同じく設定、詳細設定でインポートします。

### スマートフォンアプリとの比較

- **バックアップはアプリが開いている間に実行されます**（最小化中も含む）。ウィンドウを閉じた状態でのバックグラウンド実行はしません。アップロード中やパソコンを共有中にウィンドウを閉じようとすると、まず確認します。
- **ギャラリーの代わりにフォルダー**：アプリは選んだフォルダーを読み込み、独自のインデックス、サムネイル、キャッシュをパソコンに保存します。
- **ウィンドウは 1 つ**：アプリをもう一度開くと、2 つ目を起動せずに最初のウィンドウが前面に戻ります。
- **フォルダーからは何も削除しません**：「デバイスから削除」は非表示で、「削除」はサーバー上のコピーだけを削除します。アプリが Windows のごみ箱にファイルを送れるようになるまではこのままです。
- **マウスとキーボード**で、タッチとジャイロスコープの代わりに操作します。

<a id="not-there-yet"></a>
### まだできないこと

- **動画**：今のところプレースホルダーが表示され、サムネイルはフィルムのアイコンです。再生は次に対応します：まず平面の動画、次に 360°、3D、VR180 の動画と未加工の 360° 動画です。
- **Spatial 2.5D**（後にウェブカメラで）、**Tapo のライブ映像**、**地図**と場所のビュー、**OAuth でのサインイン**（代わりにメールアドレスとパスワードでサインインしてください）、**Google Cast**、**通知**。
- **インストーラー、署名済みビルド、自動更新**：このビルドは `immuch360.exe` の入ったフォルダーです。
- **Linux と macOS**：プロジェクトはソースに含まれていますが、それらのシステムではまだビルドも試用もしていません。Windows の後に対応します。
- **翻訳**：パソコン版の新しいテキストは、今のところ英語です。

### 既知の問題

- **ヘッドセットが共有中のパソコンからファイルを読んでいる間**（再生中の動画、ダウンロード中の写真）、Windows はそのファイルの名前変更、移動、削除ができず、Immuch360 Desktop で開かれていると表示します：先に再生を止めてください。バックアップはそのようにファイルを押さえません：アップロード中でもファイルの名前変更、移動、削除ができます。
- **粗削りな点**：上記の機能は Windows 上の自動テスト（475 件のデスクトップテスト）に合格しており、Windows 11 のパソコンではアプリが起動し、Immich サーバーの保存済みセッションを開き、同期し、正常に終了します。実際のパソコンでのすべての機能の手動テストはまだ進行中です。

問題が起きたときは、ログページから保存したログを添えて [issue](https://github.com/freeKC/Immuch360/issues) を開いていただけると助かります。[ログ](#logs) を参照してください。共有する前にログを確認してください：サーバーのアドレスが含まれていることがあります。

<a id="build-it-yourself-on-windows"></a>
### Windows で自分でビルドする

必要なもの：x64 の Windows 10 または 11、Windows 用の Flutter 3.47.2、「C++ によるデスクトップ開発」ワークロードを入れた Visual Studio 2022 またはその Build Tools、Windows の設定でオンにした開発者モード（Flutter がプラグインに必要とします）、そしてバンドルスクリプト用の Python 3。

1. `desktop` ブランチを取得し、コード生成を実行します。Java と Node を使うので、Linux、macOS、または WSL で実行してください。WSL の場合は、クローンを Windows のドライブに置きます。WSL からは `/mnt/c` または `/mnt/d` の下に見えます：

   ```bash
   git clone https://github.com/freeKC/Immuch360.git
   cd Immuch360
   git switch desktop
   cd mobile
   mise install
   mise run install
   mise run codegen
   ```

2. Windows で、同じ `mobile` フォルダーにてアプリをビルドします：

   ```bat
   flutter pub get
   REM try it, with hot reload: a debug build, with a profile of its own (Immuch360 Desktop Debug), so it runs next to the app
   flutter run -d windows -t lib/main_desktop.dart
   REM the app, in build\windows\x64\runner\Release\immuch360.exe
   flutter build windows --release -t lib/main_desktop.dart
   ```

3. `Release` フォルダーは、それをビルドしたパソコンで動作します。別のパソコン用には、フォルダー全体を残し、`immuch360.exe` の隣に Visual C++ ランタイムを追加します。クローンのルートから、バンドルスクリプトがそれをコピーし、Android にしか使わないものを除き、アプリが読み込むすべての DLL がフォルダーか Windows 自体にあることを確認して、ZIP を作ります：

   ```bat
   python .github\desktop\windows_bundle.py --release mobile\build\windows\x64\runner\Release --out <folder> --zip <file.zip>
   ```

`desktop` ブランチの CI（`.github/workflows/immuch360-desktop.yml`）は、Linux でスマートフォンのチェックとテストスイート全体を、Windows でデスクトップテストを実行し、同じ ZIP をビルドします。Linux と macOS のジョブ（`flutter build linux` と `flutter build macos`、同じ `-t lib/main_desktop.dart` 付き）は、まだそれらのシステムで実行していません。

<a id="build-it-yourself"></a>
## 自分でビルドする

ビルド環境は Immich モバイルと同じです（Flutter 3.47、[mise](https://mise.jdx.dev) で管理）：

```bash
git clone https://github.com/freeKC/Immuch360.git
cd Immuch360/mobile
mise install
mise run install
mise run codegen
flutter build apk --release --flavor phone                                   # phones: the universal APK of the GitHub releases (add --split-per-abi for the per ABI files)
flutter build appbundle --release --flavor phone                             # the App Bundle sent to Google Play (also mise run build:android)
flutter build apk --release --flavor quest --target-platform android-arm64 --android-project-arg arm64only=true   # Meta Quest 2, Pro, 3 and 3S: the -quest-release.apk of the releases (also mise run build:quest)
flutter build ios --release                                                  # iPhone and iPad, on a Mac with Xcode and your own signing team
```

ストア用のスクリーンショットは、`--dart-define=IMMUCH_SCREENSHOTS=true` を付けて作ったシミュレーター用のデバッグビルドで撮影しています。このオプションはデバッグバナーを隠すだけです。

2 つの Android フレーバーは同じアプリです。ビルド 20 から、`phone` はテレビ用アプリとしても宣言しています（テレビのランチャー項目とバナーを持ち、タッチスクリーンを必須としません）。`quest` にはこの宣言はありません。

`quest` はターゲット SDK 34 で、ヘッドセットが使う許可（写真、動画、通知）だけを残しています：メディア管理、バックグラウンドでの位置情報、従来のストレージ、音声、メディアの位置情報、デバイスの位置情報、カメラは `android/app/src/quest/AndroidManifest.xml` で削除しています。Meta Horizon Store は最初の 2 つを拒否し、その他の機密性の高い許可にはすべて理由の説明を求めるためです。同じファイルで、対応デバイスを Quest 2、Quest Pro、Quest 3、3S とし、平文の HTTP をヘッドセット自身とホームネットワークの名前に限定しています。APK が 64 ビット専用なのは、コマンドラインの 2 つの追加引数（`--target-platform android-arm64 --android-project-arg arm64only=true`）によるものです。`phone` は Google Play が求めるものです。

自分の Mac で iOS 向けにビルドするには、Xcode と自分の署名チームを使います。Xcode 26 では、Spatial のシェーダーに必要なため、最初に一度 `xcodebuild -downloadComponent MetalToolchain` を実行してください。Mac がない場合、iOS のビルドはこのリポジトリの `codemagic.yaml` ファイルから Codemagic（ホスティングされた Mac）で実行します。Android のリリースビルドは GitHub Actions（`.github/workflows/immuch360-release.yml`）で実行します。

Windows 版の Immuch360 Desktop は、`desktop` ブランチから Windows 用の Flutter でビルドします：手順は [Windows で自分でビルドする](#build-it-yourself-on-windows) にあります。

このリポジトリに秘密情報は置いていません：Android の署名鍵は暗号化された GitHub Actions のシークレットとして、Apple の署名関連のデータは Codemagic の暗号化された変数として保管しています。ワークフローのファイルは名前で参照しているだけです。自分の `android/key.jks` がない場合、リリースビルドはデバッグ鍵で署名され、GitHub やストアから入れたものの上にはインストールできません（先にそちらをアンインストールしてください）。デバッグビルドは Immuch360 debug として並べてインストールされます。Meta Horizon Store 版は、リリースの `quest` APK を別の鍵、つまりストアのアプリを最初に登録したときの鍵で署名したものなので、サイドロードした APK の上にもインストールできず、その逆もできません。

### ブランチ

- **`main`**：`immuch360` のベースとなっているコミット時点の Immich の `main`（現在のビルドでは 2026 年 9 月 29 日）で、変更は加えていません。フォークを新しい Immich にリベースすると進みます。
- **`immuch360`**：Immich の上に重ねたこのフォークの変更です。各リリースに、ベースとなっている Immich のバージョンを記載しています。
- **`desktop`**：パソコン版の Immuch360 Desktop で、`immuch360` の上に重ねています。スマートフォンのリリースはここにマージされ、デスクトップのプレリリースはここからビルドします（desktop build 1 はコミット 21f285c34 から、スマートフォンのビルド 20 にパソコン版を加えたもの）。このブランチでは `mobile/android` と `mobile/ios` の下は何も変わりません。

<a id="logs"></a>
## ログ

Android と Quest では、`adb logcat` で、ヘッドセットのイマーシブビューを `Immuch360` タグで（ビルド 19 からは Apple の空間写真の両目についても：2 つ目の目をどうデコードしたか、切り抜き、写真の配置位置）、デコーダーのチェックを `VideoDecoders` で、左右配置の RAW 動画のスティッチを `DualFisheyeEffect` で、ビルド 18 の 2 つのレンズの再生を `TwoLensPlayer`、`TwoLensCompositor`、`LensVideoRenderer` で確認できます：

```bash
adb logcat -c
# reproduce the problem, then
adb logcat -d -v time -s Immuch360 VideoDecoders DualFisheyeEffect TwoLensPlayer TwoLensCompositor LensVideoRenderer
adb logcat -d -v time > quest-full.log      # everything, including crashes and decoder errors (it can contain your server address, check before sharing)
adb logcat -d -v time -s PhoneShareService PhoneShareApi   # on the phone that shares itself (from build 19)
```

ビルド 19 から、DLNA クライアント、電話の共有、Apple の空間メディアの検出も、アプリ自身のログ（右上のプロフィール画像のメニューにあるログ）に、`Ssdp`、`DlnaFileSystem`、`NetworkBrowserPage`、`PhoneShare`、`PhoneShareServer`、`AppleSpatialService`、`HeicStereoProbe`、`NetworkMediaService` として記録します。ビルド 20 からは、テレビモードが `TvMode` と `TvTextEntry`、Plex サーバーが `Gdm`、`UdpTransport`、`PlexClient`、`PlexFileSystem`、`PlexServerEditPage`、Tapo カメラが `TapoDiscovery`、`TapoHttps`、`TapoLogin`、`TapoControl`、`TapoMedia`、`TapoFileSystem`、`TapoTest`、`TapoCamera`、`CameraPage`、`CameraEditPage`、`CameraLiveView` として記録します。Plex の行にトークン、アドレス、タイトルが含まれることはなく、カメラの行にはパスワードを含めません。ログの行は、自分でコピーしない限りデバイスの外に出ません。

パソコン（Immuch360 Desktop）では、ログページに「ログをファイルに保存」もあります：ログ、またはクラッシュがあった場合はログと直近のクラッシュレポートの ZIP です（その場合、提案される名前の末尾は「with-crash-reports」になります）。クラッシュレポートは小さなミニダンプです：スレッド、それが止まった場所、そして呼び出しをたどるのに必要なものだけを、プログラムファイルの名前付きで（フォルダーは含まず）記録します。アプリのメモリは含みません。共有する前にログを確認してください：サーバーのアドレスが含まれていることがあります。

<a id="privacy"></a>
## プライバシー

- **開発者には何も送られません**：アプリは選んだ Immich サーバー（と、地図を開いたときはそのサーバーが使う地図タイルのサービス）と通信します。広告、分析、開発者が運営するクラッシュレポートのサービスはなく、Immuch360 の開発者には何も送信しません。
- **サーバーなし**の場合、どのサーバーにも接続しません：アプリがネットワークを使うのは、開いた共有、Plex サーバー、カメラと、オンにした場合の電話の共有だけです。
- **ネットワーク共有**：共有の一覧はデバイスに保存され、サーバーに送られることはありません。パスワードはデバイスのキーチェーンまたはキーストアに保存されます。
- **Plex**（ビルド 20 から）：トークンはデバイスの安全なストレージに保存され、HTTPS 上のリクエストヘッダーで自分のサーバーにだけ送られます。アプリが plex.tv に接続することはありません。
- **Tapo カメラ**（ビルド 20 から）：TP-Link アカウントのパスワードとカメラアカウントのパスワードはデバイスの安全なストレージに保存されます。アプリはローカルネットワーク上でだけカメラと通信し、TP-Link のサーバーとは通信しません。取得したクリップはアプリのキャッシュに残り、カメラと一緒に削除されます。
- **テレビ**：デバイスがテレビかどうかはデバイス上で判定し、何も送信しません。
- **電話の共有**：ローカルネットワークのみで、ユーザー名とパスワードを使い、平文の HTTP で通信します（[この電話をネットワークで共有](#share-this-phone-on-the-network) を参照）。
- **カメラ**：Spatial 2.5D プレーヤーだけがデバイス上で使います。画像は保存されることも、どこかに送信されることもありません。
- **パソコン**（Immuch360 Desktop、Windows プレビュー版）：アプリは選んだフォルダーだけを読み込み、インデックス、サムネイル、キャッシュをパソコンに保存し、パスワードとトークンを Windows のデータ保護で、あなたの Windows アカウント専用に保存します。パソコンの共有はスマートフォンの共有と同じルールに従い、Windows がパブリックとするネットワークや種類を判別できないネットワークでは、あなたが指示しない限り始まりません。

詳しいポリシーは [PRIVACY.md](../PRIVACY.md) にあります。

<a id="roadmap"></a>
## ロードマップ

まだ実現していないことを、可能性の高い順に並べています。ここにあるものは約束ではありません。[Issue トラッカー](https://github.com/freeKC/Immuch360/issues) でのフィードバックが、何を優先するかを決める助けになります。

- **Immuch360 Desktop、まず Windows から**：最初のプレビュー版を公開しました（[Windows パソコンで](#on-a-windows-computer-immuch360-desktop-preview) を参照）。次は動画の再生（まず平面の動画、次に 360°、3D、VR180、未加工のファイル）で、ノートパソコンの 2 つのグラフィックカードで計測します。その後、Windows パソコンでの各機能のテストと修正、ウェブカメラを使った Spatial 2.5D、そして Linux と macOS、パッケージ、署名、更新です。
- **Google Play**：ビルド 18 が公開中です。ビルド 19 に代えて、ビルド 20 が 2026 年 10 月 7 日から Google の審査中です。ビルド 21 では、スマートフォンとタブレットについては何も変わりません。
- **App Store**：バージョン 3.3.0 が Apple の審査待ちです。ビルド 11 の機能が含まれているため、Immich へのアップロードと動画デコーダーのチェック（ビルド 15）、Insta360 の RAW ファイル（ビルド 16）は次の App Store のアップデートで届きます。公開されたらリンクをここに追加します。
- **Meta Horizon Store**：Meta は 2026 年 10 月 7 日にビルド 14 で掲載を承認しました。ビルド 21 を最初のアップデートとして提出しています：ビルド 14 以降のすべて（共有から Immich へのアップロード、ヘッドセットがデコードできるものに応じた動画ソースの選択、Insta360、GoPro、DJI の RAW ファイル、DLNA、スマートフォンの共有、Apple の空間写真、Plex Media Server のライブラリ、Tapo カメラ）が含まれ、ストアでは Quest 2、Quest Pro、Quest 3、3S を対象としています。ページが公開されたら、ストアのリンクをここに追加します。サイドロードしたものは先にアンインストールする必要があります（[インストール](#install) を参照）。
- **ストアの掲載文**：Google Play の掲載文は 2026 年 10 月に新しいスクリーンショットとともに書き直しており、テレビ向けリリースに合わせてテレビのスクリーンショットとテレビ用バナーを追加します。App Store の説明文はまだ初期のビルド（360° の写真と動画、RAW ファイルは平面表示）を説明しています。今後は 3D、VR180、Spatial のビューアー、サーバーなしのモード、ネットワーク共有、メディアプレーヤー、Insta360 の RAW ファイルを紹介します。Meta Horizon Store の説明文では、すでにメディアプレーヤーを紹介しています。
- **カメラの RAW 360° ファイル、次の作業**：ヘッドセット用に RAW 写真を準備している間の進行状況インジケーター。GoPro と DJI の動画の、それぞれのモーションデータによる水平補正。デュアル魚眼の .dng。継ぎ目とデコーダーの余裕を確認するための、ビルド 18 の 2 つのレンズの再生に関する実機での報告（X4、X5、X6、GoPro MAX 2、Osmo 360）。
- **DLNA、電話の共有、Apple の空間メディア、次の作業**：ビルド 19 の実機での報告（DLNA での Plex、Jellyfin、NAS、Freebox Server。テザリングを含め Quest に配信するスマートフォン。ヘッドセットでの実際の iPhone の空間写真と空間ビデオ）。iPhone がすべての DLNA サーバーを見つけられるよう Apple に申請しているマルチキャストのエンタイトルメント。ヘッドセットでの空間写真間の前へと次へ。タイムラインでのサーバーの写真への空間バッジ。デコーダーが対応していれば、Quest での空間ビデオの 3D 表示。
- **スマートフォンの 360° プレーヤー、次の作業**：iOS の 360° 動画プレーヤーのタイムバー（Android 版にはあります）、Quest のイマーシブビューのような、スマートフォンの 360° プレーヤーでの前へ・次へ、ネイティブの 360° 動画プレーヤーでの写真の表示。
- **ネットワーク共有、次の作業**：写真と動画の画面で、フォルダー内のファイルから次のファイルへのスワイプ（Quest のイマーシブビューはすでにフォルダー内の 360° ファイルを移動できます）、WebDAV の Digest 認証、Bonjour のレコードからのユーザー名の取得。
- **平面の動画**：サーバー、デバイス、共有のどの動画でも、平面のプレーヤーで音声トラックを選べるようにすること（360° と Spatial のプレーヤーにはあります）。
- **Android TV、次の予定**：Google TV エミュレーターと実際のテレビでのビルド 20 のデバイステスト、続いて Google Play でのテレビ向けリリース（テレビのスクリーンショット、テレビ用バナー、Google の審査）。その後、テレビのホーム画面のチャンネル。
- **Tapo カメラ、次の予定**：実際のカメラでのビルド 20 のデバイステスト、iPhone と iPad でのライブ映像、H.265 の録画、取得中のクリップの再生、1 日分の録画を 1 本のタイムラインで表示。
- **Plex、次の予定**：ビルド 20 のデバイステスト（スマートフォン、Quest、iPhone、テレビ、外出先）、QR コードでのコンピューターからのトークンの受け渡し、見つかったサーバーの一覧で Plex サーバーの DLNA 側を隠すこと、IPv6。
- **アップストリーム**：360° 写真ビューアーから始めて、メンテナーが望む部分について Immich に小さなプルリクエストを送ること。
