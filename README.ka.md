## 360° ფოტოები და ვიდეოები სფეროს სახით

თქვენ ფოტოების მარქაფს ინახავთ [Immich](https://github.com/immich-app/immich) სერვერზე და ზოგიერთი მათგანი 360° კამერით ან ტელეფონის სფერული ფოტოს რეჟიმით არის გადაღებული. ოფიციალურ მობილურ აპში ეს სურათები ბრტყელ, გაწელილ ზოლად ჩანს და 360° ვიდეოებიც ბრტყლად იკვრება. Immich-ის ვებ აპს შეუძლია 360° ფოტოს სფეროს სახით ჩვენება, მობილურ აპს კი არა: ამას 2024 წლის იანვრიდან ითხოვენ [დისკუსიაში #6572](https://github.com/immich-app/immich/discussions/6572).

Immuch360 მათ სფეროს სახით ხსნის, რომელშიც ირგვლივ მიმოიხედავთ, Android და iOS ტელეფონებსა და პლანშეტებზე. ფოტო ბრუნავს, როცა მას გადაათრევთ, დიდდება თითებით ან ორმაგი შეხებით, სწრაფი გადათრევის შემდეგ კიდევ ცოტას ბრუნავს, იხსნება კამერის მიერ ჩაწერილ საწყის ხედზე (GPano მეტამონაცემები) და გადიდებისას უფრო მკაფიო ტექსტურას იღებს; ნაწილობრივი პანორამებიც მუშავდება (GPano ჩამოჭრა). ვიდეო იკვრება ჩაშენებულ სფერულ პლეერში ხმით, გადათრევით და გიროსკოპით. უკვე შეკერილი 360° ფაილები ყველგან მუშაობს: ექსპორტები Insta360 აპიდან ან Studio-დან, GoPro Player-იდან, Ricoh Theta-დან და ტელეფონის სფერული ფოტოები. პირდაპირ კამერიდან აღებულ დაუმუშავებელ ფაილებს აპი კერავს, იხილეთ [კამერების დაუმუშავებელი 360° ფაილები](#raw-360-camera-files-without-the-cameras-app).

### 360° ფოტოს გახსნა სფეროს სახით

1. გახსენით ფოტო ქრონოლოგიიდან, ალბომიდან, [360° სიიდან](#find-your-360-shots-the-360-list) ან გაზიარების საქაღალდიდან. 360° ფოტოების მინიატურებს 360° ნიშანი აქვს.
2. შეეხეთ 360°-ს მნახველის ზედა ზოლში. იხსნება სფერული მნახველი ჩატვირთვის მაჩვენებლით, სანამ სრული სურათი იტვირთება; ბრტყელ ხედში არსებული გადიდება ნარჩუნდება.
3. ირგვლივ მიმოსახედად გადაათრიეთ, გასადიდებლად თითებით გაშალეთ, მისაახლოებლად ორჯერ შეეხეთ. სწრაფი გადათრევის შემდეგ ხედი კიდევ ცოტას ბრუნავს და ნელდება.
4. ტელეფონის მობრუნებით მიმოსახედად შეეხეთ გიროსკოპის ღილაკს ზედა მარჯვენა კუთხეში (ნაგულისხმევად გამორთულია).
5. ზედა მარჯვენა კუთხის დანარჩენი ორი ღილაკია 360°/180° (სრული სფერო ან VR180 ნახევარსფერო, ნაწილობრივ პანორამებზე არ ჩანს) და 3D (სტერეოსკოპიული ფოტოს განლაგება), იხილეთ [3D და VR180](#3d-and-vr180-photos-and-videos). დაუმუშავებელ Insta360 ფოტოს მხოლოდ გიროსკოპი აქვს.
6. დახურეთ ზედა მარცხენა კუთხის ჯვრით.

### 360° ვიდეოს დაკვრა

1. გახსენით ვიდეო და შეეხეთ 360°-ს ზედა ზოლში. 360° ვიდეოზე 360° ღილაკი პირველია; ტელეფონებსა და პლანშეტებზე მას Spatial ღილაკი მოსდევს, სანამ ეს პარამეტრი ჩართულია (იხილეთ [Spatial 2.5D](#depth-on-a-flat-screen-spatial-25d-experimental)).
2. ჩაშენებული 360° პლეერი სრულ ეკრანზე იხსნება და ხმით უკრავს: Android-ზე Media3, iOS-ზე SceneKit.
3. ირგვლივ მიმოსახედად გადაათრიეთ ან ამოძრავეთ ტელეფონი. Android-ის პლეერი ყოველთვის მიჰყვება ტელეფონს; iOS-ის პლეერს აქვს გიროსკოპის გადამრთველი, ნაგულისხმევად ჩართული.
4. მართვის ღილაკებისთვის შეეხეთ სურათს: ზემოთ დახურვა, 360°/180° და 3D, შემდეგ დაკვრა, გადახვევის ღილაკები და Android-ზე დროის ზოლი. iOS-ის პლეერს ჯერჯერობით მხოლოდ დაკვრა და პაუზა აქვს.
5. როცა ვიდეოს ორი ან მეტი აუდიო ტრეკი აქვს (ენები, კომენტარი), „აუდიო ტრეკი“ ღილაკით შეგიძლიათ ერთ-ერთის არჩევა. სანამ ვიდეო იტვირთება ან ჩერდება, პლეერი აჩვენებს „იტვირთება“ წარწერას თავისი დაკვრის ბუფერის შევსებით.

პლეერი უკრავს ტელეფონზე შენახულ ფაილს ან ქსელური გაზიარების ფაილს, თუ ასეთი არსებობს. წინააღმდეგ შემთხვევაში ნაკადს თქვენი სერვერიდან იღებს: ნაგულისხმევად ტრანსკოდირებულ ნაკადს, ან ორიგინალს, თუ ამას მოითხოვთ მორგება, Asset Viewer (აქტივების მნახველი), „ვიდეოს წყარო“ განყოფილებაში (ბილდ 15-დან; მანამდე „Force original video“ (ორიგინალი ვიდეოს იძულებით დაკვრა) გადამრთველი), იხილეთ [ვიდეოს დეტალები და დეკოდერები](#video-details-decoders-and-why-a-video-stutters).

### 360° ფაილი, რომელიც ბრტყლად ჩანს: ნახვა 360°-ად

ზოგიერთ 360° ფაილს პროექციის ტეგი არ აქვს, ამიტომ სერვერი მათ 360°-ად არ მონიშნავს და ისინი ბრტყლად ჩანს.

1. გახსენით ფოტო ან ვიდეო და შეეხეთ ⋮-ს ზედა მარჯვენა კუთხეში.
2. შეეხეთ „ნახვა 360°-ად“ პუნქტს, რომელიც სლაიდშოუსა და გადმოწერას შორისაა. 360° ღილაკი ზედა ზოლში ჩნდება.
3. გასაუქმებლად იგივე პუნქტი ახლა ამბობს „აღარ ჩაითვალოს 360°-ად“.

არჩევანი ტელეფონზე ინახება და სერვერზე არაფერს ცვლის. ქსელური გაზიარების ფაილზე ის მხოლოდ მიმდინარე ნახვისთვის მოქმედებს.

### შეზღუდვები

- **iOS-ის 360° ვიდეო პლეერი**: დაკვრა და პაუზა, დროის ზოლი ჯერ არ არის.
- **წინა და შემდეგი**: ტელეფონების 360° პლეერები ჯერ არ გადადიან წინა ან შემდეგ მედიაზე; Quest-ის იმერსიული ხედი გადადის.

3. შეეხეთ სერვერს: ტიპი, სერვერი, პორტი და გზა ივსება.
4. სიაში არ არის? შეავსეთ ფორმა ხელით. ტიპი: „SMB (Samba, Windows-ის გაზიარება)“, „WebDAV (Nextcloud, Synology და სხვა)“ ან „DLNA მედია სერვერი (Plex, Jellyfin, NAS, TV ბოქსი)“. შემდეგ სახელი, „სერვერის სახელი ან მისამართი“ (სახელი ან მისამართი; სრული მისამართი, როგორიცაა `smb://nas/photos`, `\\nas\photos` ან `https://nas:5006/photos`, დანარჩენ ველებს ავსებს), „პორტი (არასავალდებულო)“, როცა ის ჩვეულებრივი არ არის, „გაზიარება“ SMB-სთვის ან „WebDAV მისამართის გზა“ WebDAV-ისთვის, „საწყისი საქაღალდე (არასავალდებულო)“, „მომხმარებლის სახელი“ და „პაროლი“, და „დაცული კავშირი (HTTPS)“ WebDAV-ისთვის.
5. SMB: სერვერისა და მომხმარებლის სახელის აკრეფის შემდეგ „აირჩიეთ გაზიარება“ სერვერის გაზიარებებს ჩამოთვლის.
6. DLNA: მედია სერვერს არც მომხმარებლის სახელი აქვს და არც პაროლი. მიუთითეთ სერვერი, პორტი და მისი მოწყობილობის აღწერის „აღწერის გზა“ (minidlna-სთვის `/rootDesc.xml`), ან სერვერის ველში ჩასვით სრული მისამართი, მაგალითად `http://192.168.1.10:8200/rootDesc.xml`.
7. შეეხეთ „კავშირის შემოწმება“-ს. პასუხია „დაკავშირებულია, საწყის საქაღალდეში N ელემენტია“, ან ახსნა, თუ რატომ ვერ მოხერხდა. შემდეგ შეეხეთ შენახვას ფორმის ბოლოში.

ცარიელი პაროლით მომხმარებლის სახელი ისე იგზავნება, როგორც არის: Freebox Server-ს თავისი დისკებისთვის `freebox` და პაროლის გარეშე სჭირდება. გაზიარების მოგვიანებით შესაცვლელად ან წასაშლელად გამოიყენეთ ფანქარი მის გვერდით ქსელური გაზიარებების გვერდზე.

### დათვალიერება და დაკვრა

1. შეეხეთ გაზიარებას. ჯერ საქაღალდეებია, შემდეგ ფოტოები და ვიდეოები მინიატურების ბადეში (ასევე თითოეული ვიდეოს ერთი კადრი, მოწყობილობის ქეშში შენახული). 360°-ად ამოცნობილებს 360° ნიშანი აქვთ, ხოლო ბილდ 19-დან Apple-ის სივრცით ფოტოებსა და ვიდეოებს 3D ნიშანი. განსაახლებლად ქვემოთ ჩამოწიეთ.
2. შეეხეთ ფოტოს: ის სრულ ეკრანზე იხსნება (თითებით გადიდება, ორმაგი შეხება), და მისი 360° ღილაკი სფერულ მნახველს ხსნის.
3. შეეხეთ ვიდეოს: ის ჩაშენებულ პლეერში იკვრება (დაკვრა, პაუზა, გადახვევა), 360° ღილაკით, რომელიც 360° პლეერს ხსნის მისი 3D და 360°/180° ღილაკებით, ხოლო ტელეფონზე სტერეოსკოპიული ფაილებისთვის Spatial ღილაკით.
4. Quest 3-ზე 360° ღილაკი იმერსიულ ხედს ხსნის, ხოლო ბილდ 19-დან „ნახვა 3D-ში“ Apple-ის სივრცით ფოტოს 3D-ში ხსნის.
5. ⋮ მენიუში არის „ნახვა 360°-ად“ 360° ტეგის არმქონე ფაილებისთვის, ხოლო ტელეფონზე „Spatial 2.5D“ არასტერეოსკოპიული ვიდეოებისთვის.

360°, 3D და VR180 ამოიცნობა ფაილის GPano ან სფერული მეტამონაცემებიდან, რომლებიც დიაპაზონის მოთხოვნებით (range requests) იკითხება, ხოლო VR180 ასევე ფაილის სახელიდან. ბილდ 16-დან ამოიცნობა დაუმუშავებელი Insta360 ფაილებიც (.insp ფოტო სახელით ან კამერის კალიბრაციის ბლოკით, .insv ვიდეო სახელითა და კადრით) და იკერება.

### გაზიარების ფაილების გაგზავნა Immich-ში

ბილდ 15-დან, როცა სერვერთან ხართ დაკავშირებული:

1. გაზიარების საქაღალდეში ხანგრძლივად დააჭირეთ ფოტოს ან ვიდეოს, ან შეეხეთ არჩევას ზედა მარჯვენა კუთხეში.
2. მონიშნეთ, რაც გსურთ, ან გამოიყენეთ „ამ საქაღალდის ყველა ფოტოსა და ვიდეოს არჩევა“.
3. შეეხეთ „Immich-ზე ატვირთვა“-ს. ფაილები გაზიარებიდან თქვენს სერვერზე სათითაოდ გადაიცემა, თითოეულ ფილაზე პროგრესით, ხოლო ქვედა ზოლში წერია „იგზავნება 3 / 12“ გაუქმების ღილაკით. გაგზავნისას აპი ღია დატოვეთ.
4. ბოლოს აპი გეუბნებათ, რამდენი გაიგზავნა და რამდენი იყო უკვე სერვერზე: სერვერი საკუთარ ასლს ინახავს და უკვე არსებული ფაილების დუბლიკატებს შლის. ადრე გაგზავნილ ფაილებს ნიშანი აქვთ („ადრე გაიგზავნა Immich-ზე“) და შემდეგ ჯერზე გამოიტოვება.

გაზიარებიდან გახსნილ ფოტოს ან ვიდეოს მის მენიუში იგივე პუნქტი აქვს. სერვერის გარეშე გვერდზე წერია „ასატვირთად დაუკავშირდით Immich სერვერს“. მოწყობილობის ფოტოები და ვიდეოები იგივე გზით იგზავნება ბიბლიოთეკის ჩანართიდან: On this device, ალბომი, არჩევა, „Immich-ზე ატვირთვა“, მათ შორის იმ ალბომებიდან, რომლებიც მარქაფის არჩევანში არ შედის; გაგზავნის შემდეგ ისინი დამარქაფებულად ითვლება.

### როგორ იკვრება ჩამოტვირთვის გარეშე

პლეერები საჭირო ბაიტებს აპის შიგნით არსებული ხიდის მეშვეობით კითხულობენ (მხოლოდ loopback მისამართი, შემთხვევითი ტოკენი თითოეული სესიისთვის, ბაიტების დიაპაზონები), ამიტომ ვიდეოში გადახვევა მუშაობს და მოწყობილობაზე არაფერი კოპირდება. პლეერები და ჩაფხუტის მნახველი გაზიარების მისამართს არასოდეს იღებენ, მხოლოდ ხიდის 127.0.0.1-ს; სერვერთან მოთხოვნებს თავად აპი აგზავნის. გლუვი დაკვრისთვის გაზიარება დიდი ბლოკებით იკითხება, ფაილი წაკითხვებს შორის ღია რჩება, პლეერზე წინ 16 მბ-მდე იკითხება და დაკვრადი ვიდეო ექვსამდე პარალელური SMB კავშირით იკითხება, ცალკე იმ კავშირისგან, რომელიც მინიატურებსა და სიებს ემსახურება. Freebox Server თითოეულ წაკითხვაზე ნელა პასუხობს: ერთი კავშირი 4,5 მბ/წმ-ს იძლევა, ექვსი 19 მბ/წმ-ს, რაც საკმარისია 132 მბიტ/წმ-იანი 5.7K ექსპორტისთვის. სანამ პლეერი მონაცემებს ელოდება, 360° და Spatial პლეერები აჩვენებენ „იტვირთება“ წარწერას თავიანთი დაკვრის ბუფერის შევსებით; ბრტყელი პლეერი „იტვირთება“ წარწერას პროცენტის გარეშე აჩვენებს, სანამ ვიდეო იტვირთება ან ჩერდება.

### DLNA მედია სერვერები

ბილდ 19-დან აპი მედია სერვერების SSDP ძიებას ქსელის multicast ჯგუფს უგზავნის და იგივე მოთხოვნას ლოკალური /24 ქსელის ყველა მისამართის 1900 პორტზე, შემდეგ კითხულობს ყოველი მოპასუხე სერვერის მოწყობილობის აღწერას და ინარჩუნებს მათ, რომლებიც თავიანთ კონტენტს აქვეყნებენ (ContentDirectory). საქაღალდეები და ფაილები სერვერის Browse მოქმედებით ჩამოითვლება, გვერდ-გვერდ, და მათი სათაურებით სახელდება: ფაილი თავისი ტიპის გაფართოებას იღებს, როცა სათაურს არ აქვს, და საქაღალდეში იგივე სათაურის მეორე ფაილი `name (2)` ხდება. აუდიო გამოირიცხება. მინიატურები ალბომის ყდებია ან სერვერის მიერ შექმნილი პატარა სურათები, რომლებსაც თავად აპი ტვირთავს, ხოლო როცა სერვერს ისინი არ აქვს, აპის საკუთარი მინიატურა გამოიყენება. ფაილი იკვრება სერვერის მიერ შეთავაზებული ორიგინალიდან, და არა გარდაქმნილი ასლიდან, როცა სერვერი ორივეს სთავაზობს, დიაპაზონის მოთხოვნებით იკითხება, ამიტომ გადახვევა მუშაობს. შემოწმებულია minidlna-სა და Gerbera-ზე; აღმოჩენა ნამდვილ ქსელში, Plex, Jellyfin, NAS, Freebox Server, iPhone და Quest ბილდ 19-ის მოწყობილობაზე ტესტირებაა.

### გადაადგილებული გაზიარება

ბილდ 19-დან DLNA გაზიარება და ტელეფონის გაზიარება (იხილეთ [ამ ტელეფონის გაზიარება ქსელში](#share-this-phone-on-the-network)) ინარჩუნებენ იმ იდენტიფიკატორს, რომელსაც მათი სერვერი აცხადებს. როცა ერთ-ერთი მათგანი თავის მისამართზე აღარ პასუხობს (როუტერმა ახალი მისამართი მისცა, სერვერი სხვა პორტზე გადაიტვირთა), მისი საქაღალდის გვერდი აჩვენებს „(სახელი)-ის ძიება ქსელში“ და გაზიარებას იქ გადაიტანს, სადაც ის ახლა პასუხობს: DLNA სერვერის შემთხვევაში დაუყოვნებლივ, რადგან მას პაროლი არ აქვს, ხოლო მომხმარებლის სახელითა და პაროლით დაცული გაზიარების შემთხვევაში დადასტურების შემდეგ („გამოვიყენოთ ახალი მისამართი?“), რომელიც ორივე მისამართს აჩვენებს, რადგან ისინი ახალ მისამართზე გაიგზავნებოდა.

- **DLNA**: სერვერი, რომელიც ფაილის მხოლოდ გარდაქმნილ ასლს სთავაზობს, სწორედ ამ ასლს იძლევა; საქაღალდე მაქსიმუმ 20 000 ელემენტს ჩამოთვლის.

## ამ ტელეფონის გაზიარება ქსელში

თქვენი ფოტოები და ვიდეოები ტელეფონზეა და გსურთ მათი ნახვა ჩაფხუტში, კომპიუტერის, NAS-ის ან Immich სერვერის გარეშე. ბილდ 19-დან ტელეფონი, Android ან iPhone, Wi-Fi-ით საკუთარ ფოტოებსა და ვიდეოებს ემსახურება, ხოლო Meta Quest 3 მათ უკრავს. Immich აპს მსგავსი არაფერი აქვს.

### ჩართვა ტელეფონზე

1. გახსენით ბიბლიოთეკის ჩანართი, შემდეგ ქსელური გაზიარებები. პირველი ფილაა „ამ ტელეფონის გაზიარება ქსელში“ (წერია „გამორთულია“, ან „ჩართულია“ მისამართით).
2. შეეხეთ მას, შემდეგ ჩართეთ „ფოტოებისა და ვიდეოების გაზიარება Wi-Fi-ით“. აპი ითხოვს ფოტოებისა და ვიდეოების ნებართვას, თუ ის აკლია, ხოლო Android 13-დან ასევე შეტყობინებების ნებართვას.
3. გვერდი აჩვენებს მისამართს (მაგალითად `http://192.168.1.20:8360`: პორტი 8360, ან სხვა თავისუფალი, თუ ის დაკავებულია), სახელს, რომლითაც ტელეფონი ცხადდება („Immuch360 on“ და ტელეფონის სახელი), მომხმარებლის სახელს (`phone` და ოთხი ციფრი) და პაროლს (რვა სიმბოლო), თითოეულს კოპირების ღილაკით, შემდეგ „N მოწყობილობა დაკავშირებულია“ (მოწყობილობები, რომლებმაც ის ბოლო წუთში გამოიყენეს) ბოლოს მიწოდებული ფაილით.

მომხმარებლის სახელი და პაროლი ერთხელ იქმნება და ინახება, ამიტომ ჩაფხუტი თავის შენახულ გაზიარებას ინარჩუნებს; „ახალი პაროლი“ პაროლს ცვლის. ეს ფილა ჩაფხუტზე არ ჩანს.

### გახსნა ჩაფხუტში

1. ჩაფხუტში გახსენით ბიბლიოთეკა, ქსელური გაზიარებები, შემდეგ +.
2. „ნაპოვნია ქსელში“ ქვეშ შეეხეთ ტელეფონს: მომხმარებლის სახელი ივსება.
3. ერთხელ აკრიფეთ პაროლი (ჰარები და მთავრული ასოები მნიშვნელობა არ აქვს), შემდეგ შენახვა.

ამის შემდეგ ეს ჩვეულებრივი WebDAV გაზიარებაა: 360° ამოცნობა, დაუმუშავებელი ფაილები, იმერსიული ხედი, ვიდეოებში გადახვევა. ქსელის ნებისმიერ WebDAV კლიენტსაც შეუძლია მისი წაკითხვა. როცა ტელეფონი სხვა მისამართს იღებს, ჩაფხუტი მას ეძებს და ახალი მისამართის გამოყენებამდე გეკითხებათ (იხილეთ [გადაადგილებული გაზიარება](#a-share-that-moved)).

X3 წყვილის ორი ფაილი ერთად შეინახეთ: აპი მეორე ფაილს პირველის გვერდით ეძებს, მოწყობილობაზე, სერვერზე ან გაზიარების საქაღალდეში. როცა მეორე აკლია, აპი ამბობს „ეს ჩანაწერი ორ ფაილად არის დაყოფილი, თითო ობიექტივზე ერთი, და (სახელი) მის გვერდით ვერ მოიძებნა“ და გთავაზობთ ორივე ფაილის ერთად შენახვას ან ვიდეოს კამერის აპიდან ექსპორტს.
3. გახსენით ფაილი და შეეხეთ 360°-ს. დაუმუშავებელი ფაილები 360° ღილაკს იღებენ, დაუმუშავებელი ფოტოები კი 360° ნიშანს. ბილდ 18-დან სერვერის დაუმუშავებელი Insta360 ფაილებიც 360° სიაშია, სახელით ნაპოვნი.
4. ფოტო სფერულ მნახველში იხსნება ქვემოთ წარწერით: „დაუმუშავებელი 360° ფაილი, აპის მიერ შეკერილი“, და კალიბრაციის წყარო: „ფაილიდან წაკითხული ობიექტივების კალიბრაცია“, „იმავე კამერის ობიექტივების კალიბრაცია“ (შენახული იმავე კამერის სხვა ფაილიდან, სერიული ნომრით, ან მოდელით იმ ფაილისთვის, რომელიც მხოლოდ თავის მოდელს ასახელებს), ან „ობიექტივების ნომინალური მნიშვნელობები, შესაძლოა ნაკერები ჩანდეს“ (X3-ის მნიშვნელობები, როცა უკეთესი არაფერია).
5. ვიდეო ჩაშენებულ 360° პლეერში იხსნება და დაკვრისას იკერება. მისი 3D და 360°/180° ღილაკები დამალულია, რადგან დაუმუშავებელი ვიდეო ერთი სრული სფეროა. ვიდეო პლეერები და ჩაფხუტი წარწერას არ აჩვენებენ.
6. ჩაფხუტში იმერსიული ხედი ფოტოსთვის შეკერილ დროებით სურათს იღებს, ხოლო ვიდეოსთვის იგივე GPU ეფექტს, რაც ტელეფონზე. დაუმუშავებელი ფოტოს მომზადებისას პროგრესის მაჩვენებელი ჯერ არ არის.
7. თუ სურათი უცნაური მიმართულებით იხსნება (მაგალითად, ფოტო, რომელიც ბრტყლად დადებული კამერით არის გადაღებული), ტელეფონზე გადაათრიეთ, ხოლო ჩაფხუტში მოაბრუნეთ მარჯვენა ჯოისტიკით ან შემობრუნების ღილაკით.

### როცა მოწყობილობას ორივე ობიექტივის დაკვრა არ შეუძლია

ორობიექტივიანი ვიდეოს დაკვრამდე აპი მოწყობილობას ეკითხება, შეუძლია თუ არა ამ ზომისა და სიხშირის ორი დეკოდერის გაშვება, და როცა პასუხი უარყოფითია, ტელეფონი გაფრთხილებს: „ამ დაუმუშავებელ ვიდეოს ერთდროულად ორი (ზომა) ვიდეოდეკოდერი სჭირდება: ამ მოწყობილობაზე შეიძლება შეუფერხებლად არ დაიკრას“. როცა დეკოდერებს მუშაობა არ შეუძლიათ (მაგალითად, ორი 2880x2880 H.264 ობიექტივი Quest 3-ზე), აპი ერთ ობიექტივს უკრავს და ამას გეუბნებათ, სფეროს ნახევარი შავი რჩება, შემდეგ კი სერვერის ტრანსკოდირებულ ნაკადს, თუ ის არსებობს. თუ GPU ეფექტს მოწყობილობაზე მუშაობა არ შეუძლია, ვიდეო შეკერვის გარეშე იკვრება, ორი წრე სფეროზე, შეტყობინებით „360°-ის შეკერვა ამ მოწყობილობაზე ვერ მოხერხდა“.

ბილდ 19-დან, Android-სა და Quest-ზე:

- **კოდეკისთვის აპარატული დეკოდერი არ არის** (ემულატორი, TV ბოქსი): მოწყობილობა პროგრამულ დეკოდერებს იღებს, რომლებსაც შემოწმება თითო ობიექტივზე 2048x2048-ით ზღუდავს, როცა ორი ერთდროულად მუშაობს.
- **ობიექტივი, რომლის დეკოდირებაც მოწყობილობას საერთოდ არ შეუძლია** (მისი კოდეკისთვის დეკოდერი არ არის, ან არცერთი არ ჩამოთვლის მის პროფილს), ერთი ობიექტივის ეტაპს გამოტოვებს და გადადის სერვერის ტრანსკოდირებულ ნაკადზე, ან, თუ ის არ არის, შეუკერავ ორიგინალზე უბრალო პლეერში, ამ პლეერის საკუთარი შეტყობინებით.
- **ობიექტივი, რომელიც იცდება, მიუხედავად იმისა, რომ მისი ზომა ან სიხშირე უარყოფილი იყო**, ერთი ობიექტივის შეტყობინებას მხოლოდ მისი პირველი კადრის დახატვის შემდეგ აჩვენებს.

### როგორ მუშაობს შეკერვა

- **რას კითხულობს აპი**: კალიბრაციის ბლოკს, რომელსაც კამერა თითოეული ფაილის ბოლოს ამატებს (ობიექტივის მოდელი, ცენტრები, თითოეული ობიექტივის ორიენტაცია, კალიბრაციის ტილოს ზომა), და აქსელერომეტრის ჩანაწერს, რომელიც ჰორიზონტის გასასწორებლად გამოიყენება. ჯერ გამოიყენება კალიბრაციის სტრიქონ V3-ის Mei (ერთიანი კამერის) მოდელი, შემდეგ V6 (X6 და უფრო ახალი პროგრამული უზრუნველყოფა) თავისი პირველი წევრებით, ბოლოს ძველი ეკვიდისტანტური სტრიქონი V1. როცა ფაილს თავისი კალიბრაცია აქვს, კამერის მოდელიდან არაფერი ივარაუდება. Insta360 X5-ისა და X6-ის კალიბრაცია (V6, ინდექსირებული ბოლოსართი) და X4-ის ვიდეო ფანჯარა ფაილიდან იკითხება.
- **საიდან კითხულობს**: სერვერიდან (ორიგინალი ფაილი, რომლის ბოლო ბაიტები დიაპაზონის მოთხოვნით იკითხება), მოწყობილობის საკუთარი გალერეიდან და გაზიარებებიდან.

## 3D და VR180 ფოტოები და ვიდეოები

Immich აპში სტერეოსკოპიული 360° ფოტო ან ვიდეო ორივე თვალს ერთდროულად აჩვენებს, ორმაგ სურათს, ხოლო VR180 ფაილი, რომელიც მხოლოდ წინა ნახევარს ფარავს, მთელ სფეროზეა გაწელილი.

Immuch360 3D განლაგებებს, ზემოთ და ქვემოთ ან გვერდიგვერდ, ფაილიდან ამოიცნობს (ვიდეოს st3d ყუთიდან), ან კადრის ფორმიდან ვარაუდობს, და ყველა მნახველს აქვს 3D ღილაკი მათ შესაცვლელად. ტელეფონი მარცხენა თვალს აჩვენებს; Meta Quest 3 თითოეულ თვალს თავის ნახევარს აჩვენებს, ნამდვილ 3D-ში. VR180 ფაილები ნახევარსფეროზე იხატება, უკანა მხარე შავია გაწელილი სურათის ნაცვლად. ისინი ფაილიდან ამოიცნობა (სფერული საზღვრები ან ბადე, GPano ჩამოჭრა) ან სახელში „vr180“-ის ან „180“-ის მიხედვით, და ყველა მნახველს აქვს 360°/180° ღილაკი.

### განლაგების ან დაფარვის შეცვლა

1. გახსენით ფოტო ან ვიდეო სფეროს სახით (360° ღილაკი).
2. 3D ღილაკი რიგრიგობით ცვლის „მონო (არა 3D)“, „3D, ზემოთ და ქვემოთ“ და „3D, გვერდიგვერდ“ ვარიანტებს; მისი მინიშნება მიმდინარე განლაგებას ასახელებს.
3. 360°/180° ღილაკი „360°, სრული სფერო“-სა და „180°, ნახევარსფერო (VR180)“-ს შორის გადართავს. ნაწილობრივ პანორამებზე არ ჩანს.
4. ჩაფხუტში იგივე ორი ღილაკი იმერსიული ხედის საინფორმაციო პანელზეა.

360°/180° არჩევანი მოწყობილობაზე ბიბლიოთეკის მედიისთვის ინახება, ქსელური გაზიარების ფაილისთვის კი ჯერ არა. 3D არჩევანი მნახველის დახურვისას არ ინახება: შემდეგ ჯერზე ისევ ფაილის მიერ გამოცხადებული ან ნავარაუდევი განლაგება გამოიყენება (ქვემოთ აღწერილი Spatial 2.5D პლეერი საკუთარს ინახავს).

შემოწმებულია Galaxy S24+-სა და Quest 3-ზე ნამდვილი 3D 360° სანიმუშო ვიდეოებით (VRTogether, Vuze, Kandao) და 3D ფოტოთი; VR180 Android ემულატორსა და Galaxy S24+-ზე სინთეტიკური მედიით. სხვა კამერებიდან ანგარიშები მისასალმებელია.

## სიღრმე ბრტყელ ეკრანზე: Spatial 2.5D (ექსპერიმენტული)

სტერეოსკოპიულ ვიდეოს ბრტყელ ეკრანზეც შეუძლია სიღრმის შეძენა. ვიდეოს ორი თვალი სიღრმეს იძლევა, წინა კამერა თქვენს თავს მიჰყვება, ხოლო აპი მათ შორის ხედს სინთეზირებს, ამიტომ ეკრანი სცენისკენ გახსნილი ფანჯარასავით იქცევა: თავი გაამოძრავეთ და ახლომდებარე საგნები ფონის მიმართ გადაინაცვლებს. მხოლოდ ტელეფონები და პლანშეტები.

### გამოყენება

1. შეამოწმეთ, რომ ჩართულია: მორგება, Asset Viewer, ვიდეოები, „Spatial 2.5D (ექსპერიმენტული)“. ნაგულისხმევად ჩართულია; მისი გამორთვა Spatial ღილაკს ყველგან აქრობს.
2. გახსენით ვიდეო. სანამ პარამეტრი ჩართულია, ზედა ზოლი ყველა ვიდეოზე Spatial ღილაკს აჩვენებს (მბრუნავი 3D ხატულა); ქსელური გაზიარების საქაღალდეში მას მხოლოდ სტერეოსკოპიული ფაილები იღებენ, დანარჩენებს კი Spatial 2.5D ⋮ მენიუში აქვთ.
3. შეეხეთ მას. წინა კამერის ნებართვა პირველად მოითხოვება; კამერა მხოლოდ ღილაკზე დაჭერის შემდეგ გამოიყენება.
4. ზედა მარჯვენა კუთხეში: აუდიო ტრეკი, როცა ვიდეოს ორი ან მეტი აქვს, მიმდინარე განლაგება (შეეხეთ სიისთვის: ავტომატური, არ არის სტერეოსკოპიული, გვერდიგვერდ, ზემოთ და ქვემოთ, ბოლო ორი ასევე გაცვლილი თვალებით), 360°/180° 360° ვიდეოზე, და ხელახლა ცენტრირება, რომელიც თქვენი თავის მიმდინარე პოზიციას ცენტრად იღებს.
5. ქვემოთ: დაკვრა, დროის ხაზი, შემდეგ თავის მოძრაობის მგრძნობელობა, სანამ თქვენი თავი თვალყურის დევნების ქვეშაა, და ხედვის წერტილის სლაიდერი L-დან R-მდე, რომელიც ხედვის წერტილს ხელით ამოძრავებს; ის ჩნდება, როცა თავის თვალყურის დევნება გამორთულია ან თქვენი სახე დაკარგა.
6. დახურეთ ჯვრით ან სისტემის „უკან“ ღილაკით.

როცა მორგება, დამატებით, პრობლემების გადაწყვეტა ჩართულია, პლეერი ზედა მარცხენა კუთხეში ფენას ამატებს (რენდერისა და დისპარიტეტის სიხშირეები, ხარისხის დონე, ხედვის წერტილი, თვალყურის დევნების მდგომარეობა), ხედვის წერტილის სლაიდერს ყოველთვის აჩვენებს და ამატებს „Disparity map“ (დისპარიტეტის რუკა) მოსანიშნ ველს, რომელიც სურათის ნაცვლად შეფასებულ სიღრმეს აჩვენებს.

### ფორმატები, კონფიდენციალურობა და შეზღუდვები

- **ფორმატები**: გვერდიგვერდ და ზემოთ და ქვემოთ, ასევე გაცვლილი თვალებით, სრული ან ნახევარი სიგანით, ბრტყელი, 360° და VR180. განლაგება ფაილიდან იკითხება, სხვა შემთხვევაში კადრის ფორმიდან ან ფაილის სახელიდან ივარაუდება (sbs, ou, tb და მსგავსი; ნახევარი სიგანის ფაილი მხოლოდ სახელით ამოიცნობა), და შეიძლება ხელით აირჩიოთ პლეერში. არჩევანი ბიბლიოთეკის ვიდეოსთვის ინახება, ქსელური გაზიარების ფაილისთვის კი არა.
- **კამერა**: სურათები მხოლოდ მოწყობილობაზე მუშავდება, არასოდეს ინახება და არასოდეს იგზავნება არსად. Quest 3-ის ბილდს საერთოდ არ აქვს კამერის ნებართვა (ჩაფხუტს არ აქვს კამერა, რომელიც აპს შეუძლია გამოიყენოს), და Spatial პლეერი იქ არ არის შეთავაზებული: მისი ღილაკი და პარამეტრი ჩაფხუტზე დამალულია.
- **შეზღუდვები**: ექსპერიმენტული, მხოლოდ ტელეფონები და პლანშეტები (არა Meta Quest-ზე), საჭიროებს OpenGL ES 3.0-ს ან Metal-ს. სიღრმე შეფასებაა. საუკეთესოდ მუშაობს ჰორიზონტალურ რეჟიმში კარგად განათებული სახით. შემოწმებულია Galaxy S24+-ზე; iPhone-ის გამოხმაურება მისასალმებელია.
- **სარეზერვო ვარიანტი**: თუ რამე არასწორად წავა (კამერა არ არის, მოწყობილობა არ არის მხარდაჭერილი, განლაგება ვერ იკითხება), ჩვეულებრივ პლეერს დაუბრუნდებით.

## Apple-ის სივრცითი ფოტოები და ვიდეოები

iPhone იღებს სივრცით ფოტოებსა და ვიდეოებს, და Immich სერვერი მათ შესახებ არაფერს ამბობს: Immich აპში ისინი ბრტყელი ფოტო ან ვიდეოა. ბილდ 19-დან Immuch360 მათ ფაილების წაკითხვით ამოიცნობს და Meta Quest 3-ში სივრცით ფოტოს 3D-ში აჩვენებს. ეს არ არის ზემოთ აღწერილი Spatial 2.5D პლეერი, რომელიც გვერდიგვერდ და ზემოთ და ქვემოთ ვიდეოებისთვისაა.

- **სივრცითი ფოტოები** HEIC ფაილებია (`.heic`, `.heif`, `.hif`), რომლებიც ორ სურათს შეიცავენ, თითო თვალზე, სტერეო წყვილად დაჯგუფებულს. აპი ფაილის თავს კითხულობს (მოწყობილობაზე, სერვერის ორიგინალს დიაპაზონის მოთხოვნით, ან ქსელური გაზიარების ფაილს) და პასუხს ტელეფონზე ინახავს, ამიტომ ფოტო მხოლოდ ერთხელ იკითხება.
- **სივრცითი ვიდეოები** (MV-HEVC) ვიდეო ტრეკიდან ამოიცნობა: მეორე ფენა და ორივე თვალი გამოცხადებული.

### სივრცითი ფოტოს ნახვა 3D-ში ჩაფხუტში

1. ჩაფხუტში გახსენით სივრცითი ფოტო მნახველში, ან ქსელური გაზიარების საქაღალდეში, სადაც სივრცით ფოტოებსა და ვიდეოებს 3D ნიშანი აქვთ.
2. შეეხეთ „ნახვა 3D-ში“-ს ზედა ზოლში (გაზიარების ფოტოს გვერდსაც აქვს).
3. იმერსიული ხედი იხსნება ფოტოთი ბრტყელ ჩარჩოზე თქვენგან 2 მ წინ, თითოეული თვალი საკუთარ სურათს იღებს, სიგანით, რომელიც კამერის ხედვის ველიდან არის აღებული, როცა ფაილი მას იძლევა (სხვა შემთხვევაში 48°). ფაილში ჩაწერილი დისპარიტეტის კორექცია გამოიყენება.
4. ჯოისტიკი ზემოთ ან ქვემოთ მას ადიდებს ან ამცირებს (6°-იანი ნაბიჯებით, 30°-დან 90°-მდე); მარჯვენა ჯოისტიკი მარცხნივ ან მარჯვნივ მას თქვენს წინ აბრუნებს.
5. საინფორმაციო პანელის 3D ღილაკი 3D-სა და „2D (მარცხენა თვალი)“-ს შორის გადართავს. შემობრუნებისა და 360°/180° ღილაკები დამალულია.
6. დასაბრუნებლად დააჭირეთ B ან Y.

სივრცითი ფოტოდან წინა და შემდეგი ჯერ ხელმისაწვდომი არ არის („წინა და შემდეგი სივრცითი ფოტოებისთვის ჯერ ხელმისაწვდომი არ არის“). თუ ჩაფხუტს მეორე თვალის დეკოდირება არ შეუძლია, ფოტო 2D-ში ჩანს შეტყობინებით „მეორე თვალის დეკოდირება ვერ მოხერხდა: ნაჩვენებია 2D-ში“. 3D ხედი ორიგინალ ფაილს აჩვენებს, Immich-ში გაკეთებული რედაქტირების გარეშე.

### ყველა სხვა ადგილას

- **ფოტოები**: ტელეფონები, პლანშეტები და ჩაფხუტის ფანჯარა მარცხენა თვალს აჩვენებენ, როგორც ადრე, ხოლო ტექნიკური დეტალები ახალ სტრიქონს იღებს, მაგალითად „Apple-ის სივრცითი ფოტო, ორი ხედი 3072 x 3072“, ხედვის ველით, როცა ფაილი მას იძლევა. სერვერის ფოტოებს ქრონოლოგიაში ნიშანი არ აქვთ: აპი ამას იგებს, როცა ფოტო იხსნება.
- **ვიდეოები**: ისინი თავიანთ საბაზო ფენას, ერთ თვალს, აპის ყველა პლეერში უკრავენ. Android-ს მეორე ხედის დეკოდირების საჯარო გზა არ აქვს; MV-HEVC-ის საკუთარი დეკოდერის მქონე მოწყობილობას (ზოგიერთ Qualcomm ჩიპზე) ნაცვლად ვიდეო გადაეცემოდა, რაც ჯერ არ არის შემოწმებული. სესიაში ასეთი ვიდეოს პირველი დაკვრა ამბობს „სივრცითი ვიდეო: ეს მოწყობილობა ერთ თვალს უკრავს“ (ქსელური გაზიარების ვიდეოს ნაცვლად 3D ნიშანი აქვს), ხოლო მის ტექნიკურ დეტალებში წერია „Apple-ის სივრცითი ვიდეო (MV-HEVC), ნაჩვენებია 2D-ში“, ფაილში ჩაწერილი თვალით, ბაზისური მანძილით (baseline) და ხედვის ველით.
- **დეკოდერები**: მორგება, დამატებით, „ამ მოწყობილობის ვიდეო დეკოდერები“ შეიცავს MV-HEVC პუნქტს, რომელიც მოწყობილობის შესაბამის დეკოდერს ჩამოთვლის ან ამბობს, რომ ის არ არის.

### ჯერ არ არის შემოწმებული მოწყობილობაზე

ამოცნობა შემოწმდა Apple-ის საკუთარი გამოსახულებების ბიბლიოთეკის მიერ ჩაწერილ სანიმუშო სივრცით ფოტოზე და სინთეტიკურ ფაილებზე, ხოლო 3D კომპოზიცია ერთეულოვანი ტესტებით. ჩაფხუტში ხედი (ორივე თვალი დეკოდირებული, ფოტო სწორად მდგარი და არა სარკისებური, სიღრმე სწორი მიმართულებით, კომფორტი 2 მ-ზე) და ნამდვილი iPhone-ის ფოტოები და ვიდეოები ბილდ 19-ის მოწყობილობაზე ტესტირებაა. ანგარიშები მისასალმებელია, [ჟურნალი](#logs) განყოფილების სტრიქონებით.

## Meta Quest 3 ჩაფხუტში

ადამიანები Quest 3-ს საკუთარი 360° ფოტოებისა და ვიდეოების სანახავად ყიდულობენ, შემდეგ კი კითხულობენ, სად განათავსონ ფაილები, როგორ გადაიტანონ ისინი ჩაფხუტზე კაბელის გარეშე და რომელი პლეერი გამოიყენონ: მაღაზიის 360° და 3D ვიდეო პლეერები ფასიანია.

იგივე Android აპი Quest 3-სა და 3S-ზე ფანჯრის სახით მუშაობს, თქვენი მთელი ბიბლიოთეკით. მისი 360° ღილაკი ხსნის იმერსიულ ხედს, სადაც ფოტო ან ვიდეო ყველა მხრიდან გარს გაკრავთ და ირგვლივ თავის მობრუნებით იყურებით, სტერეოსკოპიული ფაილებისთვის ნამდვილ 3D-ში (Meta Spatial SDK). მედია მოდის თქვენი Immich სერვერიდან, თავად ჩაფხუტიდან, NAS-იდან, მედია სერვერიდან ან ტელეფონიდან და ადგილზე იკვრება (მედია სერვერი და ტელეფონი ბილდ 19-დან, ჯერ ჩაფხუტზე შეუმოწმებელი). ის უფასო და ღია კოდისაა. შემოწმებულია Quest 3-ზე და ერთი მომხმარებლის მიერ Insta360 X4 8K HEVC ვიდეოებით.

### საინფორმაციო პანელი, წინა და შემდეგი

ვიდეოს საინფორმაციო პანელს აქვს დროის ზოლი (პოზიცია, ხანგრძლივობა, რამდენია ბუფერში) ორ 10-წამიან გადახვევის ღილაკს შორის; მის ქვემოთ არის „წინა“, „დაკვრა“ ან „პაუზა“ და „შემდეგი“, შემდეგ „შემობრუნება“, 3D, 360°/180° და „უკან“. ფოტოს იგივე რიგები აქვს დროის ზოლისა და „დაკვრის“ გარეშე. 3D განლაგება და 360°/180° არჩევანი მხოლოდ პანელის ღილაკებზეა.

წინა და შემდეგი გადადის იმ ადგილის 360° მედიაზე, საიდანაც მოხვედით, იმერსიული ხედის დატოვების გარეშე: ქრონოლოგია, 360° სია (გაფილტრული), ალბომი, ქსელური გაზიარების საქაღალდე, ან ჩაფხუტის საკუთარი მედია (On this device). ბრტყელი ფოტოები და ვიდეოები გამოიტოვება. როცა აპში ქრონოლოგიიდან, ალბომიდან ან 360° სიიდან ბრუნდებით, ის იმ მედიაზე ჩერდება, რომელსაც უყურებდით (გაზიარების საქაღალდის გვერდი თქვენ მიერ გახსნილ ფაილზე რჩება), ხოლო ვიდეო, რომელზეც იმერსიული ხედი გახსენით, იქიდან გრძელდება, სადაც შეაჩერეთ.

ბილდ 17-დან მარჯვენა ჯოისტიკი ხედს აბრუნებს, როგორც ჩაფხუტის აპების უმეტესობაში: ერთი ბიძგი 30°-ით აბრუნებს, დაჭერა ბრუნვას აგრძელებს, ამიტომ ის, რაც თქვენს უკანაა, წინ გამოდის თავის ან სკამის მობრუნების გარეშე; წინა და შემდეგი მარცხენა ჯოისტიკზეა. ბილდ 16-დან, ჩაფხუტში მომხმარებლის გამოხმაურების შემდეგ, ჯოისტიკით გადახვევა, შემობრუნება ან წინა/შემდეგი აჩვენებს ერთხაზიან ფენას (დრო, კუთხე ან მედიის სათაური), რომელიც 1,5 წამის შემდეგ ქრება, საინფორმაციო პანელის გამოჩენის ნაცვლად; პანელი კვლავ ჩნდება A-თი, X-ით, სახელურით ან მენიუს ღილაკით. იგივე ბილდი უზრუნველყოფს, რომ პანელის გადართვამ იმუშაოს, როცა კონტროლერები იძინებენ, იღვიძებენ ან ხელების თვალყურის დევნებას უთმობენ ადგილს, და ამ გადასვლებს ჟურნალში იწერს, იხილეთ [ჟურნალი](#logs).

„ნახვა 3D-ში“-თი გახსნილი Apple-ის სივრცითი ფოტო სფეროზე არ თავსდება: ის თქვენს წინ ცურავს, იხილეთ [Apple-ის სივრცითი ფოტოები და ვიდეოები](#apple-spatial-photos-and-videos).

### რას აჩვენებს ჩაფხუტი

ფოტოები ჯერ წინასწარ ხედს აჩვენებენ, შემდეგ ორიგინალს, რომელიც მაქსიმუმ 8192x4096-მდე მცირდება (აპის ზღვარი). ვიდეოები უკრავენ ჩაფხუტზე შენახულ ფაილს, თუ ასეთი არსებობს, ხოლო ქსელური გაზიარების ფაილს აპის ლოკალური ხიდის მეშვეობით; სხვა შემთხვევაში ნაკადს თქვენი სერვერიდან იღებენ ვიდეოს წყაროს პარამეტრის მიხედვით (ბილდ 15-დან; ნაგულისხმევად ორიგინალი, და სერვერის ტრანსკოდირებული ვერსია, როცა ორიგინალის ნაკადად გადაცემა შეუძლებელია ან ის ჩაფხუტის დეკოდერებს აღემატება, იხილეთ [ვიდეოს დეტალები და დეკოდერები](#video-details-decoders-and-why-a-video-stutters)). ბილდ 16-დან აქ კამერების დაუმუშავებელი ფაილებიც იხსნება, აპის მიერ შეკერილი; დაუმუშავებელი ვიდეოსთვის 3D და 360°/180° ღილაკები დამალულია, რადგან ის ერთი სრული სფეროა.

3D განლაგებები, ზემოთ და ქვემოთ და გვერდიგვერდ, 360° და VR180, 3D-ში ნაჩვენებია, თითოეული თვალი კადრის თავის ნახევარს იღებს. განლაგება ფაილიდან მოდის, როცა ფაილი მას აცხადებს (ვიდეოები), სხვა შემთხვევაში ფორმიდან ივარაუდება (კვადრატი: ზემოთ და ქვემოთ, 4:1: გვერდიგვერდ); როცა ის არასწორია, გამოიყენეთ საინფორმაციო პანელის 3D ღილაკი.

### თუ სურათი თქვენკენ არ არის მიმართული

მოაბრუნეთ ის მარჯვენა ჯოისტიკით (ან საინფორმაციო პანელის „შემობრუნება“ ღილაკით), სანამ მისი ცენტრი თქვენს წინ არ აღმოჩნდება. კუთხე ნაჩვენებია როგორც „სურათი შემობრუნებულია N გრადუსზე“, პანელზე ან ერთხაზიან ფენაზე, როცა პანელი დამალულია: გამოაქვეყნეთ ეს რიცხვი [issue-ში](https://github.com/freeKC/Immuch360/issues) თქვენი კამერის მოდელთან ერთად, რომ ის ნაგულისხმევ მნიშვნელობად იქცეს. საწყისი ორიენტაცია ჯერ ყველა კამერისთვის არ არის დადასტურებული.

### იმერსიული ხედის შეზღუდვები

- **წინა და შემდეგი**: ისინი წინ ეძებენ მაქსიმუმ 400 მედიას ქრონოლოგიაში და 50 ფაილს გაზიარების საქაღალდეში, მაქსიმუმ 12 წამის განმავლობაში; ამის შემდეგ პანელი ამბობს, რომ წინა ან შემდეგი 360° მედია არ არის. გაზიარების საქაღალდე ფაილ-ფაილ მოწმდება, ამიტომ ბევრი ბრტყელი ფაილის შემდეგ პირველი 360° ფაილის პოვნას შეიძლება რამდენიმე წამი დასჭირდეს. სივრცითი ფოტოდან ისინი ჯერ ხელმისაწვდომი არ არის.
- **3D არჩევანი**: 3D ღილაკით არჩეული განლაგება მნახველის დახურვისას არ ინახება; 360°/180° არჩევანი ინახება ბიბლიოთეკის მედიისთვის.
- **გადახვევა**: ვიდეო, რომლის წყაროც ბაიტების დიაპაზონის მოთხოვნებს არ პასუხობს, ვერ გადაიხვევა; პანელი ამას ამბობს.
- **ბრტყელი ვიდეოები**: ბრტყელი (არა 360°) სტერეოსკოპიული ვიდეო ფანჯარაში იკვრება ორივე თვალის ხილვადობით; იმერსიული 3D ხედი 360° და VR180 მედიისთვისაა.
- **სხვა**: კოდეკები, რომლებსაც ჩაფხუტი დეკოდირებს, მაღაზია, ნებართვები და APK-ის ზომა აღწერილია [Meta Quest 3](#meta-quest-3) განყოფილებაში.

## იპოვეთ თქვენი 360° კადრები: 360° სია

360° კადრები ყველა სხვა ფოტოსთან არის შერეული, და ადამიანები Immich-ს სთხოვენ სფეროებისა და პანორამების გაფილტვრის გზას ([დისკუსია #12824](https://github.com/immich-app/immich/discussions/12824)). Immich აპს ასეთი სია არ აქვს.

Immuch360 360° ნიშანს ათავსებს 360° ფოტოების მინიატურებზე (ქსელური გაზიარების საქაღალდეში 360° ვიდეოებზეც) და 360° პუნქტს ბიბლიოთეკის ჩანართის ზედა ნაწილში. ბილდ 18-დან ეს სია, სერვერის არსებობისას, შეიცავს სერვერის მიერ 360°-ად მონიშნულ ფოტოებსა და ვიდეოებს, დაუმუშავებელ Insta360 ფაილებს მათი სახელით, 360° კამერის მიერ თავად შეკერილ ფოტოებს და იმათ, რომლებიც 360°-ად სანახავად აირჩიეთ, დამატებით იმას, რაც მოწყობილობის ძიებამ იპოვა; სერვერის გარეშე იმას, რაც მოწყობილობის ძიებამ იპოვა, და იმათ, რომლებიც 360°-ად სანახავად აირჩიეთ. თითოეული ერთხელ ჩნდება, სადაც არ უნდა იყოს მისი ასლები, უახლესი პირველი.

7. გახსენით ფოტო ან ვიდეო. Quest-ის იმერსიულ ხედში წინა და შემდეგი გაფილტრულ სიას მიჰყვება.

## ვიდეოს დეტალები, დეკოდერები და რატომ ჭედავს ვიდეო

ადამიანები კითხულობენ, რომელ კოდეკს, ზომასა და ბიტრეიტს უკრავს Quest 3, და რატომ ჭედავს 5.7K ექსპორტი ჩაფხუტში, როცა ტელეფონზე უპრობლემოდ იკვრება. პასუხი აპარატული დეკოდერია: Quest 3-ის (XR2 Gen 2) H.264 დეკოდერის ზღვარი დაახლოებით 4096x2304-ია, ამიტომ 5760x2880 H.264 ვიდეო (დონე 6.0, დაახლოებით 200 მბიტ/წმ, Insta360-ის ჩვეულებრივი ექსპორტი) ჩაფხუტზე დაახლოებით 17 fps-ით დეკოდირდება, ბლოკური დამახინჯებებით, მაშინ როცა იგივე ფაილი ტელეფონზე კარგად იკვრება. იგივე ვიდეო HEVC-ში (H.265) ჩაფხუტზე კარგად იკვრება: Insta360 X4 8K HEVC ვიდეო (7680x3840, 29,97 fps, 210 მბიტ/წმ, Main პროფილი, დონე 6.1, 8 ბიტი) იმერსიულ ხედში შეუფერხებლად იკვრება, თავისი საწყისი გარჩევადობით და ტრანსკოდირების გარეშე (Quest 3-ის ერთი მომხმარებლის ცნობით).

Immich აპს აქვს ერთი „Force original video“ გადამრთველი და მხოლოდ კოდეკს აჩვენებს. Immuch360 აჩვენებს, რა არის ვიდეო და რას დეკოდირებს მოწყობილობა, და ირჩევს ფაილს, რომელიც დაიკვრება.

### ვიდეოს დეტალების წაკითხვა

1. გახსენით ვიდეო და გადაასრიალეთ ზემოთ: დეტალები სურათის ქვემოთ ჩნდება.
2. კოდეკი: კოდეკი თავისი პროფილითა და კოდეკების სტრიქონით, კადრის ზომა და კადრების სიხშირე, მაგალითად „H.264 High (avc1.640033) • 3840 x 1920 • 30 fps“, როგორც ზემოთ მოცემულ სურათზე.
3. ბიტრეიტი (ბილდ 18-დან): ვიდეო ტრეკის ბიტრეიტი, ან ის, რასაც ფაილი აცხადებს; სხვა შემთხვევაში მონიშნულია „მთელი ფაილი, ხმის ჩათვლით“ ან „შეფასებულია ფაილის ზომით“.
4. გამოსახულება (ბილდ 18-დან): ბიტის სიღრმე, SDR ან HDR გადაცემის ფუნქცია (HLG, PQ, Dolby Vision) და ფერთა სივრცე.
5. დეკოდირდება ამ მოწყობილობაზე: დიახ ან არა, აპარატული ან პროგრამული, დეკოდერის მიერ მიღებული უდიდესი ზომა, და „(პროფილი)-სთვის დეკოდერი არ არის“, როცა მოწყობილობას კოდეკი აქვს, მაგრამ ეს პროფილი არა.

სტრიქონი მხოლოდ ფაილის წაკითხვის შემდეგ ჩნდება და მხოლოდ იმაზე, რასაც ფაილი ამბობს. Apple-ის სივრცითი ფოტო ან ვიდეო საკუთარ სტრიქონს იღებს, იხილეთ [Apple-ის სივრცითი ფოტოები და ვიდეოები](#apple-spatial-photos-and-videos).

### რას დეკოდირებს მოწყობილობა

მორგება, დამატებით, „ამ მოწყობილობის ვიდეო დეკოდერები“ (ბილდ 15-დან) ჩამოთვლის, რას დეკოდირებს ტელეფონი ან ჩაფხუტი: კოდეკი, აპარატული ან პროგრამული, უდიდესი ზომა, კადრების სიხშირე, ხოლო ბილდ 18-დან პროფილები (Main, Main 10, HDR10). ბილდ 19-დან მას აქვს MV-HEVC პუნქტი, Apple-ის სივრცითი ვიდეოების კოდეკი. კოპირების ღილაკი სიას ბუფერში ათავსებს შეცდომის ანგარიშისთვის.

### ორიგინალის ან ტრანსკოდირებული ნაკადის არჩევა

1. გახსენით მორგება, Asset Viewer, შემდეგ ვიდეოები.
2. „ვიდეოს წყარო“-ში („რომელი ფაილი ითამაშება, როცა სერვერს აქვს ტრანსკოდირებული ასლი“) აირჩიეთ „ორიგინალი, როცა ეს მოწყობილობა მას დეკოდირებს“, „ყოველთვის ორიგინალი“ ან „ყოველთვის ტრანსკოდირებული ნაკადი“.

ბილდ 15-დან არჩევანი სერვერის ყველა ვიდეოზე ვრცელდება: ბრტყელ პლეერზე, 360° და Spatial პლეერებზე და Quest-ის იმერსიულ ხედზე. სანამ არ აირჩევთ, ტელეფონი ინარჩუნებს იმას, რასაც ძველი „Force original video“ გადამრთველი ამბობდა (ნაგულისხმევად გამორთული: ტრანსკოდირებული ნაკადი, რომელიც თავად ორიგინალია, როცა სერვერს ის არ ტრანსკოდირებია), ხოლო Quest ორიგინალს უკრავს, როცა ჩაფხუტს მისი დეკოდირება შეუძლია. შემოწმება ფაილიდან კოდეკს, ზომასა და კადრების სიხშირეს კითხულობს და აპარატულ დეკოდერებს ადარებს (Quest 3-ზე H.264 გაზომილი 4096x2304-ით არის შეზღუდული). პლეერი, რომელსაც ორიგინალის დეკოდირება არ შეუძლია, ტრანსკოდირებულ ნაკადზე გადადის შეტყობინებით: „ითამაშება ტრანსკოდირებული ნაკადი: ორიგინალი (კოდეკი და ზომა) აღემატება ამ მოწყობილობის დეკოდირების შესაძლებლობებს“.

ჩაფხუტში იმერსიული ხედი ორიგინალს იწყებს და, პირველ კადრებზე, სერვერის ტრანსკოდირებულ ნაკადზე გადადის, როცა ორიგინალი დეკოდერებს აღემატება, და ამას საინფორმაციო პანელზე ამბობს; როცა ტრანსკოდირებული ნაკადი არ არის, როცა ის მაინც ძალიან დიდია, ან როცა ფაილი ჩაფხუტიდან ან ქსელური გაზიარებიდან მოდის, საინფორმაციო პანელი ამას 10 წამის განმავლობაში ამბობს, იმის მითითებით, თუ რა უნდა შეიცვალოს. ბილდ 14, რომელიც Horizon Store-ს წარედგინა, მხოლოდ 4096x2304-ზე დიდ H.264-ს ამოწმებს და შემდეგ იმავე გზით სერვერის დაკვრის ნაკადს ცდის.

დაუმუშავებელი ორობიექტივიანი ვიდეოებისთვის შემოწმება ერთდროულად ორ დეკოდერს ითხოვს, ხოლო ბილდ 19-დან პროგრამულ დეკოდერს არ აძლევს ორ ნაკადს, რომელთაგან თითოეული 2048x2048-ზე დიდია, იხილეთ [კამერების დაუმუშავებელი 360° ფაილები](#raw-360-camera-files-without-the-cameras-app).

### მიეცით ჩაფხუტს ვიდეო, რომლის დეკოდირებაც შეუძლია

Immich-ში გადადით ადმინისტრაცია, მორგება, Video Transcoding Settings (ვიდეოს ტრანსკოდირების პარამეტრები) და აირჩიეთ ერთ-ერთი:

- **ყველა H.264 ვიდეო ხელახლა კოდირებული HEVC-ში**: დააყენეთ Video codec (ვიდეო კოდეკი) HEVC-ზე და Target resolution (სამიზნე გარჩევადობა) Original-ზე (ნაგულისხმევი 720p 360° ვიდეოს 1440x720-მდე შეამცირებდა), ხოლო Accepted video codecs-ში (მისაღები ვიდეო კოდეკები) მხოლოდ HEVC დატოვეთ. ბიბლიოთეკის ყველა H.264 ვიდეო ტრანსკოდირდება, არა მხოლოდ 360° ვიდეოები, და ჩაფხუტი სრული გარჩევადობის HEVC-ს იღებს.
- **მხოლოდ ის, რაც 1440p-ზე დიდია**: Accepted video codecs-ში H.264 დატოვეთ, Transcode policy (ტრანსკოდირების პოლიტიკა) დააყენეთ „Videos higher than target resolution or not in an accepted format“-ზე (სამიზნეზე მაღალი გარჩევადობის ან არამისაღები ფორმატის ვიდეოები) და Target resolution 1440p-ზე, სასურველია Video codec HEVC-ზე დაყენებით. ყველაფერი უფრო დიდი ტრანსკოდირდება და ჩაფხუტი 2880x1440-ს იღებს. ჩვეულებრივი 4K ვიდეოებიც 1440p-მდე ტრანსკოდირდება.

ეს პარამეტრები მთელ სერვერზე, ყველა მომხმარებელსა და ყველა აპზე ვრცელდება, ხოლო დიდი ბიბლიოთეკის ხელახალ კოდირებას საათობით CPU დრო და დამატებითი დისკის ადგილი სჭირდება; ორიგინალები არ იცვლება. HEVC-ის მხარდაჭერის არმქონე ბრაუზერები (Firefox სისტემების უმეტესობაზე, Chrome აპარატული HEVC-ის გარეშე) Immich-ის ვებ აპში HEVC ტრანსკოდირებას ვერ დაუკრავენ. ახალი ვიდეოებისთვის ყველაზე მარტივი გამოსავალია H.265-ში ექსპორტი Insta360 აპიდან ან Studio-დან. ამ პარამეტრების შეცვლის შემდეგ არსებული ვიდეოები ხელახლა უნდა ტრანსკოდირდეს: ადმინისტრაცია, Job Queues (დავალებების რიგები) (Immich-ის ძველ ვერსიებში დავალებები), Transcode videos (ვიდეოების ტრანსკოდირება), ყველა.

ალტერნატივა, და ერთადერთი ქსელური გაზიარების ან ჩაფხუტის ფაილებისთვის (მათ ტრანსკოდირებული ნაკადი არ აქვთ), არის ექსპორტის HEVC-ში ხელახლა კოდირება მის ატვირთვამდე ან გაზიარებაზე კოპირებამდე:

```bash
ffmpeg -i VID_360.mp4 -c:v libx265 -crf 20 -preset medium -tag:v hvc1 -c:a copy -movflags +faststart VID_360_hevc.mp4
exiftool -overwrite_original -tagsFromFile VID_360.mp4 -XMP-GSpherical:all VID_360_hevc.mp4
exiftool -ProjectionType VID_360_hevc.mp4        # must print: equirectangular
```

`-tag:v hvc1` HEVC ტრეკს ისე მონიშნავს, როგორც Apple-ის მოწყობილობები და ბრაუზერები ელიან, `-c:a copy` ხმას ისე ინარჩუნებს, როგორც არის. ffmpeg ექსპორტის 360° ტეგს კარგავს, exiftool-ის სტრიქონი მას უკან აკოპირებს; მის გარეშე Immich ვიდეოს ბრტყელ ვიდეოდ აჩვენებს.

### ორიგინალები, რომელთა ნაკადად გადაცემა შეუძლებელია

როცა სერვერი ორიგინალზე HTTP Range მოთხოვნებს უგულებელყოფს და MP4 ინდექსი (moov) ფაილის ბოლოშია, პირველ კადრამდე მთელი ფაილის ჩამოტვირთვა იქნებოდა საჭირო, ამიტომ აპი სერვერის დაკვრის ნაკადზე გადადის. Immich-ის წინ მდგარმა უკუპროქსიმ (reverse proxy), რომელიც პასუხებს ბუფერში ინახავს ან Range სათაურებს შლის, შეიძლება ეს გამოიწვიოს.

## დანარჩენი ყველაფერი Immich-ია

ყველაფერი, რასაც ოფიციალური Immich მობილური აპი აკეთებს, აქაც არის: მარქაფი, ქრონოლოგია, ალბომები, ძებნა, გაზიარება, პარტნიორები, ყველაფერი თქვენს სერვერთან სინქრონიზებული, იგივე სერვერითა და იგივე ანგარიშით, რაც ვებ აპში. ## Meta Quest 3

Immuch360 ასევე მუშაობს Meta Quest 3-სა და 3S-ზე (Horizon OS v69 ან უფრო ახალი; Horizon Store-ის ბილდი მხოლოდ ამ ორისთვისაა მითითებული; უნივერსალური `-release.apk` ასევე უნდა დაყენდეს Quest 2-ზე ან Quest Pro-ზე, გამოუცდელია). მისი გამოყენება აღწერილია [Meta Quest 3 ჩაფხუტში](#in-the-meta-quest-3-headset) განყოფილებაში; ეს განყოფილება ეხება დაყენებას და იმას, რაც ჩაფხუტზე განსხვავდება.

ჩაფხუტის ბილდი სერვერებთან მხოლოდ HTTPS-ით ურთიერთობს, ან უბრალო HTTP-ით სახლის ქსელის სახელებთან (`.local`, `.lan`, `.home`, `.internal`, `.home.arpa`) და თავად ჩაფხუტთან, როგორც ამას Horizon Store მოითხოვს. სერვერი, რომელიც IP-ით უბრალო HTTP მისამართად არის აკრეფილი, მაგალითად `http://192.168.1.10:2283`, ამ ბილდის მიერ უარყოფილია: გამოიყენეთ HTTPS, სახლის ქსელის სახელი (`nas.local`), ან უნივერსალური `-release.apk`, რომელიც ტელეფონების ღია პოლიტიკას ინარჩუნებს. ლოკალური ქსელის უბრალო HTTP მისამართზე არსებულ WebDAV, DLNA და ტელეფონის გაზიარებებს ეს არ ეხება: აპი მათ თავად კითხულობს და თავის პლეერებს მხოლოდ თავისი ლოკალური ხიდის მისამართს აძლევს (DLNA-სა და ტელეფონის გაზიარებისთვის, რომლებიც ბილდ 19-ში ახალია, ეს ჩაფხუტზე ჯერ დასადასტურებელია).

<a id="install"></a>
### დაყენება

Horizon Store-ის განცხადება Meta-ს განხილვას ელოდება, წარდგენილია ბილდ 14-ით; სანამ ის დამტკიცდება, ხელით დააყენეთ რელიზის `-quest-release.apk` ფაილი (აგებულია ჩაფხუტისთვის: 64 ბიტი, სამიზნე SDK 34, მხოლოდ ის ნებართვები, რომლებსაც ჩაფხუტი იყენებს), ან უნივერსალური `-release.apk`:

1. ერთხელ ჩართეთ დეველოპერის რეჟიმი. Meta Horizon-ის ტელეფონის აპში გახსენით Devices (მოწყობილობები), აირჩიეთ ჩაფხუტი, შემდეგ Headset settings (ჩაფხუტის პარამეტრები), შემდეგ Developer mode (დეველოპერის რეჟიმი). ამისთვის საჭიროა დეველოპერის ანგარიში, რომელიც უფასოა developers.meta.com-ზე. კომპიუტერზე ასევე გჭირდებათ adb (Android SDK Platform Tools) ან SideQuest.
2. დაუკავშირეთ ჩაფხუტი კომპიუტერს USB-C კაბელით. ჩაფხუტში მიიღეთ „Allow USB debugging“ (USB-ით გამართვის დაშვება).
3. დააყენეთ APK:

   ```bash
   adb devices                      # the headset must be listed as "device"
   adb install -r Immuch360-v<version>-quest-release.apk   # for example Immuch360-v3.3.0-rc.0-19-quest-release.apk
   ```

4. ჩაფხუტში გახსენით Library (ბიბლიოთეკა), აირჩიეთ „Unknown sources“ (უცნობი წყაროები) ფილტრი და გაუშვით Immuch360.
5. ხელით დაყენებული APK თავისით არ განახლდება: შემდეგი რელიზი იგივე გზით დააყენეთ (`adb install -r` შესვლასა და პარამეტრებს ინარჩუნებს). Horizon Store-ის ვერსია და GitHub-ის APK სხვადასხვა გასაღებით არის ხელმოწერილი, ამიტომ ჩაფხუტი ერთს მეორეზე არ აყენებს: გადასართავად ჯერ წაშალეთ აპი, რაც შესვლას, პარამეტრებსა და ქსელური გაზიარებების სიას კარგავს.

### ფანჯარაში

მთელი აპი ზომაცვალებადი 2D ფანჯრის სახით მუშაობს: შესვლა, ქრონოლოგია, ალბომები, ძებნა, ბიბლიოთეკის ჩანართი (360° სია, On this device, ქსელური გაზიარებები), პარამეტრები, და ფოტოებისა და ვიდეოების მნახველები, სადაც ბრტყელი ფოტოები და ვიდეოები იკვრება. ჩაფხუტზე 360° ღილაკი და ⋮ მენიუს „ნახვა 360°-ად“ პირდაპირ იმერსიულ ხედს ხსნიან ტელეფონების სფერული მნახველის ნაცვლად, ხოლო Spatial 2.5D ღილაკი და მისი პარამეტრი არ ჩანს. ბილდ 19-დან Apple-ის სივრცით ფოტოს აქვს „ნახვა 3D-ში“ ღილაკი, ხოლო „ამ ტელეფონის გაზიარება ქსელში“ ფილა არ ჩანს: ჩაფხუტი არის ის, ვინც ტელეფონის გაზიარებას კითხულობს.

## ააგეთ თავად

აგების ჯაჭვი იგივეა, რაც Immich mobile-ის (Flutter 3.47, მართული [mise](https://mise.jdx.dev)-ით):

```bash
git clone https://github.com/freeKC/Immuch360.git
cd Immuch360/mobile
mise install
mise run install
mise run codegen
flutter build apk --release --flavor phone                                   # phones: the universal APK of the GitHub releases (add --split-per-abi for the per ABI files)
flutter build appbundle --release --flavor phone                             # the App Bundle sent to Google Play (also mise run build:android)
flutter build apk --release --flavor quest --target-platform android-arm64 --android-project-arg arm64only=true   # Meta Quest 3: the -quest-release.apk of the releases (also mise run build:quest)
flutter build ios --release                                                  # iPhone and iPad, on a Mac with Xcode and your own signing team
```

მაღაზიების ეკრანის სურათები გადაიღება სიმულატორის debug ბილდებზე, რომლებიც აგებულია `--dart-define=IMMUCH_SCREENSHOTS=true`-ით, რაც მხოლოდ debug ბანერს მალავს. Android-ის ორი ვარიანტი (flavor) ერთი და იგივე აპია. `quest` SDK 34-ს უმიზნებს და მხოლოდ იმ ნებართვებს ინარჩუნებს, რომლებსაც ჩაფხუტი იყენებს (ფოტოები, ვიდეოები, შეტყობინებები): მედიის მართვა, ფონური მდებარეობა, ძველი მეხსიერება, აუდიო, მედიის მდებარეობა, მოწყობილობის მდებარეობა და კამერა წაშლილია `android/app/src/quest/AndroidManifest.xml`-ში, რადგან Meta Horizon Store პირველ ორს უარყოფს და ყველა სხვა მგრძნობიარე ნებართვისთვის დასაბუთებას ითხოვს; იგივე ფაილი მხარდაჭერილ მოწყობილობებად Quest 3-სა და 3S-ს ასახელებს და უბრალო HTTP-ს თავად ჩაფხუტითა და სახლის ქსელის სახელებით ზღუდავს. APK მხოლოდ 64-ბიტიანია მისი ბრძანების ხაზის ორი დამატებითი არგუმენტის გამო (`--target-platform android-arm64 --android-project-arg arm64only=true`). `phone` არის ის, რასაც Google Play მოითხოვს. საკუთარ Mac-ზე iOS-ისთვის ასაგებად გამოიყენეთ Xcode და თქვენი საკუთარი ხელმოწერის გუნდი; Xcode 26-ით ჯერ ერთხელ გაუშვით `xcodebuild -downloadComponent MetalToolchain`, რადგან Spatial shader-ებს ის სჭირდება. Mac-ის გარეშე iOS ბილდები Codemagic-ზე (ჰოსტინგის Mac) ეშვება ამ საცავის `codemagic.yaml` ფაილიდან. Android-ის რელიზის ბილდები GitHub Actions-ზე ეშვება (`.github/workflows/immuch360-release.yml`).

ამ საცავში საიდუმლო არ ინახება: Android-ის ხელმოწერის გასაღები დაშიფრული GitHub Actions-ის საიდუმლოებების სახით ინახება, ხოლო Apple-ის ხელმოწერის მასალა დაშიფრული ცვლადების სახით Codemagic-ზე. სამუშაო ნაკადის ფაილები მათ მხოლოდ სახელით მიმართავენ. თქვენი საკუთარი `android/key.jks`-ის გარეშე რელიზის ბილდი debug გასაღებით იხელმოწერება და ვერ დაყენდება GitHub-იდან ან მაღაზიიდან მიღებულ ასლზე (ჯერ ის წაშალეთ); debug ბილდი გვერდით დგება Immuch360 debug სახელით. Meta Horizon Store-ის ასლი რელიზის `quest` APK-ია, ხელმოწერილი სხვა გასაღებით, იმით, რომლითაც მაღაზიის აპი პირველად დარეგისტრირდა, ამიტომ ისიც ვერ დაყენდება ხელით დაყენებულ APK-ზე, და პირიქით.

## ჟურნალი

Android-სა და Quest-ზე `adb logcat` აჩვენებს ჩაფხუტის იმერსიულ ხედს `Immuch360` ტეგით (ბილდ 19-დან ასევე Apple-ის სივრცითი ფოტოს ორ თვალს: როგორ დეკოდირდა მეორე თვალი, ჩამოჭრა, სად განთავსდა ფოტო), დეკოდერების შემოწმებებს `VideoDecoders`-ით, გვერდიგვერდ დაუმუშავებელი ვიდეოს შეკერვას `DualFisheyeEffect`-ით, და ბილდ 18-ის ორობიექტივიან დაკვრას `TwoLensPlayer`, `TwoLensCompositor` და `LensVideoRenderer` ტეგებით:

```bash
adb logcat -c
# reproduce the problem, then
adb logcat -d -v time -s Immuch360 VideoDecoders DualFisheyeEffect TwoLensPlayer TwoLensCompositor LensVideoRenderer
adb logcat -d -v time > quest-full.log      # everything, including crashes and decoder errors (it can contain your server address, check before sharing)
adb logcat -d -v time -s PhoneShareService PhoneShareApi   # on the phone that shares itself (from build 19)
```

ბილდ 19-დან DLNA კლიენტი, ტელეფონის გაზიარება და Apple-ის სივრცითი მედიის ამოცნობა ასევე წერენ აპის საკუთარ ჟურნალში (ჟურნალი, ზედა მარჯვენა კუთხეში პროფილის სურათის მენიუში), `Ssdp`, `DlnaFileSystem`, `NetworkBrowserPage`, `PhoneShare`, `PhoneShareServer`, `AppleSpatialService`, `HeicStereoProbe` და `NetworkMediaService` სახელებით. ჟურნალის სტრიქონები მოწყობილობაზე რჩება, თუ თავად არ დააკოპირებთ.
