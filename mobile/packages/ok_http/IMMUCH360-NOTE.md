`pkgs/ok_http` in https://github.com/mertalev/http at commit `549c24b0a4d3881a9a44b70f4873450d43c1c4af`, the git ref

upstream Immich and an upstream bump shows in a merge.

Left out: `example/` and the `.metadata` of the Flutter tool, and the dev dependencies of `pubspec.yaml`
(dart_flutter_team_lints, jnigen). `pubspec.yaml`: `publish_to: none`, version `0.1.1-wip+immuch360`. The code is
unchanged but for punctuation (three comments of `lib/src/ok_http_client.dart` and `lib/src/ok_http_web_socket.dart`
had a spaced hyphen, the fork's texts having none) and for the patch below.

The JNI bindings (`lib/src/jni/bindings.dart`, generated by jnigen) are those of upstream, untouched. They look the
Kotlin classes up by name and signature at run time, so the bound members of the Kotlin side must keep their
signatures; the patch below keeps them:
- `RedirectInterceptor.Companion.addRedirectInterceptor(OkHttpClient.Builder, int, boolean, RedirectReceivedCallback):
  OkHttpClient.Builder`
- `RedirectReceivedCallback.onRedirectReceived(Response, String)`

A change to a bound member needs the bindings generated again (`dart run jnigen --config jnigen.yaml`, which reads
`example/` for the Gradle dependencies: take it from the same upstream commit for that run). Members added to the
Kotlin side that Dart does not call need nothing.

When upstream Immich moves the ok_http ref of `mobile/pubspec.yaml`, copy `pkgs/ok_http` of the new ref here and apply
the changes below again (every change is marked `Immuch360`). The copy can go once upstream ok_http follows a relative
`Location` itself.
